GRPO: Group-Relative Policy Optimization

PPO can align LLMs to human preferences — but it needs four heavyweight models and a learned critic. GRPO asks a simpler question: what if the group average of sampled completions is the baseline? Same clipped policy update, zero value network, and the algorithm behind DeepSeek-R1.

00 — THE TURNING POINT

From Alignment to Reasoning

Before GRPO, reinforcement learning on LLMs mostly meant RLHF: train a reward model on human preferences, run PPO, nudge the policy toward responses people like. That worked for chat alignment — but there was no strong link between RL and reasoning.

GRPO changed that. Released alongside DeepSeek-R1 in early 2025, it showed that a stripped-down PPO variant — no critic, group-normalized advantages, verifiable rewards on math — could induce chain-of-thought reasoning without supervised fine-tuning on reasoning traces. Everything in chapters 04–10 built toward this moment: policy gradients (Ch.08), PPO clipping (Ch.09–10), LLM-as-agent notation (Ch.10). GRPO is where the stack finally clicks for reasoning models.

This chapter is the penultimate step. Ch.12 applies GRPO end-to-end to train a reasoning model. If GRPO feels fuzzy here, nothing in the final chapter will land — so we go deep.

01 — THE PPO PROBLEM

Four Models Is Too Many

Recall the LLM-as-agent framing from the prior lecture: prompt X, completion Y, policy πθ (the LLM itself), token-level actions, sparse outcome reward at the end. PPO plugs directly into this — but at a steep cost.

The PPO clipped surrogate (from Ch.09–10) limits how far the policy can move per update:

LPPO = E[ min(ρθ·A,   clip(ρθ, 1−ε, 1+ε)·A) ]

That part is kept in GRPO. The expensive part is computing A.

For each prompt, PPO:

  1. Sample one completion from the policy LLM.
  2. Score it with a fixed reward model R.
  3. Estimate advantage via GAE — which requires a separate value/critic model V trained alongside the policy.
  4. Update using the clipped surrogate objective, keeping the policy close to a frozen reference πref.

That is four models in memory: policy, reference, reward, and value. The value model exists because advantage compares "how good was this completion?" against "what does the policy normally get?" — and that baseline requires estimating expected return, which PPO learns with a critic.

A(s, a) = Q(s, a) − Vπ(s)   // PPO needs V to compute advantage

PPO succeeded for RLHF (ChatGPT-style alignment), but researchers noticed the same pain point: training two large networks (policy + critic) on every step consumes enormous GPU memory. For billion-parameter LLMs, the critic is not a small add-on — it is often another full-sized transformer.

PPO pipeline (4 models) Prompt X ──► πθ ──► one completion Y │ │ │ ├──► Reward model R ──► r │ │ │ └──► Value model V ──► V(s) ──► GAE advantage A │ └──► Reference πref (KL / drift control) │ ▼ Update πθ AND train Vφ # two trainable giants

The question GRPO answers: Can we compute advantages without a value function at all — without training a second giant model on every RL step?

02 — THE KEY INSIGHT

The Group Average Is the Baseline

In classical actor-critic methods, V(s) estimates the average reward the policy expects from state s — averaged over all possible completions. That expectation is hard to compute from a single sample, which is exactly why you train a value network.

GRPO's insight is embarrassingly simple: sample multiple completions instead of one, score each, and use the empirical mean of those rewards as your baseline.

PPO baseline

Learned value function Vφ(s) — a separate neural network updated every step. Estimates expected reward over the full completion distribution.

GRPO baseline

Group mean mean(r1, …, rG) — computed from G samples for the same prompt. No extra model. Monte Carlo estimate of the baseline.

Think of it this way: if you ask "Roger has 5 tennis balls, buys 2 cans of 3… how many?" and sample 64 answers, some get reward 1 (correct) and some get 0 (wrong). The average reward in that group is what the policy "normally" achieves on this prompt. Completions above the group mean get positive advantage; below get negative. No critic needed.

Simplicity is the feature. GRPO trades the critic's modeling capacity for sampling diversity. With large G, the group mean is a low-variance baseline — and you were going to sample multiple completions for training anyway.

03 — GROUP SAMPLING

Sample G Completions Per Prompt

Standard PPO: one completion per prompt X. GRPO: sample G independent completions Y1, …, YG from the current policy πθ (with temperature > 0 for diversity).

Prompt X ──► πθ ──► sample Y1, Y2, …, YG (same prompt, G different rollouts) │ │ │ ├──► r1 = R(X, Y1) │ ├──► r2 = R(X, Y2) │ └──► … rG = R(X, YG) │ │ └──────────────────────────────────────┴──► Âi = normalize(ri within group)

In practice, G is large — DeepSeek and follow-up work often use G = 64 or more. The demo below uses G = 8 so you can read every number.

Rewards can come from:

  • Reward model — human-preference-trained scorer (RLHF-style GRPO).
  • Verifiable checker — binary correct/incorrect for math, code, logic (DeepSeek-R1-Zero style). No reward model at all — just 2 models: policy + reference.

For reasoning on math, binary rewards are ideal: r ∈ {0, 1}, low variance within groups that mix right and wrong answers, and no risk of the reward model diverging from ground truth.

Worked Example: G = 4 Completions

Group statistics: mean = (1+0+0+0)/4 = 0.25, std ≈ 0.433. Normalized advantages:

Â1 = (1 − 0.25) / 0.433 ≈ +1.73  → reinforce   |   Â2,3,4 = (0 − 0.25) / 0.433 ≈ −0.58  → penalize

Only the correct completion beats the group average — exactly the signal PPO would need a critic to approximate. GRPO gets it from four extra rollouts.

04 — GROUP-RELATIVE ADVANTAGE

Normalize Rewards Within the Group

For each prompt, collect rewards r1, …, rG. GRPO defines the advantage of sample i by subtracting the group mean and dividing by the group standard deviation:

Âi = ( ri − mean(r1, …, rG) ) / ( std(r1, …, rG) + ε )

When std = 0 (all rewards identical — e.g. all wrong on a hard problem), implementations add a small ε or skip the update. The normalization serves two roles:

  • Baseline subtraction — replaces V(s) from actor-critic.
  • Scale control — advantages have unit variance across prompts, stabilizing gradients when reward scales differ (binary vs. continuous RM scores).

Classical advantage: A = Q − V. In outcome-supervised GRPO with one terminal reward per completion, Q is just ri and V is approximated by the group mean. Same math, different estimator.

Ai ≈ ri − (1/G) Σj=1G rj   before normalization

05 — THE GRPO OBJECTIVE

Same Clipping as PPO, Different Advantage

GRPO keeps PPO's trust-region clipping on the probability ratio — the innovation is entirely in how Â is computed. The per-sample surrogate (for completion i, token t) uses the ratio between new and old policy:

ρθ(Yi | X) = πθ(Yi | X) / πθold(Yi | X)

For autoregressive LLMs, this factorizes over tokens: πθ(Y|X) = ∏t πθ(yt | X, y<t).

LCLIPi = min( ρθ · Âi,   clip(ρθ, 1−ε, 1+ε) · Âi )

GRPO adds a KL penalty to the reference policy (PPO for LLM alignment often relied on clipping alone; GRPO explicitly penalizes drift from πref):

KL(πθ || πref) = EX,Y [ log πθ(Y|X) − log πref(Y|X) ]

The full GRPO objective averages over the group:

LGRPO = (1/G) Σi=1G LCLIPi  −  β · KL(πθ || πref)

Maximize LGRPO (or minimize its negative). Hyperparameters: clip ε ≈ 0.2 (same as PPO), KL coefficient β tuned for stability, group size G ≈ 8–64+.

Token-Level Surrogate (LLM Form)

When written for language models, the inner sum runs over output tokens. For sample i and token t:

ρθ,t = πθ(yi,t | X, yi,<t) / πθold(yi,t | X, yi,<t)
LCLIPi = Σt min( ρθ,t · Âi,   clip(ρθ,t, 1−ε, 1+ε) · Âi )

Positive Âi pushes token probabilities up (if ρ is within clip); negative Âi pushes them down — the same "climb or descend the mountain" intuition from PPO, but the direction comes from group rank instead of GAE.

Process supervision variant: When rewards are assigned to intermediate chain-of-thought steps (not just the final answer), advantages are computed per step with normalization within step-level groups, then accumulated backward — reinforcing reasoning traces, not only outcomes. DeepSeek-R1-Zero uses outcome supervision; process supervision GRPO can fine-tune individual thoughts.

Outcome vs Process Supervision

Outcome supervision

Single reward at end of completion. One Âi per sample. Simpler — this is what R1-Zero used. Enough for emergent CoT when groups are diverse.

Process supervision

Rewards on intermediate reasoning steps (R1…R5 before final R6). Normalize within step groups across G samples; accumulate advantages backward along each chain. Stronger signal on how to think.

08 — WHY GRPO FOR REASONING

Diverse Groups, Binary Rewards, No Critic

GRPO is not just cheaper PPO — it is unusually well-matched to reasoning tasks:

Diverse group samples

Sampling G completions at temperature > 0 produces a spread of reasoning paths — some correct, many wrong. The group mean baseline automatically calibrates to prompt difficulty. Hard prompts where everything fails still yield near-zero advantages; easy prompts where all succeed yield little gradient — training focuses on comparative quality within each prompt.

Binary verifiable rewards

Math and code have ground truth: reward = 1 if check passes, else 0. No reward-model drift, no human label noise. DeepSeek-R1-Zero dropped the reward model entirely — only policy + reference + verifier.

No value model overfitting

Long chain-of-thought trajectories have enormous state spaces. A critic must predict expected return from partial reasoning — easy to mis-estimate. GRPO sidesteps this: the baseline comes from actual rollouts on the same prompt, not a learned approximation.

Outcome → reasoning emergence

Even with only a final-answer reward, GRPO can reinforce longer CoT: completions that reason correctly score higher within the group. The model discovers thinking patterns without supervised reasoning data — the R1-Zero result.

Before GRPO, RL and reasoning were loosely connected. After GRPO + DeepSeek-R1, group-relative RL became the default recipe for training reasoning LLMs — simpler than PPO, cheaper in models, and better aligned with verifiable tasks.

09 — DEEPSEEK R1

The Algorithm Behind R1

DeepSeek-R1 (January 2025) established the link between GRPO and emergent reasoning. The pipeline has two stages relevant here:

  1. R1-Zero: Pure RL with GRPO on base DeepSeek-V3 — no supervised fine-tuning, no reasoning demonstrations. Verifiable rewards on math/code. The model spontaneously develops self-reflection, backtracking, and long CoT — because GRPO rewards completions that outperform their siblings in the group.
  2. R1: Adds cold-start SFT plus further GRPO with human-readable formatting — same optimizer, refined data and rewards.

The technical report's core claim: using pure reinforcement learning and fine-tuning with GRPO, you can induce reasoning patterns without telling the model how to think. No "think step by step" in the training set required — the group-relative signal is enough.

DeepSeek-R1 training stack Base LLM (πref) │ ├──► [Optional] Cold-start SFT │ └──► GRPO loop: For each math prompt X: Sample G completions {Yi} ri ← verify(Yi) # binary 0/1 Âi ← (ri − mean) / std Update πθ via LGRPO │ └──► Reasoning model (CoT emerges)
10 — PSEUDOCODE

GRPO Training Loop

End-to-end algorithm merging both lectures — outcome supervision, verifiable rewards, KL penalty:

# GRPO — Group-Relative Policy Optimization
# Inputs: policy π_θ, frozen reference π_ref, prompt batch {X}, group size G
for epoch = 1, 2, … do
  for each prompt X in batch do
    θ_old ← θ
    # ── Group sampling ──
    for i = 1 … G do
      Y_i ~ π_θ_old(· | X)   # sample completion i
      r_i ← Reward(X, Y_i)   # RM score or binary verifier
    # ── Group-relative advantage ──
    μ ← mean(r_1, …, r_G)
    σ ← std(r_1, …, r_G) + ε
    for i = 1 … G do   Â_i ← (r_i − μ) / σ
    # ── GRPO objective (maximize) ──
    L ← 0
    for i = 1 … G do
      ρ_i ← π_θ(Y_i|X) / π_θ_old(Y_i|X)   # probability ratio
      L_i ← min(ρ_i·Â_i, clip(ρ_i, 1−ε, 1+ε)·Â_i)
      L ← L + L_i
    L ← L/G − β · KL(π_θ || π_ref)
    θ ← θ + α · ∇_θ L   # gradient ascent on surrogate
  end for
end for

Formula checklist: probability ratio ρ = πθ/πθ_old · clipped surrogate min(ρÂ, clip(ρ)Â) · group advantage Âi = (ri−μ)/σ · KL penalty β·KL(πθ‖πref) · full objective LGRPO = (1/G)Σ LCLIPi − β·KL.

10b — COMMON QUESTIONS

GRPO FAQ

Is GRPO still policy gradient?

Yes. You still differentiate through log πθ; GRPO only changes the advantage estimate. The policy gradient theorem from Ch.08 still applies — GRPO is a variance-reduction trick (group baseline) plus PPO clipping.

Why sample G times — isn't that wasteful?

Sampling is parallelizable on GPUs and replaces an entire critic forward/backward pass. For long CoT, dropping Vφ often saves more memory than G extra generations cost. Trade sampling FLOPs for model FLOPs.

What if every sample in the group gets reward 0?

All advantages are zero (std = 0) — no gradient for that prompt. The model gets no update, which is correct: on a hard prompt where nothing works, there is no relative winner to reinforce. Mixed groups (some 0, some 1) give the strongest signal.

Do I still need a reference model?

Yes for stable RL on LLMs. GRPO adds an explicit KL penalty β·KL(πθ‖πref) — stronger than clipping alone. Without it, the policy can collapse into high-reward gibberish that drifts far from useful pretraining.

RM-based GRPO vs verifier-only (2 models)?

General GRPO (3 models): policy + reference + reward model — same as PPO minus the critic. DeepSeek-R1-Zero (2 models): policy + reference; reward is a deterministic checker. Reasoning on math favors verifiers; open-ended chat still needs an RM.
