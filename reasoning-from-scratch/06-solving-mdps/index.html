CHAPTER 06

Solving MDPs: DP, Monte Carlo & TD

Chapter 05 gave us the Bellman equations — recursive contracts that define what value means. This chapter asks the operational question: how do you actually compute those values and improve the policy? Three algorithm families answer that question in progressively more realistic settings, from chess-with-a-rulebook to learning purely from experience.

01 — FROM EQUATIONS TO ALGORITHMS

The Gap Chapter 05 Left Open

In Chapter 05 we defined MDPs, wrote down discounted returns, and derived the Bellman equation and Bellman optimality equation. Those are identities — they tell you what the true value function satisfies. They do not, by themselves, tell you how to find it when the state space has thousands of states and you only have partial knowledge of the world.

This chapter closes that gap. Every method here shares one goal: estimate value functions (prediction) and/or find better policies (control). The methods differ in what information they require and when they can update:

Step 1

Dynamic Programming

You know the full model — transition probabilities and rewards. Sweeps over the Bellman equation converge to true values.

Step 2

Monte Carlo

No model needed. Run complete episodes, average actual returns. Unbiased, but high variance and you must wait until each episode ends.

Step 3

Temporal Difference

Still model-free, but update after every step by bootstrapping from the next state's estimate. Online, lower variance, some bias.

Prediction vs control: In all three families, prediction means estimating Vπ for a fixed policy π. Control means improving π toward optimality. Dynamic programming alternates evaluation and improvement in policy iteration; Monte Carlo and TD extend the same split with exploring starts or ε-greedy behavior.

Keep the Bellman equation from Chapter 05 visible in your head throughout — every algorithm here is a different way to approximate its fixed point.

02 — THE STORY ARC

Model → Episodes → Steps

Imagine teaching an agent to play a game. With dynamic programming, you sit down before the first move with a complete rulebook: every transition probability is known. You can iterate the Bellman backup without ever touching the environment. That power comes with a cost — for chess, Go, or the open web, nobody hands you P(s′|s,a).

Monte Carlo says: forget the rulebook. Deploy the agent, let it play full games, and average the returns it actually received. You learn the true expected value from data — no bias — but you cannot update until the episode terminates, and noisy returns make learning slow.

Temporal difference learning splits the difference. After each action you observe a reward and land in a new state. Instead of waiting for the episode to finish, you nudge your current estimate toward r + γV(s′) — a one-step guess built from your existing estimates. That is bootstrapping: using approximate values to refine approximate values. TD trades a little bias for much lower variance and the ability to learn online — the property that makes Q-learning and modern RLHF-style training feasible at scale.

DP needs model P(s′,r|s,a) ──► bootstraps from exact successor values MC needs episodes ──► samples full returns Gt (no bootstrap) TD(0) needs one step ──► bootstraps from estimated V(s′) after each step
03 — DYNAMIC PROGRAMMING

When You Know the World Model

Dynamic programming (in the RL sense) is a collection of algorithms that compute optimal policies when the MDP model — rewards and transition probabilities — is fully available. The name is slightly misleading if you know DP from algorithms class; here it specifically means Bellman backups over a known model.

Policy Evaluation (Prediction)

Given a fixed policy π, policy evaluation estimates Vπ. Despite the name, you are not “evaluating whether π is good” — you are computing its value function. This is the prediction problem.

Start with an arbitrary V0(s) — often all zeros. Apply the Bellman expectation backup repeatedly. Each sweep produces Vk+1 from Vk until convergence:

Vk+1(s) = Σa π(a|s) · Σs′,r P(s′,r|s,a) · [ r + γ Vk(s′) ]

This is iterative policy evaluation. Terminal states keep their value (often 0) and are not updated. Non-terminal states pull their estimates from successor states — classic bootstrapping, but using the exact model rather than sampled experience.

Worked example: three-state chain (γ = 0.9, step reward −1)

States S0 → S1 → S2 (terminal). Policy always moves right. Terminal V(S2) = 0 fixed.

Each backup substitutes the previous sweep's successor values. Values propagate backward from the terminal state one layer per iteration.

Policy Improvement

Once Vπ is known, ask at each state: is there a better action? Policy improvement sets π′ to be greedy with respect to Vπ:

π′(s) = argmaxa Σs′,r P(s′,r|s,a) · [ r + γ Vπ(s′) ]

The policy improvement theorem guarantees π′ ≥ π (component-wise value never decreases). If π′ = π, you have found an optimal policy.

Policy Iteration & Value Iteration

Policy iteration alternates full policy evaluation with policy improvement until π stops changing — evaluate → improve → repeat. This is also called generalized policy iteration (GPI): value and policy chase each other until both stabilize at optimality.

Value iteration truncates evaluation: each sweep applies the Bellman optimality backup directly, without holding π fixed for many passes:

Vk+1(s) = maxa Σs′,r P(s′,r|s,a) · [ r + γ Vk(s′) ]

Value iteration interleaves evaluation and improvement in a single update. In practice it often converges faster than full policy iteration when evaluation is expensive.

Generalized Policy Iteration (GPI)

Policy iteration is the cleanest picture of GPI: two processes — evaluation and improvement — pursue each other until both stabilize. Evaluation drives values toward Vπ for the current π; improvement drives π toward greediness with respect to current values. Neither need finish before the other begins; value iteration is an extreme case where evaluation gets a single sweep per round.

π₀ ──evaluate──► Vπ₀ ──improve──► π₁ ──evaluate──► Vπ₁ ──improve──► … ──► π*

Synchronous vs In-Place Evaluation

The worked backup uses synchronous updates: compute all Vk+1(s) from Vk before overwriting. In-place evaluation overwrites V(s) immediately as each state is swept, using partially updated values within the same sweep — often faster in practice and what the grid demo implements (Gauss–Seidel style). Both converge under standard conditions for tabular MDPs.

The DP limitation: Every backup sums over P(s′,r|s,a). Without the model — as in robotics, dialogue, or token generation — DP is unusable. You cannot write down transition probabilities for every chess position before playing. That constraint motivates everything that follows.

05 — MONTE CARLO METHODS

Learning From Complete Episodes

Monte Carlo (MC) methods estimate value functions from sampled experience without ever using P(s′|s,a). The agent interacts with the environment, generates episodes, and uses actual returns as training targets.

Returns and Averaging

From state s at time t, the return is the discounted sum of future rewards until termination:

Gt = Rt+1 + γ Rt+2 + γ² Rt+3 + …

MC estimates V(s) by averaging returns observed after visiting s. After N episodes where s was visited, with returns G1, G2, …, GN:

V(s) ≈ (1/N) · Σi=1N Gi

Equivalently, use an incremental sample-average update after each episode k (αk = 1/k for pure averaging):

V(s) ← V(s) + α · [ Gk − V(s) ]

First-visit MC

Count only the first time s appears in an episode toward V(s). Each episode contributes at most one sample per state. Theoretically cleaner; converges to Vπ.

Every-visit MC

Average returns for every occurrence of s in an episode. Often similar in practice; can differ when states repeat within one trajectory.

Incremental MC Updates

Rather than storing all returns and recomputing the mean, maintain a running average. After episode k yields return Gk for a first visit to s:

V(s) ← V(s) + (1/k) · [ Gk − V(s) ]    (sample-average α = 1/k)

Constant step-size α ∈ (0,1] keeps adapting in non-stationary settings but introduces bias toward recent episodes. The bandit update from Chapter 04 — Q ← Q + α(R − Q) — is the same incremental form with a different target.

MC Control with Exploring Starts

For control, MC alternates policy evaluation (via return averages) with policy improvement (greedy with respect to estimated action values Q). On-policy MC control with exploring starts requires every state-action pair to have a non-zero probability of being the first step of some episode — ensuring every Q(s,a) gets data. Without exploring starts or ε-soft policies, a deterministic π might never try better actions.

First-visit vs every-visit (small example)

Episode: S0 → S1 → S0 → S2 (terminal). Returns from first visit: G(S0) includes the full tail after the first S0; the second pass through S0 is ignored in first-visit. Every-visit averages both occurrences of S0 separately. Both converge to Vπ under standard assumptions; first-visit is more common in theory texts.

Episode path: S0 → S1 → S2 (terminal). Rewards: −1, −1, +10. With γ = 0.9:

MC strengths: Model-free, unbiased (returns are unbiased estimates of Vπ), works for arbitrary policies. MC weaknesses: Requires episodic tasks (or a reset), high variance, and delayed learning — no credit assignment until termination.

06 — TEMPORAL DIFFERENCE LEARNING

One-Step Bootstrapping From Experience

TD methods combine ideas from DP and MC. Like MC, they learn from raw experience without a model. Like DP, they update estimates using other learned estimates — bootstrapping — without waiting for episode completion.

TD(0) Prediction

After transitioning from S to S′ and observing reward R, TD(0) updates:

V(S) ← V(S) + α · [ R + γ V(S′) − V(S) ]

The bracketed term is the TD error δ:

δ = R + γ V(S′) − V(S)

Think of R + γV(S′) as a one-step return target — a short-horizon guess at the true return. If your estimate already matches reality, δ = 0 and no change occurs. If the immediate reward plus discounted next value exceeds your current estimate, V(S) ticks upward.

Worked example: TD(0) step-by-step

Same episode S0 → S1 → S2 with rewards −1, −1, +10; γ = 0.9; α = 0.5; all V initialized to 0.

StepTransitionTD targetδNew V
1S0 → S1, R=−1−1 + 0.9×0 = −1−1V(S0)=−0.5
2S1 → S2, R=−1−1 + 0.9×0 = −1−1V(S1)=−0.5
3S2 terminal, R=+1010 + 0 = 1010V(S2)=5.0

After step 3, a second pass would bootstrap from V(S2)=5 when updating S1, gradually propagating reward backward — online, without waiting for another full episode. MC would have updated all three states only after step 3 finished.

Why TD Error Matters

The TD error δ is the surprise signal: how much better or worse the transition was than you expected. In actor–critic methods and advantage estimation (GAE in PPO), the same idea becomes the advantage A(s,a) = Q(s,a) − V(s) — how much that action beat the baseline. TD learning is not just a tabular trick; it is the template for credit assignment in large-scale RL.

MC target

Gt = Rt+1 + γ Rt+2 + γ² Rt+3 + …

Must wait until episode ends. Unbiased sample of true return.

TD(0) target

Rt+1 + γ V(St+1)

Available immediately after one step. Bootstrapped, lower variance.

TD(0) is a special case of TD(λ), which blends n-step returns; Chapter 07 extends TD to control (SARSA, Q-learning) and function approximation with neural nets — the bridge to training LLM policies.

08 — ALGORITHM REFERENCE

Prediction Algorithms at a Glance

All three solve the same prediction problem — estimate Vπ for a given π — but with different data requirements and update timing.

DP Iterative Policy Evaluation

  1. Initialize V(s) arbitrarily; V(terminal) = 0.
  2. Repeat until Δ < θ: for each non-terminal s, apply the Bellman expectation backup using current V for all s′.
  3. Output converged V ≈ Vπ.

MC First-Visit Policy Evaluation

  1. Generate an episode following π.
  2. For each state s, record Gt on first visit only in that episode.
  3. Append Gt to Returns(s); set V(s) = average(Returns(s)).
  4. Repeat over many episodes until V stabilizes.

TD TD(0) Policy Evaluation

  1. Initialize V(s) arbitrarily; V(terminal) = 0.
  2. For each step of each episode: observe S, R, S′; update V(S) ← V(S) + α[R + γV(S′) − V(S)].
  3. Repeat until V stabilizes.

The Bias–Variance Lens

View each update as estimating a target. MC targets the full return Gt — correct in expectation (unbiased) but built from a long random trajectory (high variance). TD targets R + γV(S′) — a shorter, less noisy quantity (lower variance) but V(S′) itself is wrong early in training (bias). As estimates improve, TD bias shrinks.

DP sits at the opposite corner: zero variance backups because the model is exact, but unavailable in most real problems. Modern deep RL — including the policy optimization chapters ahead — is largely TD-flavored: bootstrap from learned value networks, trade a controlled bias for sample efficiency, and never require a full environment simulator in closed form.

Connection to reasoning LLMs: RLHF and GRPO do not know the “transition model” of human language. They sample completions (episodes), score them with reward models, and apply TD-style advantage estimates (via GAE in PPO, or group-relative baselines in GRPO). The DP → MC → TD arc is the conceptual spine of how we train models when the Bellman equation cannot be written down explicitly.

10 — SUMMARY

Key Takeaways

  • One goal, three tools: estimate Vπ and improve π — via model-based sweeps (DP), episode averages (MC), or one-step TD updates.
  • Policy evaluation backup: Vk+1(s) = Σa π(a|s) Σ P(s′,r|s,a)[r + γVk(s′)] — iterative Bellman expectation.
  • Policy iteration alternates evaluation and greedy improvement; value iteration applies the Bellman optimality backup directly.
  • MC averages returns Gt after complete episodes — unbiased, model-free, high variance; first-visit vs every-visit counts visits differently.
  • TD(0): V(S) ← V(S) + α[R + γV(S′) − V(S)]; TD error δ = R + γV(S′) − V(S).
  • TD combines MC's sampling with DP's bootstrapping — online, lower variance, some bias.
  • Next: Chapter 07 turns TD into control (SARSA, Q-learning) and scales value functions with function approximation — the path to neural RL.
