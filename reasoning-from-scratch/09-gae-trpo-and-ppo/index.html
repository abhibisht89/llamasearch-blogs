CHAPTER 09

GAE, TRPO & PPO

Chapter 08 gave us REINFORCE — direct policy optimization with brutal variance. This chapter closes the loop: GAE tames the advantage estimates, TRPO constrains how far the policy can move, and PPO replaces hard KL math with one elegant clipping trick. These three ideas power RLHF, InstructGPT, and the PPO stages behind ChatGPT-class models.

00 — THE ARC FROM REINFORCE

High Variance, Then Trust, Then Clipping

Chapter 08 established the policy gradient theorem and REINFORCE: sample trajectories, multiply returns by ∇ log πθ, update. Baselines and actor-critic helped, but two problems remained for training large neural policies at scale.

Problem 1 Noisy Advantages

REINFORCE uses raw returns or simple TD targets. Monte Carlo is unbiased but high-variance; one-step TD is low-variance but biased. Policy updates wobble.

Problem 2 Catastrophic Updates

Large gradient steps can shift πθ so far that collected data is instantly stale — performance collapses instead of improving. We need a trust region.

REINFORCE (Ch.08) — high variance, unconstrained steps
  ↓ GAE (Schulman et al., 2016) — better Â estimates
  ↓ TRPO (Schulman et al., 2015) — KL-constrained surrogate
  ↓ PPO (Schulman et al., 2017) — same idea, clipped objective
  ↓ RLHF / InstructGPT / reasoning-model fine-tuning (Ch.10–12)

Intuition to keep: GAE answers “how good was this action?” TRPO and PPO answer “how far can we change the policy?” PPO is the workhorse you will see in every modern LLM alignment stack.

01a — ADVANTAGE RECAP

Why Advantages Beat Raw Returns

Before GAE, the lectures build intuition for the advantage function itself. At state s, suppose the policy’s default action yields Qπ(s, a₀) = 50, but an alternative action yields 60. The advantage A(s, a₁) = 60 − 50 = +10 signals “this action is ten units better than average.” Actions below average get negative advantages.

Aπ(s, a) = Qπ(s, a) − Vπ(s)

Using A instead of raw Q in the policy gradient subtracts a baseline per state, cutting variance without changing the expected gradient direction. GAE is the next step: a better estimator of this same A from sampled trajectories and a learned V(s).

One-step TD advantage

Â ≈ r + γV(s′) − V(s) = δt. Fast, uses critic heavily — biased if V is wrong.

GAE advantage

Weighted sum of δt, δt+1, … with (γλ) weights. Tunable bias–variance via λ.

01 — GENERALIZED ADVANTAGE ESTIMATION

GAE: One Knob Between TD(0) and Monte Carlo

Recall the advantage function from the lectures: Aπ(s, a) = Qπ(s, a) − Vπ(s). It measures how much better action a is compared to the policy’s average behavior in state s. Positive advantage → increase probability; negative → decrease.

The policy gradient with advantages (replacing raw returns in REINFORCE) becomes:

∇θ J(θ) ≈ Eπθ [ Ât · ∇θ log πθ(at | st) ]

The hard part is estimating Ât. A one-step TD residual is fast but biased because it bootstraps from V̂. A full Monte Carlo return Gt − V(st) is unbiased but noisy — every reward in the episode perturbs the estimate.

N-Step Returns and the Bias–Variance Tradeoff

Chapter 06 introduced n-step backups: look ahead n rewards before bootstrapping. One-step (n=1) → low variance, high bias. Full episode (n=∞) → low bias, high variance. GAE (Schulman et al., 2016) takes an exponentially-weighted average of all n-step advantages instead of picking one n.

Define the TD error (one-step advantage residual):

δt = rt + γ V(st+1) − V(st)

The GAE advantage at timestep t is the infinite sum of discounted TD errors:

ÂtGAE(γ,λ) = Σl=0∞ (γλ)l δt+l

Equivalently, as a weighted mixture of n-step returns (weights (1−λ)λn−1 for the n-step term):

Ât = (1−λ) [ δt + λ(δt+δt+1) + λ²(δt+δt+1+δt+2) + … ]

λ = 0 → TD(0)

Only δt matters. You look one step ahead. High bias, low variance. Updates are stable but can systematically mis-rank actions when V is wrong.

λ = 1 → Monte Carlo

Full return minus baseline. Low bias, high variance. True long-term quality, but individual trajectories swing wildly.

Practical default: λ ≈ 0.95 is common in robotics and games. For LLM RLHF, λ is often 0.9–1.0 depending on episode length (a long chain-of-thought is one “episode”). The λ knob is the cleanest bias–variance dial in modern policy optimization.

Why GAE Matters for Policy Gradients

With GAE plugged in, every policy gradient step uses a smoother, more reliable Ât. That directly reduces gradient variance without abandoning bootstrapping entirely. TRPO and PPO both assume you already have decent advantage estimates — GAE is how production code produces them.

∇θ J(θ) ≈ E [ ÂtGAE · ∇θ log πθ(at|st) ]

Composite Returns: Building Intuition

Before the closed-form GAE sum, the lectures walk through a two-step composite backup: half weight on the one-step TD target, half on the two-step return. Generalizing to n steps with weights (1−λ)λn−1 gives the exponential decay you see in the slider below — nearby rewards matter most; distant rewards fade unless λ → 1.

Half-and-half example (λ = 0.5 conceptually)

One-step estimate: δt = rt + γV(st+1) − V(st). Two-step: rt + γrt+1 + γ²V(st+2) − V(st). A 50/50 blend averages bias and variance — GAE formalizes this for all n with principled weights that sum to 1.

Implementation Sketch (Backward Pass)

In code, GAE is computed backwards along a trajectory after rollout collection. Starting from the last timestep T:

gae = 0
for t in reversed(0..T):
  δt = rt + γ V(st+1) − V(st)   # bootstrap V(sT+1)=0 if terminal
  gae = δt + γλ · gae
  advantages[t] = gae

This recurrence is equivalent to the infinite sum Σ(γλ)lδt+l but runs in O(T) time — exactly what PPO implementations call after each rollout batch.

02 — TRUST REGION POLICY OPTIMIZATION

TRPO: Don’t Destroy What You Already Know

TRPO (Schulman et al., 2015) asks: when we improve π, can we express the new policy’s performance in terms of the old one plus a sum of advantages? Yes — but the state distribution under the new policy is unknown, so TRPO fixes the old policy’s state distribution and optimizes a surrogate instead.

The Surrogate Objective

Let rθ(a|s) = πθ(a|s) / πθold(a|s) be the probability ratio. The surrogate (using advantages under the old policy’s visitation distribution) is:

L(θ) = Es∼dπold, a∼πθ [ rθ(a|s) · Ât ]

Maximizing L(θ) alone is dangerous — r can blow up, making the surrogate a poor stand-in for true performance. TRPO adds a hard trust region via KL divergence:

maximizeθ L(θ)   subject to   KL(πθold ‖ πθ) ≤ δ

Equivalently, the penalized form from the lectures:

L(πold, πnew) − C · KLmax(πold, πnew)

When KL is small, the surrogate matches true improvement; when KL grows, the penalty dominates. δ (typically ~0.01–0.05) defines the trust region radius — you may only move π so far from πold before the constraint binds.

Why “trust region”? Around πold, the surrogate is trustworthy. Step outside the KL ball and linear/quadratic approximations break — the policy can collapse. TRPO literally restricts each update to a neighborhood where the math still describes reality.

Surrogate Iteration Picture

TRPO imagines a true performance landscape η(θ) you cannot write down explicitly. At each θold, you construct a surrogate curve that touches the true curve at θold, lies below it everywhere (underestimates improvement), and is easier to maximize. You step to the surrogate’s peak → new θ → repeat. PPO’s clipped objective is a simpler surrogate with the same “stay near θold” flavor.

Decoupled TRPO formulation (used in practice)

Maximize L(θ) subject to KL(πθold ‖ πθ) ≤ δ. The penalty form L − C·KL with adaptive C is equivalent in spirit: increase C until the KL constraint is satisfied after each proposed step.

Natural Gradient, Fisher Matrix, Conjugate Gradient

Enforcing KL exactly requires second-order optimization. TRPO expands KL in a Taylor series around θold; the second-order term involves the Fisher information matrix F:

KL(πθold ‖ πθ) ≈ ½ (θ − θold)T F (θ − θold)

The natural gradient premultiplies the ordinary gradient by F−1, scaling steps by curvature instead of raw parameter magnitude. Computing F−1 for millions of neural network weights is impossible directly — TRPO uses conjugate gradient to solve Fx = g without inverting F, then performs a line search to satisfy the KL constraint δ.

1. Collect trajectories under πold

Compute advantages (often with GAE) for each (s, a) pair.

2. Build surrogate L(θ) and estimate KL

Surrogate uses old state distribution; advantages tell you which direction helps.

3. Conjugate gradient + line search

Find the largest improving step still satisfying KL ≤ δ. Repeat until convergence.

Why TRPO Is Hard to Implement

TRPO works beautifully in theory and on moderate-scale benchmarks, but production teams hit friction:

  • Conjugate gradient and Fisher-vector products add engineering complexity.
  • Multiple forward/backward passes per update — expensive for billion-parameter LMs.
  • Line search can fail or stall; hyperparameters δ and CG iterations need tuning.
  • Hard KL constraints interact badly with distributed training and mixed precision.

The research community wanted TRPO’s stability without TRPO’s machinery. That motivation produced PPO.

Performance Decomposition (Why the Surrogate Works)

TRPO’s theoretical backbone: the performance of a new policy η(πnew) can be written as η(πold) plus an expected advantage term — but only if you evaluate states under πnew’s visitation distribution. Since that distribution is unknown before training, TRPO freezes the old distribution and optimizes:

η(πnew) ≈ η(πold) + Es∼dπold [ Σa πnew(a|s) · Aπold(s,a) ]

The surrogate L(θ) replaces πnew(a|s) with rθ(a|s)·πold(a|s) for importance sampling while keeping states from πold. The KL constraint ensures this approximation stays valid.

Monotonic improvement guarantee (informal): TRPO’s analysis shows that if the surrogate improves and KL ≤ δ, true policy performance improves within bounded error. PPO’s clipping heuristically enforces the same “don’t trust the surrogate too far” principle without the proof machinery at each step.

03 — PROXIMAL POLICY OPTIMIZATION

PPO: TRPO’s Idea, One Clipping Line

PPO (Schulman et al., 2017) keeps the probability ratio rθ = πθ(a|s) / πθold(a|s) and the surrogate rθ·Â, but replaces the KL constraint with a clipped objective. The policy cannot gain more credit than ±ε from the old probabilities — a soft trust region implemented in one min() call.

LCLIP(θ) = E [ min( rθ·Â , clip(rθ, 1−ε, 1+ε)·Â ) ]

Typical ε = 0.2, so r is clamped to [0.8, 1.2]. The clip function is:

clip(r, 1−ε, 1+ε) = max(1−ε, min(r, 1+ε))

Why Clipping Mimics a Trust Region

Â > 0 (good action)

You want to increase πθ(a|s). Unclipped objective grows linearly with r — incentive to make huge updates. Clipping at 1+ε caps the reward once r exceeds 1.2. No extra gradient for over-confidence.

Â < 0 (bad action)

You want to decrease probability. For r < 1−ε, the clipped term is less negative than r·Â — again limiting how aggressively you punish. Symmetric protection both ways.

The min() selects the pessimistic (conservative) estimate — the objective never optimistically assumes a bigger policy shift than ε allows. Empirically, this keeps KL near ε without ever computing it in the loss.

PPO training loop (multiple epochs on same batch): collect rollouts → compute GAE advantages → optimize LCLIP for several SGD steps while πθ stays near πθold. Much simpler than TRPO’s CG line search, yet stable enough for LLM-scale RLHF.

Full PPO Objective (What Actually Gets Optimized)

Production PPO adds a value-function loss and sometimes an entropy bonus. The complete loss minimized each step looks like:

L = −LCLIP + c1 (V(s) − Vtarget)² − c2 H(πθ)

Clipping applies only to the policy term. The value network still learns to predict returns (often with its own clipping). Entropy encourages exploration early in training — less critical for fine-tuned LMs but standard in robotics benchmarks.

PPO Pseudocode

θold ← θ
for iteration = 1, 2, …:
  Run policy πθold for N steps → collect {(s,a,r)}
  Compute V(s) and GAE advantages Ât for each timestep
  for epoch = 1 .. K:   # reuse same batch K times
    Shuffle and split into mini-batches
    θ ← θ + α ∇θ LCLIP(θ)   # gradient ascent on clipped objective
  θold ← θ

Notice θold is fixed for all K epochs within one iteration — that is what makes rθ well-defined. After K passes, snapshots update and fresh rollouts are collected.

Common PPO Pitfalls

  • ε too small: policy barely moves; learning stalls despite good advantages.
  • Too many epochs K: same batch reused until r drifts far from 1 — defeats clipping purpose.
  • Bad value function: GAE inherits critic bias; garbage V → garbage Â → wrong clip direction.
  • Reward scale: advantages must be reasonable magnitude; normalize or clip rewards in LLM RLHF.

04 — WORKED EXAMPLE

PPO Clipping by Hand: r = 1.3, Â = 2, ε = 0.2

Suppose after one SGD mini-batch the new policy assigns action a probability 30% where the old policy assigned 23%. The ratio r = 0.30/0.23 ≈ 1.30 — a 30% relative increase. The advantage estimate is Â = +2 (this action beat the value baseline by two units).

  • Compute the ratio. rθ = πθ(a|s) / πθold(a|s) = 1.3. Since Â > 0, we want to reward increasing probability — but only up to the trust boundary.
  • Unclipped term. r · Â = 1.3 × 2 = 2.6. Vanilla policy gradient would use this; it encourages pushing r even higher.
  • Clip the ratio. clip(1.3, 1−ε, 1+ε) = clip(1.3, 0.8, 1.2) = 1.2 because 1.3 > 1.2 = 1+ε.
  • Clipped term. clip(r) · Â = 1.2 × 2 = 2.4. This is the maximum credit PPO allows for this (s,a) pair in this update.
  • Take the minimum. LCLIP = min(2.6, 2.4) = 2.4. The objective ignores the extra 0.2 — gradient w.r.t. θ vanishes for r beyond 1+ε when Â > 0.

Interpretation: The action was good (Â > 0), so PPO still increases its probability — but only until r reaches 1.2. Further increases yield zero additional surrogate reward, preventing the catastrophic “overshoot” updates TRPO’s KL constraint was designed to stop.

For contrast, if Â = −2 and r = 0.7 (policy already reduced bad action): unclipped = −1.4, clip(0.7, 0.8, 1.2) = 0.8, clipped term = −1.6, min = −1.6 (more penalty than unclipped — clipping bites when you try to move too far in the direction of a negative advantage).

Second Numeric Case: r = 1.1, Â = +2, ε = 0.2

When r stays inside [0.8, 1.2], clipping is inactive:

  • r · Â = 1.1 × 2 = 2.2
  • clip(1.1, 0.8, 1.2) = 1.1 (unchanged)
  • LCLIP = min(2.2, 2.2) = 2.2 — full credit; gradients flow normally.

This is the “trust but verify” sweet spot: meaningful policy change is allowed until r hits the ε rails.

05 — ALGORITHM COMPARISON

REINFORCE vs TRPO vs PPO

The progression is not random — each algorithm fixes the previous one’s pain point while preserving what worked.

Aspect REINFORCE TRPO PPO
Core update ∇ log π · Gt (or Â) Surrogate L(θ) with KL ≤ δ Clipped min(r·Â, clip(r)·Â)
Advantage estimate MC return − baseline GAE (typical) GAE (typical)
Trust region None — any step size Hard KL constraint δ Soft clip ε ≈ 0.2

Implementation Simple Complex Simple + stable

REINFORCE → GAE

Same policy gradient skeleton; GAE replaces noisy return estimates with a bias–variance-controlled Ât.

GAE + unconstrained PG → TRPO

Good advantages aren’t enough if one update destroys the policy. KL trust region bounds policy drift.

TRPO → PPO

Same ratio-based surrogate spirit; clipping approximates the trust region without Fisher matrices or line search.

06 — PPO MEETS LANGUAGE MODELS

Why Every Alignment Pipeline Runs PPO

When OpenAI trained InstructGPT (Ouyang et al., 2022), the RL fine-tuning stage used PPO with a learned reward model — classic RLHF. ChatGPT and successors follow the same pattern: supervised fine-tuning first, then PPO against human preference rewards. The “agent” is the language model; each token is an action; the prompt is the state; a reward model scores the completed response.

RL mapping

State st: prompt + tokens generated so far
Action at: next token from vocabulary
Reward: reward model score (often only at EOS)
Policy: LM softmax over vocab

Why PPO specifically

Billions of parameters, distributed training, many PPO epochs per rollout batch. TRPO’s conjugate gradient would be prohibitive. Clipping gives stability; GAE (or variants) handles sparse terminal rewards across long sequences.

DeepSeek-R1 and other reasoning models often use GRPO (Group Relative Policy Optimization) — a PPO descendant that drops the value network and normalizes rewards within prompt groups. Chapter 11 covers GRPO in depth; the key point here: GRPO’s clipped ratio objective inherits directly from PPO, which inherits from TRPO’s trust-region insight, which sits atop GAE-cleaned policy gradients.

Chapter roadmap: Ch.10 maps RL notation to LLM training pipelines (RLHF, verifiable rewards). Ch.11 dissects GRPO. Ch.12 builds a reasoning model. None of that works without the GAE → TRPO → PPO stack you just learned.
