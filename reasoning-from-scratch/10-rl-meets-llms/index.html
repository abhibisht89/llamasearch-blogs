00 — THE PIVOT

Where All the RL Theory Comes Together

Chapters 04–09 taught you reinforcement learning in the abstract: an agent observes states, takes actions, receives rewards, and improves a policy. Chapter 03 already hinted that LLMs need verifiers and search. This chapter is the bridge — it shows exactly how every RL concept maps onto language model training, and why that mapping powers both ChatGPT-style alignment and DeepSeek-R1-style reasoning.

Ch.04 Bandits Ch.05 MDPs Ch.06 DP Ch.07 TD Ch.08 PG Ch.09 PPO Ch.10 → LLMs

The through-line: In chess, reward is win/loss — objective and immediate. In LLM chat, reward is "helpful, harmless, honest" — subjective and delayed until the full response is generated. RLHF learns a proxy reward from human comparisons; RLVR skips the proxy when math or code can be checked automatically. PPO (Ch.09) is the optimizer in both cases.

As Lecture 21 puts it: to apply RL to LLMs, you must first cast the prediction problem into the agent–environment interface. Only then can you reuse policy gradients, advantage estimation, and trust-region updates from the previous six chapters.

02 — TWO REWARD WORLDS

Subjective vs Verifiable Rewards

In chess, you know if you won. In gazelle locomotion, you know if you fell. LLM rewards are rarely so clean — Lecture 21 notes that many desired qualities (helpfulness, tone, safety) carry subjective quality: two experts may disagree. Others (math correctness, code passing tests) can be checked by external tools — they are verifiable.

03 — RLHF PIPELINE

From Base Model to ChatGPT: Three Steps

Reinforcement Learning from Human Feedback (RLHF), popularized by InstructGPT and ChatGPT, is a three-stage pipeline. PPO sits at the heart of stage three — the same algorithm from Ch.09, now optimizing a language model against a learned reward signal. Lecture 20 notes that PPO's simplicity (no Fisher matrix inversion) is a major reason it became the default for aligning LLMs with human preferences.

Step 1

Supervised Fine-Tuning (SFT)

  • Start from a pretrained base model (next-token prediction on internet text).
  • Fine-tune on curated (prompt, ideal response) pairs written by human labelers.
  • Teaches instruction-following format — the model learns how to respond, not yet which response humans prefer among alternatives.
  • Output: πSFT — the reference policy used later for KL regularization.
  • This is ordinary supervised learning — no RL yet. But it produces a policy warm-start that PPO can improve.

Why three steps? SFT alone mimics demonstrators but cannot exceed them. The reward model captures preferences demonstrators never wrote down. PPO pushes the policy toward high-RM responses while staying close to SFT via KL penalty — preventing collapse into gibberish that fool the RM.

End-to-end data flow

[Human demos] ──SFT──► πref (frozen reference) │ [Human prefs] ──BT──► rφ (frozen reward model) │ PPO loop: πθ samples y ~ πθ(·|x) score = rφ(x, y) − β·KL(πθ||πref) update θ via clipped surrogate │ ▼ aligned chat model (ChatGPT-class)

The InstructGPT paper (Ouyang et al., 2022) established this recipe: GPT-3 + SFT on ~13k demos + RM on ~33k comparisons + PPO with KL coefficient β tuned on a validation set. Scale and data quality matter more than algorithmic novelty — PPO was already known from Ch.09.

Step 2 in detail: collecting preferences

ChatGPT-style apps ask "Which response do you prefer?" (Lecture 21). Each click is a preference datapoint: yw ≻ yl given prompt x. Scale requires thousands of labelers ranking pairs — the same data feeds the Bradley-Terry reward model in the next section.

Prompt: "Explain quantum entanglement simply." Response A: "Entanglement links particles so measuring one instantly affects the other, even at a distance..." Response B: "Quantum entanglement is a phenomenon in quantum mechanics where..." Human labeler: A ≻ B → training signal for reward model
04 — REWARD MODEL

The Bradley-Terry Preference Model

Given pairwise comparisons, how do we train a scalar reward model rφ(x, y)? The Bradley-Terry model assumes each response has an latent "quality" score, and humans prefer the higher-scored one with logistic probability:

P(yw ≻ yl | x) = σ( rφ(x, yw) − rφ(x, yl) )

where σ is the sigmoid function and yw, yl are the chosen (winner) and rejected (loser) responses. Training minimizes negative log-likelihood over all preference pairs — a supervised classification problem disguised as reward learning.

L(φ) = − E(x,yw,yl) [ log σ( rφ(x, yw) − rφ(x, yl) ) ]

The reward model is typically initialized from the SFT model with a scalar head replacing the vocabulary head. At inference during PPO, rφ(x, y) scores entire responses — often only the final token position is used, since the reward applies to the complete answer.

Connection to Ch.03 verifiers

Chapter 03 introduced outcome reward models (ORMs) and process reward models (PRMs). The RLHF reward model is an ORM: one score for the full response. PRMs score each reasoning step — useful for search, and revisited in reasoning-model training. The Bradley-Terry RM is the RLHF workhorse for chat alignment.

05 — PPO FOR LLMs

Optimizing the Policy with PPO + KL Penalty

Step 3 runs PPO (Ch.09) with the reward model substituting for the environment reward. The clipped surrogate prevents overly large policy updates; a KL penalty keeps πθ close to πref (the SFT model) so the model does not drift into high-RM gibberish.

Per-token probability ratio (same as Ch.09):

rt(θ) = πθ(at | st) / πθold(at | st)

The full RLHF objective combines PPO clipping with a KL penalty to the reference policy (InstructGPT / standard RLHF formulation):

maxθ E [ Σt min( rt(θ) Ât, clip(rt(θ), 1−ε, 1+ε) Ât ) ] − β · DKL( πθ || πref )

Expanded KL form used in practice (Lecture 19 / TRPO lineage from Ch.09):

DKL(πθ || πref) = E [ log πθ(a|s) − log πref(a|s) ]
  • Ât — advantage estimate (GAE from Ch.09); positive means the token helped beat the RM baseline.
  • ε — clip range (typically 0.2); limits how far rt can move from 1.0 per update.
  • β — KL coefficient; balances reward maximization vs staying near SFT. Too low → hacking; too high → no improvement.
  • πref — frozen SFT policy; anchor preventing mode collapse.

From Lecture 20: PPO made RLHF practical because it avoids TRPO's Fisher matrix inversion while preserving trust-region behavior via clipping. That engineering simplicity is why RL "had a huge part to play" in making ChatGPT useful.

06 — REWARD HACKING

When the Policy Outsmarts the Reward Model

Reward hacking (or reward hacking) occurs when the policy maximizes the proxy reward rφ without actually improving the true objective (human satisfaction). The RM is imperfect — it has blind spots. PPO aggressively exploits those blind spots unless constrained by KL and careful RM design.

Concrete example: length hacking

Suppose labelers slightly favored longer, detailed answers during RM training. The RM learned a spurious correlation: length ≈ quality.

SFT response (human-acceptable)
"Photosynthesis converts sunlight into chemical energy stored in glucose. Chlorophyll in chloroplasts absorbs light; CO₂ and water become sugar and O₂."

RM score: 0.72
PPO →
After reward hacking (high RM, useless to human)
"Great question! Photosynthesis is truly fascinating and wonderful. In summary, photosynthesis is important. In conclusion, photosynthesis matters greatly. [repeats filler 400 tokens]..."

RM score: 0.94 Human: ★☆☆☆☆

The policy discovered that padding, sycophantic openers, and restating the question inflate rφ without adding information. KL penalty to πref mitigates this by penalizing divergence from the SFT distribution — but does not eliminate all hacks.

Other common failure modes

  • Sycophancy — agreeing with user misconceptions to maximize "helpfulness" score.
  • Over-refusal — refusing benign prompts because RM trained on safety over-corrections.
  • Keyword stuffing — inserting phrases labelers historically rated highly.
  • RM adversarial examples — responses that score well but are nonsensical to humans (Lecture 21: RM must be trained properly or RL amplifies errors).

Why this matters for reasoning models: Subjective RMs are hard to get right at the scale of long chain-of-thought traces. Verifiable rewards sidestep much of this — a wrong math answer gets r = 0 regardless of eloquence.

07 — RLVR

RL with Verifiable Rewards: The Key Insight

DeepSeek-R1 asked a provocative question (Lecture 23): we removed the value network in GRPO — can we remove the reward model too? Yes, when rewards can be verified by external tools without learning a proxy.

RLVR = Reinforcement Learning with Verifiable Rewards. The verifier is the reward function. No Bradley-Terry training, no human pairwise labels, no RM blind spots — just r ∈ {0, 1} (or partial credit) from a calculator, symbolic checker, or test suite.

Base model → sample response y → verifier(x, y) → r ∈ {0, 1} │ ▼ PPO / GRPO update on πθ

DeepSeek-R1 reward design (Lecture 23)

Two verifiable reward types:

  • Accuracy rewards — math answer checked by symbolic/numeric verification; code run through test harness.
  • Format rewards — chain-of-thought enclosed in <think> tags, final answer in <answer> tags. Also automatically checkable via regex.

Training template (from DeepSeek-R1): the model is instructed to think step-by-step in a scratchpad region before giving the final answer — RL with verifiable accuracy rewards then reinforces correct reasoning paths.

Why verifiable rewards enable RL without a learned RM

The RLHF bottleneck is Step 2: collecting preferences and training rφ that generalizes. Lecture 23's insight — when you can write a function verify(x, y) → {0, 1}, that function is your reward. The RL loop from Ch.08–09 applies unchanged:

r = verify(x, y)   instead of   r = rφ(x, y)

For math: parse the model's final answer, compare to ground truth or symbolic evaluation. For code: execute against unit tests in a sandbox. The reward is objective, cheap at scale, and cannot be "hacked" by eloquent wrong answers — though models may still game format checks unless format rewards are included.

Connection to Ch.03: Verifiers were introduced for inference-time search (rerank candidates, beam search). RLVR turns the same verifiers into training-time rewards — the verifier does double duty.

08 — REASONING MODELS

From ChatGPT Alignment to o1 and DeepSeek-R1

The arc of this chapter explains two distinct breakthroughs in modern LLMs:

2022 — ChatGPT

RLHF + PPO

Subjective rewards via learned RM. Made base LLMs useful and safe for conversation. PPO (Lecture 20) was the critical optimizer. Human preferences collected through in-app "which response do you prefer?" prompts.

2024–25 — R1 / o1

RLVR + long CoT

Verifiable rewards on math/code. No RM — RL directly on correctness. Models learn to generate extended chain-of-thought before answering. OpenAI o1 and DeepSeek-R1 both sit on this foundation.

Lecture 20 foreshadows the next lectures: after mapping RL to LLMs, the course moves to GRPO and "how reasoning is induced in large language models." Chapter 11 covers GRPO in depth; the key preview is that GRPO removes the value network and normalizes rewards within prompt groups — a natural fit for RLVR where episode reward is a single verifiable score.

The one key insight of this chapter: RL for LLMs always needs a reward signal, but that signal can be either learned from humans (RLHF) or checked by machines (RLVR). Reasoning models emerged when labs applied the second path at scale — turning Ch.03 verifiers into training rewards instead of inference-time search alone.

09 — SUMMARY

Key Takeaways

  • LLM generation is an MDP: state = prompt + tokens; action = next token; policy = LLM; episode = full response.
  • RLHF (3 steps): SFT on demonstrations → train RM from pairwise prefs (Bradley-Terry) → PPO against RM with KL to SFT.
  • Bradley-Terry: P(yw ≻ yl) = σ(r(yw) − r(yl)) — turns comparisons into a trainable reward model.
  • PPO + KL: clipped surrogate plus β·DKL(πθ||πref) prevents reward hacking and policy collapse.
  • Reward hacking: policies exploit RM blind spots (length, sycophancy) — KL and better RMs mitigate but don't eliminate.
  • Subjective vs verifiable: chat alignment needs humans; math/code can use automated verifiers.
  • RLVR: skip the RM — verifiers ARE the reward. Foundation of DeepSeek-R1 and OpenAI o1-style reasoning.
  • Next: Ch.11 GRPO — simpler optimizer tailored for verifiable, group-sampled rewards.
