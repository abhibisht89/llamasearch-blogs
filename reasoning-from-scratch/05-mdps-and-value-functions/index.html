CHAPTER 05

MDPs, Returns & Value Functions

Multi-armed bandits have no memory — pull an arm, get a reward, repeat. Real reasoning and control require state: where you are shapes what you should do next. This chapter formalizes sequential decision-making as Markov Decision Processes and introduces the value functions that every RL algorithm ultimately estimates.

01 — FROM BANDITS TO SEQUENTIAL RL

Why Bandits Are Not Enough

Chapter 04 treated the environment as a single static state. The agent chose among arms, received a scalar reward, and never moved. That model captures explore–exploit but misses the core difficulty of reasoning: actions change what happens next.

Multi-armed bandit

One state · many actions · i.i.d. rewards · no transitions

Markov Decision Process

Many states · many actions · state transitions · delayed rewards

Chess, maze escape, bioreactor control, and LLM token generation all share the same structure: observe a state, take an action, receive a reward, land in a new state. Reinforcement learning problems with this structure — where the state signal has the Markov property — are called Markov Decision Processes (MDPs).

What changes when we add states?

In a bandit, the agent always sits in the same implicit state — only the action distribution matters. In an MDP, the same action can be good or bad depending on where you are. Moving "forward" in a maze is excellent near the exit and disastrous near a cliff. The policy must become a function of state: π(a|s), not a single fixed distribution over arms.

FeatureMulti-armed banditMDP
States1 (implicit)Many — possibly infinite
TransitionsNone — always same stateP(s′|s,a) moves the agent
Policyπ(a) — same every stepπ(a|s) — depends on location
Reward timingImmediate per pullImmediate + delayed (path-dependent)
PlanningNot neededEssential — consider future consequences

Agent–environment interface: At each timestep t, the agent observes state St, selects action At, receives reward Rt+1, and transitions to St+1. The policy π(a|s) maps each state to action probabilities. The agent's goal is to maximize cumulative reward over time — not just the next immediate reward.

02 — THE MDP FORMAL DEFINITION

Five Components: (S, A, P, R, γ)

An MDP is a mathematical model of an agent interacting with an environment. When state signals satisfy the Markov property, the entire RL problem reduces to five symbols:

S — States

All configurations the agent can observe: chess board, sensor readings, grid position, prompt + tokens so far.

A — Actions

Decisions available in each state: move direction, target temperature, next token.

P — Dynamics

P(s′|s,a) = probability of reaching s′ after taking action a in state s.

R — Rewards

Scalar feedback. Can depend on (s, a, s′). Defines what "good" means.

γ — Discount

γ ∈ [0,1). Weights immediate rewards over distant ones. Essential for continuing tasks.

Reward design matters. In chess, +1 for winning and −1 for losing is clean. Rewarding "capture the queen" as a sub-goal confuses the agent about the true objective. In a maze, −1 per timestep before escape incentivizes speed: escaping in 2 steps yields total reward −2; escaping in 10 steps yields −10.

Episodic tasks and terminal states

Many MDPs include terminal states where the episode ends. Once entered, no further actions or rewards occur — Vπ(terminal) = 0 by convention (no future return). Chess checkmate, maze exit, and correct LLM answer with EOS token are all terminal. The set of non-terminal states is S+; terminal states form ST. Episodes are sequences S0, A0, R1, … ending in ST.

St ──agent selects──► At ~ π(·|St)     │                                                 ▼     │                            Environment: P(St+1|St,At)     │                                                 ▼     └────────────── receives ──────────► Rt+1, St+1

Expected immediate reward for a state–action pair is written r(s,a) = E[R | St=s, At=a]. When reward also depends on the landing state, use r(s,a,s′). Transition dynamics and rewards fully specify the environment; the policy specifies the agent.

Example: the recycling robot

A mobile robot collects empty cans. It can search (find cans, drain battery) or wait (fewer cans, recharge). State is battery level: high or low. Actions have stochastic outcomes — searching from low battery might fail and leave the robot stuck. This is a continuing MDP: no terminal state, so γ < 1 is required to keep returns finite.

StateActionNext state (prob)Typical reward
High batterySearchHigh (0.8), Low (0.2)+2 (cans found)
High batteryWaitHigh (1.0)+0 (recharge slowly)
Low batterySearchHigh (0.3), Low (0.5), Stuck (0.2)+2 or penalty
Low batteryWaitHigh (0.9), Low (0.1)+0

The optimal policy is not "always search" — context matters. From low battery, waiting to recharge may maximize long-run return even though searching yields higher immediate reward. Value functions encode exactly this tradeoff.

03 — THE MARKOV PROPERTY

Future Depends Only on the Present

A state signal has the Markov property if it retains all information from the past that is relevant for choosing future actions. Formally, the probability of the next state depends only on the current state and action — not on the full history:

P(St+1 = s′ | St, At, St−1, …, S0) = P(St+1 = s′ | St, At)

Chess illustrates this cleanly: the current board configuration encodes the entire game history. A cannonball's position and velocity suffice to predict its next position — you do not need the trajectory of every prior timestep. Poker is a counterexample: if your state is only the visible cards and not the betting history, the Markov property fails because past actions inform optimal play.

State design is critical. A state must be whatever information enables the agent to act optimally. Too little information breaks Markov; too much makes learning harder. For LLMs, the state is typically the full generated prefix — sufficient for the Markov assumption at the token level.

Grid worlds: the canonical teaching MDP

Grid worlds place an agent on a 2D lattice. States are cell coordinates. Actions move up/down/left/right (or stay). Walls block movement; terminal cells absorb the agent with a fixed reward. Dynamics may be deterministic (move exactly as commanded) or stochastic (slip to a perpendicular cell with probability ε).

4×4 Grid (Section 07 demo):   S  ·  ·  G(+1)   ·  #  ·  ·   ·  ·  ·  ·   ·  ·  T(−1)  · S = start (0,0) · G = goal (+1) · T = trap (−1) · # = wall · step cost = −0.04

From start, a greedy policy toward G avoids the trap. A random policy diffuses probability mass everywhere, lowering V(s) in most cells. The grid makes Bellman backups visual: each cell's value is a weighted average of neighbor values plus step rewards.

04 — RETURNS & DISCOUNTING

Optimizing for the Long Run

The agent does not maximize the next reward alone. It maximizes the return — the cumulative discounted reward from the current timestep onward:

Gt = Rt+1 + γ Rt+2 + γ² Rt+3 + … = Σk=0∞ γk Rt+k+1

Without discounting, returns in continuing tasks (a rover exploring indefinitely, a bioreactor running forever) can diverge to infinity. Discounting assigns higher value to immediate rewards — analogous to inflation making ₹100 today worth more than ₹100 in five years.

Episodic vs continuing tasks

Episodic tasks have a natural terminal state: chess ends at checkmate, a maze ends at the exit. Summing undiscounted rewards is fine when episodes are bounded. Continuing tasks have no fixed horizon; γ < 1 keeps returns finite and makes "sooner is better" explicit.

Worked example: computing Gt with γ = 0.9

Suppose an agent is in state s at time t and, following its policy, receives rewards +0, +0, +10 over the next three steps (then the episode ends with zero thereafter):

For a maze with −1 per step: escaping in 2 steps gives G = −1 + 0.9×(−1) = −1.9. Escaping in 10 steps gives G = −1 − 0.9 − 0.81 − … ≈ −6.51. The agent learns to minimize steps, not just to wander.

Worked example: maze escape with γ = 0.9

An agent receives −1 at every non-terminal step. It takes 3 steps to reach the exit, where the episode ends (no further reward):

Compare a 2-step escape: G = −1 + 0.9×(−1) = −1.9. Shorter paths dominate under negative per-step rewards — the return objective naturally encodes "get out fast."

Why γ matters numerically

With γ = 0, the agent is purely myopic: Gt = Rt+1. With γ → 1, distant rewards weigh almost equally — fine for short episodic tasks, problematic for infinite horizons. Typical choices: γ = 0.9 or 0.99 for continuing control; γ = 1.0 for episodic tasks with guaranteed termination.

Finite-horizon tasks fix a maximum episode length T; returns sum only to T and discounting is optional. Infinite-horizon continuing tasks require γ < 1 so that Σ γk converges geometrically. The recycling robot and bioreactor examples are infinite-horizon — without γ, even a +1 per-step reward would yield infinite total return.

Cricket analogy: A player's value is not their score in the last two matches but their expected cumulative contribution over the entire tournament. Value functions formalize this long-run perspective.

05 — STATE & ACTION VALUE FUNCTIONS

How Good Is a State (or Action)?

Value functions answer the central question of RL: starting from here, how much total reward can I expect if I follow policy π?

State-value function Vπ(s)

The expected return when starting in state s and thereafter following π:

Vπ(s) = Eπ[ Gt | St = s ] = Eπ[ Σk=0∞ γk Rt+k+1 | St = s ]

Vπ(s) is not the immediate reward. It aggregates all future rewards the agent can reach from s, weighted by γ.

Action-value function Qπ(s, a)

The expected return when starting in state s, taking action a first, then following π:

Qπ(s, a) = Eπ[ Gt | St = s, At = a ]

From the same state, different actions lead to different futures. Qπ captures the value of each (state, action) pair — essential for deciding which move to make.

Relationship between V and Q

The state value is the policy-weighted average of action values:

Vπ(s) = Σa∈A π(a|s) · Qπ(s, a)

Under a deterministic policy that always picks action a* in state s, this collapses to Vπ(s) = Qπ(s, a*). Q is strictly more informative: it tells you the value of each action, not just the average.

Worked example: V from Q at one state

At state s, an agent has two actions. Under a stochastic policy π(right) = 0.6, π(left) = 0.4:

ActionQπ(s, a)π(a|s)Contribution
Right → toward goal8.50.65.10
Left → toward trap−2.00.4−0.80
Vπ(s) =4.30

Vπ(s) is the weighted average — neither 8.5 nor −2.0 alone. To choose the best action, compare Q values directly: argmaxa Qπ(s,a) = right.

Vπ(s)

"How good is it to be here?" — one number per state.

Qπ(s,a)

"How good is it to do this from here?" — one number per (state, action).

06 — BELLMAN EXPECTATION EQUATIONS

Values Decompose into Immediate Reward + Future Value

The Markov property yields a recursive structure: the value of a state equals the expected immediate reward plus the discounted value of wherever you land next. Richard Bellman captured this in the Bellman expectation equation.

For Vπ

Vπ(s) = Σa π(a|s) Σs′ P(s′|s,a) [ R(s,a,s′) + γ Vπ(s′) ]

For Qπ

Qπ(s,a) = Σs′ P(s′|s,a) [ R(s,a,s′) + γ Σa′ π(a′|s′) Qπ(s′,a′) ]

Read the V-equation as: "take action a with probability π(a|s); transition to s′ with probability P(s′|s,a); collect reward R and discounted future value γVπ(s′); sum over all actions and next states."

This is a backup diagram idea: V(s) at the root splits into branches for each action, each branch splits into successor states, each leaf contributing R + γV(s′). The Bellman equation is the algebra of that tree.

Where the recursion comes from

Start from the definition and split off the first reward:

Gt = Rt+1 + γ (Rt+2 + γ Rt+3 + …) = Rt+1 + γ Gt+1

Taking expectation under π and using the Markov property (future depends only on St+1):

Vπ(s) = Eπ[Rt+1 + γ Vπ(St+1) | St = s]

Expanding the expectation over actions and next states yields the full Bellman expectation equation above. The same logic applied to Qπ, conditioning on the first action being fixed at a, gives the Q-equation.

Numeric Bellman backup (single state)

State s has two actions under π: go right (π = 0.7) lands in s′ with R = 0, Vπ(s′) = 5; go down (π = 0.3) lands in s″ with R = −1, Vπ(s″) = 2. With γ = 0.9:

Vπ(s) = 0.7×[0 + 0.9×5] + 0.3×[−1 + 0.9×2] = 0.7×4.5 + 0.3×0.8 = 3.15 + 0.24 = 3.39

This demo uses deterministic P(s′|s,a) — each action moves exactly one cell. Real robots and slippery grid worlds add stochastic slippage: P might spread 0.8 to intended direction and 0.1 to each perpendicular direction. The Bellman equation handles both; only the inner sum over s′ changes.

08 — OPTIMAL VALUES & BELLMAN OPTIMALITY

The Best Possible Policy

Policy π is better than π′ if Vπ(s) ≥ Vπ′(s) for every state s — not just some. An optimal policy π* achieves the maximum possible value everywhere. Multiple optimal policies may exist, but they share the same optimal value functions V* and Q*.

A deterministic policy maps each state to one action: π(s) = a. A stochastic policy outputs a distribution π(a|s) — necessary when multiple actions tie or when exploration is built in. Optimal policies for MDPs can always be chosen deterministic (pick any max-Q action), but learning algorithms often use stochastic policies during training.

V*(s) = maxπ Vπ(s) = maxa Q*(s, a)
Q*(s, a) = maxπ Qπ(s, a)

Optimal policies are greedy with respect to Q*: in every state, pick the action that maximizes expected return. The Bellman optimality equation replaces the policy-weighted sum with a max over actions:

V*(s) = maxa Σs′ P(s′|s,a) [ R(s,a,s′) + γ V*(s′) ]
Q*(s, a) = Σs′ P(s′|s,a) [ R(s,a,s′) + γ maxa′ Q*(s′, a′) ]

Finding π* means solving these equations — exactly when the MDP is small (dynamic programming, next chapter), approximately when it is large (Monte Carlo, TD, policy gradients for LLMs).

Optimal values on the demo grid

Under the optimal policy for the Section 07 grid (γ = 0.9, step cost −0.04), V*(G) = 0 and V*(T) = 0 at terminals. Cells closer to G have higher V* — the value gradient points toward the goal. Cells near T have depressed values; the agent learns to route around the trap even though each step only costs −0.04. Greedy policy with respect to V* (move to neighbor with highest R + γV*) recovers the shortest safe path.

Bellman expectation

Uses fixed π. Computes Vπ, Qπ. Policy evaluation.

Bellman optimality

Uses maxa instead of π. Computes V*, Q*. Policy improvement.

Summary of equations: Bellman expectation decomposes Vπ and Qπ under a fixed policy. Bellman optimality replaces π with maxa to characterize V* and Q*. Every RL algorithm — from tabular Q-learning to PPO on billion-parameter models — is ultimately trying to approximate these objects.

09 — MDPs & REASONING LLMs

Why Value Functions Matter for Training Reasoners

RLHF and GRPO frame LLM training as an MDP: state = prompt plus generated tokens, action = next token, reward = verifier score or human preference. DeepSeek-R1-style training estimates whether continuing a reasoning chain will yield high final reward — a value-function question at scale.

MDP conceptReasoning LLM analogue
State SPrompt + chain-of-thought tokens generated so far
Action ANext token (or next reasoning step)
Transition PDeterministic given autoregressive sampling
Reward RORM/PRM score, correctness check, preference signal
Vπ(s)Expected final answer quality from this partial trace
Qπ(s,a)Expected quality if we emit token a next
π*Policy that maximizes correct, verifiable reasoning

Chapter 03's verifiers supply R; Chapter 04's explore–exploit dilemma reappears when sampling diverse reasoning paths during training. The Bellman structure explains why credit must propagate backward from a final answer score to intermediate tokens — each token's value depends on the discounted value of the continuation.

Process vs outcome rewards

An outcome reward model (ORM) scores only the final answer — sparse signal, hard credit assignment. A process reward model (PRM) scores intermediate reasoning steps — closer to Q(s,a) at each token. PRMs approximate the Bellman idea: the value of a partial solution depends on whether the continuation can still reach a high final score. Training with PRM feedback is effectively pushing Q-values up on good intermediate actions.

Scale challenge: Tabular V and Q store one number per (state) or (state, action). LLM state spaces have size |V|L for vocabulary V and length L — far too large for tables. Function approximation (neural networks) replaces lookup tables; the Bellman structure remains the same. Chapter 07 covers this transition.

10 — SUMMARY

Key Takeaways

  • MDPs extend bandits with state transitions: (S, A, P, R, γ).
  • The Markov property: future depends on current state, not full history.
  • Return Gt = Σ γk Rt+k+1; discount γ handles continuing tasks and time preference.
  • Vπ(s) = expected return from s; Qπ(s,a) = expected return after taking a in s.
  • Vπ(s) = Σa π(a|s) Qπ(s,a).
  • Bellman expectation recurses: value = expected [reward + γ × next value].
  • V*, Q*, Bellman optimality: replace π with maxa to characterize the best policy.
  • Next: Chapter 06 solves these equations with dynamic programming, Monte Carlo, and TD learning.
