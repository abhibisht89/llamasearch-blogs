01 — A NEW ARC

Why We Need Reinforcement Learning Now

Arc 1 taught three ways to get better answers from a frozen model: chain-of-thought prompting changes what the model proposes; verifiers and search pick the best among many samples. All of that compute is spent at test time — the weights never move.

Arc 2 is different. The goal is to change the model itself so it learns to reason, not just be nudged at inference. Pure reinforcement learning is the mechanism behind converting a non-reasoning LLM into a reasoning model — the path DeepSeek-R1 and similar systems take. But RL has its own language: agents, environments, reward signals, policies, value functions. This chapter builds that foundation from the ground up.

Arc 1 — Inference

CoT, self-consistency, beam search + PRM. More compute at test time; weights frozen.

Question: How do I get a better answer from this model right now?

Arc 2 — Training

RL updates policy weights from reward feedback. The model learns over many episodes.

Question: How do I make the model better at reasoning permanently?

Verifier → reward model: Chapter 03's ORM/PRM scores candidates at inference. In RL training, a reward model plays the same grading role — but the signal flows backward through the policy to update weights. Bandits are where we first learn to maximize reward from experience.

02 — THE RL PROBLEM

What Is Reinforcement Learning?

Reinforcement learning studies how an agent learns to make decisions by interacting with an environment. Unlike supervised learning, there are no fixed input–label pairs. Instead, the agent takes actions, receives scalar rewards, and improves over time through trial and error.

Agent

The learner and decision-maker — a gazelle learning to run, a chess engine choosing moves, or (later) an LLM generating tokens.

Environment

Everything external the agent interacts with — the physical world, a game board, or the user/problem context surrounding an LLM.

State

A snapshot of the situation — chess board position, robot location, or the prompt + generated prefix for an LLM.

Action

A choice the agent makes — move a chess piece, pull a slot lever, emit the next token.

Reward

A single number from the environment after each action. The agent's sole objective: maximize cumulative reward over time.

Every RL problem shares the same skeleton: an active decision-making agent interacting with an environment toward a goal. The agent uses experience to improve — the more it interacts, the better it gets. A gazelle falls repeatedly before it runs fast; we acquire skills through practice until one day we notice we are much better than two months ago.

Reward as pleasure/pain: Touch a hot vessel → negative reward → avoid that action. Lose a chess game → negative signal → don't repeat that sequence. Rewards define the goal; the agent learns which actions lead to more of them.

Four Elements of an RL System

Beyond the five-tuple, Sutton & Barto describe four main elements that any RL method must represent:

ElementRoleTime horizon
Policy πMapping from states → actions; the agent's behavior ruleDecision rule
Reward signalImmediate feedback defining the goalShort-term
Value functionExpected long-term return from a state or actionLong-term
Model (optional)Predicts next state and reward; enables planningSimulation

Reward signals tell you what is good right now; value functions tell you what is good in the long run. A tournament player may score poorly in early matches (low reward) while the captain still believes their long-term value is high — value accumulates future rewards, reward does not.

03 — THREE PARADIGMS

RL vs Supervised vs Unsupervised Learning

Why is RL a separate field? Because many real problems — learning to walk, preparing breakfast, playing games — cannot be cast as supervised or unsupervised learning. You cannot label every intermediate action ("reach cupboard → label: good"). You cannot cluster gazelle running motions and call it done — the goal is to run fast, not discover structure.

AspectSupervised LearningUnsupervised LearningReinforcement Learning
Training signalFixed labels for each inputNo labels; find hidden structureScalar rewards from interaction
Feedback timingImmediate, per exampleNone (or reconstruction error)Delayed; may come many steps later
Data sourceStatic datasetStatic datasetAgent generates data by acting
GoalMinimize prediction errorDiscover patterns / representationsMaximize cumulative reward
Explore/exploitNot applicableNot applicableCentral dilemma
ExampleImage classificationClustering, autoencodersChess, robotics, LLM alignment
LLM analogyNext-token prediction (pre-training)Representation learningRLHF, GRPO, reasoning training

Why breakfast is not supervised: Phil preparing breakfast involves a sequence of decisions — reach cupboard, grab cereal, find spoon. There is no natural label for each micro-action. RL fits because the agent learns from the outcome (a satisfying meal, or hunger) rather than step-by-step supervision.

04 — THE RL LOOP

Observe → Act → Reward → Learn

At each time step, the agent perceives a state, selects an action, receives a reward, and updates its strategy. This loop repeats; performance improves with more interactions.

→ state st
Agent Policy π(a|s)
→ action at

↺ learn
t = 0, 1, 2, … Agent observes state st │ ▼ Agent selects action at ~ π(· | st) │ ▼ Environment returns (st+1, rt) │ ▼ Agent updates policy / value estimates ──► repeat

The unique feature of RL: unlike supervised learning on a fixed dataset, the agent's data distribution changes as it learns. Better policies visit different states, which produce different training signal — a feedback loop that makes RL both powerful and tricky.

05 — MULTI-ARMED BANDITS

The Simplest RL Problem

A one-armed bandit is a slot machine with one lever: pull it, receive a random reward. A multi-armed bandit (MAB) has k levers — each arm returns rewards from its own hidden distribution. You do not know the true values upfront; your goal is to maximize total reward over T pulls.

One-armed bandit

Single lever, single unknown reward distribution. No choice — just estimate expected payout.

k-armed bandit

k levers, k unknown distributions. Every pull is both an experiment (learn Q) and a bet (earn reward).

Why "bandit"? Early slot machines were called one-armed bandits because they took your money. The name stuck in RL literature as the canonical explore–exploit problem.

Single-state RL: In a bandit, there is only one situation — you stand in front of the machine and pull levers. No state transitions. That simplicity makes bandits the perfect gateway before full MDPs in Chapter 05.

The bandit is a sequential decision problem without states. Actions are pulling levers; rewards are the slot payouts. The entire challenge is balancing exploration (try unfamiliar arms to learn their value) against exploitation (pull the arm that looks best so far).

07 — THE CENTRAL DILEMMA

Exploration vs Exploitation

Exploitation means choosing the action that currently looks best — pull the lever with the highest Q estimate. Exploration means trying other arms to gather information, even if they look worse now.

Exploitation

Pick the arm with highest Qt. Maximizes expected reward given current knowledge.

Risk: never learn that another arm is better.

Exploration

Try under-sampled arms. May yield lower immediate reward but reduces uncertainty.

Risk: waste pulls on clearly bad arms.

The conflict is fundamental. Lecture experiments on a 10-arm bandit show pure greedy (ε = 0) performing worst — the algorithm gets stuck pulling one lever repeatedly, never exploring others. With ε = 0.1, average reward improves by ~0.4 — a significant gap from a single hyperparameter change.

Every bandit algorithm is really a strategy for balancing these two forces. The three we cover next — ε-greedy, UCB, Thompson sampling — differ in how they allocate exploration budget.

08 — BANDIT ALGORITHMS

Three Ways to Balance Explore & Exploit

1. ε-Greedy

With probability ε, select uniformly at random among all arms (explore). With probability 1 − ε, select the greedy arm argmax Qt(a) (exploit).

ε = 0.1 means ~10 random pulls per 100 steps. Simple, effective, and the baseline in the lecture's Colab demo comparing greedy vs ε = 0.1 vs ε = 0.01.

2. Upper Confidence Bound (UCB)

Instead of random exploration, UCB selects the arm with the highest upper confidence bound — optimistic about uncertain arms:

The √(ln t / Nt(a)) term grows for rarely-pulled arms, encouraging exploration where uncertainty is high. Constant c controls exploration aggressiveness. UCB has strong theoretical regret bounds — it explores systematically rather than randomly.

3. Thompson Sampling

Maintain a belief (posterior) over each arm's true reward. Each step, sample one reward value from each arm's posterior, then pull the arm with the highest sample:

For Bernoulli rewards, use Beta posteriors; for Gaussian rewards, use Normal–Normal conjugate updates. Thompson sampling is Bayesian, handles uncertainty naturally, and often outperforms ε-greedy in practice with no ε to tune.

10 — BEYOND BANDITS

Why Bandits Are Not Enough

Bandits teach interaction and the explore–exploit tradeoff, but they omit the defining feature of full RL: state transitions.

In a bandit, you face one situation forever — pull levers, estimate values, done. In real RL, actions change the world. Learning to ride a bicycle: one pedal stroke puts you in a new state; the next pedal stroke faces a different situation requiring a different action. Learning to walk, play chess, or generate a multi-step reasoning chain all involve sequences of states.

Bandit

  • Single state (one situation)
  • Actions don't change context
  • No planning over futures
  • Action values Q(a) suffice

MDP (Ch.05)

  • Many states, sequential decisions
  • Actions cause state transitions
  • Delayed rewards, long horizons
  • State values V(s), Q(s,a), Bellman
Bandit: same state ──► pull arm ──► reward ──► same state ──► … MDP: s₀ ──a₀──► s₁ ──a₁──► s₂ ──a₂──► … ──► terminal reward

Bandits are the gateway, not the destination. Chapter 05 introduces Markov Decision Processes — states, transitions, returns, and value functions — the framework needed for chess, robotics, and LLM token generation where each token changes the context for the next.

11 — RL MEETS REASONING LLMS

Why This Matters for Reasoning Models

Arc 1 improved reasoning without changing weights. Arc 2 — starting here — trains the model to reason by optimizing a reward signal. The bandit is the simplest instance of that loop; LLM alignment is the most consequential.

Bandit conceptLLM training analogue
AgentThe LLM (policy πθ)
ActionGenerate next token (or full response)
StatePrompt + tokens generated so far
RewardORM/PRM score, human preference, verifiable answer check
Explore/exploitSample diverse completions vs exploit high-probability paths
Q(a) estimateExpected reward for a response style or reasoning pattern

Chapter 03's reward models become the reward signal in RLHF. Instead of picking the best sample at inference (best-of-N), RL propagates reward backward to update θ — the model learns to produce high-reward outputs directly. Later chapters extend this to GRPO, which groups samples and normalizes advantages — but the core loop remains: observe, act, reward, learn.

Inference-time (Arc 1) Prompt ──► LLM ──► many samples ──► Verifier picks best ──► answer Training-time (Arc 2+) Prompt ──► LLM ──► completion ──► Reward model ──► update θ ──► better policy
