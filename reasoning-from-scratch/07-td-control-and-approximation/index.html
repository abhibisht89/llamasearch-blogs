CHAPTER 07

TD Control & Function Approximation

Chapter 06 taught TD prediction: estimate Vπ for a fixed policy. This chapter crosses into control — learning Qπ while improving the policy — and then escapes the tabular trap. SARSA and Q-learning differ in one line of math but produce radically different behavior; function approximation turns a Q-table into a neural network and opens the door to DQN, AlphaGo, and LLM training.

01 — FROM PREDICTION TO CONTROL

Why Control Is the Next Step

In TD prediction, we fixed a policy π and learned its value function:

V(S) ← V(S) + α [ R + γ V(S′) − V(S) ]

That update bootstraps from the next state’s value — no need to wait for episode end, unlike Monte Carlo. TD methods blend the strengths of dynamic programming (bootstrapping) and Monte Carlo (learning from experience without a model).

Control asks the opposite question: which policy is optimal? The recursive recipe from dynamic programming and Monte Carlo still applies — estimate values, improve policy, repeat — but now we work with the action-value function Q(s, a) instead of V(s), because Q directly tells us which action is best in each state.

Prediction

Given π, estimate Vπ or Qπ. The policy is fixed.

Control

Find π* that maximizes expected return. Values and policy co-evolve.

Implicit policy iteration: With ε-greedy action selection, you rarely write “update policy” explicitly. Q-values change every step; the greedy action from Q changes too — policy iteration happens continuously in the background.

Both SARSA and Q-learning use ε-greedy exploration (probability ε of a random action, otherwise greedy) to balance exploration and exploitation — the same trick from Monte Carlo control in Chapter 06.

The Three Families (Recap)

The commuting analogy from the lectures: Monte Carlo will not revise your estimate for “junction 3” until you reach home and finish the whole trip. TD revises immediately using the value of the next junction — bootstrapping a guess about the remainder of the journey.

02 — TD CONTROL

Online Control Without a Model

TD control algorithms learn optimal behavior from sample transitions (S, A, R, S′) — no transition probabilities required. They update after every step, making them far more sample-efficient than Monte Carlo for long episodes (think of updating a traffic junction’s value immediately when you hit congestion, rather than waiting until you reach home).

TD control loop Initialize Q(s, a) arbitrarily │ ▼ For each episode: Observe S, choose A ~ ε-greedy(Q) Take action, observe R, S′ Update Q(S, A) using TD target ← SARSA or Q-learning S ← S′; choose next A (SARSA only) │ └── repeat until Q converges → greedy policy ≈ π*

The entire difference between the two major TD control algorithms lies in what they put in the TD target for the next state — the actual next action (SARSA) or the max over actions (Q-learning).

Action-Value Control with ε-Greedy

Tabular control with TD follows the same recursive pattern as Monte Carlo control from the prior chapter:

  1. Start with a random or zero Q-table and an ε-greedy policy derived from it.
  2. Generate episodes; after each transition, apply a TD update to Q(S, A).
  3. Because Q changed, the greedy action per state may change — the policy improves implicitly.
  4. Repeat until Q stabilizes; the greedy policy approximates π*.

With probability ε the agent explores a random action (possibly discovering a better path); with probability 1−ε it exploits the current best action. Without exploration, the agent can get stuck on a suboptimal action it tried first — the same problem that does not arise in dynamic programming where every action’s outcome is known from the model.

π(a|s) = (1−ε) · 𝟙[a = argmaxa′ Q(s,a′)] + ε/|A|   (uniform random with prob ε)
03 — ON-POLICY TD CONTROL

SARSA: State–Action–Reward–State–Action

SARSA is named after the five symbols in its update: (St, At, Rt+1, St+1, At+1). The algorithm is on-policy: it learns the value of the policy it is actually following, including exploratory random actions.

Q(S, A) ← Q(S, A) + α [ R + γ Q(S′, A′) − Q(S, A) ]

Compare to TD prediction: replace V with Q, and use the Q-value of the next state–action pair (S′, A′) where A′ is the action the agent will actually take next under the current ε-greedy policy.

SARSA algorithm (outline)

  1. Initialize Q(s, a) for all s, a (e.g., zeros or small random values).
  2. For each episode: initialize S; choose A from S using ε-greedy(Q).
  3. Loop: take action A, observe R and S′; choose A′ from S′ using ε-greedy(Q).
  4. Apply SARSA update with (S, A, R, S′, A′).
  5. Set S ← S′, A ← A′ until S is terminal.

Why include A′? Because the agent might randomly explore a dangerous action near a cliff. SARSA’s backup accounts for that risk — it learns “if I’m following this exploratory policy, what is Q(S, A) really worth?” That makes SARSA conservative and safe.

TD Error for Control

The bracketed term in both updates is the TD error δ, now defined over Q rather than V:

δ = R + γ Q(S′, A′) − Q(S, A)    (SARSA target)
δ = R + γ maxa′ Q(S′, a′) − Q(S, A)    (Q-learning target)

Positive δ means the transition was better than expected — bump Q(S, A). Negative δ means worse than expected — lower the estimate. The learning rate α controls how quickly old estimates are overwritten.

04 — OFF-POLICY TD CONTROL

Q-Learning: Learning Q* While Exploring

Q-learning makes one critical change: replace Q(S′, A′) with maxa′ Q(S′, a′). The update no longer depends on which action you will actually take next.

Q(S, A) ← Q(S, A) + α [ R + γ maxa′ Q(S′, a′) − Q(S, A) ]

This is the off-policy TD control algorithm. The agent can follow an exploratory ε-greedy behavioral policy while the update targets the optimal action-value function Q*. The max operator directly encodes the Bellman optimality equation — it always asks “what if I took the best action next?”

Q-learning algorithm (outline)

  1. Initialize Q(s, a) for all s, a.
  2. For each episode: initialize S.
  3. Loop: choose A from S using ε-greedy(Q); take action, observe R, S′.
  4. Apply Q-learning update (uses max over next actions, not actual A′).
  5. S ← S′ until terminal.

Optimistic but risky during training: Q-learning’s max pushes values toward the optimal path even when exploration wanders near danger. After convergence, the greedy policy is optimal — but during learning, the agent may fall off cliffs more often because it overestimates safe-looking cliff-edge states.

05 — ON-POLICY VS OFF-POLICY

Two Policies, One Update Rule Apart

Every RL algorithm involves at least two policies conceptually:

  • Behavior policy — the one generating experience (usually ε-greedy).
  • Target policy — the one whose values we are trying to learn.

On-policy (SARSA)

Behavior = target. You learn about the policy you follow — like improving your bicycle riding by noting mistakes from your own riding style.

Off-policy (Q-learning)

Behavior ≠ target. You explore randomly but learn optimal Q* — like watching a coach’s perfect form while you practice messily, updating toward the ideal.

07 — BEYOND TABULAR METHODS

Why Q-Tables Break at Scale

Tabular methods store one number per state (or per state–action pair). They work beautifully for grid worlds with dozens of cells — and fail catastrophically at scale. Chess has on the order of 1046 states; a Go board has 10170. LLM “states” are essentially all possible token sequences — astronomically larger.

The fix is generalization: learn values for states you have visited, then extrapolate to states you have not. This is function approximation — the same idea as supervised learning, but with two twists that make RL harder:

  • The target is unknown — we never observe the true V(s) or Q(s, a).
  • The target is non-stationary — as weights update, the target moves (especially with bootstrapping).

Three Approximation Methods

1. State aggregation

Group similar states into buckets; share one value per bucket. Coarse graining reduces the table size but loses detail. A robot might treat “battery 47%” and “battery 49%” as the same abstract state.

2. Linear function approximation

Represent value as a weighted sum of features:

V̂(s, w) = w · x(s) = Σi wi xi(s)

Feature vector x(s) is hand-designed from domain knowledge (distance to goal, threat level, piece counts). Weights w are learned via gradient descent on a TD error. For linear V̂, the gradient ∇w V̂(s) = x(s), giving clean semi-gradient TD updates:

w ← w + α [ R + γ V̂(S′, w) − V̂(S, w) ] x(S)

Linear methods are simple, analyzable, and still used when features are well understood — but they cannot represent arbitrary nonlinear value surfaces.

3. Neural network approximation

Replace the linear dot product with a deep network: states (or state–action pairs) enter an input layer, pass through hidden layers, and output V(s) or Q(s, a). Weights are connection strengths — the network fine-tunes them so outputs match TD targets. Nonlinear activations let the network approximate complex functions; depth and width trade off expressiveness against data and compute.

Q̂(s, a; θ) ≈ Q*(s, a)    where θ are all network weights

Semi-gradient TD: When the TD target involves V̂(S′, w), the target itself depends on w. Strict gradient descent would backprop through that dependency; semi-gradient ignores it and treats the target as fixed for one step. It works well in practice despite being “wrong” on paper.

Loss Functions and Targets

Function approximation in RL starts by defining a loss — how far is our estimate from the truth?

L(w) = ½ [ V(s) − V̂(s, w) ]²

In supervised learning, V(s) is known (exam score given hours studied). In RL, V(s) is never observed directly. The trick from the lectures: replace the unknown true value with a target whose expectation equals the true value:

  • Monte Carlo target: Gt — the full return from t onward. Unbiased but high variance.
  • TD target: R + γ V̂(S′, w) — bootstrapped one-step lookahead. Lower variance but biased while w is wrong.

Gradient descent on w using the TD target gives the semi-gradient update shown above. The same pattern extends to Q̂(s, a; w) for action-value control with SARSA or Q-learning targets.

Linear vs Nonlinear — When to Use Which

ApproachStrengthsLimitationsExample domains

AlphaGo used neural networks to approximate value and policy over the enormous Go state space — the same nonlinear FA idea, combined with Monte Carlo tree search. Reasoning models use transformers as function approximators over token sequences, trained with policy-gradient variants instead of tabular Q updates — but the generalization problem is identical.

08 — FROM Q-TABLE TO Q-NETWORK

The Path to Deep RL — and Reasoning LLMs

Combining Q-learning with a neural network Q̂(s, a; θ) gives DQN (Deep Q-Network): the breakthrough that solved Atari from pixels and launched modern deep RL. The recipe is exactly what this chapter built:

Tabular Q-learning → large state space → Linear Q̂(s,a) = w·x(s,a) → nonlinear problems → Neural Q̂(s,a; θ) → DQN (2015) → continuous control, Go, robotics, ...
StageRepresentationScaleLandmark

Why This Matters for Reasoning LLMs

An LLM generating a chain of thought is an agent in an enormous MDP: states are prompts plus generated tokens; actions are next tokens; rewards come from verifiers or human preference. Storing a Q-table over all possible contexts is impossible — the model is the function approximator.

Systems like DeepSeek-R1 and GRPO use policy-gradient methods (a sibling branch to Q-learning) with neural networks containing billions of parameters θ. But the conceptual lineage is unchanged from this chapter:

  • Estimate value of states/actions (now via forward pass through a transformer).
  • Update weights from reward signal (now via backprop on a surrogate loss).
  • Balance exploration (sampling diverse reasoning paths) with exploitation (rewarding correct answers).
  • Choose on-policy (PPO: learn from own rollouts) vs off-policy (learn from replay buffers or human demos) — the same SARSA/Q-learning tradeoff at LLM scale.

DQN: Q-Learning at Neural Scale

Deep Q-Networks (Mnih et al., 2015) replace the Q-table with a convolutional network that maps Atari frames to Q-values for each action. Experience replay and target networks stabilize the non-stationary TD target — engineering fixes for the same bootstrapping issues discussed in the semi-gradient section. From DQN, the path runs through Double DQN, Rainbow, and distributed variants to AlphaStar and beyond.

09 — SUMMARY

Key Takeaways

  • TD control extends TD prediction: learn Q while improving policy via ε-greedy.
  • SARSA (on-policy): Q(S,A) ← Q(S,A) + α[R + γ Q(S′,A′) − Q(S,A)]. Learns Qπ for the exploratory policy — safe paths.
  • Q-learning (off-policy): Q(S,A) ← Q(S,A) + α[R + γ maxa′ Q(S′,a′) − Q(S,A)]. Learns Q* — optimal but riskier during training.
  • Cliff walking makes the on/off-policy difference visceral: safe detour vs cliff-hugging shortcut.
  • Tabular methods fail at chess/Go/LLM scale; function approximation generalizes from seen to unseen states.
  • Linear FA: V̂(s) = w · x(s). Neural FA: Q̂(s,a; θ) → DQN → modern deep RL → LLM RL training.
