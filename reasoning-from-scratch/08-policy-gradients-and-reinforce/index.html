Policy Gradients & REINFORCE

00 — FROM VALUES TO POLICIES

Everything So Far Was Indirect

Chapter 04 introduced the RL loop. Chapters 05–07 built MDPs, Bellman backups, Monte Carlo returns, and TD control (SARSA, Q-learning). Each method answered: “How good is action a in state s?” The policy was derived afterward — ε-greedy over Q, or argmax over tabular entries.

That pipeline works beautifully for small problems. It breaks down when:

  • States are sequences of thousands of tokens (every prefix is a distinct state).
  • Actions are stochastic by design — reasoning models sample diverse chains-of-thought.
  • You want end-to-end training: backprop from reward directly into the network that chooses actions.

Arc 3 begins here. Policy gradient methods are how DeepSeek-R1, OpenAI reasoning models, and RLHF systems actually move LLM weights. The next four chapters (08–11) build the optimization stack; chapters 10–12 apply it to reasoning.

01 — THE TURNING POINT

Why Policy Gradients?

Reinforcement learning’s goal is to find the optimal policy — the rule that maps states to actions maximizing long-term reward. Chapters 06–07 took an indirect route: for each state, estimate expected returns for every action, build a table or neural Q-function, then pick the action with the highest value.

Value-based (Ch.06–07)

Compute Q(s, a) for all actions → select argmaxa Q(s, a). The policy is a by-product of the value function.

Works for discrete actions; struggles with continuous control and stochastic policies.

Policy-based (this chapter)

Parameterize πθ(a|s) directly and climb the performance landscape in θ-space. No argmax over actions required at each step.

Natural fit for neural nets, softmax over vocabularies, and sampling-based training.

The value-based pipeline has three pain points that matter enormously for LLMs:

  • Scale: tabular Q needs one entry per (state, action). Chess has ~1047 states — a table is impossible.
  • Indirect optimization: you never gradient-descend on “policy quality”; you fit Q and hope argmax Q equals the best policy.
  • Determinism: argmax policies cannot represent exploration or stochastic reasoning (sampling diverse chain-of-thought paths).

Every reasoning LLM that uses RL relies on policy gradient methods. DeepSeek-R1, OpenAI o-series models, and essentially all RLHF/GRPO pipelines update token probabilities via ∇ log πθ. This chapter is where Arc 3 begins in earnest.

02 — PARAMETERIZE THE POLICY

Direct Policy Optimization

Instead of storing action values, we write the policy as a parametric function πθ(a|s) — the probability of action a in state s, controlled by parameters θ (often neural network weights).

πθ(a | s)  ∈  [0, 1],   Σa πθ(a | s) = 1

θ lives in a d-dimensional space. If d = 2, we can visualize policy search as moving a point (θ1, θ2) across a performance landscape — exactly the mental picture behind gradient ascent.

From preferences to probabilities

A raw scoring function h(s, a, θ) might output any real number. Policies must be valid probabilities, so we use a softmax — the same trick as classification heads in neural networks:

πθ(a | s) = exp(h(s, a, θ)) / Σa′ exp(h(s, a′, θ))

The performance measure J(θ) is the expected return from the start state under policy πθ — typically Vπθ(s0). Our job: find θ that maximizes J(θ) using gradient ascent:

θt+1 = θt + α · ∇θ J(θt)

The hard question — answered by the policy gradient theorem — is how to compute ∇θ J(θ) without differentiating through the environment’s state distribution.

Discrete actions: logits → softmax

Suppose state s has five actions with learned preferences h(s, a, θ). Raw scores might be 1–5, but probabilities must lie in [0, 1]. The softmax maps arbitrary scores to a valid distribution — identical to the final layer of a classifier, and identical to how an LLM turns hidden states into token probabilities over the vocabulary.

state s ──► network ──► logits h(s, ·, θ) ──► softmax ──► πθ(·|s) │ ▼ sample action a ~ πθ

Policy search becomes gradient ascent on θ in a high-dimensional space. For a 7B-parameter LLM, θ is enormous — but the update rule remains the same weighted sum of score functions.

03 — THE BEDROCK THEOREM

The Policy Gradient Theorem

Naively, J(θ) depends on θ both through the policy and through the state distribution μ(s) induced by that policy. Differentiating both seems to require ∇θ μ(s) — expensive and unstable.

The policy gradient theorem (Sutton et al., 2000) delivers a remarkable simplification: the gradient of J(θ) does not involve ∇θ μ(s), even though μ depends on θ.

∇θ J(θ) = Es∼μ, a∼π [ Qπ(s, a) · ∇θ log πθ(a | s) ]

Equivalently, using the full sum form over states and actions:

∇θ J(θ) ∝ Σs μ(s) Σa Qπ(s, a) · ∇θ πθ(a | s)

Three terms appear — and only three:

TermSymbolMeaning
State distributionμ(s)How often the agent visits state s under πθ (visit counts / total steps)
Action valueQπ(s, a)Expected future return after taking action a in state s
Policy gradient∇θ log πθ(a|s)Score function — direction in θ-space that increases P(a|s)

Intuition: increase the probability of actions that lead to high Q-values; decrease the probability of bad actions. The theorem tells us the exact direction in parameter space — and we never touch ∇μ.

Using a Monte Carlo return Gt as an unbiased sample of Qπ(st, at), we get the REINFORCE-friendly form:

∇θ J(θ) ≈ E [ ∇θ log πθ(at | st) · Gt ]

Why ∇μ disappears (chain rule intuition)

Write J(θ) = f(μ(θ), πθ) where μ is the state distribution induced by the policy. The chain rule suggests ∇J should include ∇θμ. The policy gradient theorem’s proof shows this term telescopes to zero when you expand ∇J as an expectation over trajectories — leaving only the score function weighted by returns.

Practically: you can estimate the gradient by sampling episodes from the current πθ and averaging Gt ∇ log πθ(at|st) across timesteps. No model of the environment required.

04 — THE SCORE FUNCTION

∇ log π — The Score Function

Policy gradient methods lean on one identity constantly. For any parameterized distribution:

∇θ log πθ(a | s) = ∇θ πθ(a | s) / πθ(a | s)

This is the score function. Multiplying by π and summing over actions recovers the policy gradient — the trick used to eliminate the action summation in REINFORCE (multiply and divide by πθ(a|s), then interpret the sum as an expectation).

LLM connection: when a transformer emits token w with log-probability log πθ(w | context), backprop already computes ∇θ log πθ. RL loss terms like −A · log π are literally policy gradients — the same object you will see in PPO and GRPO.

For a softmax policy, the score function has a clean form. If ha = h(s, a, θ) are logits:

∇θ log πθ(a | s) = ∇θ h(s, a, θ) − Σa′ πθ(a′|s) · ∇θ h(s, a′, θ)

That second term is the “softmax correction” — the gradient depends on all actions, not just the one taken. In practice autodiff handles this automatically.

05 — REINFORCE (WILLIAMS, 1992)

The REINFORCE Algorithm

REINFORCE is the first policy gradient algorithm: run a full episode with πθ, compute returns Gt for each timestep, then update θ proportional to Gt and the score function of the action actually taken.

θ ← θ + α · Σt=0T Gt · ∇θ log πθ(at | st)

Click Step through to highlight each line of the pseudocode. The same sequence runs automatically when you Sample + Update in the landscape demo above.

REINFORCE — episodic Monte Carlo policy gradient

Initialize policy parameters θ // random weights
repeat until convergence:
  Generate episode s0, a0, r1, …, sT ~ πθ
  for t = 0 … T−1:
    Gt ← Σk=tT γk−t rk+1  // return from t
    θ ← θ + α · Gt · ∇θ log πθ(at|st)
return θ

Why REINFORCE works (vector intuition)

Fix a timestep: if Gt is large and positive, we nudge θ in the direction that increases log πθ(at|st) — make that action more likely. If Gt is negative, the same gradient step pushes probability away from at. Over many episodes, probability mass flows toward trajectories with high return.

From theorem to sample: the π trick

The full theorem sums over all actions a at each state. REINFORCE avoids that sum by multiplying and dividing by πθ(a|s):

Σa πθ(a|s) Q(s,a) ∇log πθ(a|s) = Ea∼π[ Q(s,a) ∇log πθ(a|s) ]

Now only the action actually sampled in the episode appears in the update — critical when the action space has thousands or millions of choices (like a vocabulary).

Implementation loop from the lectures:

  1. Roll out trajectory with current πθ.
  2. At each step t, you know st, at, and can compute ∇ log πθ(at|st) immediately.
  3. Wait until episode end to compute each Gt (Monte Carlo return).
  4. Accumulate θ updates for all timesteps; repeat until J(θ) plateaus.
06 — THE VARIANCE PROBLEM

Why Vanilla REINFORCE Struggles

REINFORCE is unbiased — in expectation, its gradient equals ∇J(θ) — but it can have enormous variance. Two sources dominate:

  • Return noise: Gt varies wildly between episodes even from the same state, because stochastic transitions and actions compound.
  • Full-episode wait: you cannot update until the episode ends, so credit assignment is delayed and gradients correlate across all timesteps.

In the landscape demo, watch how sample-to-sample G jumps even at the same θ — updates zigzag before slowly climbing. That jitter is why production systems rarely stop at vanilla REINFORCE.

Three variance reducers (all covered below): (1) subtract a baseline b(s), (2) use advantage A(s,a) instead of raw G, (3) replace Monte Carlo returns with TD targets in actor-critic. PPO and GRPO add clipping and group normalization on top of these ideas.

Reading the jitter in the demo

Run Sample ten times without updating. J(θ) at fixed θ is constant, but G bounces — sometimes 0.9, sometimes 0.4. Each would produce a different θ update. That spread is variance. Toggle baseline off in the landscape panel and watch updates become wilder; toggle it on and the same samples produce smaller, more stable steps.

Production LLM training uses large batch sizes, PPO clipping, and KL penalties for the same reason: vanilla policy gradients are correct in expectation but too noisy step-to-step.

07 — REINFORCE WITH BASELINE

Baselines: Same Expectation, Lower Variance

Subtract any function b(s) that depends only on the state — not the action — from the return:

θ ← θ + α · (Gt − b(st)) · ∇θ log πθ(at | st)

This leaves the expected gradient unchanged (the baseline trick proof) but reduces variance when b(s) tracks typical returns. A natural choice is the value function V(s) or its approximation V̂w(s).

A(s, a) = Q(s, a) − V(s)   ≈   Gt − b(st)

When b(s) = average return across episodes, updates shrink toward zero for “typical” outcomes and amplify for unusually good or bad ones — exactly the signal-to-noise improvement PPO’s value baseline provides.

REINFORCE + baseline:   b(s) = V̂w(s)   (often learned by a separate critic network)

Choosing b(s)

The baseline must not depend on the action at — otherwise you introduce bias into the gradient. Valid choices:

  • Constant: b = average return across recent episodes (cheap, helps a little).
  • Value estimate: b(s) = V̂w(s) from a critic network (standard in PPO).
  • Group mean (GRPO preview): b = mean reward among K completions for the same prompt.

Define the advantage A(st, at) = Gt − b(st). Positive advantage → reinforce action; negative → suppress it.

08 — ACTOR-CRITIC

Two Networks, One Update

Actor-critic combines policy gradients with TD learning from Chapter 07. The actor πθ chooses actions; the critic Vw(s) estimates how good each state is. Instead of waiting for Gt, use a one-step TD target:

A(st, at) ≈ rt+1 + γ Vw(st+1) − Vw(st)
θ ← θ + α · A(st, at) · ∇θ log πθ(at | st)

The critic weights w are updated separately to minimize TD error — same as value learning, but now serving the actor’s advantage estimate.

Critic update (parallel training)

The actor and critic train simultaneously. The critic minimizes TD error with target y = r + γ Vw(s′):

w ← w − β · ∇w ( Vw(s) − y )²

As Vw improves, advantages become sharper and actor updates less noisy — the same actor–critic split used in PPO, where a value head shares trunk layers with the policy.

Names matter: “Actor” = policy πθ (chooses actions). “Critic” = value Vw (judges states). The critic never picks actions; it tells the actor whether the current state is better or worse than expected.

09 — WORKED EXAMPLE

REINFORCE by Hand (Tiny Tabular Policy)

One state s, two actions {L, R}. Softmax policy with logits θ = (θL, θR) = (0.0, 0.5):

π(L) = e0/(e0+e0.5) ≈ 0.378,   π(R) ≈ 0.622

Episode: agent samples action R, receives rewards +1 then +2 (terminal). With γ = 1, return from t = 0 is G0 = 3.

  1. Score for action R: with softmax, ∇θ log π(R) = (−π(L), 1−π(R)) = (−0.378, 0.378).
  2. REINFORCE update with α = 0.1: Δθ = 0.1 × 3 × (−0.378, 0.378) = (−0.113, 0.113).
  3. New parameters: θ′ = (−0.113, 0.613). Because G > 0, θR increases and π(R) rises to ≈ 0.68 — action R becomes more likely after a good episode.
  4. With baseline b = 2 (typical return): use (G − b) = 1 instead of 3 → update magnitude shrinks by 3×, same direction.
  5. Actor-critic step: if V(s) = 1.5 and r + γV(s′) = 2.5 at t = 0, advantage A = 1.0 — usable before episode ends.

These softmax partial derivatives are exactly what autodiff computes when you implement −A log π loss in PyTorch or JAX.

Roadmap: Ch.09 adds GAE, trust regions, and PPO clipping — stabilizing the same ∇ log π update you learned here. Ch.11 (GRPO) removes the critic and normalizes rewards within prompt groups. None of that works without the policy gradient theorem from this chapter.

The loss function you will actually implement

Modern trainers express the policy gradient as a loss to minimize. For a generated sequence (a0, …, aT) with advantage A:

L(θ) = − E [ Σt=0T At · log πθ(at | st) ]

PPO replaces A with a clipped surrogate; GRPO sets A relative to the mean reward of K samples for the same prompt. Underneath, it is still REINFORCE’s skeleton: weighted log-probability gradients.

11 — SUMMARY

Key Takeaways

  • Policy gradients optimize πθ directly — essential for large action spaces and stochastic policies.
  • Policy gradient theorem: ∇J(θ) = E[∇ log πθ · Q] — no gradient through state distribution.
  • REINFORCE: Monte Carlo policy gradient using full returns Gt and score functions.
  • Variance is the main weakness; baselines and advantages fix it without bias.
  • Actor-critic: actor updates πθ; critic supplies TD advantages for faster, lower-variance learning.
  • LLMs: tokens are actions, sequences are trajectories, log-prob gradients are the training signal for reasoning models.
