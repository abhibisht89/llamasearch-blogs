Late Interaction & Learned Sparse

Between bi-encoders (one vector per document, blazing fast) and cross-encoders (joint scoring, accurate but not index-friendly) sits a rich family of late interaction architectures—ColBERT, SPLADE, MiniCOIL, and extensions into vision and ANN-friendly encodings. This page explains how they preserve token-level detail while still enabling pre-computation, and when each approach earns a place in your retrieval stack.

00 · The Middle Ground

First-stage retrieval systems are judged on two almost conflicting axes: latency at scale and ranking fidelity under lexical variation, typos, and semantic paraphrase. Classical BM25 and learned sparse models lean on inverted indexes and excel at exact-ish term overlap. Dense bi-encoders map each document to a single embedding ahead of time, so at query time you pay roughly the cost of encoding the query plus a nearest-neighbor search in a fixed-dimensional space. That is the sweet spot for billions of vectors—but the representation is intrinsically a summary: one vector must compress an entire passage’s worth of claims, entities, and constraints.

Cross-encoders flip the trade-off. They read query and document together through full self-attention, so every query token can attend to every document token. The resulting relevance signal can be remarkably precise for ranking a modest candidate list. The catch is operational: you cannot pre-compute a single document-side tensor that answers arbitrary future queries. Each new query forces fresh joint computation for every scored pair, which is why cross-encoders are typically confined to reranking top-k rather than indexing the whole corpus.

Late interaction models aim for a third path. They retain multiple contextualized vectors per document—usually one per token or subword—so the scoring function can still compare query tokens against document tokens in a structured way. Unlike cross-encoders, much of the heavy document-side computation happens offline: you store token embeddings (or sparse activations) in an index structure and reuse them for every query. The interaction is “late” because the deep transformer work is mostly done before query arrival; only the comparatively lightweight similarity aggregation runs online.

ColBERT is the canonical late-interaction dense design over text tokens. SPLADE is a learned sparse model that writes weights over the full vocabulary—including terms not literally present in the source text. MiniCOIL compresses contextualized token vectors to a handful of dimensions so inverted lists stay small while staying neural. MUVERA targets ANN-friendly multi-vector search; ColPali (preview below; see Chapter 21) applies the same idea to visual documents.

01 · ColBERT — Contextualized Late Interaction

ColBERT (Contextualized Late Interaction over BERT) is often the first architecture people reach for when they want cross-encoder-like token alignment without scoring every query–document pair with a full joint transformer pass. The model encodes queries and documents with a shared backbone (commonly BERT-style) but does not pool the sequence into one vector per side. Instead, each token position carries its own contextualized embedding in a space of moderate dimensionality—historically on the order of 128 dimensions per token after projection, though exact widths depend on the checkpoint and training recipe.

Given query token embeddings {qi} and document token embeddings {dj}, ColBERT scoring uses MaxSim: for every query token, take the maximum cosine similarity to any document token, then sum those maxima across query tokens. Intuitively, each query term “looks” for its best matching evidence anywhere in the document; the score rewards coverage of query concepts without forcing a single global pooling vector to align uniformly.

Score(Q, D) = Σi maxj cos(qi, dj)

Why MaxSim works. Relevance is often disjunctive at the token level: a mention of “python” in the query might align strongly with “asyncio” or “CPython” in the body even if average pooling would dilute the signal. MaxSim is a simple, differentiable-enough aggregator that preserves a per-query-term best match, analogous in spirit to soft OR semantics across positions. It is not a full attention matrix between every pair—computational cost is linear in the number of query and document tokens for a single pair—but you still pay storage proportional to tokens indexed, which is far larger than one vector per document.

ColBERTv2 refines the practical story. Training and distillation recipes emphasize denoised supervision so token representations are not dominated by generic language modeling signals alone, and residual compression techniques shrink stored embeddings via quantization and residual coding so disk and memory footprints move closer to what operations teams can tolerate. Even compressed, a token-level index remains heavier than single-vector dense retrieval—this is the explicit cost of richer structure.

Index size. Expect materially larger footprints than bi-encoder indexes. Mitigations include aggressive quantization, pruning low-energy tokens, document chunking strategies, and hybrid pipelines that only promote a subset of the corpus into ColBERT storage.

02 · SPLADE — Sparse Lexical and Expansion

SPLADE (Sparse Lexical and Expansion Models) is not a late-interaction dense design in the ColBERT sense; it is a learned sparse retriever that outputs a high-dimensional vector aligned with a vocabulary of size |V|—the same order of magnitude as the lexical space used by classical inverted indexes. The pipeline conceptually runs a masked language model backbone (often BERT-family), uses the MLM head logits at each input position, and transforms them into non-negative sparse weights. A common construction applies ReLU to logits, takes a logarithmic saturation such as log(1 + ReLU(·)), and max-pools across positions so each vocabulary term receives at most one aggregated activation per document.

The resulting vector is enormous in principle but mostly zeros after sparsification and truncation. That makes SPLADE indexable with the same family of data structures that power BM25: postings lists, skip pointers, compression schemes for docids and frequencies. The crucial neural twist is expansion: weights can appear on synonyms, related entities, or broader hypernyms even when the surface form never occurred in the raw text. A passage that says “canine” might accumulate mass on “dog” if the model learned that mapping from pretraining and fine-tuning signals.

wt(d) = maxpos ∈ d log(1 + ReLU(zt,pos))  →  sparse vector over terms t

Operationally, SPLADE marries neural disambiguation with inverted-index efficiency. Query processing looks like lexical retrieval: intersect or weak-AND postings, score with inner products in sparse space, optionally fuse with BM25 or dense scores. The downside is vocabulary maintenance, index refresh when models change, and the engineering complexity of very wide sparse vectors compared to compact dense embeddings—though still far more ANN-friendly than storing full token matrices for every document.

03 · MiniCOIL — Contextualized Inverted Lists

MiniCOIL, developed by Qdrant, targets a niche between classical sparse retrieval and full multi-vector dense late interaction. Each token is associated with a very short contextualized embedding—on the order of 4 dimensions per token in published descriptions—rather than a hundred-plus-dimensional ColBERT vector. The representation is still contextual: the same surface word in different sentences should map to different mini-vectors when syntax or topic shifts.

Storage follows an inverted index pattern familiar from BM25: each lexical term maps to a postings list of (document_id, payload) entries, but the payload now includes the token’s 4D vector instead of only counts or positions. At query time, for each query token you fetch its list, score candidates with dot products between query-token vectors and stored token vectors, and accumulate evidence across query terms—conceptually a sparse traversal with tiny dense arithmetic inside each posting.

Compared to ColBERT, MiniCOIL dramatically reduces bytes per token at the cost of expressiveness per position. Compared to SPLADE, it keeps explicit token-level geometry in a micro-embedding rather than collapsing everything into vocabulary activations. The right choice depends on corpus statistics, latency budgets, and how often you need fine-grained token alignment versus vocabulary-level expansion.

04 · ColPali — Late Interaction for Visual Documents

05 · MUVERA — Efficient Multi-Vector Search

Standard ANN indexes—HNSW, IVF, LSH families implemented in FAISS and similar libraries—expect each database item to be a single fixed-length vector. ColBERT-style representations break that assumption: a document is a variable-length set of token embeddings. Naïvely, you might index every token as its own point and deduplicate at search time, but memory explodes and candidate generation becomes noisy.

MUVERA proposes encoding multi-vector objects into a fixed-dimensional signature amenable to ordinary ANN search. The recipe combines random projections with pooling: token vectors are multiplied by a shared random matrix (or structured transform), passed through a nonlinearity, and aggregated—max-pooling features prominently—into one vector per document. Retrieval becomes a standard nearest-neighbor problem in that compressed space; the original MaxSim can still be applied as a second-stage rescorer on survivors.

Reported results suggest a large speedup with small quality loss when the ANN index is used as a recall-oriented filter. Like all approximate pipelines, you validate on your domain: aggressive compression trades recall of tail entities for throughput.

06 · Comparison Matrix

The table below is qualitative: absolute numbers depend on hardware, batching, quantization, corpus token statistics, and evaluation collections. Treat cells as design heuristics for conversations with your team rather than guarantees from a benchmark suite.

Method Latency @ scale Accuracy (nDCG@10) Index size Storage pattern Training / data When to prefer
BM25 Excellent Strong lexical baseline Small Inverted index, counts None (tuning only) Exact terms, legal keywords, SKU codes
ColBERT Moderate (token index) Often near top text neural Large Token embedding store + MaxSim MS MARCO-style ranking data Token alignment, semantic precision Stage-1
SPLADE Good (sparse) Competitive learned sparse Medium–large Wide sparse inverted lists Contrastive / ranking fine-tune Lexical + expansion without dense ANN
MiniCOIL Good Between BM25 & ColBERT Smaller than ColBERT Term → (doc, 4D) lists Supervised token signals Tight storage, contextualized postings

Hybrid stacks rarely pick one row. A robust pattern keeps BM25 for head terms and compliance-style queries, adds a dense bi-encoder ANN index for paraphrase and cross-language gaps, and reserves ColBERT or SPLADE (or both) for segments of the corpus or query classes where their inductive bias wins. Fusion via RRF (reciprocal rank fusion) or learned models on top of score features is standard in open-source retrieval toolkits.

Decision prompts

  • If your SLA is single-digit milliseconds at billions of docs, bi-encoder ANN + BM25 is still the default spine.
  • If you can spend tens of milliseconds per query and disk is available, ColBERT-style Stage-1 is attractive.
  • If you must stay inside inverted-index ops, SPLADE or MiniCOIL align with existing posting-list machinery.
  • If documents are visually structured, budget for ColPali-style late interaction or multimodal embeddings.
