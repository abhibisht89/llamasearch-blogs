00 What We Are Building

A complete, text-only search engine in plain Python — no retrieval library required. Once tokens, postings, scores, and phrase constraints are visible in one file, Elasticsearch, Solr, and Lucene stop looking like opaque boxes.

Five cooperating pieces:

  • Tokenizer — normalizes raw strings into a sequence of lexical terms (lowercasing, punctuation stripping, optional stop-word removal, optional stemming).
  • Inverted index — maps each term to the documents where it appears and records every position inside each document for phrase and proximity logic later.
  • BM25 scorer — turns query terms plus collection statistics into a relevance score per document using the standard Robertson–Walker formulation.
  • Phrase search — intersects posting lists and checks consecutive token positions so "new york" does not match unrelated co-occurrences of new and york.
  • Query parser — accepts structured text queries with quoted phrases and AND / OR, producing an abstract syntax tree for evaluation against the index.

Not production code. Managed engines add segment merges, skip lists, compression, and sharding — but the same objects (terms, positions, collection statistics) sit underneath. A toy implementation makes those semantics printable and debuggable.

01 The Tokenizer

Tokenization is the boundary between messy human text and discrete symbols the index can count. A practical pipeline for English-like prose often applies four deterministic transforms in order: lowercase for case insensitivity, punctuation removal so don't and dont align (you may prefer smarter apostrophe handling in production), whitespace splitting, and optional stop-word removal followed by stemming to collapse inflections.

Stop words (articles and common function words) are removed in many classical systems because they explode posting lists without helping discrimination. Modern engines sometimes keep them for phrase queries or neural models. Stemming reduces running, runs, and ran toward a shared root; Porter stemming is the common default, though lemmatization is linguistically cleaner.

02 Building the Inverted Index

      

        An inverted index answers the question “which documents contain term t?” in O(1) lookup time after hashing, plus the cost of
        traversing that term’s posting list. For phrase search you store not only document identifiers but also every occurrence position in document
        order. The canonical nested structure is { term: { doc_id: [positions] } }: a map from lexical types to maps from documents to
        sorted integer positions.
      

      

        Document length in tokens is required for BM25 length normalization. Average document length avgdl and collection
        size N should be recomputed whenever documents arrive or disappear so IDF and length factors stay coherent.
      

      

        

          
The highlighted loop writes positional data — required for phrase queries.

1from collections import defaultdict
2
3class InvertedIndex:
4    def __init__(self, tokenizer):
5        self.tokenizer = tokenizer
6        self.index = defaultdict(lambda: defaultdict(list))
7        self.doc_lengths = {}
8        self.documents = {}
9        self.avg_dl = 0
10        self.N = 0
11
12    def add_document(self, doc_id, text):
13        tokens = self.tokenizer.tokenize(text)
14        self.documents[doc_id] = text
15        self.doc_lengths[doc_id] = len(tokens)
16        for pos, token in enumerate(tokens):
17            self.index[token][doc_id].append(pos)
18        self._update_stats()

03 The BM25 Scorer

      

        BM25 combines inverse document frequency with a saturating term frequency transform and document-length normalization.
        For each query term appearing in document D, you compute an IDF-like weight using smoothed counts, multiply by a
        numerator that grows sublinearly with raw term frequency, and divide by a denominator that scales with document length relative to the
        collection average. Summing across query terms yields the final score.
      

      

      

        Parameters k1 and b behave exactly as in the dedicated BM25 chapter: k1 controls saturation
        of term frequency, b controls how strongly length deviates from the average matter. The scorer reads N, avg_dl,
        doc_lengths, and the nested posting map from the index object.
      

      

        

          
Highlighted lines: IDF from document frequency and the length-normalized denominator.

        

        

          
bm25.py1–26

          

1import math
2
3class BM25Scorer:
4    def __init__(self, index, k1=1.2, b=0.75):
5        self.index = index
6        self.k1 = k1
7        self.b = b
8
9    def score(self, query_tokens, doc_id):
10        score = 0
11        for token in query_tokens:
12            if token in self.index.index:
13                posting = self.index.index[token]
14                df = len(posting)
15                tf = len(posting.get(doc_id, []))
16                idf = math.log((self.index.N - df + 0.5) / (df + 0.5) + 1)
17                dl = self.index.doc_lengths[doc_id]
18                norm = 1 - self.b + self.b * (dl / self.index.avg_dl)
19                tf_norm = (tf * (self.k1 + 1)) / (tf + self.k1 * norm)
20                score += idf * tf_norm
21        return score

04 Phrase Search with a Positional Index

      

        Bag-of-words retrieval happily returns a document that mentions new in the first paragraph and york five pages later.
        Users typing multi-word queries usually intend adjacency or at least proximity. Phrase search therefore intersects documents that contain
        all phrase tokens, then verifies that there exists a sequence of positions p0, p1, … with p_{i+1} = p_i + 1.
      

      

        Implementation-wise, you fetch each token’s posting map, intersect document IDs, and for each surviving document run a small positional merge.
        If any token is missing from the vocabulary, the phrase match set is empty. This is exponentially cheaper than scanning raw text because you
        only touch candidate documents already proven to contain every token.
      

      

        

          
When phrase tokens repeat, the adjacency checker may need backtracking rather than a simple two-pointer merge.

        

        

          
phrase.py1–22

          

1    def phrase_search(self, phrase):
2        tokens = self.tokenizer.tokenize(phrase)
3        if not tokens:
4            return []
5        postings = [self.index.index.get(t, {}) for t in tokens]
6        candidates = set(postings[0].keys())
7        for p in postings[1:]:
8            candidates &= set(p.keys())
9        results = []
10        for doc_id in candidates:
11            positions = [postings[i][doc_id] for i in range(len(tokens))]
12            if self._check_adjacency(positions):
13                results.append(doc_id)
14        return results

05 The Query Parser

      

        Free-text boxes in real products accept more than flat keyword lists. A minimal yet instructive grammar adds double-quoted phrases,
        explicit Boolean AND with higher precedence than OR, and parentheses for grouping. Parsing turns a string such as
        "machine learning" AND python into a tree: a conjunction whose left child is the phrase node for
        machine learning and whose right child is the term node for python.
      

      

        Recursive descent fits naturally: one function per grammar rule, a token cursor, immutable AST nodes. A generic syntax exception is enough here.
      

      

        

          
query_parser.pysketch

          

1def parse_query(q):
2    tokens = tokenize_query(q)   # words, AND, OR, quoted spans
3    return parse_or_expr(tokens, 0)[0]
4
5def parse_or_expr(toks, i):
6    left, i = parse_and_expr(toks, i)
7    while i < len(toks) and toks[i] == 'OR':
8        right, i = parse_and_expr(toks, i + 1)
9        left = ('OR', left, right)
10    return left, i

06 Putting It All Together

      

        The façade wires tokenizer, index, scorer, phrase helper, and parser into one API: index_text, search,
        phrase_search.
      

      

        

          
search parses the query, evaluates the AST for candidates, ranks with BM25, returns sorted scores.

        

        

          
engine.pyexcerpt

          

1class SearchEngine:
2    def __init__(self):
3        self.tokenizer = Tokenizer()
4        self.index = InvertedIndex(self.tokenizer)
5        self.scorer = BM25Scorer(self.index)
6        self.parser = QueryParser(self.tokenizer)
7
8    def search(self, query):
9        ast = self.parser.parse(query)
10        candidates = self._eval_ast(ast)
11        qt = self.parser.flatten_terms(ast)
12        ranked = sorted(
13            candidates,
14            key=lambda d: self.scorer.score(qt, d),
15            reverse=True
16        )
17        return [(d, self.scorer.score(qt, d)) for d in ranked]
