Encoding Position

From Integers to Rotary Embeddings — integer, binary, and sinusoidal encodings through to the rotation mathematics behind RoPE in DeepSeek.

Transformers have no built-in sense of order. Attention treats every token as an unordered set — which is catastrophic when the same word appears twice in different roles. This chapter covers integer encodings, binary encodings, sinusoidal encodings from Attention Is All You Need, and Rotary Positional Embeddings (RoPE) — the encoding DeepSeek couples with Multi-Head Latent Attention.

Prerequisites: Chapter 02 (Attention Mechanism) and Chapter 03 (Multi-Head Attention). You should understand Q/K/V projections and dot-product attention before starting here. Outcome: After this chapter you will understand every term in the DeepSeek-V2 section 2.1.3 "Decoupled Rotary Position Embedding" — and why RoPE rotates queries and keys instead of adding to token embeddings.

00

Why Positional Encodings Exist

DeepSeek's Decoupled Rotary Position Embedding combines Multi-Head Latent Attention (MLA) with Rotary Positional Encoding (RoPE). DeepSeek-V2 section 2.1.3 introduces this design; DeepSeek-V3 and DeepSeek-R1 use MLA with RoPE by default. Positional encodings are the prerequisite for understanding that mechanism.

The reason positional encodings matter is simple and profound: the position at which a word appears in a sentence is critical to its meaning. As we saw in Chapter 2 with the "dog chased dog" example, word order is crucial for meaning — without positional encoding, identical tokens at different positions receive identical representations, and the model cannot distinguish their roles.

Empirical check: With only token embeddings and no positional information, self-attention produces identical context vectors for the same token regardless of position — unacceptable for language understanding.

Input text → Tokenizer → Token Embeddings
↓
+ Positional Embeddings → Input Embeddings
↓
Transformer Block(s) → Context Vectors → Next Token

Positional embeddings are added to token embeddings in the input block before the Transformer sees anything. The question is: how do we construct those positional embedding vectors? This chapter progresses integer → binary → sinusoidal → rotary.

First Principles: How Would You Encode Position?

Consider the design problem: each token has a token embedding vector capturing word meaning. You need a positional embedding vector of the same dimension to add to each token embedding. How do you encode "this is position 200" vs "this is position 203"?

The most natural first attempt: use the integer 200 itself. Repeat it across all dimensions. This works for distinguishing positions but fails on magnitude. The second attempt: binary-encode 200 as [1,1,0,0,1,0,0,0]. Bounded, but discontinuous. The third attempt: replace binary oscillation with smooth sine/cosine waves. Continuous, but added to token embeddings. The fourth attempt: rotate Q/K vectors using the same frequencies. Magnitude preserved, semantics untouched. Each step solves the previous step's problem while preserving its insights.

Each step explains a design choice in DeepSeek's decoupled RoPE: why rotation over addition, why Q/K rather than token embeddings, and why the 100002i/d frequency structure.

Step 1 Integer positional encoding — simple but magnitude problems
Step 2 Binary positional encoding — bounded but discontinuous
Step 3 Sinusoidal encoding — smooth, differentiable, rotation-ready
Step 4 Rotary (RoPE) — rotate Q/K, preserve magnitude, no token pollution
A common question is: are positional encoding and positional embedding the same thing?

Yes — the terms are used interchangeably in the literature and in the DeepSeek papers. Both refer to the mechanism for injecting position information into the model. "Encoding" emphasizes the functional transformation; "embedding" emphasizes the vector representation. This chapter uses both terms as equivalent.

01

Integer Positional Encoding

The simplest idea is the most natural: encode position by using the position number itself. If "dog" appears at position 200 in the context, create a positional encoding vector where every dimension equals 200. If the embedding dimension is 8, the positional vector is:

PEdog₁ = [200, 200, 200, 200, 200, 200, 200, 200]

For the sentence "the dog chased another dog" starting at position 200 in a long context:

TokenPositionPositional Encoding Vector (d=8)
the199[199, 199, 199, 199, 199, 199, 199, 199]
dog (1st)200[200, 200, 200, 200, 200, 200, 200, 200]
chased201[201, 201, 201, 201, 201, 201, 201, 201]
another202[202, 202, 202, 202, 202, 202, 202, 202]
dog (2nd)203[203, 203, 203, 203, 203, 203, 203, 203]

This achieves the primary goal: the first dog gets [200,…,200] and the second dog gets [203,…,203]. Their input embeddings (token + position) are now different. The Transformer can tell them apart — but magnitude problems remain.

The Magnitude Problem

Token embedding values in large language models are initialized to be clustered around zero — typically small values like 0.1, −0.05, 0.08. They encode semantic meaning: similar words (kitten, cat) lie close together in vector space; dissimilar words (kitten, airplane) lie far apart. When we add positional encodings, we must not destroy this carefully learned structure.

But integer positional values can be enormous. With a context length of 1024, positional values reach 1024. When you add a token embedding value of 0.12 to a positional value of 200, the sum is 200.12. The positional component contributes over 99.9% of the input embedding. The semantic information from the token embedding is almost completely drowned out.

Consider a numerical example across the full input embedding vector. Suppose the token embedding for "dog" is [0.12, −0.08, 0.15, 0.03, −0.11, 0.09, 0.07, −0.05]. The integer positional encoding at position 200 is [200, 200, 200, 200, 200, 200, 200, 200]. The input embedding (sum) is [200.12, 199.92, 200.15, 200.03, 199.89, 200.09, 200.07, 199.95]. If you compute cosine similarity between the input embeddings of "dog" at position 200 and "cat" at position 200, the token embedding difference (0.12 vs whatever cat's values are) is invisible compared to the shared 200 offset. All words at the same position look nearly identical in input embedding space — the position number swamps the word identity.

The pollution problem: Adding very large positional values to very small token embedding values causes the positional information to dominate and dilute the semantic information captured by token embeddings. Token embeddings encode semantics — we want that information retained when entering the Transformer block. Integer encoding fails this requirement catastrophically at scale.

Ideally, positional encoding values should be constrained — hopefully between 0 and 1, or at least comparable in magnitude to token embeddings. That constraint leads us to the next idea: represent positions in binary.

A common question is: why not just divide the integer by the context length to normalize it?

Normalization helps with magnitude but does not solve the deeper problems that binary, sinusoidal, and rotary encodings address: structured oscillation across dimensions, differentiability, and relative position relationships. Integer encoding — even normalized — treats every dimension identically, wasting the representational capacity of a high-dimensional vector.

02

Binary Positional Encoding

Integers are unbounded — they can take arbitrarily large values. If we want positional encoding values constrained between 0 and 1, why not represent every position as a binary number? Each bit is either 0 or 1, naturally bounded. If the embedding dimension is 8, we use an 8-bit binary representation.

Position 200 in binary (8 bits) is 11001000. Position 201 is 11001001. Position 203 (the second "dog") is 11001011. The positional encoding vectors are now:

PE(200) = [1, 1, 0, 0, 1, 0, 0, 0]    PE(203) = [1, 1, 0, 0, 1, 0, 1, 1]

Every value is 0 or 1 — the same order of magnitude as token embedding values. Different positions produce different vectors. The magnitude problem from integer encoding is solved.

Two Variables: Position and Index

Binary encoding introduces a crucial conceptual framework with two variables:

  1. Position — where the token sits in the sequence (x-axis: 64, 65, 66, …)
  2. Index — which dimension of the encoding vector (y-axis: 1 through 8)

Within each position, we have index numbers 1 through 8. Index 1 is the Least Significant Bit (LSB) — it changes fastest. Index 8 is the Most Significant Bit (MSB) — it changes slowest. This same position/index framework appears in sinusoidal and rotary encodings.

Oscillation Frequency Across Indexes

Consider positions 64 through 75. Watch how each index behaves:

IndexOscillation PeriodBehavior (positions 64–75)
1 (LSB)Every 1 positionFlips 0→1→0 with every new position
2Every 2 positionsSame for 2 positions, then flips
3Every 4 positionsSame for 4 positions, then flips
4Every 8 positionsSame for 8 positions, then flips
5Every 16 positionsNo change visible in 64–75 range
6Every 32 positionsNo change visible in 64–75 range
7Every 64 positionsNo change visible in 64–75 range
8 (MSB)Every 128 positionsConstant across 64–75

The pattern is geometric: index k oscillates every 2k−1 positions. If you plot oscillation frequency versus index, lower indexes have the highest frequency; higher indexes have progressively lower frequency.

Key insight — fine vs. coarse encoding: Lower indexes change more frequently → fine-grained encoding — they capture fast changes among nearby positions. Higher indexes change less frequently → coarse encoding — they capture broad-level positional structure, not minute shifts.

When two identical words appear close together (spaced 3–4 positions apart), their positional difference is mostly captured by lower indexes because those indexes oscillate fast enough to distinguish nearby positions. Higher indexes remain unchanged for small position shifts.

The Discontinuity Problem

Binary encoding solved the magnitude problem but introduced a new one: discontinuities. Values jump abruptly between 0 and 1 — there is nothing in between. During pre-training, the optimizer must deal with these sharp jumps via backpropagation. Discontinuous functions make gradient-based optimization harder.

What we want instead: the same oscillation structure as binary encoding — lower indexes changing fast, higher indexes changing slow — but with smooth, continuous values. That structure maps directly to sine and cosine functions.

Reading the Position-Index Graph

Index 4: Groups of 8. Period = 8. Indexes 5–8: Solid bands within the 64–75 window because periods (16, 32, 64, 128) exceed 12 positions shown.

When you see the sinusoidal heatmap for GPT-2 (1024 positions × 768 indexes), the pattern is identical — smooth sine waves instead of sharp 0/1 bands. Row 1 oscillates rapidly; row 768 is nearly flat. Lower indexes oscillate fast (fine-grained); higher indexes oscillate slow (coarse-grained). Sinusoidal encoding makes this graph smooth; RoPE makes each cell value a rotation angle applied to Q/K pairs.

A common question is: why does the oscillation period double at each index?

Because binary counting works exactly this way. The least significant bit toggles every increment (period 1). The next bit toggles every 2 increments (period 2), then 4, 8, 16, and so on — each bit represents a power of 2. Sinusoidal encoding preserves this geometric frequency structure but replaces hard 0/1 jumps with smooth waves.

A common question is: can I use different embedding dimensions for binary encoding?

Yes — the number of bits equals the embedding dimension d. With d=8 you represent positions 0–255. With d=16 you represent 0–65535. The oscillation period of index k is always 2k−1 regardless of d. More dimensions give you more frequency bands — finer control over the multi-scale positional structure.

A common question is: what happens to binary encoding for positions larger than 2d−1?

With d=8 bits, you can uniquely encode positions 0 through 255. Beyond 255, the binary representation wraps or requires more bits. This is another limitation of binary encoding — context length is bounded by embedding dimension. Sinusoidal encoding has no such hard bound; it cycles smoothly via sin/cos periodicity.

03

Sinusoidal Positional Encoding

Sinusoidal positional encodings solve the discontinuity problem of binary encoding. Instead of values that are either 0 or 1, every dimension takes a continuous real value between −1 and 1. The encoding is smooth, differentiable, and friendly to backpropagation.

These encodings were introduced in the landmark paper "Attention Is All You Need" (Vaswani et al., 2017) — the paper that proposed the Transformer architecture and freed attention from recurrent neural networks.

PE(pos, 2i) = sin(pos / 100002i/dmodel)

PE(pos, 2i+1) = cos(pos / 100002i/dmodel)

Two variables govern every value:

  • pos — the position of the token (depends on context size)
  • i — the pair index, from 0 to (dmodel/2 − 1)

Even indices (0, 2, 4, …) use the sine formula. Odd indices (1, 3, 5, …) use the cosine formula. For a given position, you fill an entire dmodel-dimensional vector by applying these formulas at every index.

Concrete Walkthrough: GPT-2, Position 2

GPT-2 has dmodel = 768 and context size = 1024. Positions range from 0 to 1023 (or 1 to 1024 depending on convention). Index i ranges from 0 to 383 (since we have 768 dimensions in pairs).

For position 2, we build a 768-dimensional vector. At i = 0 (indices 0 and 1 of the vector):

PE(2, 0) = sin(2 / 100000/768) = sin(2 / 1) = sin(2) ≈ 0.9093
PE(2, 1) = cos(2 / 100000/768) = cos(2 / 1) = cos(2) ≈ −0.4161

At i = 1 (indices 2 and 3):

PE(2, 2) = sin(2 / 100002/768) = sin(2 / 100000.00260) ≈ sin(2 / 1.061) ≈ 0.9324
PE(2, 3) = cos(2 / 100002/768) ≈ cos(1.885) ≈ −0.3614

At i = 2 (indices 4 and 5):

100004/768 = 100000.00521 ≈ 1.127
PE(2, 4) = sin(2/1.127) = sin(1.775) ≈ 0.9797
PE(2, 5) = cos(1.775) ≈ −0.2004

At i = 10 (indices 20 and 21) — mid-range index:

1000020/768 ≈ 100000.026 ≈ 1.82
PE(2, 20) = sin(2/1.82) = sin(1.099) ≈ 0.8906
PE(2, 21) = cos(1.099) ≈ 0.4546

At i = 100 (indices 200 and 201) — high index, slow oscillation:

10000200/768 ≈ 100000.260 ≈ 28.5
PE(2, 200) = sin(2/28.5) = sin(0.070) ≈ 0.0700
PE(2, 201) = cos(0.070) ≈ 0.9975

Continue this for i = 2, 3, … up to i = 383 to fill all 768 values. The denominator 100002i/d grows with i, so higher-index pairs oscillate more slowly across positions — exactly mirroring binary encoding's bit behavior.

Wavelength Calculations

The wavelength λ of index pair i is the number of positions before the sine wave completes one full cycle:

λi = 2π · 100002i/dmodel = 2π / ωi

For GPT-2 (d=768):

Index iωiWavelength λ (positions)Meaning

This confirms the binary encoding intuition numerically: i=0 captures changes every few positions; i=50 barely changes across the entire 1024-token context window.

Reading the Formula — Step by Step

To compute PE(pos, idx) for any model:

  1. Fix the position pos (e.g., 2).
  2. You need a vector of length dmodel (e.g., 768).
  3. For each index idx from 0 to dmodel−1:
  4.   If idx is even: compute pair index i = idx/2, apply sin(pos / 100002i/d).
  5.   If idx is odd: compute pair index i = (idx−1)/2, apply cos(pos / 100002i/d).
  6. Fill all 768 (or d) values. Add vector to token embedding.

The even/odd split is not arbitrary — even dimensions carry sine (y-coordinate), odd dimensions carry cosine (x-coordinate), forming rotation-ready pairs.

Why 10,000?

The base 10,000 is an experimental choice. Model dimensions are typically around 1,000 (768 for GPT-2, 4096 for LLaMA). The value 10,000 ensures that:

  • At i = 0, frequencies are very high (rapid oscillation)
  • At i = 150, 200, 300, frequencies gradually die down
  • At high i, waves become nearly flat across the context window

Change 10,000 to a smaller number and high-index waves die too fast. Change it to a larger number and low-index waves oscillate too wildly. 10,000 provides an empirically good balance.

Reframing as Frequency

The formula can be rewritten as:

PE(pos, 2i) = sin(ωi · pos)    where    ωi = 1 / 100002i/dmodel

ωi is the frequency of oscillation for pair index i. Because i appears in the denominator of the exponent, lower i → higher ω → faster oscillation. Higher i → lower ω → slower oscillation. This is precisely why i must be in the denominator — not the numerator. If i were in the numerator (10000i), lower indexes would oscillate slower and higher indexes faster — the opposite of what we want and the opposite of binary encoding behavior.

Why not put i in the numerator? Consider what would happen with PE(pos, 2i) = sin(pos × 100002i/d). At i=0: frequency = 1 (same as correct formula). At i=1: frequency = 100002/768 ≈ 1.06 — barely different from i=0. At i=10: frequency = 1000020/768 ≈ 28 — still moderate. All indexes would oscillate at roughly similar rates — losing the multi-scale structure. The denominator placement creates the geometric frequency spread that mirrors binary bit periods (1, 2, 4, 8, 16, …).

From the Attention Is All You Need Paper

The original paper describes the motivation tersely in three paragraphs. The core requirement: "Since our model contains no recurrence and no convolution, in order for the model to make use of the order of the sequence, we must inject some information about the relative or absolute position of the tokens in the sequence."

They note that learned positional embeddings were also tested and performed nearly identically to sinusoidal encodings. They chose sinusoidal because it "may allow the model to extrapolate to sequence lengths longer than the ones encountered during training." This extrapolation property — encoding positions beyond the training context via a fixed formula — remains valuable today, though RoPE has largely superseded direct sinusoidal addition in production LLMs.

Verification: Same Intuition as Binary

Plot PE values for index 1, 50, and 150 across all 1024 positions. Index 1 oscillates extremely rapidly — flipping nearly every position. Index 50 oscillates moderately. Index 150 is nearly flat across the entire context. This matches binary encoding's LSB/MSB behavior exactly, but with smooth curves instead of discrete jumps.

To verify numerically, compare PE(64, idx=1) vs PE(65, idx=1) for GPT-2: PE(64, 1) = cos(64) ≈ 0.1768, PE(65, 1) = cos(65) ≈ −0.3460 — a large flip. Compare PE(64, idx=150) vs PE(65, idx=150): The denominator 10000300/768 ≈ 100000.391 ≈ 39.2, so angles are 64/39.2 ≈ 1.633 and 65/39.2 ≈ 1.658 — nearly identical. This is exactly the binary behavior: index 1 flips every position, index corresponding to i=75 would not flip between 64 and 65.

04

Why Sine and Cosine? The Rotation Property

One property unlocks the sin/cos formula's purpose: relative positional encodings are rotations of each other. Understanding this property is the bridge to Rotary Positional Embeddings (RoPE).

The Desired Property: Linear Relation Between Positions

When constructing positional encodings, we want a linear mathematical relationship between encoded positions. If we know the encoding at position p, it should be straightforward to compute the encoding at position p + k. Why? Because the Transformer learns positional patterns more easily when positions are mathematically related.

Visual Proof with i = 0

Fix pair index i = 0 and position p. Define θ = p / 100002×0/d = p / 100000 = p. At this pair:

y₁ = PE(p, index 2) = sin(θ)   |   x₁ = PE(p, index 3) = cos(θ)

Geometrically, (x₁, y₁) is a point on the unit circle at angle θ. The vector v₁ = (x₁, y₁) represents the positional encoding for position p at this index pair.

Concrete example at p = 5, d = 512: θ = 5 / 100000/512 = 5 radians. x₁ = cos(5) ≈ 0.2837, y₁ = sin(5) ≈ −0.9589. The point (0.2837, −0.9589) lies on the unit circle at angle 5 rad ≈ 286.5°.

Now we want encodings at position p + k. Define θ₁ = ω × k where ω = 1/100002i/d. For i = 0: ω = 1, so θ₁ = k. By the angle addition formulas:

sin(θ + θ₁) = sin(θ)cos(θ₁) + cos(θ)sin(θ₁)
cos(θ + θ₁) = cos(θ)cos(θ₁) − sin(θ)sin(θ₁)

The new values are:

y₂ = sin(θ + θ₁) = PE(p+k, index 2)   |   x₂ = cos(θ + θ₁) = PE(p+k, index 3)

Geometrically, v₂ is just v₁ rotated by angle θ₁ = ω·k. To find positional encodings at position p + k, rotate the vector at position p by ω·k radians. No re-computation from scratch — just rotation.

Numerical verification: p = 5, k = 3, so p+k = 8. θ = 5, θ₁ = 3, θ + θ₁ = 8. y₂ = sin(8) ≈ −0.9894, x₂ = cos(8) ≈ −0.1455. Direct computation: sin(8) ≈ −0.9894 ✓, cos(8) ≈ −0.1455 ✓. Rotation and direct evaluation match exactly.

Matrix form: The rotation is equivalent to:

[x₂] [cos(θ₁) −sin(θ₁)] [x₁]
[y₂] = [sin(θ₁) cos(θ₁)] [y₁]

Substituting x₁ = cos(5), y₁ = sin(5), θ₁ = 3: x₂ = cos(5)cos(3) − sin(5)sin(3) = cos(5+3) = cos(8) ✓ y₂ = sin(5)cos(3) + cos(5)sin(3) = sin(5+3) = sin(8) ✓ This is the standard rotation matrix — the same matrix RoPE applies to Q/K pairs.

This is why we need BOTH sin and cos: Rotation in 2D requires both coordinates. Sin alone cannot rotate a vector — you need cos for the x-component and sin for the y-component. Alternate even/odd indices as sin/cos precisely because relative positional encodings must be rotations of each other.

Relative Position Through Rotation

v₁ and v₂ are rotations of each other. Given encoding at one position, find encoding at another by rotation. Relative position k maps to a fixed angular difference ω·k — predictable and learnable by attention patterns. Rotations ensure relative shifts translate into fixed angular differences, which the Transformer can learn during training.

Limitations of Sinusoidal Encoding

Despite its elegance, sinusoidal encoding has a critical flaw: positional embeddings are added directly to token embeddings in the input block. Even though sinusoidal values lie in [−1, 1], addition still modifies the token embedding vector. Semantic information carried by token embeddings gets polluted before the Transformer block.

Where Each Encoding Is Applied in the Architecture

Understanding where positional information enters the model is as important as understanding how it is encoded:

Input Block: Token Embedding + Positional Encoding → Input Embedding
↓ (integer, binary, sinusoidal all apply here)
Layer Norm → Multi-Head Attention (Q, K, V projections)
↓ (RoPE applies here — rotates Q and K after projection)
Attention Scores = softmax(Q·KT/√d) → Context Vectors

Sinusoidal path: Token emb. + PE → input emb. → Q/K/V all derived from position-contaminated input. Every downstream computation inherits the pollution. RoPE path: Token emb. → input emb. (clean) → Q/K projections (clean) → RoPE rotation on Q/K → attention. Token semantics preserved. Position injected only where it matters for attention scoring.

The attention mechanism is where positional information matters most — queries and keys determine which tokens attend to which. So two questions arise:

  1. Why add positional information to token embeddings? Why not augment Q and K vectors inside attention instead?
  2. Why add a positional vector (changing magnitude)? Why not rotate the vector (preserving magnitude)?

These two insights — apply encoding in Q/K, use rotation not addition — lead directly to RoPE.

Sinusoidal (2017)

Add PE to token embeddings in input block. Semantic pollution. Magnitude changes. Used in original Transformer.

RoPE (2021+)

Rotate Q and K in attention block. Token embeddings untouched. Magnitude preserved. Used in LLaMA, DeepSeek, Mistral.

The transition from sinusoidal addition to RoPE rotation is the last major innovation in positional encoding before DeepSeek's decoupled variant.

05

Rotary Positional Encoding (RoPE)

Rotary Positional Encoding (RoPE), introduced in the RoFormer paper (2021) and widely adopted by LLaMA, DeepSeek, and modern LLMs, applies the sinusoidal frequency formula — but instead of adding to token embeddings, it rotates query and key vectors inside the attention mechanism.

The Two Core Ideas

Apply positional encoding in Q and K — not in token embeddings
↓
Rotate vectors instead of adding — preserve magnitude

Consider the sentence "the dog chased another dog" with 5 tokens. Each token has a 4-dimensional query vector (for demonstration; real models use hundreds of dimensions). For the first token "the" at position 1 with query vector [x₁, x₂, x₃, x₄]:

Step-by-Step: RoPE on a 4-Dimensional Query

Step 1 — Form pairs. Split the vector into groups of 2:

Group 1 (i=0)

Vector (x₁, x₂) — first two dimensions

Group 2 (i=1)

Vector (x₃, x₄) — next two dimensions

Step 2 — Compute rotation angle. For each group i at position p:

θi = p × ωi    where    ωi = 1 / 100002i/d

For position p = 1, d = 4:

Group 1 (i=0): θ₀ = 1 × (1/100000/4) = 1 × 1 = 1.0 rad (≈ 57.3°)
Group 2 (i=1): θ₁ = 1 × (1/100002/4) = 1 × (1/100) = 0.01 rad (≈ 0.57°)

Step 3 — Apply rotation matrix. For group (x₁, x₂) rotated by θ₀:

[x₁'] [cos θ₀ −sin θ₀] [x₁]
[x₂'] = [sin θ₀ cos θ₀] [x₂]

Concrete example with x₁ = 0.8, x₂ = 0.5, θ₀ = 1.0 rad:

x₁' = 0.8·cos(1.0) − 0.5·sin(1.0) = 0.8×0.5403 − 0.5×0.8415 = 0.0117
x₂' = 0.8·sin(1.0) + 0.5·cos(1.0) = 0.8×0.8415 + 0.5×0.5403 = 0.9435
|original| = √(0.8² + 0.5²) = 0.9434
|rotated| = √(0.0117² + 0.9435²) = 0.9434 ✓ magnitude preserved

Repeat for group (x₃, x₄) with θ₁ = 0.01 rad. The RoPE-encoded query vector is [x₁', x₂', x₃', x₄']. The same operation applies to key vectors. Token embeddings are never modified.

RoPE Intuition: Frequency, Distance, and Context

Effect of Position: Higher Positions → Larger Rotations

θ = ωi × p varies directly with position. Fix any index i and increase position: the rotation angle grows. Token at position 1 rotates slightly; token at position 100 rotates much more.

Closer tokens have similar positional encodings because their p values are nearby, giving similar θ. Distant tokens have different encodings because their p values differ substantially. This matches linguistic intuition: nearby words are more likely related; distant words less so.

The RoFormer paper proves a long-term decay property: the inner product ⟨R(q,m), R(k,n)⟩ decays as relative distance |m−n| increases. Tokens far apart naturally receive lower attention scores — without explicit distance masking.

Interactive · Relative Position Dot Product

Effect of Index: Lower Indexes Change Fast, Higher Indexes Change Slow

The same conclusion from binary and sinusoidal encoding applies to RoPE rotation angles:

Lower index (i=0)

ω is large → θ changes rapidly with position → high frequency → captures small positional shifts

Higher index (i=383)

ω is tiny → θ barely changes with position → low frequency → captures long-range dependencies

Lower Indexes: Capturing Small Shifts in Meaning

Compare two sentences that differ only in word order:

Ijusttoldherthetruth

"I just told her the truth" — recently, with respect to time. "just" at position 2.

Itoldjustherthethetruth

"I told just her the truth" — only her, among all people. "just" at position 3.

"told" moves from position 3 to position 2 — a shift of one position that completely changes meaning. Lower-index fast oscillations capture this: even a 1-position shift produces a noticeably different rotation angle in low-index pairs. At i=0, position 2 gives θ = 2.0 rad while position 3 gives θ = 3.0 rad — a difference of 1 full radian, which significantly changes the rotated Q/K vectors.

Higher Indexes: Capturing Long-Range Dependencies

Consider a longer passage:

Einsteindevelopedthetheoryofrelativity.Thisbreakthroughreshapedphysics.

"This breakthrough" at positions 8–9 refers to "the theory of relativity" at positions 3–6. At higher index pairs, rotation angles change so slowly that distant positions produce nearly identical high-index values — a signal for long-range coreference. Lower indexes would oscillate wildly over the same span, destroying any stable similarity signal.

Position vs Index: The Two-Axis Intuition Grid

Rows are index pairs; columns are positions. Each cell holds θ = p · ωi. Moving right increases θ — faster in upper rows (low i), slower in lower rows (high i). Moving down decreases oscillation rate; diagonal neighbors differ more at low i than high i. This is the same position-index heatmap from binary encoding, with rotation angles instead of 0/1 bits.

The complete picture: RoPE bakes in multi-scale positional structure. Lower index pairs = fast rotation = fine-grained local position sensitivity. Higher index pairs = slow rotation = coarse long-range relationship preservation. Higher absolute positions = larger rotation = natural distance encoding. All without touching token embeddings.

A common question is: why do higher positions lead to larger rotations?

Because words closer together in a sentence are more likely to be syntactically or semantically related. Similar rotation angles for nearby positions means similar Q/K representations, which means higher attention scores. Distant words get very different rotations, naturally reducing their attention connection — the long-term decay property.

Why DeepSeek Needs RoPE

DeepSeek's Multi-Head Latent Attention (MLA) compresses the KV cache by projecting keys and values into a lower-dimensional latent space. The basic MLA version does not include positional information. DeepSeek-V2 section 2.1.3 introduces Decoupled Rotary Position Embedding — MLA coupled with RoPE — creating a much more powerful attention mechanism. DeepSeek-V3 and DeepSeek-R1 use this by default.

The DeepSeek-V2 paper describes the motivation clearly: standard MLA without RoPE cannot distinguish tokens at different positions within the compressed latent space. Adding RoPE to the query and key projections in the MLA pathway restores positional sensitivity while maintaining the cache compression benefits. The "decoupled" aspect refers to separating the RoPE application in the query pathway from the key-value latent compression pathway — covered in the next chapter.

Encoding Evolution — Design Decisions at Each Step

Each encoding type solved a specific problem while revealing the next:

Integer → Binary: bound values to [0,1]; reveals multi-frequency oscillation structure.

Binary → Sinusoidal: replace discontinuous 0/1 with sin/cos waves; reveals rotation between positions.

Sinusoidal → RoPE: rotate Q/K instead of adding to embeddings; relative position in dot products.

RoPE → DeepSeek Decoupled RoPE: decouple RoPE across MLA's query and latent KV pathways.

Integer Encoding — Complete Specification

Given token at position pos and embedding dimension d:

PEinteger(pos) = [pos, pos, pos, …, pos]   (d copies)

Input embedding: e = token_embedding + PEinteger(pos). Problem: |PE| ≈ context_length while |token_embedding| ≈ 0.1, so semantics are drowned out.

Binary Encoding — Complete Specification

Convert pos to binary with d bits: pos = Σ bj · 2j where bj ∈ {0, 1}.

PEbinary(pos)[j] = bd−1−j   for j = 0, …, d−1

Oscillation period of index j: T(j) = 2j positions. Problem: discontinuous at every bit flip — gradient-unfriendly during pre-training.

Relative Position Property — Full Proof

Claim: ⟨R(q, m), R(k, n)⟩ depends only on (m − n), not on m and n individually.

Proof sketch: RoPE rotates pair j of query at position m by θj(m) = m·ωj and pair j of key at position n by θj(n) = n·ωj. The dot product of rotated pairs involves cos(θj(m) − θj(n)) = cos((m−n)·ωj). Summing across all pairs, the total attention score depends on relative distance (m−n) only. This is the relative position property that makes RoPE so effective in attention.

Long-term decay: As |m−n| increases, cos((m−n)·ωj) oscillates but the aggregate dot product tends to decay for well-separated pairs — matching the linguistic prior that distant tokens should have weaker direct connections.

Angle Addition — Connecting Sinusoidal to RoPE

The bridge between sinusoidal addition and RoPE rotation:

sin(θ + φ) = sin θ cos φ + cos θ sin φ
cos(θ + φ) = cos θ cos φ − sin θ sin φ

These are exactly the entries of the 2×2 rotation matrix R(φ) applied to vector (cos θ, sin θ). Sinusoidal encoding stores (cos θ, sin θ) as consecutive dimensions. RoPE applies R(φ) directly to (x, y) pairs in Q and K. Same mathematics — different application point in the architecture.

Implementation Notes (PyTorch-style)

# Sinusoidal positional encoding (Attention Is All You Need)
def sinusoidal_pe(seq_len, d_model):
    pe = torch.zeros(seq_len, d_model)
    position = torch.arange(seq_len).unsqueeze(1).float()
    div_term = torch.exp(torch.arange(0, d_model, 2).float()
                       * (-math.log(10000.0) / d_model))
    pe[:, 0::2] = torch.sin(position * div_term)
    pe[:, 1::2] = torch.cos(position * div_term)
    return pe  # add to token embeddings

# RoPE (applied to Q and K, not token embeddings)
def apply_rope(x, position, d_model):
    # x: (batch, seq, d_model), position: (seq,)
    for i in range(0, d_model, 2):
        pair_idx = i // 2
        freq = 1.0 / (10000 ** (2 * pair_idx / d_model))
        theta = position * freq
        x_i, x_i1 = x[..., i], x[..., i+1]
        x[..., i]   = x_i * cos(theta) - x_i1 * sin(theta)
        x[..., i+1] = x_i * sin(theta) + x_i1 * cos(theta)
    return x

Attention Is All You Need — Paper Context

The 2017 paper by Vaswani et al. introduced two revolutionary ideas simultaneously: the Transformer architecture (encoder-decoder with self-attention, no RNN) and sinusoidal positional encoding. Until this paper, attention mechanisms were always coupled with recurrent neural networks. The Transformer freed attention from sequential processing — but that freedom came at a cost: attention is permutation-invariant. Without positional encoding, shuffling input tokens would not change the output. Sinusoidal encoding was the authors' solution — fixed, deterministic, and extrapolatable beyond training context length.

The paper's exact wording on positional encoding: "We inject some information about the relative or absolute position of the tokens in the sequence." They chose sinusoidal over learned embeddings because learned embeddings would be limited to the maximum sequence length encountered during training. Sinusoidal encodings, being a deterministic function of position, can theoretically extend to any sequence length — a property that became critical as context windows grew from 512 to 128K tokens.

RoFormer Paper — Long-Term Decay Property

The RoFormer paper (Su et al., 2021) introduced RoPE and proved a key property: the inner product ⟨R(q,m), R(k,n)⟩ decays as relative distance |m−n| increases (for most frequency pairs). They state: "A pair of tokens with a long relative distance should have less connection." This aligns with linguistic intuition — words far apart in a document are less likely to have direct syntactic or semantic dependencies than nearby words. RoPE encodes this prior directly into the attention mechanism's geometry.

Common Questions — Complete Reference

Why not learn positional embeddings instead of using fixed sin/cos?

Learned embeddings (used in BERT) work well but do not generalize beyond the training context length. Sinusoidal and RoPE encode a mathematical structure that extrapolates to longer sequences. DeepSeek and LLaMA use RoPE precisely because it scales to long contexts without retraining positional parameters.

Why 10,000 specifically in the denominator?

It is an empirical constant chosen so that frequencies span a useful range for typical d_model values (~512–4096). With d=768, i=0 gives ω=1 (wavelength ≈ 2π positions), while i=383 gives extremely low frequency (wavelength ≈ thousands of positions). The value 10,000 creates a smooth frequency spectrum across all index pairs.

Does RoPE apply to value vectors too?

Standard RoPE applies only to Q and K, not V. Position information is needed to compute attention scores (which tokens attend to which), but the value vectors carry content, not positional matching information. DeepSeek's decoupled RoPE follows this convention with modifications for MLA's compressed KV structure.

What is "decoupled" RoPE in DeepSeek-V2?

In standard RoPE, the same rotation is applied to Q and K. DeepSeek's decoupled variant separates how positional information is injected into the latent compressed KV pathway versus the query pathway — allowing MLA's cache compression to coexist with rotary position encoding. The next chapter covers this integration in full detail.

How does RoPE interact with causal masking?

RoPE and causal masking are orthogonal. Causal masking prevents attending to future tokens (upper triangle set to −∞ before softmax). RoPE modifies Q and K before the dot product, encoding relative distance. Together: causal mask enforces temporal order; RoPE encodes how far apart allowed tokens are.

Positional Encoding (PE): A vector added to or applied onto token representations to encode position information.
