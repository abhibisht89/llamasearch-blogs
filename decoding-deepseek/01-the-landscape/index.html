Large Language Models: The Probabilistic Engine

You have used ChatGPT. You type "Make a travel plan for me to visit Italy" and receive a detailed itinerary. That response comes from a large language model — but what is an LLM, mathematically?

Strip away the interface, the branding, and the product packaging. At its heart, a large language model is an engine that takes in a sequence of tokens and outputs a probability distribution over the next token. When tokens are sampled from that distribution and appended to the sequence, one token at a time, the result is coherent text — travel plans, essays, code, reasoning chains.

P(wn | w1, w2, …, wn−1)

Large language models are probabilistic engines for next-token prediction. This is the first and most important mental model. Everything else — emergent abilities, reasoning, translation — is a consequence of doing this one task at enormous scale with a transformer architecture.

Probabilistic, Not Deterministic

ChatGPT's answers look deterministic. They feel confident. But underneath, every token carries a probability. Consider completing this sentence:

"After years of hard work, your effort will take you ___"

The model's top prediction might be "to" — and if you always pick the highest-probability token (greedy decoding), the output appears deterministic. But the model also assigns non-trivial probability to tokens like "far", "places", and others. The full distribution over the vocabulary reveals the model's uncertainty and alternative completions.

Interactive · Next-Token Probability Distribution

Simulated log-scale distribution for a confident completion. The top token dominates, but alternatives retain measurable probability.

On a log-log scale, the typical next-token distribution looks like a steep power law: the first token has very high probability (especially for confident predictions), and probability falls off rapidly for lower-ranked tokens. This shape is why greedy decoding often works well — the top token is usually far ahead — but also why sampling with temperature can produce creative variation.

Key insight: Never confuse fluent output with certainty. Every token the model generates is a sample from a probability distribution. Understanding this distribution — its shape, its entropy, its tail behavior — is essential for debugging model behavior and designing decoding strategies.

Size, Scaling Laws, and Emergent Properties

What Does "Large" Mean?

No one has an exact definition of when a language model becomes "large." But there is a well-documented phenomenon: as model size increases, performance improves dramatically. The paper that crystallized this for modern LLMs was OpenAI's GPT-3 work, titled "Language Models are Few-Shot Learners." The authors demonstrated that scaling model size to 175 billion parameters produced dramatic improvements in both one-shot and few-shot learning — capabilities that simply did not exist at smaller scales.

GPT-2 (2019)

Largest variant: 1.5 billion parameters. Impressive text generation, but limited task generalization.

GPT-3 (2020)

Largest variant: 175 billion parameters. Crossed the size barrier from 1.3B → 13B → 175B. Few-shot learning emerged.

The scaling journey did not stop at 175 billion. A Nature paper charting neural network size from the 1950s to 2020 shows an exponential increase in parameter count. Language models (shown as orange dots on recent charts) have dominated the size space, reaching approximately 1 trillion parameters and beyond. The y-axis is log-scale — this is exponential growth, not linear.

Interactive · Scaling Law & Emergent Pickup

Drag the model-size slider. Watch task performance stay flat, then suddenly "pick up" past a critical scale — emergent behavior.

Emergent Properties

As model size increases beyond a critical threshold, models develop emergent properties — capabilities absent in smaller models but present in larger ones. Examples include:

  • Performing arithmetic
  • Word unscrambling
  • Translation between languages
  • Summarization
  • Grammar checking
  • Following complex instructions
  • Writing emails from custom instructions — trivial for modern LLMs, impossible for earlier NLP systems

The x-axis in emergent-behavior charts is roughly computational power (FLOPs) or model size. The y-axis is task performance. For each task, there is a pickup point — a scale beyond which performance suddenly jumps. Before that point, the model fails; after it, the model succeeds. This is why companies like OpenAI and Anthropic have publicly stated they are "just chasing size" — there is still hope that at 10 trillion or 100 trillion parameters, entirely unknown capabilities may emerge.

LLMs vs. Task-Specific NLP

Earlier NLP models were designed for specific tasks: machine translation systems for translation, parsers for syntax, classifiers for sentiment. Large language models, trained only on next-token prediction, develop general capabilities through emergent properties. A single LLM can translate, summarize, check grammar, write code, and reason — tasks that previously required separate specialized systems.

The transformer secret: All of this scaling power runs on one architecture — the Transformer, introduced in the 2017 paper "Attention Is All You Need" by Vaswani et al. The sections below unpack it from input tokenization through output projection.

Why Size Matters

The training objective — next-token prediction on internet-scale text — does not explicitly teach translation, arithmetic, or summarization. These capabilities emerge when the model is large enough to capture the statistical patterns that implicitly encode them. Smaller models simply lack the capacity.

A common question is: will scaling ever stop delivering returns?

Nobody knows for certain. OpenAI and Anthropic have publicly stated they are still "chasing size" because emergent capabilities continue appearing at new scales. There may be a wall — a scale beyond which more parameters yield diminishing returns — but we have not hit it yet. DeepSeek's contribution is showing that when you do hit diminishing returns from raw scale, architectural innovation (MoE, MLA, quantization) can extract dramatically more performance per active parameter and per dollar of compute.

Creating an LLM: Pre-Training and Fine-Tuning

Building a large language model involves two distinct stages. Understanding this pipeline is essential because DeepSeek's breakthroughs span both stages — architectural innovations during pre-training and a revolutionary reinforcement-learning approach during post-training.

1

Pre-Training

Auto-regressive training on massive unlabeled text. The model creates its own labels by predicting the next token. Produces a foundational model.

2

Fine-Tuning

Training on labeled data to teach specific behaviors: instruction following, translation, safety. GPT-3.5 (ChatGPT) used RLHF.

Stage 1: Pre-Training

Pre-training uses no human-labeled data. The model is fed enormous quantities of text assembled from the internet, textbooks, media, research articles, and curated corpora. GPT-2, for example, was trained on data from Reddit, books, Wikipedia articles, and the Open WebText corpus.

The training objective is simple: given a sequence of tokens, predict the next one. Because the "correct" next token is always known (it is the token that actually appears in the text), the model generates its own supervision signal. This is the auto-regressive training paradigm. After pre-training, the model has basic language capabilities — grammar, facts, patterns — but may not follow instructions or produce helpful dialogue.

Pre-training at scale is extraordinarily expensive. Costs run upward of millions of dollars, and for the largest models, potentially tens or hundreds of millions. As model size increases, so does the compute bill.

Stage 2: Fine-Tuning

After pre-training, the model is fine-tuned on labeled datasets to teach specific behaviors. Examples of labeled fine-tuning data:

  • Instruction following: "Convert 45 kilometers to meters" → "45,000 meters"
  • Translation pairs: French sentence → English sentence
  • Dialogue formatting: User message → helpful assistant response

GPT-3.5, which became the product ChatGPT, was fine-tuned with Reinforcement Learning from Human Feedback (RLHF). Human annotators graded model outputs for quality, and those grades were fed back as a reward signal during training. This alignment step is what made raw GPT-3 into a conversational assistant.

Where DeepSeek changed the game: Instead of relying primarily on human-labeled feedback for reasoning, DeepSeek used large-scale reinforcement learning with rule-based reward systems — Group Relative Policy Optimization (GRPO). No human judgment required for the reward; pure rules. This is the main reason DeepSeek-R1 excels at step-by-step reasoning. Later chapters cover GRPO in depth.

A common question is: if pre-training already teaches language, why fine-tune at all?

Pre-training teaches the model what language looks like — statistics, facts, patterns. Fine-tuning teaches the model how to be useful — follow instructions, refuse harmful requests, format answers helpfully, reason step-by-step. A pre-trained model asked "Convert 45 km to meters" might continue with unrelated text because continuation is what it was trained to do. Fine-tuning reshapes the output distribution toward task completion.

DeepSeek vs. the World: Performance, Cost, and Trade-offs

A Mathematical Showdown

Benchmarks on standard test suites tell one story. A single hard problem tells another. Consider this definite integral from the 1968 Putnam competition — a competition known for exceptionally difficult problems:

∫₀¹ x⁴(1−x)⁴ / (1+x²) dx = 22/7 − π

The result is beautiful. Many people know the approximation π ≈ 22/7, but 22/7 is actually greater than π by a tiny amount. This integral captures exactly that difference. The proof was first devised around 1944.

When GPT-4o was given this integral as a multiple-choice question with option A = 22/7 − π as the correct answer, it selected option B (2×10⁵/5) — a spectacular failure. DeepSeek solved it step-by-step and arrived at the correct answer, 22/7 − π, in roughly 10–15 seconds. One example does not prove universal superiority, but it demonstrates capability on genuinely difficult reasoning problems.

Pillar 1: Five Architectural Innovations

1. Multi-Head Latent Attention (MLA)

Standard multi-head attention (from "Attention Is All You Need") uses a key-value cache that stores full-dimensional keys and values. DeepSeek stores the KV cache in a latent (compressed) space. Result: the attention mechanism uses less memory, runs faster, and remains computationally efficient — without the quality degradation of simpler approximations like Multi-Query Attention.

2. Mixture of Experts (MoE)

In a standard transformer, the entire feed-forward network activates for every token. In MoE, the network contains multiple "experts" (separate feed-forward sub-networks), and a router decides which expert(s) activate for each token. Of 671 billion total parameters, only about 37 billion are active at any given time. This is the second major efficiency driver.

3. Multi-Token Prediction

Standard LLMs predict one token at a time. DeepSeek implements a recent innovation: predict multiple tokens simultaneously. If the model can accurately predict several tokens in parallel, inference speed increases substantially.

4. Quantization

Instead of storing every parameter as a full floating-point number, parameters are represented in compressed form — blocky at fine granularity, nearly identical at model scale. Quantization compresses transformer parameters with minimal quality loss.

5. Rotary Positional Encodings (RoPE)

Original transformers added positional encodings directly to token embeddings — "polluting" the embedding vector with position information. RoPE instead rotates the query and key vectors to encode position. Rotation preserves magnitude while encoding relative position — a highly efficient approach applied later in the attention computation rather than at the embedding stage.

Pillar 2: Reinforcement Learning Reborn

The DeepSeek-R1 paper makes the field of reinforcement learning for LLMs feel reborn. GPT-3.5 relied on human annotators grading output quality. DeepSeek-R1 uses large-scale reinforcement learning with a rule-based reward system — no human judgment in the loop. The framework is called Group Relative Policy Optimization (GRPO), and it is the primary reason DeepSeek-R1 excels at complex, step-by-step reasoning.

Pillar 3: GPU Optimization Tricks

DeepSeek bypassed industry-standard CUDA for certain functions, using NVIDIA's Parallel Thread Execution (PTX) — an intermediate representation closer to machine code than CUDA. This contributed to training and inference efficiency, reducing costs.

Pillar 4: Model Ecosystem & Distillation

DeepSeek did not stop at the 671B model. They distilled it into smaller variants — as small as 1.5 billion parameters — creating a full model ecosystem. Distillation transfers knowledge from the large "teacher" model to compact "student" models, making capable AI accessible on modest hardware.

Roadmap: The series follows the same four-phase structure — Architecture (bulk of content) → Training Methodology → GPU Optimization → Model Ecosystem/Distillation — culminating in a mini DeepSeek-R1 recreation.

Deep Dive: Mixture of Experts Routing

A router — a small neural network within each MoE layer — examines the incoming token's representation and selects which expert FFN(s) activate. The rest stay idle: they contain learned weights but consume no compute for that token. Standard transformers activate every parameter for every token; MoE activates only the relevant subset — more total parameters (more storage), far fewer active parameters (less compute per token).

Deep Dive: Multi-Head Latent Attention and the KV Cache

During inference, autoregressive generation requires caching previously computed Key and Value vectors so they are not recomputed for every new token. Standard multi-head attention stores full-dimensional K and V tensors — this cache grows linearly with sequence length and can dominate memory usage for long contexts.

DeepSeek's MLA compresses the KV cache into a latent space — lower-dimensional representations that preserve the information needed for attention while using dramatically less memory. The attention computation itself also becomes faster because it operates on these compressed representations. This is not a free lunch — the compression must be designed carefully to avoid quality loss — but DeepSeek's papers demonstrate that the trade-off is favorable.

PTX vs. CUDA: The Performance Stack

NVIDIA's software stack has layers: CUDA at the top (high-level parallel programming), PTX (Parallel Thread Execution) in the middle (assembly-like intermediate representation), and machine code on the GPU silicon. DeepSeek used PTX for certain critical functions instead of standard CUDA kernels, eliminating abstraction overhead in the hottest code paths — operations executed billions of times during training and inference. At DeepSeek's scale, engineering optimizations translate directly into dollar savings.

Deep Dive: GRPO vs. RLHF

GPT-3.5's alignment used Reinforcement Learning from Human Feedback (RLHF): human annotators rated outputs, and a reward model learned to predict those ratings. DeepSeek-R1's alignment uses Group Relative Policy Optimization (GRPO) with rule-based rewards. For mathematical reasoning, the rule is simple: is the final answer correct? No human needed. For code, does it compile and pass tests? Rule-based. This scales to millions of training examples without annotation bottlenecks.

Opening the Engine: The LLM as a Next-Token Prediction Machine

LLMs are next-token prediction engines. To understand DeepSeek's innovations — MLA in the attention block, MoE in the feed-forward block — we need to see every component: token embeddings, transformer blocks, output projection. The architecture determines what token comes next; there is no magic layer beneath it.

Where Do the Parameters Live?

GPT-3 has approximately 175 billion parameters. GPT-4 is estimated at roughly 1 trillion. GPT-4.5 may reach 5–10 trillion. These numbers are not abstract — each parameter is a learned weight in a specific layer. They are scattered across:

  • Token embedding matrices
  • Positional embedding matrices
  • Multi-head attention projections (Query, Key, Value, Output)
  • Feed-forward network weights (inside every transformer block)
  • Layer normalization parameters
  • Output projection layer (vocabulary-sized)

Language learning is a byproduct of the next-token prediction task. The engine is complex because learning language requires complexity — you cannot predict the next word accurately with a trivial architecture. The 175 billion parameters exist because next-token prediction at scale demands them.

A common question is: why is the architecture so complex if the task is just "predict the next word"?

Because "predict the next word" implicitly requires understanding grammar, facts, context, discourse structure, and world knowledge. A model that only memorized bigram statistics would fail on long-range dependencies ("The cat, which had chased the mouse through the garden despite the rain, finally caught ___"). The transformer's depth (many stacked blocks) and attention mechanism (dynamic context lookup) exist precisely to capture these dependencies. Complexity in architecture mirrors complexity in language.

Part 1: The Input Block

Given a sentence like "The next day is bright", three operations happen to every token before processing begins:

  1. Tokenization — split text into tokens and assign token IDs from the vocabulary
  2. Token Embedding — map each token ID to a dense vector capturing semantic meaning
  3. Positional Embedding — encode where each token sits in the sequence

Token embedding and positional embedding are added together to produce the input embedding — a single dense vector per token entering the processor.

DeepSeek's two primary architectural innovations map directly onto this block: Multi-Head Latent Attention replaces standard attention, and Mixture of Experts replaces the standard feed-forward network. Opening the engine and identifying these two components is the first step toward understanding why DeepSeek is efficient.

Part 3: The Output Block

After passing through all transformer blocks, tokens undergo final layer normalization, then a projection layer that maps from embedding dimension (e.g., 768) to vocabulary size (e.g., 50,000). The highest-scoring token ID becomes the next-token prediction.

The Journey of a Token — Input Phase

The input block is easiest to follow through a single token. Take "friend" in the sentence "A true friend accepts you." — five tokens total, with the model predicting what comes after "you." The sections below trace one token through all five input-phase stages.

Interactive · Token Journey: Input Phase

Step through the five input-phase stages. Watch "friend" transform from raw text to a 768-dimensional input embedding.

Phase 1: Isolation

The first step is isolation: every word is detached from its neighbors. The sentence is broken apart; each token is examined individually before receiving an ID.

Phase 2: Token ID Assignment

Isolated, each token needs an identity. The model consults the vocabulary — a lookup table of token IDs listing every token the model knows, each with a unique number. This vocabulary contains three types of entries:

  • Characters: a, b, c, … z
  • Subwords: fragments like "isation", "tion", common morphemes
  • Full words: "token", "enter", "begin", "friend"

Vocabulary size varies by model — 50,000 tokens for GPT-2, roughly 100,000 for GPT-4 — so the token ID assigned to "friend" may differ across models. In our example, "friend" receives token ID 20112. Every other token in the sentence gets its own ID. The token ID carries no semantic meaning; it is purely an index into the vocabulary table.

friend → Token ID: 20112

How the Vocabulary Is Built: Byte Pair Encoding

The vocabulary is constructed using Byte Pair Encoding (BPE) — a subword tokenization algorithm that iteratively merges the most frequent character pairs in a training corpus. The process:

  1. Start with individual characters as the base vocabulary
  2. Count all adjacent character pairs in the training text
  3. Merge the most frequent pair into a new token
  4. Repeat until the vocabulary reaches the desired size (50,000 for GPT-2)

The result: common words like "friend" become single tokens. Rare words get split into subwords ("unhappiness" → "un" + "happiness" or similar). Unknown words at inference time can always be decomposed into character-level tokens — no word is ever truly "unknown." GPT-4 uses a larger vocabulary (~100,000 tokens), likely with an improved BPE variant.

A common question is: why use subwords instead of whole words or individual characters?

Whole-word tokenization creates enormous vocabularies (every word in every language) and cannot handle novel words. Character-level tokenization creates very long sequences (every word spelled out letter by letter), making attention quadratic costs unbearable. Subword tokenization hits the sweet spot: common words are single tokens (efficient), rare words decompose into meaningful fragments (no unknown-token failures), and vocabulary size stays manageable at 50,000–100,000 entries.

Phase 3: Token Embedding

A token ID alone carries no meaning. Token embedding maps each ID to a dense vector — in GPT-2 small, 768 dimensions. Each dimension is a learned feature; the model discovers what they represent during training, not through hand-designed categories like "noun" or "emotion."

"Friend" might score 0.1 on one dimension, 2.1 on another, 0.3 on a third — producing a 768-dimensional vector that encodes semantic content. GPT-2 XL uses 1,600 dimensions. These embedding values are learned parameters — initialized randomly, optimized during training through backpropagation.

Phase 4: Positional Embedding

Meaning alone is insufficient. Consider: "The dog the dog chased another dog." Both instances of "dog" have identical token embeddings, yet they refer to different entities. The only way to distinguish them is position: the first "dog" is at position 2, the second at position 5.

Positional embedding adds another 768-dimensional vector encoding where the token sits in the sequence. For "friend" in "A true friend accepts you," the position is 3 (A=1, true=2, friend=3, accepts=4, you=5). Like token embeddings, positional embedding weights are learned parameters.

Phase 5: Input Embedding

Token embedding and positional embedding are added together:

input_embedding = token_embedding + positional_embedding   (768-dim each)

The result is the input embedding — a single 768-dimensional vector combining meaning and position. The transformer block does not see words; it sees 768-dimensional vectors.

Input block summary: Tokenization (ID assignment via vocabulary) → Token Embedding (meaning, 768-dim) → Positional Embedding (position, 768-dim) → Add → Input Embedding. Five steps. One vector per token. Ready for the processor.

Mapping Phases to Architecture Labels

The five narrative phases map directly onto the three labeled steps in the architecture diagram:

  • Tokenization = Phase 1 (Isolation) + Phase 2 (Token ID Assignment)
  • Token Embedding = Phase 3
  • Positional Embedding = Phase 4
  • Input Embedding = Phase 5 (addition of the two vectors)

When you see "tokenized text" in a codebase or paper, it refers to the integer token IDs (Phase 2). When you see "input embeddings," it refers to the final 768-dimensional vectors after all five phases complete.

The Journey of a Token — Through the Transformer Block

With input embeddings computed, all five tokens — "A," "true," "friend," "accepts," "you" — enter the transformer block as a matrix of shape (5 × 768): five rows (tokens), 768 columns (features). By the time they exit, the model has encoded context, grammar, and relationships between all five tokens.

Click through the six sub-layers of one transformer block. Highlight shows where DeepSeek innovates.

Step 1: Layer Normalization

Each 768-dimensional vector enters layer normalization first. Layer normalization adjusts mean and standard deviation so the mean becomes 0 and the standard deviation becomes 1. This stabilizes training — without it, activations can drift to extreme values across deep networks, causing gradients to vanish or explode.

LN(x) = γ ⊙ (x − μ) / √(σ² + ε) + β

Step 2: Multi-Head Attention — Context Mapping

This is where the transformer earns its name. Multi-head attention asks: for the token "friend," how much attention should be paid to each neighbor? It builds an attention map:

  • "friend" → "A": low attention
  • "friend" → "true": moderate attention (modifies "friend")
  • "friend" → "accepts": high attention (friend accepts…)
  • "friend" → "you": moderate attention

Consider completing: "I am from Pune, India. I speak ___." To predict the next word ("Hindi" or "Marathi"), the model must attend heavily to "Pune" and "India," not to "I am from." Attention encodes context — which tokens matter for which predictions. This is DeepSeek's first innovation site: Multi-Head Latent Attention (MLA) makes this step faster and more memory-efficient.

Select a query token and see simulated attention weights across the sentence "I am from Pune, India. I speak ___."

Step 3: Dropout

Dropout randomly sets a fraction of activations to zero during training. If the dropout rate is 0.5 and there are 100 parameters, roughly 50 are zeroed each step. Why? Some parameters become "lazy" — they rely on others to do the work. Forcing random parameters offline compels the remaining ones to learn independently. Dropout improves generalization and prevents overfitting. There are two dropout layers per transformer block — one after attention, one after the feed-forward network.

Skip Connections (Shortcut Connections)

The "+" signs in the architecture diagram are skip connections (also called residual connections). They add the input of a sub-layer directly to its output, creating an alternate path for gradients during backpropagation. Without skip connections, gradients flowing through many chained multiplications either shrink to zero (vanishing gradients — learning stops) or grow without bound (exploding gradients — training becomes unstable). Skip connections are the highway that keeps gradients flowing.

Step 4: Second Layer Normalization

Same operation as step 1 — normalize the vector after the attention sub-layer and its skip connection merge.

Step 5: Feed-Forward Neural Network — Expansion and Contraction

The feed-forward network (FFN) is the second major innovation site for DeepSeek (Mixture of Experts). In a standard transformer, the FFN:

  1. Takes the 768-dimensional input
  2. Expands to a higher-dimensional space: 4 × 768 = 3,072 dimensions
  3. Applies a non-linearity (ReLU, GELU, or similar)
  4. Compresses back to 768 dimensions

This expand-contract pattern lets the model explore richer representational spaces with more parameters, capturing complexity that the 768-dimensional space alone cannot express. In DeepSeek's MoE variant, instead of one FFN, there are multiple "expert" FFNs, and a router selects which expert(s) activate per token — dramatically increasing total parameters while keeping active parameters manageable.

Step 6: Dropout + Skip Connection

Final dropout, then another skip connection merging the FFN output with the pre-FFN signal. One transformer block complete.

Twelve Blocks, Not One

One transformer block is not the whole journey. GPT-2 model sizes:

VariantTransformer BlocksEmbedding Dim
GPT-2 Small12768
GPT-2 Medium241,024
GPT-2 Large361,280
GPT-2 XL481,600

Every token passes through all blocks sequentially — 12 times for GPT-2 Small, 48 times for GPT-2 XL. Modern models may stack 96 or more blocks. Critically, the output dimension remains 768 (for GPT-2 Small) after every block — the vector shape is preserved, but the values are transformed at each layer, building increasingly abstract representations.

Full pipeline cost: Five steps in the input block. Six sub-layers × 12 blocks = 72 operations in the processor. Then normalization and vocabulary projection. Every token traverses this pipeline on every inference pass — which is why DeepSeek's efficiency innovations (MLA, MoE, quantization) matter.

The Journey of a Token — Output, Prediction, and Training

After 12 transformer blocks, each token still carries a 768-dimensional vector — same shape, transformed values. All five tokens ("A," "true," "friend," "accepts," "you") exit together. The output block converts these vectors into vocabulary-sized predictions.

Final Layer Normalization

One more normalization step — final layer normalization — stabilizes the representations before projection. Every 768-dimensional vector is normalized using the same layer norm formula as inside the transformer blocks.

The Output Projection Layer

The model must convert 768-dimensional vectors into predictions over the full vocabulary. The output layer is a linear projection:

logits = input_embedding × Wout + b    where Wout is (768 × 50,000)

For vocabulary size 50,000 (GPT-2), each token's 768-dimensional vector is multiplied by a weight matrix of shape (768 × 50,000), producing a 50,000-dimensional logits vector. Each dimension corresponds to one token in the vocabulary. The highest logit indicates the model's top prediction for the next token.

Multiple Prediction Tasks in One Sequence

A critical detail: the sentence "A true friend accepts you" is not one prediction task — it is five:

Input (prefix)Target (next token)
Atrue
A truefriend
A true friendaccepts
A true friend acceptsyou
A true friend accepts you??? (what we want to predict)

During training, every position in the sequence generates a loss term. The model predicts "true" given "A," "friend" given "A true," and so on. During inference, only the final position matters — the next token after the full prefix.

Choosing the Next Token: Logits, Softmax, and Decoding

For each token's 50,000-dimensional logits vector, the index with the highest value maps back to the predicted token. Example: if the highest logit at position "you" corresponds to token ID 555, look up ID 555 in the vocabulary — perhaps "." or "well" or "always."

Before training, predictions are random. The model might predict "4" when the correct answer is "true." This gap between prediction and reality is the loss.

Raw logits are not probabilities — they can be any real number. To convert to a valid probability distribution, apply softmax:

P(token_i) = exp(logit_i) / Σⱼ exp(logit_j)

Softmax squashes logits into positive values that sum to 1.0. The token with the highest probability is selected (greedy decoding) or sampled (stochastic decoding). During training, cross-entropy loss compares the predicted distribution against the one-hot target (the actual next token) and penalizes divergence.

At inference time for our example, only the final position matters: given "A true friend accepts you," what comes next? The model produces a 50,000-dimensional logits vector at that position, softmax converts it to probabilities, and the top token becomes the prediction.

Backpropagation: Training Every Parameter

The loss is computed (typically cross-entropy between predicted and actual token distributions), then backpropagated through the entire network. Every learnable parameter is updated:

ComponentLearnable?Notes
Token embedding matrix★ YesVocabulary × embedding_dim
Positional embedding matrix★ YesMax_seq_len × embedding_dim
Multi-head attention (Q, K, V, O projections)★ YesPer transformer block
Feed-forward network weights★ YesPer transformer block; MoE adds experts

These parameters, repeated across 12 (or 48, or 96) transformer blocks, sum to the total parameter count: 175 billion for GPT-3, 671 billion for DeepSeek-V3 (with only ~37B active per token due to MoE). Backpropagation optimizes all of them jointly so that next-token predictions improve, and as a byproduct, the model learns language itself.

The complete journey: Isolation → Token ID (20112) → Token Embedding (768-dim) → Positional Embedding (768-dim) → Input Embedding (sum) → [LayerNorm → Attention → Dropout → Skip → LayerNorm → FFN → Dropout → Skip] × N blocks → Final LayerNorm → Output Projection (50,000-dim logits) → Argmax → Next token. DeepSeek modified the Attention and FFN sub-layers; everything else in this chapter is the baseline we build upon.

A common question is: if the task is next-token prediction, how does the model learn summarization, translation, or coding?

Emergent properties. At sufficient scale, optimizing next-token prediction on diverse internet text implicitly requires learning grammar, facts, reasoning patterns, code syntax, and multilingual structure. No explicit summarization loss is needed — a model that accurately predicts tokens in a news article "knows" how news articles are structured, and can generate summaries by continuing text in summary-like patterns. Fine-tuning and reinforcement learning then steer these latent capabilities toward useful behaviors.

A common question is: can I run DeepSeek-V3 on my laptop?

Not the full 671B model — that requires a cluster of high-memory GPUs (think dozens of H100s or equivalent). However, DeepSeek provides distilled models as small as 1.5B parameters that can run on consumer hardware. Quantization (covered in later chapters) further reduces memory requirements. The open-source weights mean you can choose the size that fits your hardware budget.

A common question is: how is DeepSeek-R1 different from DeepSeek-V3?

DeepSeek-V3 is the foundational model — pre-trained on massive text corpora with next-token prediction. DeepSeek-R1 is built on top of V3 using reinforcement learning (GRPO with rule-based rewards) to teach step-by-step reasoning. V3 is the engine; R1 is the engine plus a reasoning module trained to show its work. You need V3 (or its weights) before you can create R1.

A common question is: why do we need positional embeddings if attention handles context?

Attention is permutation-invariant — if you shuffle the input tokens, the attention output (before positional info) would be the same. Without positional embeddings, "Dog bites man" and "Man bites dog" would produce identical representations. Positional embeddings break this symmetry, encoding each token's location in the sequence. RoPE (used by DeepSeek) is a more sophisticated way to inject this positional information directly into the attention computation by rotating query and key vectors.
