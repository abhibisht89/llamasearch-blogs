The Attention Mechanism

Multi-head attention is the single most important step inside every Transformer block — the component that gave large language models their remarkable ability to understand language. 00

Why Do We Need Attention?

To understand DeepSeek — or any modern large language model — we must open the engine and inspect what happens inside. An LLM is a next-token prediction engine: you feed in a sequence of words (the fuel), and the model outputs the most likely next word. GPT-3 has 175 billion parameters; GPT-4 likely has around 1 trillion; GPT-4.5 probably has 5–10 trillion. The architecture has three major sections: input, processor, and output.

Building on the token pipeline from Chapter 1, we now focus on the attention mechanism — the core of how transformers understand context.

Each Transformer block contains: normalization → multi-head attention → dropout → skip connection → normalization → feed-forward network → dropout → skip connection. Out of all these steps, the most important lies within one step of the Transformer block: attention. This single block gives LLMs the properties that make them so good at understanding language.

Key insight: Self-attention is the mechanism that gives LLMs their ability to understand language — and understanding why it exists is the foundation for everything that follows, including DeepSeek's MLA.

From ELIZA to ChatGPT: 64 Years of Progress

In the 1960s, Joseph Weizenbaum described ELIZA — the first natural language processing chatbot, designed to simulate a therapist. Ask ELIZA "I am having a hard time learning AI, can you help me?" and you get a vague, unhelpful response. Compare that to ChatGPT today, which immediately presents actionable steps to learn AI. Within 64 years, the field of natural language processing has come an extraordinarily long way.

ELIZA (1966)

"You believe it is normal to be having a hard time learning AI?"

Rule-based pattern matching. No real understanding.

ChatGPT (2020s)

Deep neural networks with attention at the core.

Inside the Transformer Block

Each Transformer block is a repeating unit. A token's journey through one block:

Layer Norm → Input embedding normalized
↓
Multi-Head Attention → Input embeddings become context vectors
↓
Dropout → Random neurons deactivated (training only)
↓
Skip Connection → Add original input back (residual)
↓
Layer Norm → Normalize again
↓
Feed-Forward Network → Non-linear per-token transformation
↓
Dropout + Skip Connection → Output of this block

This block repeats 12, 24, 96, or more times. The attention step — highlighted above — is where context flows between tokens. Everything else supports stable training (normalization, skip connections) or per-token computation (FFN).

The Token Lifecycle in Numbers

A token enters as a 768-dimensional input embedding vector. After passing through all Transformer blocks, it reaches the output layer which projects it to a 50,000-dimensional vector (vocabulary size). Softmax over this vector gives a probability distribution over all possible next tokens. The argmax (or sampled token) is the model's prediction.

Why does attention matter so much more than the other components in a Transformer block?

Because attention is the only component that lets every token directly access every other token in the sequence. The feed-forward network processes each token independently; normalization stabilizes training; skip connections help gradients flow. But attention is what encodes relationships between words — the fundamental requirement for language understanding. Without it, you have a bag of independent vector transformations with no way to know that "it" in "The dog chased the ball but it couldn't catch it" refers to "ball," not "dog."

01

The Context Bottleneck Problem

Between 1960 and 2020, two fundamental building blocks dominated sequence modeling: Recurrent Neural Networks (RNNs), which emerged in the 1980s, and Long Short-Term Memory networks (LSTMs), introduced in 1997. Both built on the neural network boom of the 1970s and solved a critical problem: memory.

Why Memory Matters

When predicting the next word or generating text, you need to know what came at the start of a paragraph. Context means that if there is a huge paragraph and you want the model to answer a question, looking only at the immediately preceding sentence is not enough. You need a context of what was told at the beginning.

Take "I am from Pune, India." Then you write a huge bunch of sentences in the middle. Finally you ask: "What language do I speak?" All the things in the middle are not very important — but you need the context of what came at the beginning, because your dialect is heavily influenced by the region you come from.

How RNNs Capture Memory

People typically used RNNs or LSTMs for sequence-to-sequence tasks like language translation. Take the English sentence "I will eat" and translate it to French "Je mangerai."

Encoder: x₁="I" → h₁, x₂="will" → h₂, x₃="eat" → h₃
Decoder: h₃ → s₁="Je", s₁ → s₂="mangerai", ...

Hidden states h₀, h₁, h₂, h₃ in the encoder; s₁, s₂, s₃ in the decoder.

In the encoder block, you give the first word "I" and get hidden state h₁. For the second hidden state h₂, you use the second input and the previous hidden state h₁. That's how memory is captured: the previous hidden state is used to compute the current hidden state. When you reach h₃, it has knowledge of h₁ and h₂ — it retains memory of the past.

Think of it as a relay race: the baton starts at h₁, passes through h₂ to h₃, then to the decoder. Each runner carries everything accumulated from previous runners — but h₁ and h₂'s individual contributions are irretrievably merged in h₃. Attention fixes this by letting the decoder look back at h₁, h₂, and h₃ individually with learned weights.

LSTMs are a bit different: to predict the current hidden state, they also maintain a cell state, giving provision for both long memories and short memories to increase the context window. But the architecture fundamentally remains the same — the mathematics beneath is just more complicated.

LSTM: A Brief Detour

Long Short-Term Memory networks (Hochreiter & Schmidhuber, 1997) attempted to extend RNN memory through a cell state — a separate highway for information that could flow across many time steps with minimal degradation. LSTMs maintain both a hidden state (for output) and a cell state (for long-term memory). Gates (forget, input, output) control what information passes through.

LSTMs handle longer sequences better than vanilla RNNs, but the fundamental bottleneck remains: all information must eventually flow through fixed-size state vectors. For a 500-word paragraph, no 1000-dimensional vector can losslessly encode every nuance. Attention bypasses this entirely by giving every decoding step direct access to every encoding position.

The Context Bottleneck

RNNs rely on only one hidden state — one vector — to capture all past context. Compressing an entire paragraph into a single 500- or 1000-dimensional vector inevitably loses information.

And remember: the decoder does not take input from h₁ or h₂. It only takes the final hidden state h₃ as input. The context going from encoder to decoder is only from the final hidden state. This is called the context bottleneck problem.

The core problem: You cannot compress an entire paragraph into a single 500-dimensional vector without losing information. Context bottleneck in RNNs is really not good for retaining long-range context.

The Ideal Solution: Selective Access

What if, during decoding, instead of having access to just the final hidden state, you had access to all hidden states of the encoder and all the inputs? When decoding the first token, you could give 80% importance to h₁, 10% to h₂, and 10% to h₃. When decoding the second token, different weights apply.

The main thing that can solve the context bottleneck is developing a mechanism that quantifies how much importance to give to every hidden state. Even if the paragraph is long, if you can attend to all tokens and give importance to something from the past, the context bottleneck problem is solved.

α₁₁ = relative importance of h₁ when decoding token 1  |  α₂₁ = importance of h₂ when decoding token 1

The ideal solution: selectively access parts of the sequence during decoding — quantifying importance to each position at each step.

The History of Attention

The first paper to implement attention was not "Attention Is All You Need." Many people believe attention was first introduced in the 2017 Transformer paper — which has around 170,000 citations — but the first paper to actually implement attention for translation was Bahdanau, Cho, and Bengio (2014), published at ICLR 2015.

1966

ELIZA — Joseph Weizenbaum's rule-based chatbot. The first NLP system, but no neural networks.

1980s

RNNs — Recurrent neural networks introduce hidden states for sequential memory.

1997

LSTMs — Long short-term memory networks add cell states for longer context.

2014

Bahdanau Attention — Attention added to RNN encoder-decoder. Still uses RNN architecture.

2017

Transformer — Vaswani et al. remove RNNs entirely. Attention + Transformer block.

2018

GPT — Decoder-only architecture. Attention retained, encoder removed.

Historical note: The ELIZA chatbot (1966) used pattern matching, not neural networks. RNNs (1980s) added recurrence. LSTMs (1997) extended memory. Bahdanau attention (2014) added selective access. Transformers (2017) removed recurrence entirely. GPT (2018) simplified to decoder-only. Each step addressed a specific limitation of the previous approach.

One sentence to remember: We need to selectively access parts of the input sequence during decoding.

Bahdanau Attention (2014)

Bahdanau et al. implemented an architecture where you can selectively decide how much attention to pay to each hidden state. Attention scores α₁, α₂, α₃ quantify relative importance, and they proved sequence-to-sequence translation works much better with attention.

Their visualization plots English sentences on the x-axis and French translations on the y-axis. The brightest cells show which English word pays the most attention to which French word. Notably, the brightest areas are not always on the diagonal.

"Agreement on the European Economic Area" in English translates to "accord sur la zone économique européenne" in French — "European" in English occurs at position 5, but "européenne" in French occurs at position 7. Translation does not always happen word-by-word; nouns, verbs, and adjectives are arranged differently across languages. The attention mechanism captures these off-diagonal alignments automatically.

From 2014 to 2017: Removing the RNN

The progression from Bahdanau (2014) to Transformer (2017) was not incremental — it was a paradigm shift.

2014

Bahdanau attention: RNN encoder + RNN decoder + attention between them. Attention solves the bottleneck but RNNs remain the backbone.

2015

Published at ICLR. Alignment visualizations show off-diagonal attention patterns across languages.

2017

"Attention Is All You Need" — Vaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser, Polosukhin. RNNs removed entirely. Self-attention + position encoding + FFN = Transformer.

2018

GPT-1 (Radford et al.): Decoder-only Transformer. Proves you can pre-train on raw text with causal attention and fine-tune for downstream tasks.

The original Transformer had both encoder (for input) and decoder (for output). GPT kept only the decoder — because next-token prediction only needs to generate, not encode a separate input. DeepSeek, like GPT, uses a decoder-only architecture with causal attention at its core.

Many people cite "Attention Is All You Need" as the origin of attention, but Bahdanau et al. (2014) deserve credit for the original insight: let the decoder look at all encoder states instead of just the last one. The Transformer paper's contribution was showing that even the RNN encoder-decoder could be removed — attention alone, combined with position encodings and feed-forward layers, is sufficient.

Attention Is All You Need (2017)

Three years after Bahdanau, researchers figured out that RNN architectures are not even needed for building deep neural networks for NLP. They proposed the Transformer architecture.

2014: Bahdanau

RNN encoder-decoder + attention mechanism. RNN retained.

2017: Transformer

RNNs scrapped. Attention mechanism coupled with the Transformer block.

The original Transformer paper had both an encoder and a decoder. The GPT architecture (2018) is based on this but uses only the decoder block, retaining the attention mechanism. The reason attention is needed manifests itself right here in the LLM architecture — inside every Transformer block.

One sentence to remember: We need to selectively access parts of the input sequence during decoding. First attention was introduced in RNNs; then researchers removed RNNs and merged attention with the Transformer block.

03

Self-Attention vs Cross-Attention

Self-attention is a mechanism that allows every position in the input sequence to attend to all positions in the same sequence.

Cross-Attention (2014)

Attention between two sequences. English encoder → French decoder. "How much should the French word attend to each English word?"

Self-Attention (2017+)

Attention within one sequence. "How much should each word attend to every other word in the same sentence?"

LLMs predict the next token — they are not specifically trained for translation. Instead of attention between two languages, you take the same sentence and ask: if you look at one token, how much attention should you pay to all other tokens?

Cross-Attention: The Original Formulation

In Bahdanau's encoder-decoder setup for translation:

  • Encoder processes "I will eat" → hidden states h₁, h₂, h₃
  • Decoder generates "Je mangerai" one word at a time
  • When decoding "Je", the query comes from the decoder state; keys and values come from all encoder hidden states
  • Attention weights α₁, α₂, α₃ tell the decoder how much to rely on each encoder position

Self-attention removes the encoder-decoder split. The same sequence serves as both source and target for Q, K, and V. This is what LLMs use: one sequence in, enriched sequence out.

The Pune Example

Consider: "I am from Pune, India. I speak …" When you look at the word "speak", maximum attention needs to be paid to "Pune" and "India". All other words are not as relevant — your dialect is heavily influenced by the region you come from. When your architecture has information about how one word relates to surrounding words and how much importance to pay, predicting the next token becomes much easier.

"The next day is bright"

When tokens enter the Transformer, they are vectors — the model does not understand words or sentences. Every token has a 768-dimensional input embedding:

the → X₁ next → X₂ day → X₃ is → X₄ bright → X₅

If we focus on "next" (the query token), we want attention scores: α₂₁ (next→the), α₂₂ (next→next), α₂₃ (next→day), α₂₄ (next→is), α₂₅ (next→bright). The token we focus on is the query; the other tokens are the keys.

Why is it called "self"-attention?

Because the query and keys come from the same sequence. In cross-attention (Bahdanau), the query comes from the decoder sequence and the keys come from the encoder sequence — two different sequences. In self-attention, both come from one sentence. You look at tokens within the sentence and see how they relate to each other. That is why 2014 was a critical turning point: instead of looking at words in isolation, researchers started asking how different words relate to each other — exploiting the maximum richness from text.

04

Context Vectors: Enriched Representations

The whole goal of the attention mechanism — specifically self-attention — is to convert all input embedding vectors into context vectors.

Input Embedding Vector

Token embedding + position embedding. Encodes the meaning of the word and its position. No information about neighbors.

Context Vector

An enriched embedding that combines information from all other input elements. Encodes how much importance to pay to surrounding tokens.

All tokens have a 768-dimensional input embedding when they enter the multi-head attention layer. What comes in is an input embedding vector; what comes out is a context vector — something much richer. The context vector retains context because it encodes information of other tokens.

Individual tokens don't mean much in isolation. A paragraph only makes sense when you look at all words together and how they relate to each other — just like images are made up of patterns of pixels. This fundamental insight is what made LLMs so much better. Until attention (2014), models looked at words largely in isolation.

Visualizing the Transformation

Input embedding space gives each word a fixed location based on its meaning — unchanged by neighbors. Context vector space moves each word to a new location that depends on its neighbors: "next" in "the next chapter is boring" shifts differently than in "the next day is bright." This is why the attention block is marked in a different color in architecture diagrams — static word representations become dynamic, context-aware representations.

From Input Embedding to Context Vector

You have an input embedding vector for "next" and attention scores α₂₁ through α₂₅. The simplest approach: take dot products to get scores, then compute a weighted sum:

Context(next) = α₂₁·X₁ + α₂₂·X₂ + α₂₃·X₃ + α₂₄·X₄ + α₂₅·X₅

A dot product encapsulates whether vectors are similar or closer to each other. If "next" and "the" are more similar, they should have a higher attention score. Calculate dot products, scale vectors by their scores, add them up — that sum is the context vector.

05

Why Simple Dot Products Fail

The naive approach — dot product between input embeddings, then weighted sum — seems sensible, but it has a fatal flaw:

The dog chased the ball but it couldn't catch it.

Suppose the input embedding for dog, ball, and the second it are vectors such that dot(it, dog) = 0.51 and dot(it, ball) = 0.51. Both attention scores are completely identical — but that's not what we want.

"The dog chased the ball but it couldn't catch it" — the second "it" means the ball, not the dog. When looking at this "it", we need to pay much more attention to "ball" than "dog". The first "it" (if there were one referring to the dog) would attend more to "dog."

The problem: Simple dot product only measures semantic similarity. It cannot deal with contextual issues. "Catch" is more likely to refer to a moving object (the ball). Dot products cannot distinguish these subtle contextual relationships.

The Coreference Problem in Depth

Coreference resolution — determining what a pronoun refers to — is one of the hardest problems in NLP. Consider the full sentence again:

The dog chased the ball but it couldn't catch it.

There are two pronouns and two possible antecedents:

PronounPositionCorrect referentWhy
it (1st)After "but"ball"couldn't catch it" — you catch a ball, not a dog
it (2nd)End of sentenceballSame reasoning — the ball was being chased

Raw dot product between input embeddings gives score(it, dog) = score(it, ball) = 0.51. The model has no way to distinguish them because input embeddings encode static word meaning, not contextual role.

After projection through WQ and WK:

query(it) = W_Q · embed(it) = [0.5, 0.1, 0.5]
key(dog) = W_K · embed(dog) = [0.92, 0.1, 1.8]
key(ball) = W_K · embed(ball) = [0.1, 1.8, 1.0]

score(it, dog) = 0.5×0.92 + 0.1×0.1 + 0.5×1.8 = 0.46 + 0.01 + 0.90 = 0.56
score(it, ball) = 0.5×0.1 + 0.1×1.8 + 0.5×1.0 = 0.05 + 0.18 + 0.50 = 0.96

The trainable matrices learned to project "it" and "ball" into a space where they align strongly, while "it" and "dog" align weakly — even though their raw embeddings had identical dot products.

06

Query, Key, and Value Matrices

In physics, if you were stuck with this problem, you might spend six months developing a law for the underlying mechanism. In deep learning, you take a different approach: replace the unknown relationship with trainable weight matrices and let backpropagation figure it out.

Researchers invented three new matrices:

Q = X · WQ    K = X · WK    V = X · WV
  • WQ — query weight matrix. Transforms the focused token into a query vector.
  • WK — key weight matrix. Transforms all other tokens into key vectors.
  • WV — value weight matrix. Transforms tokens into value vectors for the final weighted sum.

Concrete 3×3 Example

For dog, ball, and it with 3-dimensional embeddings, if WQ and WK are both 3×3:

Input embeddings → multiply by WK:

key(dog) = [0.92, 0.1, 1.8]T

key(ball) = [0.1, 1.8, 1.0]T

query(it) = WQ · embed(it) = [0.5, 0.1, 0.5]T

score(it, ball) = 0.96 > score(it, dog) = 0.56 ✓

There is actually no proper physical reason why queries and keys are introduced. Humans could not figure out how to capture attention scores themselves. The trick: initialize WQ, WK, WV randomly, then train them through backpropagation. This same trick has been used in computer vision for decades — if you cannot figure out the relationship, let the neural network do its job.

Why Separate Q, K, and V Projections?

In the previous naive approach, we used the same input embedding for both the query side and the key side. The query for "it" and the key for "dog" were both just the raw input embeddings. There was no way to encode the contextual information that "it" after "chased the ball" should prefer "ball."

By introducing WQ, we transform "it" into a query vector that asks: "I am a pronoun following an action — which noun am I referring to?" By introducing WK, we transform "dog" and "ball" into key vectors that answer: "here is what I offer as a match candidate." The dot product between transformed query and key captures compatibility in this learned space — not just raw semantic similarity.

WV serves a separate purpose. Even after we know "it" should attend to "ball" with weight 0.96, we need to decide what information from "ball" to pass along. The value vector carries that content. Attention weights select which values to blend; value vectors determine what gets blended.

Matrix Dimensions in Production Models

In GPT-style models, the input and output dimensions of WQ, WK, WV are typically kept the same as the model dimension (768 for GPT-2 small, 4096 for larger models). For our worked example, we use 8-dimensional input embeddings projected to 4-dimensional query/key/value spaces for clarity. The math is identical — only the dimensions change.

# PyTorch-style initialization (bias=False)
self.W_q = nn.Linear(d_in, d_out, bias=False)
self.W_k = nn.Linear(d_in, d_out, bias=False)
self.W_v = nn.Linear(d_in, d_out, bias=False)

All three weight matrices are initialized randomly and learned through backpropagation during training. No hand-crafted rules — the network discovers contextual relationships from data.

Why three matrices instead of just one?

Because queries, keys, and values serve different roles. Queries ask "what am I looking for?" Keys answer "what do I contain?" Values carry "what information should I pass along if selected?" Using separate projections gives the model three independent knobs to tune. WQ and WK determine compatibility (attention scores); WV determines what information flows through once a token is selected. This separation is what allows the model to learn that "it" should attend to "ball" (high Q·K score) while passing along ball-related semantic content (via V).

Self-Attention: The Full Mathematics

Self-attention with trainable weights on the sentence "the next day is bright", with concrete matrix dimensions:

Setup: Input Embedding Matrix

5 tokens × 8 dimensions = a 5×8 input embedding matrix. WQ, WK, WV are all 8×4 matrices.

X: 5×8
×
WQ: 8×4
=
Q: 5×4

Every row corresponds to a token. From 8 dimensions we project into a 4-dimensional output space. The same applies to K (5×4) and V (5×4).

Step 1: Compute Q, K, V

Q = X · WQ    K = X · WK    V = X · WV

Step 2: Attention Scores = Q · KT

Q is 5×4. KT is 4×5 (transpose of the 5×4 keys matrix). Multiplying 5×4 by 4×5 gives a 5×5 attention scores matrix.

Focus on row 2 ("next"). To get α₂₁ (attention between "next" and "the"): take the query row for "next" and dot it with the key column for "the" — the first column of KT. Similarly, α₂₂ = dot(querynext, keynext), and so on.

Step 3: Scale and Softmax

Attention Weights = softmax( Q · KT / √dk )

where dk = 4 (the key dimension). Scale by √4 = 2 before applying softmax.

Step 4: Context Vectors = Weights · V

Context = Attention Weights · V

Multiply the 5×5 attention weights matrix by the 5×4 values matrix → 5×4 context vector matrix. Each row is the context vector for one token.

Detailed Walkthrough: Row 2 ("next")

Tracing every step for the query token "next" (row 2, index 1):

Step 2 — Raw Attention Scores for "next"

α₂₁ = query(next) · key(the)   → dot product of row 2 of Q with column 1 of KT
α₂₂ = query(next) · key(next)   → dot product of row 2 of Q with column 2 of KT
α₂₃ = query(next) · key(day)    → row 2 · column 3
α₂₄ = query(next) · key(is)     → row 2 · column 4
α₂₅ = query(next) · key(bright) → row 2 · column 5

Each score is a single number — the dot product of two 4-dimensional vectors. The full 5×5 matrix contains these scores for every (query, key) pair.

Step 3 — Scaling and Softmax for Row 2

Suppose raw scores for row 2 are [0.8, 2.4, 1.6, 0.4, 0.4]. Divide each by √dk = √4 = 2: [0.4, 1.2, 0.8, 0.2, 0.2]. Apply softmax:

e0.4 = 1.492, e1.2 = 3.320, e0.8 = 2.226, e0.2 = 1.221, e0.2 = 1.221

Sum = 1.492 + 3.320 + 2.226 + 1.221 + 1.221 = 9.480

softmax = [1.492/9.480, 3.320/9.480, 2.226/9.480, 1.221/9.480, 1.221/9.480]

= [0.157, 0.350, 0.235, 0.129, 0.129] — sums to 1.0 ✓

Step 4 — Context Vector for "next"

Multiply each value vector by its attention weight and sum:

context(next) = 0.157·V(the) + 0.350·V(next) + 0.235·V(day) + 0.129·V(is) + 0.129·V(bright)

Each V(token) is a 4-dimensional vector. The weighted sum is also 4-dimensional. This context vector encodes not just "next" but how "next" relates to every other word in the sentence.

Dimension check: (5×5 weights) × (5×4 values) = (5×4 context matrix). Five tokens in, five richer context vectors out. Same number of tokens, same output dimension — but each vector now carries contextual information.

The Five Steps Summarized

  1. Multiply input embedding matrix with WQ, WK, WV → query, key, value vectors
  2. Multiply queries with keys transpose → attention scores (5×5)
  3. Scale attention scores by √dk and apply softmax → attention weights (rows sum to 1)
  4. Multiply attention weights with values matrix → context vector matrix

These four steps are the entire self-attention module. Input embedding matrix in → context vector matrix out.

08

Softmax and Scaling by √dk

What Softmax Does

Given values X₁, X₂, X₃, X₄, X₅, softmax replaces each with:

softmax(Xᵢ) = eXᵢ / (eX₁ + eX₂ + eX₃ + eX₄ + eX₅)

All outputs lie between 0 and 1, and they sum to 1. Softmax gives a lot of weightage to very high values and very low weightage to very low values.

Softmax: Full Numeric Walkthrough

Given attention scores for "next" after scaling: X = [0.4, 1.2, 0.8, 0.2, 0.2]

e^0.4 = 1.4921
e^1.2 = 3.3201
e^0.8 = 2.2255
e^0.2 = 1.2214
e^0.2 = 1.2214

Sum = 1.4921 + 3.3201 + 2.2255 + 1.2214 + 1.2214 = 9.4805

softmax(X₁) = 1.4921 / 9.4805 = 0.1574 (attention to "the")
softmax(X₂) = 3.3201 / 9.4805 = 0.3502 (attention to "next")
softmax(X₃) = 2.2255 / 9.4805 = 0.2347 (attention to "day")
softmax(X₄) = 1.2214 / 9.4805 = 0.1288 (attention to "is")
softmax(X₅) = 1.2214 / 9.4805 = 0.1288 (attention to "bright")

Check: 0.1574 + 0.3502 + 0.2347 + 0.1288 + 0.1288 = 1.0000 ✓

Notice "next" attends most to itself (0.35) — a common pattern. It also attends significantly to "day" (0.23) and "the" (0.16), capturing the phrase "the next day."

The Problem: Softmax Is Too Sharp

If attention scores are [0.1, 1.8, 6.1, 0.1, 0.1] and you apply softmax directly, the value 6.1 gets ~0.95 weight and everything else becomes negligible. That's not good — we want to pay attention to multiple keys, not just one.

Now multiply all values by 8 before softmax: [0.8, 14.4, 48.8, 0.8, 0.8]. Softmax places almost all weight on 48.8 — the distribution becomes extremely peaked. Large values before softmax cause one key to dominate.

The Fix: Scale by √dk

Before applying softmax, divide attention scores by √dk (the square root of the key dimension). With dk = 4, divide by √4 = 2. This keeps values in a reasonable range so softmax produces a more balanced distribution.

Why √dk specifically? As dimensionality increases, dot products grow larger in magnitude (more terms summed). Dividing by √dk counteracts this growth, keeping the variance of dot products roughly constant regardless of dimension. This prevents softmax from becoming too peaked in high dimensions.

Numeric Example: Why Multiply by 8 Breaks Softmax

Start with balanced scores: [0.1, 0.2, 0.3, 0.2, 0.1]. Softmax gives roughly equal weights (~0.18 each). Good.

Now multiply by 8: [0.8, 1.6, 2.4, 1.6, 0.8]. e2.4 = 11.02 dominates the sum. Softmax ≈ [0.05, 0.10, 0.68, 0.10, 0.05]. One key gets 68% of attention — the rest are nearly ignored.

With √dk scaling (divide by 2 first): [0.4, 0.8, 1.2, 0.8, 0.4]. Softmax ≈ [0.10, 0.18, 0.44, 0.18, 0.10]. Still peaked at the highest score, but other keys retain meaningful weight.

The "Attention Is All You Need" Formula

Vaswani et al. (2017) write:

"We call this 'Scaled Dot-Product Attention.' The scaling factor 1/√dk is used to counteract the effect of the dot products growing large in magnitude for large dk."

Without scaling, dot products in high dimensions push softmax into extreme distributions where one token hogs all attention. Scaling keeps gradients healthy and attention patterns diverse.

Context Vector Calculation with Numbers

For "next" with attention weights [0.1, 0.5, 0.2, 0.1, 0.1]:

Context(next) = 0.1·V(the) + 0.5·V(next) + 0.2·V(day) + 0.1·V(is) + 0.1·V(bright)

Scale each value vector by its attention weight, add all scaled vectors together. The result is the context vector for "next" — richer than the input embedding because it incorporates neighbor information.

Causal Attention: Don't Peek into the Future

Self-attention allows every token to attend to every other token — including future tokens. That works for understanding, but breaks next-token prediction. When training an LLM, to predict the output you only have access to tokens that come before it. You cannot cheat. You cannot look into the future.

Next-Token Prediction Setup

Consider pre-training on a book. With context size = 4 and stride = 1, the data is divided into chunks of 4 tokens. The input batch has token IDs; the output batch is the input shifted right by one.

Input row 1: [1, 15, 18, 22] → "Mr and Mrs Dursley"
Output row 1: [15, 18, 22, 3] → shifted right by 1

For every output token, the model should only use tokens that come before it — not future tokens in the sequence.

To predict "Mrs" given input "Mr", you do not have access to "Dursley" or any future tokens. This seems trivial, but it is the whole premise of causal attention.

Bidirectional vs Unidirectional

Bidirectional (Full Self-Attention)

Every token attends to all tokens — before and after. Used in BERT (encoder models).

Unidirectional (Causal / Masked)

Each token attends only to itself and previous tokens. Also called autoregressive attention or masked attention. Used in GPT and all decoder LLMs.

Negative Infinity Masking: Full Row Example

For the sentence "your journey starts with one step" with 6 tokens, here is row 2 ("journey") through the causal mask:

Raw scores (row 2): [0.1, 1.8, 2.1, 3.5, 1.2, 0.8]

After causal mask: [0.1, 1.8, −∞, −∞, −∞, −∞]

After softmax:

e^0.1 = 1.105, e^1.8 = 6.050, e^−∞ = 0

Sum = 1.105 + 6.050 = 7.155

Weights = [1.105/7.155, 6.050/7.155, 0, 0, 0, 0] = [0.154, 0.846, 0, 0, 0, 0]

"journey" attends 84.6% to itself, 15.4% to "your", and 0% to all future tokens. Row sums to 1.0 ✓

The Masking Mechanism

Compute attention scores as before: Q · KT gives a 6×6 matrix for 6 tokens. In causal attention, set all elements above the diagonal to zero — or better, to −∞ before softmax.

Why −∞ instead of zero? Because attention weights (after softmax) must sum to 1 in each row. If you zero out elements after softmax, rows won't sum to 1. But e−∞ = 0, so setting scores to −∞ before softmax gives exact zeros in the weights while preserving the sum-to-1 property.

Row 1 (token "your"): [6.0, −∞, −∞, −∞, −∞, −∞] → softmax → [1.0, 0, 0, 0, 0, 0]

Row 2 (token "journey"): [0.1, 1.8, −∞, −∞, −∞, −∞] → softmax → [0.31, 0.69, 0, 0, 0, 0]

Row 3 (token "starts"): [2.0, 1.1, 1.2, −∞, −∞, −∞] → softmax → [0.52, 0.23, 0.25, 0, 0, 0]

Stride controls how many tokens to skip before creating the next input window. Stride = 1 means maximum overlap (every token position becomes a training example). The output is always the input shifted one position to the right.

Two Strategies for Masking (and Why −∞ Wins)

Strategy 1: Zero After Softmax

Compute full softmax weights, then zero out upper triangle. Problem: rows no longer sum to 1. Requires a second normalization pass.

Strategy 2: −∞ Before Softmax ✓

Set upper-triangle scores to −∞. Softmax: e−∞ = 0. One normalization step. Rows sum to 1 automatically. This is the standard approach.

Dropout on Attention Weights

Causal attention adds one more component not present in basic self-attention: dropout on attention weights. During training, random attention weights in each row are set to zero. This prevents the model from relying too heavily on specific tokens and improves generalization. At inference time, dropout is disabled.

CausalAttention Class Parameters

CausalAttention(d_in, d_out, context_length, dropout_rate)

d_in = input embedding dimension (e.g., 3)

d_out = output projection dimension (e.g., 2)

context_length = max sequence length (e.g., 6)

dropout_rate = probability of zeroing attention weights (e.g., 0.1)

Input shape: (batch, seq_len, d_in) → e.g., (2, 6, 3)

Causal vs Self-Attention: What's Different?

The difference between self-attention and causal attention happens after attention scores are calculated:

  1. Replace elements above the diagonal with −∞
  2. Apply softmax (one normalization step — not two)
  3. Apply dropout (randomly zero out some attention weights during training for generalization)

Everything else stays the same: Q, K, V projections, scaling by √dk, and context vector = weights · V.

The Deep Learning Philosophy Behind Q, K, V

There is a fundamental difference between physics and deep learning in how they handle unknown mechanisms. In physics, if you cannot explain why "it" refers to "ball" rather than "dog," you would search for an underlying law — perhaps syntactic role, semantic selectional restrictions, or world knowledge about what can be caught.

In deep learning, the approach is different: parameterize the unknown and optimize. Initialize WQ, WK, WV randomly. Feed millions of sentences through the model. Define a loss function (cross-entropy on next-token prediction). Backpropagate. The matrices gradually learn to project tokens into spaces where contextual relationships become dot-product-detectable.

This is the same philosophy behind convolution in CNNs — humans did not hand-design edge detectors; the network learned them. Attention projections are the same: we do not hand-design coreference resolution; the network learns it from data.

SelfAttention Class: Forward Pass Pseudocode

class SelfAttention:
    def __init__(self, d_in, d_out):
        self.W_q = nn.Linear(d_in, d_out, bias=False)
        self.W_k = nn.Linear(d_in, d_out, bias=False)
        self.W_v = nn.Linear(d_in, d_out, bias=False)

    def forward(self, x):
        Q = self.W_q(x)                          # Step 1
        K = self.W_k(x)
        V = self.W_v(x)
        scores = Q @ K.transpose(-2, -1)       # Step 2
        scores = scores / math.sqrt(K.size(-1)) # Step 3a: scale
        weights = F.softmax(scores, dim=-1)    # Step 3b: softmax
        context = weights @ V                  # Step 4
        return context

This is the complete self-attention module. CausalAttention adds two lines after Step 2: scores = scores.masked_fill(causal_mask, float('-inf')) and applies dropout after Step 3b.

Summary: Causal attention is a central building block on the path to multi-head attention, key-value cache, and ultimately multi-head latent attention in DeepSeek. The simplest explanation: you cannot cheat — you cannot look into the future.

Why not just zero out future weights after softmax instead of using −∞ before it?

Zeroing after softmax breaks the sum-to-1 property of each row. You would need a second normalization pass. Setting scores to −∞ before a single softmax achieves both goals at once: future positions get weight 0, and remaining weights automatically renormalize to sum to 1. This is the standard trick used in every GPT-style model.

Attention Is All You Need — The Canonical Formula

The 2017 paper by Vaswani, Shazeer, Parmar, Uszkoreit, Jones, Gomez, Kaiser, and Polosukhin defines:

Attention(Q, K, V) = softmax( QKT / √dk ) · V

With causal masking for decoder models:

MaskedAttention(Q, K, V) = softmax( mask(QKT) / √dk ) · V

where mask sets upper-triangular entries to −∞.

What You've Learned

  • Why attention exists: RNNs suffer from the context bottleneck — one vector cannot hold an entire paragraph.
  • Historical arc: Bahdanau (2014) added attention to RNNs; Transformer (2017) removed RNNs; GPT (2018) kept decoder + attention.
  • Self-attention: Every token attends to all tokens in the same sequence, producing context vectors.
  • Q, K, V: Trainable projections that replace naive dot products and capture contextual relationships.
  • Four steps: Project → score → scale+softmax → weighted sum of values.
  • Scaling: Divide by √dk before softmax to prevent overly peaked distributions.
  • Causal masking: Set future positions to −∞ so the model cannot peek ahead during training.

Next up: multi-head attention — running multiple attention operations in parallel to capture different relationship types. Each head learns to focus on different aspects: syntactic dependencies, semantic similarity, positional patterns, and more.
