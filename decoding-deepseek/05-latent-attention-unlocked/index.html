The Innovation That Changed Attention

Among all the architectural choices in DeepSeek-V2 (introduced June 2024), one stands above the rest: Multi-Head Latent Attention. It is the primary reason DeepSeek achieved dramatically lower inference costs while maintaining frontier-level language model performance. The standard transformer attention block — multi-head attention with separate key and value caches — was the bottleneck. MLA replaced it.

Think of a transformer as three regions: an input block (embeddings and positional encoding), a processor block (stacked transformer layers with attention and feed-forward networks), and an output block (final projection to vocabulary logits). MLA transforms specifically the multi-head attention component inside every processor layer. Everything else — feed-forward networks, layer normalization, residual connections — remains familiar. But attention itself is fundamentally different.

DeepSeek-V2 paper: The schematic in the DeepSeek-V2 technical report shows four attention variants side by side: standard MHA, Grouped Query Attention, Multi-Query Attention, and finally Multi-Head Latent Attention. This chapter focuses on the simplest MLA variant: low-rank key-value joined compression. A later chapter covers decoupled rotary position embeddings (RoPE) applied to MLA.

The Long Journey to Latent Attention

Understanding MLA requires understanding the path that led to it. The journey has clear milestones:

  1. Standard inference is wasteful — every token recomputes attention over the full prefix
  2. KV cache fixes compute — store keys and values, compute only new token's q, k, v
  3. KV cache creates memory crisis — 400 GB at DeepSeek scale with 100K context
  4. MQA sacrifices quality — share K/V across all heads for N× memory savings
  5. GQA partially compromises — share K/V within groups for N/G× savings
  6. MLA breaks the trade-off — compress via latent space, preserve diversity via up-projections

Each step solved the previous problem while introducing a new constraint. MLA is the first approach that simultaneously achieves low cache footprint and full multi-head representational capacity — not by sharing content across heads, but by sharing a compressed latent representation that each head decodes differently.

The KV Cache Story — From Repetition to Storage

Chapter 4 derived the KV cache in full. The essentials: during inference, each new token triggers a full forward pass, but only the last token's output matters — and most intermediate attention work repeats unchanged.

Inside Multi-Head Attention — The Four-Token Example

Take the prompt "The next day is" — four tokens. Each token is converted to an input embedding vector. Stacking these gives an input embedding matrix X of shape (4 × dmodel). Using a 4×4 matrix example, dmodel = 4 for simplicity.

Three trainable weight matrices transform X:

  • Q = X · WQ → query matrix, shape (4 × 4)
  • K = X · WK → key matrix, shape (4 × 4)
  • V = X · WV → value matrix, shape (4 × 4)

Attention scores are computed as Q · KT, producing a (4 × 4) matrix where entry (i, j) measures how much token i attends to token j. We scale by √dk, apply softmax along each row, and apply the causal mask so future tokens receive zero weight. The resulting attention weights multiply V to produce the context matrix — also (4 × 4), where row i is the context vector for token i.

MatrixShapeRow i Represents
Input embeddings X(4 × d)Embedding for token i
Queries Q(4 × d)Query vector for token i
Keys K(4 × d)Key vector for token i
Values V(4 × d)Value vector for token i
Attention scores(4 × 4)Token i's raw scores over all tokens
Context(4 × d)Enriched representation for token i

Predicting "bright" — Then Repeating Everything

The context matrix passes through the rest of the transformer layers. At the output, we get a logits matrix — one row per token, one column per vocabulary entry. We examine only the logits row for "is" (the last token), find the maximum probability, and decode token ID → "bright".

Now the input becomes five tokens: "The next day is bright". The entire pipeline runs again. We recompute Q, K, V for all five tokens. The attention score matrix is now (5 × 5). The context matrix is (5 × d). But rows 0–3 of Q, K, V, attention scores, attention weights, and context are bit-for-bit identical to what we computed in the previous step. Only row 4 is genuinely new.

The waste quantified: At step t with t tokens, we recompute (t−1)² attention entries that were already computed. Summing over all generation steps gives O(T²) total attention work for a sequence of length T — even though only O(T) of that work produces new information.

Tracing backward from next-token prediction for "bright":

Need: logits row for "bright"
↓
Need: context vector for "bright" only
↓
Need: attention weights row for "bright" × full V matrix
↓
Need: qbright × KT for scores, plus full K and V caches

For the new token, compute qnew, knew, vnew. Append knew to the K cache and vnew to the V cache. Multiply qnew by the full cached KT to get scores. Apply softmax. Multiply weights by the full cached V. Done — one context vector, one logits row, one predicted token.

Queries for prior tokens? Never needed. Keys and values for prior tokens? Already computed — just store them. This is the KV cache.

Conclusion: Cache the keys and values matrices during inference. This is the KV cache. It eliminates recomputation of all prior keys and values, reducing per-step compute from quadratic growth to linear growth in context length.

02

The Dark Side — and the MQA/GQA Response

KV Cache Memory Formula

The KV cache is not free. Every cached key and value parameter occupies memory. For each transformer layer, the cache size is:

KV cache size = L × B × N × H × S × 2 × 2 bytes

Where:

  • L — number of transformer blocks (layers)
  • B — batch size
  • N — number of attention heads
  • H — head dimension (dmodel / N)
  • S — context length (number of tokens cached)
  • First 2 — separate caches for keys and values
  • Second 2 — bytes per FP16 parameter (16-bit floating point)

For DeepSeek-R1 or DeepSeek-V3 at scale: L = 61 layers, B = 1, N = 128 heads, H = 128 head dimension, S = 100,000 context window. Plugging into the formula:

61 × 1 × 128 × 128 × 100,000 × 2 × 2 ≈ 400 GB

Four hundred gigabytes — just for the KV cache. DeepSeek's actual inference costs are far lower than this naive calculation would suggest, which is direct evidence they are not using a standard MHA KV cache. They are doing something fundamentally different — and that something is MLA.

03

The Best of Both Worlds Problem

Two goals must be satisfied simultaneously:

Goal 1: Low Cache Size

In the KV cache formula, the terms N × H (number of heads × head dimension) dominate the per-token storage cost. For DeepSeek, N × H = 128 × 128 = 16,384 dimensions per token per cache (keys and values separately). We cannot easily change L (layers), B (batch), or S (context) — but we can attack N × H.

Goal 2: High Performance

Every attention head should have different K and V values. We want K1 ≠ K2 ≠ K3 ≠ K4 and V1 ≠ V2 ≠ V3 ≠ V4. This requires WK1 ≠ WK2 and WV1 ≠ WV2 — distinct trainable weights per head.

These goals appear contradictory. MQA reduced cache size by making all heads share content — directly violating Goal 2. How can we shrink N × H while keeping heads diverse?

DeepSeek's Reframing

DeepSeek asked a different question: what if we don't cache keys and values separately at all?

Currently we cache two matrices (K and V), each with N × H columns per token. That gives a factor of 2 × N × H in the cache size. DeepSeek proposed:

  1. Cache only one matrix instead of two (eliminate the factor of 2)
  2. Make that matrix's column dimension dL much smaller than N × H

This sounds like a magic bullet. How do you cache one small matrix and still compute full multi-head attention with diverse keys and values per head? The answer is the latent space.

A common question is: why not just use GQA with more groups?

GQA still forces heads within a group to share identical K/V — a hard constraint on representational diversity. MLA compresses via a learned latent bottleneck that is shared, but reconstructs head-specific K and V through separate up-projection matrices WUK and WUV that differ per head. The compression is soft, not hard.

04

Latent Space Compression — The Down-Projection

The idea of latent spaces has existed in machine learning for decades — autoencoders, variational models, and recommendation systems all project high-dimensional inputs into lower-dimensional representations. DeepSeek brought this concept to language model attention for the first time at scale.

The Latent Matrix CKV — What DeepSeek Caches

DeepSeek's insight: instead of caching K and V separately (each S × N × H), cache a single matrix CKV = X · WDKV with shape S × dL. The down-projection matrix WDKV maps from dmodel-dimensional embedding space to dL-dimensional latent space.

Using a 4×4 matrix example: input embeddings are (4 × 8). WDKV is (8 × 4). The latent matrix CKV is (4 × 4). Per-token storage drops from 8 columns to 4 — before accounting for the K/V factor.

DeepSeek-V2 uses dL = 576 with dmodel corresponding to N × H = 128 × 128 = 16,384 total key/value dimensions per cache. The compression within the latent space alone is 16,384 / 576 ≈ 28×. Combined with storing one cache instead of two, the total reduction reaches ~57×.

The Full MLA Pipeline (Simplest Variant)

Queries: Q = X · WQ unchanged from MHA
↓
Latent: CKV = X · WDKV CACHED
↓
Keys: K = CKV · WUK per-head up-projection
↓
Values: V = CKV · WUV per-head up-projection
↓
Attention: softmax(Q · KT / √d) · V → Context

Later MLA variants also project queries into a latent space and apply decoupled RoPE (Rotary Positional Embeddings). This chapter covers the simplest variant where queries use standard WQ projection — sufficient to understand the core compression and absorption mechanisms.

Why "Absorption Trick"?

DeepSeek calls the matrix rearrangement an absorption trick because WUK — which traditionally lives in the key computation path — gets absorbed into the query computation path at inference time. Instead of computing full keys and caching them, we fold WUKT into WQ and query the latent cache directly. The keys are never materialized during inference — they are implicitly represented through the absorbed query against CKV.

The Core Workflow

Start with an input embedding matrix X of shape (S × dmodel). In a toy example, four tokens each with 8-dimensional embeddings give X of shape (4 × 8).

Step 1 — Queries (unchanged): X is multiplied by WQ to produce the queries matrix Q. In the simplest MLA variant, queries work exactly as in standard attention.

Step 2 — Down-projection to latent space: Instead of computing K = X · WK and V = X · WV directly, we first multiply X by WDKV — the down-projection KV matrix. The "D" means down, "KV" means this projection serves both keys and values jointly.

CKV = X · WDKV   (shape: S × dL)

WDKV has shape (dmodel × dL). If dmodel = 8 and dL = 4, then a (4 × 8) input produces a (4 × 4) latent matrix CKV. We went from 8 dimensions to 4 — a 2× compression per token before even considering the K/V factor.

Step 3 — Up-projection to keys and values: The latent matrix is multiplied by separate up-projection matrices:

K = CKV · WUK   |   V = CKV · WUV

WUK and WUV each have shape (dL × dmodel). The "U" means up-projection. Critically, these matrices are different per attention head — so reconstructed K and V differ across heads even though they share the same latent cache CKV.

Step 4 — Standard attention: Q · KT → attention scores → softmax → attention weights · V → context matrix. Everything after obtaining K and V is identical to standard multi-head attention.

X · WQ → Q
↓
X · WDKV → CKV CACHED
↓
CKV · WUK → K  |  CKV · WUV → V
↓
softmax(Q · KT / √d) · V → Context

At first glance this seems worse: We added an extra matrix multiplication (the down-projection) and two up-projections. How does adding computation reduce cache size? The answer lies in what we store during inference — and the absorption trick that follows.

05

The Absorption Trick — Mathematics That Makes It Work

Adding a latent matrix only helps if we can still compute attention scores and context vectors using just the cached CKV. The absorption trick is the mathematical rearrangement that makes this possible.

Deriving the Absorbed Query

We know:

Q = X · WQ  |  CKV = X · WDKV  |  K = CKV · WUK = X · WDKV · WUK

Attention scores are Q · KT:

Scores = (X · WQ) · (X · WDKV · WUK)T
Scores = X · WQ · WUKT · WDKVT · XT

Now the crucial step. WQ and WUKT are both fixed after pre-training. They never change during inference. So we can pre-multiply them into a single absorbed matrix:

Wabsorbed = WQ · WUKT  (computed once, never cached)

For a new token x (a single row of X), the attention scores against the cached latent vectors become:

scores = (x · Wabsorbed) · CKVT

The absorbed query is qabs = x · WQ · WUKT. Compare this to standard attention where q = x · WQ. We have absorbed WUKT into the query computation. No key cache needed — we multiply the absorbed query directly against the latent cache CKV.

Absorbing Values into the Output Projection

The same logic applies to the context vector. The values matrix is V = X · WDKV · WUV = CKV · WUV. The context vector is attention_weights · V, and eventually we multiply by the output projection WO to get logits.

Context = AttnWeights · CKV · WUV  →  Logits = Context · WO

Since WUV and WO are fixed at training time, we can absorb WUV · WO into a single precomputed matrix. During inference, we use the same cached CKV to compute values (via CKV · WUV) and then weight-sum with attention weights to get the context vector for the new token.

The absorption trick in one sentence: Because matrix multiplication is associative and WQ, WUK, WUV, WO are fixed after training, we fold the up-projection weights into the query and output paths — leaving only CKV to be cached and updated at inference time.

Why Heads Stay Diverse

WUK and WUV have different weights for every attention head. Even though all heads read from the same latent cache CKV, the up-projection reconstructs head-specific keys and values. Head 0's WUK differs from Head 1's WUK, producing different K matrices. This is fundamentally different from MQA, where the same K/V content is literally shared.

What Happens When a New Token Arrives

The following traces the exact inference steps when a new token — say "bright" — arrives, assuming "The next day is" is already cached as four latent vectors.

Before MLA: Standard KV Cache Steps

With standard MHA caching, when "bright" arrives:

  1. Compute qbright = xbright · WQ
  2. Compute kbright = xbright · WK, append to K cache
  3. Compute vbright = xbright · WV, append to V cache
  4. scores = qbright · KT (using full K cache)
  5. context = weights · V (using full V cache)

Two separate caches (K and V), each growing by N × H dimensions per new token.

With MLA: Latent Cache Steps

  1. Absorbed query: qabs = xbright · WQ · WUKT (WQ · WUKT precomputed)
  2. New latent vector: cnew = xbright · WDKV (optionally layer-normalized)
  3. Update cache: append cnew to CKV cache → shape grows from (4 × dL) to (5 × dL)
  4. Attention scores: scores = qabs · CKVT (one cache, no key cache)
  5. Attention weights: scale by √d, apply causal mask, softmax
  6. Values from same cache: V = CKV · WUV (same CKV, no separate V cache)
  7. Context vector: context = weights · V → only the row for "bright" matters

The single-cache insight: The same updated CKV matrix is used twice — once to compute attention scores (via the absorbed query) and once to reconstruct values (via WUV). No key cache. No value cache. Just one latent cache.

Intuition and Numerical Examples

Building Intuition: The Autoencoder Analogy

Think of MLA as applying an autoencoder pattern to the KV cache. An autoencoder compresses input into a bottleneck (encoder), then reconstructs from that bottleneck (decoder). Here:

  • Encoder: WDKV compresses the input embedding into the latent vector c (dimension dL)
  • Bottleneck (cached): CKV — the compressed representation stored in memory
  • Decoders (per head): WUK and WUV reconstruct head-specific keys and values from the shared bottleneck

Unlike MQA — where every head reads the same decoded output — each head in MLA has its own decoder weights. Head 1's WUK produces different keys from the same CKV than Head 2's WUK. The bottleneck is shared; the reconstructions are not.

Numerical Example: Toy Model Cache Bytes

For d_model=8, n_heads=2, d_h=4, d_L=4, S=6 tokens, L=1 layer, B=1 batch, FP16 (2 bytes):

MHA: L × B × S × (2 × N × d_h) × 2 bytes

= 1 × 1 × 6 × (2 × 2 × 4) × 2 = 1 × 6 × 16 × 2 = 192 bytes

MLA: L × B × S × d_L × 2 bytes

= 1 × 1 × 6 × 4 × 2 = 48 bytes

Ratio: 192 / 48 = 4×

Scale to DeepSeek: replace 2×2×4=16 with 2×128×128=32768, replace d_L=4 with d_L=576, replace S=6 with S=100000, replace L=1 with L=61. The ratio grows from 4× to ~57× because d_L scales sublinearly with model capacity.

Theory is necessary but not sufficient. This section implements the simplest MLA variant in PyTorch, walking through every matrix dimension. The class is named RolessMLA because advanced MLA variants incorporate rotary positional embeddings (RoPE) — which we omit here for clarity.

import torch import torch.nn as nn import torch.nn.functional as F class RolessMLA(nn.Module): def __init__(self, d_model, n_heads, latent_dim): super().__init__() self.d_model = d_model self.n_heads = n_heads self.d_h = d_model // n_heads self.latent_dim = latent_dim # Query projection: (d_model → d_model) self.WQ = nn.Linear(d_model, d_model, bias=False) # Down-projection KV: (d_model → latent_dim) — THE key matrix self.WDKV = nn.Linear(d_model, latent_dim, bias=False) # Up-projections: (latent_dim → d_model) self.WUK = nn.Linear(latent_dim, d_model, bias=False) self.WUV = nn.Linear(latent_dim, d_model, bias=False) # Output projection self.WO = nn.Linear(d_model, d_model, bias=False) # Layer norm on latent vectors (as in DeepSeek implementation) self.ln = nn.LayerNorm(latent_dim) def forward(self, x, kv_cache=None): # x shape: (batch, seq_len, d_model) — during inference often (1, 1, 8) B, T, D = x.shape # Step 1: Precompute absorbed query matrix WQ @ WUK.T # WQ.weight: (d_model, d_model), WUK.weight: (d_model, latent_dim) absorbed_qk = torch.matmul(self.WQ.weight, self.WUK.weight.T) # absorbed_qk shape: (d_model, d_model) = (8, 8) # Split absorbed matrix across heads: (n_heads, d_h, latent_dim) absorbed_qk = absorbed_qk.view(self.n_heads, self.d_h, self.d_model) # Actually split columns by head: view as (n_heads, d_h, d_model) absorbed_qk = absorbed_qk.view(self.n_heads, self.d_h, -1) # For d_model=8, n_heads=2: shape (2, 4, 8) — but we need (2, 4, 4) latent absorbed_qk = torch.matmul( self.WQ.weight.view(self.n_heads, self.d_h, D), self.WUK.weight.T.view(D, self.n_heads, self.d_h) ) # Per-head absorbed: (n_heads, d_h, latent_dim) # Step 2: Compute new latent KV vector for incoming token(s) new_kv = self.ln(self.WDKV(x)) # (B, T, latent_dim) # Step 3: Update cache — append new latent vectors if kv_cache is not None: kv_cache = torch.cat([kv_cache, new_kv], dim=1) else: kv_cache = new_kv # kv_cache shape: (B, S_total, latent_dim) e.g. (1, 6, 4) # Step 4: Compute absorbed query vectors per head x_heads = x.view(B, T, self.n_heads, self.d_h).transpose(1, 2) # x_heads: (B, n_heads, T, d_h) q_abs = torch.matmul(x_heads, absorbed_qk) # (B, n_heads, T, latent_dim) # Step 5: Attention scores = q_abs @ kv_cache.T scores = torch.matmul(q_abs, kv_cache.transpose(-2, -1)) # (B, n_heads, T, S_total) e.g. (1, 2, 1, 6) scores = scores / (self.d_h ** 0.5) # Causal mask + softmax S = kv_cache.shape[1] mask = torch.triu(torch.ones(T, S), diagonal=S-T+1).bool() scores = scores.masked_fill(mask, float('-inf')) weights = F.softmax(scores, dim=-1) # Step 6: Values from same cache values = self.WUV(kv_cache) # (B, S, d_model) values = values.view(B, S, self.n_heads, self.d_h).transpose(1, 2) # values: (B, n_heads, S, d_h) # Step 7: Context = weights @ values context = torch.matmul(weights, values) # (B, n_heads, T, d_h) context = context.transpose(1, 2).contiguous().view(B, T, D) return context, kv_cache

Initializing Weight Matrices in PyTorch

Using nn.Linear instead of raw nn.Parameter provides better weight initialization out of the box. All linear layers use bias=False — standard for attention projections in modern LLMs.

# Matrix dimensions for d_model=8, latent_dim=4, n_heads=2 self.WQ = nn.Linear(8, 8, bias=False) # (d_model × d_model) self.WDKV = nn.Linear(8, 4, bias=False) # (d_model × latent_dim) — CRITICAL self.WUK = nn.Linear(4, 8, bias=False) # (latent_dim × d_model) self.WUV = nn.Linear(4, 8, bias=False) # (latent_dim × d_model) self.WO = nn.Linear(8, 8, bias=False) # output projection self.ln = nn.LayerNorm(4) # normalize latent vectors

The Forward Pass — Line by Line

Line 1: Absorbed Query Matrix

absorbed = WQ.weight @ WUK.weight.T

WQ.weight shape: (8, 8). WUK.weight shape: (4, 8), transpose → (8, 4). Product: (8, 8). This is computed once per forward call (or precomputed and stored). Reshape to (n_heads, d_h, d_h) = (2, 4, 4) for per-head absorbed query matrices.

Line 2: New Latent Vector + Cache Update

new_kv = ln(WDKV(x)) then kv_cache = cat([kv_cache, new_kv], dim=1)

Input x: (1, 1, 8). WDKV output: (1, 1, 4). After layer norm: (1, 1, 4). Previous cache (5 tokens): (1, 5, 4). Updated cache: (1, 6, 4).

Line 3: Per-Head Absorbed Query

Split x into heads: (1, 2, 1, 4). For head 0: x_head0 (1, 1, 4) multiplied by absorbed[0] (4, 4) → q_abs0 (1, 1, 4). Same for head 1.

Line 4: Attention Scores

scores = q_abs @ kv_cache.transpose(-2, -1)

q_abs0: (1, 1, 4). kv_cache.T: (1, 4, 6). scores0: (1, 1, 6). Six scores because six tokens in cache. Scale by √4 = 2. Apply causal mask. Softmax.

Line 5: Values from Same Cache

values = WUV(kv_cache) → (1, 6, 8). Split into heads: (1, 2, 6, 4).

Line 6: Context Vector

context = weights @ values → (1, 2, 1, 4). Merge heads: (1, 1, 8). This is the context vector for the new token — the only output we need for next-token prediction.

In a demonstration with dmodel = 512 and dL = 256:

  • Standard MHA KV cache: stores 2 × dmodel = 2 × 512 = 1024 dims per token → ~80 KB

At DeepSeek scale the reduction reaches 57× because dL = 576 ≪ 2 × 128 × 128.

Trade-offs, Compute, and Ecosystem Context

Compute Complexity — With and Without KV Cache

Without KV cache, generating T tokens requires attention computations of size 1² + 2² + 3² + ... + T² = O(T³/3) total attention score entries across all steps. With standard KV cache, each step computes only one new query against T cached keys: O(T) per step, O(T²) total — linear per step instead of quadratic.

MLA preserves this O(T) per-step compute advantage while reducing the memory per cached token from 2×N×H to dL. The down-projection WDKV and up-projections WUK, WUV add constant-factor FLOPs per token, but these are negligible compared to the memory bandwidth savings at long context lengths.

GPU Memory Bandwidth

Every byte stored in GPU memory during inference consumes bandwidth. Modern GPUs are compute-rich but memory-bandwidth limited. The A100 delivers ~19.5 TFLOPS of FP32 compute but only ~1.9 TB/s of memory bandwidth — a 10× imbalance. When the KV cache grows to hundreds of gigabytes, memory bandwidth becomes the bottleneck for attention, not FLOPs.

MLA directly attacks this bottleneck by storing 57× fewer bytes per token in the cache. Fewer bytes to read means faster attention score computation and lower cloud inference bills. For a company serving millions of requests, reducing KV cache from 400 GB to 6 GB per sequence translates directly into serving more users on the same hardware — or charging lower prices while maintaining margins.

Summary — The Best of Both Worlds

Multi-Head Latent Attention is DeepSeek's answer to a problem that stumped the field for years: how to shrink the KV cache without making every attention head read the same keys and values.

What Changed

  • Keys and values are not cached directly
  • Input embeddings are down-projected to latent space via WDKV
  • Only CKV is cached — one matrix, dL columns per token
  • Up-projections WUK, WUV recover head-specific K and V
  • Absorption trick folds fixed weights into query and output paths

What Was Achieved

  • ~57× KV cache reduction at DeepSeek scale
  • 400 GB → ~6 GB at 100K context
  • Full multi-head diversity preserved
  • Linear compute growth in context length maintained
  • Low inference cost without quality collapse

Seven Key Takeaways

  1. Inference repeats work. Without caching, every new token triggers full recomputation of all prior attention states.
  2. Only the last context vector matters for next-token prediction — but computing it requires the full prefix via attention.
  3. KV cache saves compute but costs memory — growing linearly with context, reaching 400 GB at DeepSeek scale with standard MHA.
  4. MQA and GQA reduce memory by sharing K/V across heads or groups — but degrade quality by limiting head diversity.
  5. MLA compresses via latent space: CKV = X · WDKV replaces separate K and V caches with one dL-dimensional matrix per token.
  6. The absorption trick folds WUKT into WQ at inference, eliminating the need to materialize or cache keys.
  7. Per-head WUK and WUV ensure reconstructed K and V differ across heads — preserving MHA-quality diversity from a shared latent bottleneck.

Latent spaces have existed in machine learning for decades. DeepSeek's insight was applying them to the KV cache in transformer attention — compress once, reconstruct per head, absorb the rest. That single architectural move is a major reason DeepSeek models run inference at a fraction of the cost of comparable frontier models.

What Comes Next

This chapter covered the simplest MLA variant. The DeepSeek-V2/V3 architecture adds several layers on top:

  1. Rotary Positional Embeddings (RoPE) — encoding token position via rotation in embedding space
  2. Decoupled RoPE in MLA — applying RoPE separately to query and key latent paths within MLA
  3. Mixture of Experts (MoE) — sparse feed-forward layers where only a subset of experts activate per token
  4. Multi-Token Prediction — predicting multiple future tokens simultaneously for training efficiency
  5. Full DeepSeek-V3 assembly — combining MLA, MoE, and training innovations into the complete architecture

Each builds on the foundation established here. If you understand CKV, the absorption trick, and the per-head up-projections, the RoPE-extended variant is a incremental modification — not a fundamentally new mechanism.
