What is Micrograd?

Micrograd is an autograd engine — automatic differentiation via backpropagation. Given a scalar loss computed from many operations, it finds ∂loss/∂w for every parameter w so you can nudge weights to reduce the loss.

Here is a concrete flex of what that looks like before you have built anything yourself: wrap two leaves, say a = Value(-4.0) and b = Value(2.0), then compose them with adds, multiplies, powers, offsets, negation, ReLU-style squashes, division, and so on until you hold a single output g. After the forward pass, g.data might read 24.7 (the exact number depends on the specific expression you wire). Call g.backward(): the engine walks the graph backward and fills a.grad and b.grad. In one representative run those read 138 and 645 — meaning a tiny positive nudge to a increases g with slope about 138 at that point, and a tiny positive nudge to b increases g with slope about 645. That local sensitivity is exactly what optimization consumes.

The library Micrograd itself is open source on GitHub (authored by Andrej Karpathy as a teaching artifact). The point of the scalar version is pedagogical: you decompose a network all the way to individual + and * on floats so the chain rule and graph bookkeeping are impossible to hide. Production stacks then pack the same scalars into tensors and run fused kernels — the math is unchanged; only layout and throughput change.

Numbers live in Value objects. Arithmetic builds a computational graph: each Value remembers _prev (children) and _op (how it was made). The forward pass fills .data; backward() on the output runs the backward pass and fills .grad on every node.

∂L/∂(each node) → stored in node.grad

Micrograd is scalar-first: one float per Value. Frameworks like PyTorch and JAX pack scalars into tensors and use vectorized kernels. The chain rule and graph semantics are the same; tensors are for speed and memory layout, not a different theory.

Everything else is just efficiency: the autograd engine — the piece that knows nothing about “layers” — is on the order of ~100 lines of plain Python. The nn.py file on top (neuron, layer, MLP) is deliberately tiny: define a neuron, define a layer as a list of neurons, define an MLP as a sequence of layers. Altogether you are in the ballpark of ~150 lines for the ideas that matter for training. Everything beyond that in a real framework is batching, memory layout, autograd scheduling at scale, and hardware.

Neural networks are a particular shape of expression: dot products of inputs and weights, plus biases, plus nonlinearities like tanh, then a loss comparing predictions to targets. Backpropagation applies to any differentiable scalar graph; nets are the main application.

Forward

Evaluate from leaves to root. Each Value’s data is the numeric result of its op.

Backward

Traverse from the output backward. Each op implements local gradients; the chain rule multiplies them into grad.

01

Understanding Derivatives

Consider f(x) = 3x² − 4x + 5. At x = 3, f(3) = 20. The derivative f′(x) is the limit of rise-over-run as the step goes to zero:

f′(x) = limh→0 (f(x+h) − f(x)) / h

With a small h (e.g. 0.001), (f(x+h)−f(x))/h approximates the slope. If h is too tiny, floating-point cancellation makes the estimate unreliable — a practical nuance for numerical gradient checks.

Analytically f′(x) = 6x − 4. At x = 3, f′ = 14 (positive — the curve rises to the right). At x = −3, f′ = −22. At x = 2/3, f′ = 0 — a flat point (the vertex of the parabola).

Multiple inputs

For d = a·b + c with a = 2.0, b = −3.0, c = 10.0, you get d = 4.0. Partial derivatives: ∂d/∂a = b = −3, ∂d/∂b = a = 2, ∂d/∂c = 1. Nudging a up slightly decreases d because b is negative: the product a·b contributes less when a moves opposite to the sign of b.

Walk the numerics once, because they reappear in backprop. With h = 0.001, d1 = a*b + c = 4.0. Bump a only: d2 = (a+h)*b + c. Because b = −3, increasing a pulls the sum down: d2 lands near 3.997. The finite-difference slope (d2 − d1) / h is about −3.0, matching ∂d/∂a = b. Bump b instead and you get slope 2.0 (∂d/∂b = a). Bump c and the output moves one-for-one: slope 1.0.

If z depends on y and y depends on x, then dz/dx = (dz/dy)·(dy/dx).

Standard calculus texts state the chain rule for nested dependencies. A compact form: if a variable z depends on y, and y depends on x, then z depends on x through the intermediate y, and

dz/dx = (dz/dy) · (dy/dx)

Picture three speeds stacked: if a car travels twice as fast as a bicycle, and the bicycle travels four times as fast as a person walking, then the car travels 2 × 4 = 8 times as fast as the walker. You do not add the two ratios; you multiply them. That multiplicative composition is the same combinatorics backpropagation uses when it threads a gradient from a loss through many intermediate ops.

Building the Value class

Start with a wrapper around a Python float: self.data. Implement __repr__ for readable printing. Override __add__ and __mul__ so a + b and a * b return new Value instances whose data is the ordinary float result.

To record structure, pass children=(self, other) into new values. Store _prev as a set of children. A common pattern is to accept _children as a tuple in the constructor (so caller order is preserved) and immediately wrap it: self._prev = set(_children). The set avoids duplicate bookkeeping in some graph traversals; the tuple is for convenience at construction sites. Set _op to a short string like '+' or '*' for debugging and visualization.

Manual backpropagation

Build a small graph: e = a*b, d = e+c, f a separate leaf, L = d*f. Example numbers: a=2, b=-3, c=10 → e=-6, d=4, with f=-2 gives L=-8.

Add self.grad = 0.0 on every Value. Zero means “no effect yet.” The base case is ∂L/∂L = 1, so set L.grad = 1.

For multiplication L = d·f, hold the other factor fixed. From the limit definition: increment d by h, so the new output is (d+h)·f, subtract d·f, divide by h:

((d+h)·f − d·f) / h = (d·f + h·f − d·f) / h = f

So ∂L/∂d = f. Symmetrically ∂L/∂f = d. With d = 4 and f = −2, set d.grad = f.data = −2 and f.grad = d.data = 4. You can sanity-check with finite differences: bump f.data by h and read slope ≈ 4; bump d.data by h and read slope ≈ −2.

For addition d = e + c, the local partials are ∂d/∂e = 1 and ∂d/∂c = 1. From the definition with a bump h on c only:

((c+h) + e − (c + e)) / h = h/h = 1

By the chain rule, ∂L/∂c = (∂L/∂d)(∂d/∂c) = (∂L/∂d)·1. The little + node does not know about L; it only knows “I added two parents.” Its local Jacobian entries are both 1. Whatever gradient arrives from above — here ∂L/∂d = −2 — is routed unchanged to c and e: c.grad = e.grad = −2. That is why people call a sum node a gradient distributor or router.

For e = a·b, ∂e/∂a = b and ∂e/∂b = a (same limit argument as for d·f). You already have ∂L/∂e = −2 from the sum node. Chain again:

∂L/∂a = (∂L/∂e)(∂e/∂a) = (−2)·(−3) = 6  ∂L/∂b = (∂L/∂e)(∂e/∂b) = (−2)·(2) = −4

So a.grad = 6 and b.grad = −4 for this graph. Finite-difference bumps on a and b should reproduce those slopes up to floating-point noise.

Gradient ascent preview: if your goal were to increase L (unusual for training, but good for intuition), you would nudge each leaf by a small step along its gradient. After one such update and a fresh forward pass, L might move from −8 toward a less negative value (for example −7 in a representative run). Training normally minimizes loss, so you step in the opposite direction — same sensitivity information, flipped sign.

Key insight: backpropagation is the chain rule applied recursively backward through the graph. Each node only needs local derivatives; global sensitivities compose by multiplication.

Chain rule visualizer

Step backward from L through d to c. Watch how ∂L/∂d combines with ∂d/∂c = 1.

L← d← c

∂L/∂c = (∂L/∂d)(∂d/∂c) = ∂L/∂d × 1

Numerical gradient checking: bump one leaf’s data by h, recompute L, compare (L_new - L_old)/h to leaf.grad. Optimization picture: increasing a leaf a little in the direction of its gradient increases L (for maximization); training usually minimizes loss, so you step against the gradient.

Backprop through a neuron

A classical neuron computes z = w·x + b (dot product of weights and inputs, plus bias), then applies an activation such as tanh, which squashes ℝ into (−1, 1).

Biological neurons are intricate; the usual mathematical cartoon is simpler. Inputs xᵢ arrive along connections modeled as synapses with strengths wᵢ. Each synapse contributes wᵢ·xᵢ into the cell body. A bias b acts like baseline “trigger happiness”: it shifts how easy it is for the neuron to fire even when inputs are weak. The body sums ∑ wᵢxᵢ + b, then passes that scalar through a squashing nonlinearity (historically sigmoid or tanh). The output is that squashed value.

Read tanh qualitatively from its plot: at input 0, output 0. Large positive inputs saturate smoothly toward +1; large negative inputs toward −1. If you crank a neuron’s bias so the pre-activation feeding tanh is large (for example bias 8 with small weights), the output might land near 0.96 — you are already on the shoulder of the curve approaching the plateau at 1.

tanh(x) = (e2x − 1) / (e2x + 1)

You can implement tanh as one primitive op with derivative d/dx tanh(x) = 1 − tanh(x)², or decompose it into exp, adds, and divides — both are valid as long as forward and backward are consistent.

Worked numbers (2-D neuron): Arrange inputs, weights, and bias so the pre-activation n is a nice value — for example, setting bias to about 6.8814… makes the arithmetic clean. Suppose the raw sum feeding tanh is 0.8814… so that o = tanh(n) ≈ 0.7071. Then the local derivative d o / d n = 1 − tanh(n)² = 1 − o² evaluates to 0.5 exactly in that configuration. With o.grad = 1 (treating o as the scalar you differentiate), n.grad = 0.5.

Every + below n copies that upstream 0.5 to each summand branch (because local partials are 1). At a product node x₂·w₂, x₂.grad = w₂.data × (upstream) and w₂.grad = x₂.data × (upstream). If x₂ = 0, then w₂.grad = 0: wiggling a weight that is multiplied by a zero input does not move the output — the derivative correctly vanishes. Meanwhile x₂.grad can still be nonzero (here 0.5) because the input channel still routes gradient from the other side of the graph. For the companion branch, you might see w₁.grad = −1.5 and x₁.grad = 1.0 in the same worked example — concrete targets when you hand-verify your engine.

Manual backward through tanh

If o = tanh(n) and you have ∂L/∂o, then ∂L/∂n = (1 − o²)·∂L/∂o. Below that, + distributes the gradient to w·x and b; * splits between paired operands.

05

Automating the backward pass

Each Value stores a closure _backward that knows how to route out.grad into its parents’ grad using local Jacobian entries. For +: both parents get out.grad. For *: self.grad += other.data * out.grad and symmetrically. For tanh: self.grad += (1 − t²) * out.grad with t = tanh(self.data).

Do not call the closure at assignment time. Write out._backward = _backward, not out._backward = _backward(). Calling it immediately runs the function (which returns None) instead of storing the function object for later topological execution.

_backward closures

Click line numbers for chain-rule notes. Accumulate with += (explained in the next section).

engine.pyL40–58 / ~120
40        def _backward_mul():
41            self.grad += other.data * out.grad
42            other.grad += self.data * out.grad
45        def _backward_add():
46            self.grad += out.grad
47            other.grad += out.grad

Order matters: before calling a node’s _backward, all nodes that consume it must already have final grad. A topological sort of a directed acyclic graph lays nodes out so every edge goes “forward” along the list: parents before children in the dependency order you need for the forward pass. The classic recursive recipe: depth-first from the output, mark visited, recurse into each child in _prev, then append this node. That post-order list ends with the root last; walking it reversed means you hit each node only after everything above it in the forward graph has already propagated grad into its outputs.

Post-order append: a node’s _backward reads out.grad, which must already include every path from the loss through later ops. Visiting children first ensures downstream contributions have deposited into out.grad (with += when multiple paths exist) before you propagate into parents.

backward() and topological sort

Depth-first search builds a post-order list; reversing gives a valid backward schedule. Set out.grad = 1, then visit nodes from output toward inputs.

The accumulation bug (+=)

Consider b = a + a. The same Value appears twice as a child. If _backward for + uses assignment self.grad = out.grad twice, the second write overwrites the first — you lose a factor of 2. The derivative of b = 2a with respect to a should be 2; a broken engine reports 1.

A richer failure mode: let d = a·b, e = a + b, f = e·d, and backprop from f. Early branches may write a.grad and b.grad correctly, but when d.backward runs later, bare assignment can overwrite those tensors instead of adding a second contribution. Any time a variable is reused in more than one sub-expression, multiple backward paths converge on the same leaf.

The fix is the multivariate chain rule: contributions from disjoint paths through the graph sum. Implementation-wise, always accumulate with += starting from grad = 0 at leaves.

The accumulation bug: always update with += in _backward implementations, not =, unless you have proven a single consumer.

This matches PyTorch semantics: .grad tensors accumulate until you zero them.

07

More operations

Decompose tanh into exp, multiply, add, divide, power — useful practice. exp: d/dx eˣ = eˣ, so self.grad += out.data * out.grad because the forward output out.data equals eˣ at that node. For pow with a constant exponent k (Python int or float, not a different Value), the power rule is

d/dx (xᵏ) = k · xᵏ⁻¹

Implement self.grad += (k * self.data**(k-1)) * out.grad — local derivative times upstream. Division is the special case k = −1: a / b = a · b⁻¹ once pow exists.

Rebuilding tanh from exp uses the same rational form as the math references: tanh(n) = (e²ⁿ − 1) / (e²ⁿ + 1) (equivalently the (eⁿ − e⁻ⁿ)/(eⁿ + e⁻ⁿ) layout). Forward values and leaf gradients should match the fused tanh op up to floating-point noise — a strong correctness check.

Division: implement as a * b**(-1) once pow exists. Subtraction: a + (-1)*b. Implement __neg__, __sub__, and __rmul__ so literals like 2 * v work — Python tries v.__rmul__(2) when int.__mul__ fails.

Verifying: atomic tanh vs composite tanh should give identical forward values and leaf gradients (up to float noise). In PyTorch, scalar tensors with requires_grad=True mirror the same story; .backward() fills .grad.

Neuron, Layer, MLP

Neuron(nin) holds nin weights and a bias; __call__(x) returns tanh(w·x+b). Layer(nin,nout) is a list of independent neurons. MLP(nin, [n1,n2,...]) chains layers so each layer’s vector output feeds the next.

Shape story: an MLP pictured with three inputs, two hidden layers of four neurons each, and one output neuron is instantiated like MLP(3, [4, 4, 1]). Internally you maintain sz = [nin] + list(nouts) and create Layer(sz[i], sz[i+1]) for each consecutive pair. A convenience: if the last layer has exactly one neuron, return that scalar Value directly instead of a one-element list so call sites stay clean.

zip for the dot product: zip(w, x) pairs wᵢ with xᵢ. Sum wᵢ * xᵢ with a start value self.b so you do not initialize the accumulation separately — sum((wi*xi for wi, xi in zip(self.w, x)), self.b) in Python.

Add parameters() on each class returning a flat list of leaf Values — mirroring nn.Module.parameters() in spirit. Training loops iterate p.data -= lr * p.grad for each parameter.

Training the network

Pick a toy dataset — four planar points with binary targets in {−1, +1}. The network should learn to emit +1.0 on some corners and −1.0 on others (a tiny XOR-style classification lesson). Before training, forward passes might read roughly 0.91, 0.88, 0.80 on examples where you wanted negative outputs — clearly wrong but typical under random init.

Define loss as a single scalar scoring overall fit. A simple choice is sum of squared errors (related to MSE): for each pair (y_gt, y_pred), add (y_gt − y_pred)². Squaring removes sign disagreement and grows steeply when you are far off. When prediction equals target, that term is zero. A representative initial total might land near 7.12 once you sum all four contributions — dominated by the egregious mistakes, with almost-no loss on the one prediction already close to its target.

Calling loss.backward() paints gradients on every intermediate, including input coordinates. You usually ignore data gradients because examples are fixed; you care about weights. If a particular weight’s grad is negative, slightly increasing that weight decreases the loss at first order — that is the sign check people perform mentally before trusting an optimizer.

Before a step

Random weights produce biased outputs; loss is high (order ~7 in the canonical four-point demo, exact value depends on init).

After many steps

Predictions approach ±1; total loss can drop to ~1e−9 territory when the problem is easy and the step size is well behaved.

A concrete parameter count for the 3 → 4 → 4 → 1 MLP above is 41 scalar Values when you tally every w and b — tiny, but already unwieldy to differentiate by hand, which is why the graph machinery matters.

If you visualize draw_dot(loss) after forward-evaluating all four examples and summing their squared errors, the diagram explodes: it contains four full forward replicas of the MLP glued together under one loss node. That is “excessive” on purpose — it shows how a training step is literally one giant differentiable expression. In practice, million-point datasets use minibatches so each step forwards only a slice of data, but the autograd pattern is identical.

Each step: forward to compute L, L.backward() to fill grad, then update p.data += -lr * p.grad for every parameter p (minus because you minimize loss). Before the next backward(), reset p.grad = 0 for all parameters — otherwise gradients accumulate across steps.

Zero grad before backward: if you forget to clear grad, the second backward adds on top of the first. Always zero (or detach in frameworks) between optimization steps unless you intentionally sum gradients.

Why forgetting zero_grad can still “work” on toy data: every _backward uses +=, so stale gradients accumulate and act like an uncontrolled step size. On a tiny, easy dataset that can accidentally converge; on harder problems it usually breaks training.

Learning rate lr: too small → painfully slow progress; too large → oscillation or divergence (loss explodes or NaNs). This mirrors full-scale training, just easier to see in two dimensions.

Gradient descent interprets the gradient vector as pointing uphill on the loss. Minimization therefore steps opposite the gradient: p.data += -lr * p.grad (equivalently subtract lr * p.grad). A representative manual sequence might show loss moving 4.84 → 4.36 → 3.9 → … as you iterate forward → backward → update. Push lr too high and you can overshoot a valley; sometimes you recover, sometimes the loss blows up — tuning step size remains part art, part science, especially for plain vanilla SGD.

PyTorch tensors are the same autograd story at industrial scale: leaves with requires_grad=True, .backward(), and .grad — just packed into arrays and updated by fused kernels instead of Python floats. Chapter 2 walks through that translation.

Summary and real-world context

Neural nets are large differentiable expressions plus a loss. Backpropagation is automatic application of the chain rule backward through the graph. Gradient descent (or variants) steps parameters opposite the loss gradient to improve fit.

Value maps to a scalar PyTorch tensor with requires_grad=True; backward() and parameters() mirror the same ergonomics. Chapter 2 scales this to tensors, batches, and fused kernels — the autograd story is unchanged.

Next-scale topics (not required to grasp the core): batching, cross-entropy for classification, L2 regularization, learning-rate schedules, adaptive optimizers, mixed precision, etc.

At industrial scale the mechanism is unchanged: a forward graph, a scalar loss, reverse-mode AD, and parameter updates. Language models such as GPT family systems boil down to predicting the next token from context — billions or (in the largest public systems) hundreds of billions of parameters, trained with losses like cross-entropy rather than sum-of-squares on tiny toy grids — but it is still forward → backward → step at the logical level.

The public Micrograd repository mirrors this lesson in miniature: engine.py holds Value, backward, _prev, _op, and ops including a ReLU nonlinearity in the maintained code path. The walkthrough above stresses tanh because its smooth derivative exercises the chain rule nicely; ReLU, sigmoid, and tanh are interchangeable MLP nonlinearities in principle — pick one, implement forward and local backward, compose. A test harness in the project builds the same expression in Micrograd and PyTorch and asserts forward and backward agreement. A richer demo.ipynb shows batched points, a max-margin loss variant, L2 regularization, and learning-rate decay (shrinking step size late in training for finer fitting).
