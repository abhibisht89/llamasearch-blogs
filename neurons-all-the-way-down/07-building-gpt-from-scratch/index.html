00

Language models and probabilistic completion

A language model assigns probabilities to sequences of discrete units (words, subwords, or characters) and extends a prefix by sampling the next unit again and again. At core it performs conditional next-step prediction.

Because the next token is sampled from a distribution, the same prompt can yield different continuations. Ask twice for a haiku about why people should understand AI, and you might get two competent poems with different images and line breaks. That is not a bug: it is the defining behavior of a stochastic completer. The model defines P(x_{t+1} | x_1, …, x_t); it does not define a single canonical completion. Temperature, top-k, and nucleus sampling change how sharply you draw from that distribution.

P(sequence) = ∏t P(xt | x<t)

Key idea: A language model is a probabilistic engine over tokens. “Understanding” and “reasoning” emerge from compressing statistical regularities in training data into weights — the architecture we build here is the workhorse inside that story.

In production stacks, the same core is paired with retrieval, tool use, safety filters, and alignment stages. Here we focus on the decoder-only Transformer that performs the raw next-token prediction.

01

“Attention Is All You Need” and what GPT stands for

The Transformer architecture was introduced in the 2017 paper Attention Is All You Need (Vaswani et al.). On the page it can read like a specialized machine-translation system—and that was the original target: encode a source sentence and decode a translation. The same core—multi-head self-attention, position-aware embeddings, feed-forward sublayers, residuals, and depth—was reused with minor engineering tweaks in a huge fraction of later models.

GPT stands for Generatively Pre-trained Transformer: generative because it models the joint distribution of sequences; pre-trained because a large stage fits weights on broad text before task-specific adaptation; Transformer because attention blocks perform the heavy lifting.

The title’s “Attention Is All You Need” slogan highlights what changed relative to RNN-heavy stacks: attention is the primary routing mechanism that lets tokens exchange information across distance in parallel. The surrounding MLPs still matter—they are per-token computation after mixing—but the architectural bet is on attention as the workhorse.

Transformer core

Alternating communication (attention mixes positions) and computation (position-wise MLP thinks locally).

GPT family

Stacks those blocks in a decoder-only, left-to-right, causally masked form suited to open-ended generation.

Minor engineering details differ across years (activation, normalization placement, parameter sharing), but the blueprint you will code — embeddings, causal attention, FFN, residuals, depth — matches what scales to billions of parameters.

02

Tiny Shakespeare and character-level tokenization

We train on Tiny Shakespeare — about one million characters in a single input.txt file. Character-level tokenization (stoi/itos, vocab_size ≈ 65) follows the same pipeline as Chapter 02; here it is applied to one long concatenated corpus instead of per-name lines.

Production systems often use subword tokenizers (SentencePiece, tiktoken) to trade codebook size against sequence length. We stay character-level so Transformer mechanics stay transparent while the plumbing stays simple.

After encoding, split the tensor: first 90% train, last 10% validation. Training draws random chunks of length block_size (context length). With block_size = 8, a slice x[0], …, x[8] yields inputs X = x[0:8] and targets Y = x[1:9] — eight supervised next-character problems in one pass, calibrated for both short and long prefixes at generation time. Beyond block_size you must crop, because positional embeddings only cover indices 0 … block_size−1.

Stack batch_size independent chunks for GPU throughput: with batch_size = 4 and block_size = 8, you get X of shape (4, 8) and 32 independent predictions per forward pass. Batch rows never share attention edges.

03

Baseline: bigram model as an embedding lookup

The simplest neural language model scores the next token from the current token alone: nn.Embedding(vocab_size, vocab_size) indexed by id returns a row of logits. Chapter 02 derived the same idea as counts and gradients; here it is the baseline before adding context.

After reshaping to (B*T, vocab_size) for cross-entropy, the first random loss is about 4.87 with vocab_size = 65. Uniform guessing gives ln(65) ≈ 4.17; seeing 4.87 > 4.17 confirms the loss is wired correctly. Trained bigram runs on this corpus often land near val loss ≈ 2.5.

The shared generate routine feeds the full growing prefix even though only the last token matters for bigrams — one code path survives when self-attention is added later. Sampling uses the last time index’s logits, softmax, and torch.multinomial (one draw per batch row). A common starting token is integer 0, which in this encoding is typically the newline—a neutral way to begin “at the start of a line.” Before training, generations read as noise; after optimization they pick up bigram texture but remain globally incoherent.

Why this shape?

Input idx has shape (B, T). Embedding lookup yields (B, T, C) with C = vocab_size for the pure bigram parameterization. Those tensors are interpreted as logits for a categorical distribution at every position.

PyTorch detail: F.cross_entropy expects class dimension in a specific layout; reshape to (B*T, C) for logits and (B*T) for targets before the loss call.

04

Self-attention: queries, keys, and values

Before learned queries and keys, a useful warmup is causal averaging (sometimes described informally as a bag-of-words over the past): for each time t, replace the token vector with the mean of its own vector and all previous vectors. That coupling is extremely lossy—spatial order within the prefix is washed out—but it introduces the key implementation trick: a lower-triangular matrix of weights, row-normalized to sum to one, left-multiplies the sequence matrix so each row becomes a weighted sum of allowed predecessors. Plain matrix multiply with a mask of ones under the diagonal implements cumulative sums; dividing each row by its count implements cumulative means. PyTorch’s tril builds that mask; batched @ applies the same logic independently for every batch row.

To let positions communicate in a data-dependent way, each token builds three linear projections: a query q (“what am I looking for?”), a key k (“what do I contain?”), and a value v (“what do I broadcast if selected?”). Raw affinities are wei = q @ k^T with the last two dimensions transposed appropriately under a batch dimension.

Intuition: an eighth-position token might behave like a vowel that “asks” for consonantal evidence earlier in the prefix; if some channel in a key vector encodes “consonant in positions ≤4,” the dot product can spike and softmax will route a large fraction of mass to that key’s value vector. You aggregate v, not the raw token embedding x: think of x as private state, and v as the packet you agree to transmit to whoever finds you relevant.

Directed-graph view: attention is a communication mechanism on a graph. In autoregressive language modeling with eight slots, node 1 listens only to itself, node 2 to {1,2}, …, node 8 to {1…8}. Other tasks use other topologies: bidirectional encoder blocks (e.g. for sentence-level classification) omit the future mask so all nodes may attend to all nodes. Cross-attention is the general case where queries come from one stream and keys/values from another—as in encoder–decoder translation, where decoder queries read from encoder memory.

Worked micro-example (why tril + matmul = causal sums). Let B be a 3×2 matrix of token features. With a 3×3 matrix of all ones, the first row of the product is the column-wise sum across all three rows—e.g. first column 2+6+6 = 14 if that column is [2,6,6]^T, second column 7+4+5 = 16 if it is [7,4,5]^T. Replace the all-ones matrix by a lower-triangular mask of ones: row 1 selects only the top row of B; row 2 sums rows 1–2 (2+6 = 8 and 7+4 = 11 in this toy); row 3 sums all three (14 and 16). Renormalize each mask row to sum to one and those partial sums become causal means—the bag-of-previous-tokens construction, vectorized without a Python loop over time.

After a single head is wired with scaled dot-product, masked softmax, and values, training typically needs a lower learning rate than the bigram baseline.

05

Scaled dot-product attention

Attention(Q, K, V) = softmax(QKT / √dk) V

Dot products grow in variance with dimension. If q and k are roughly zero-mean, unit-variance per dimension, the dot product variance scales with head size d_k. Multiplying the logits by 1/√d_k restores unit-scale variance before the nonlinearity. That is the scaled in “scaled dot-product attention” from the paper.

Why care for softmax? Compare applying softmax to a nearly flat vector versus the same vector scaled by a large constant (say ×8). In the flat case you get a diffuse distribution; as magnitudes grow, mass collapses onto the argmax—approaching a one-hot. At initialization you do not want every token to listen to only one predecessor; you want broad, trainable mixing. Scaling keeps pre-softmax scores moderate so early training remains stable.

Dividing by sqrt(head_size) in code (e.g. head_size = 16 in a first head) is therefore not cosmetic—it is variance control feeding directly into the sharpness of attention weights.

You might wonder: is scaling optional? For toy dims it can seem fine; for width 64, 128, … it becomes essential for stable optimization at depth.

06

Causal masking and the wei matrix

Language modeling conditions on the past only. For position t, logits predicting token t+1 must not depend on tokens >t. A clean pattern: start from a lower-triangular scaffold, set entries where tril == 0 to negative infinity via masked_fill, then apply softmax along the key dimension. Future positions contribute exp(−∞) = 0. Before masking, raw wei may show positive and negative affinities between all pairs; the upper triangle is then disallowed.

It is common to name the pre-softmax affinity tensor wei while learning — think “weights” in gestation. Initialize it to zeros (before learned q/k) and uniform mixing appears; after learning, rows become sparse or peaked depending on context. After masked_fill and softmax, each row is a proper convex combination of past value vectors.

Attention has no built-in notion of “left vs. right.” Without positional encodings, permuting token order would yield the same pairwise attention structure up to permutation. Convolution, by contrast, bakes in locality on a grid. That is why we add token and position embeddings before attention: you must inject structural bias explicitly.

07

Softmax turns affinities into mixture weights

softmax(z)i = exp(zi) / Σj exp(zj)

Exponentiation emphasizes larger logits; normalization forces non-negative entries summing to one. Combined with causal masking, row t assigns zero mass to all future columns.

Concretely, softmax(z)_i = exp(z_i) / Σ_j exp(z_j). If all z_i are near zero, the outputs approximate a uniform distribution over the allowed (unmasked) entries. Multiply z by a large scalar and the largest coordinate hogs probability mass—useful to understand temperature in sampling, and useful to fear at the attention layer if pre-softmax logits are poorly scaled.

If logits are tiny, the distribution is diffuse (closer to uniform over allowed positions). If logits are huge, one entry dominates — a hard selection. Training nudges the network toward confident but not pathological peaks.

08

Multi-head attention: parallel heads, concatenate

A single head must compress everything into one subspace. Multi-head attention runs several attention operations in parallel with separate W_q, W_k, W_v projections, then concatenates along the channel axis and linearly mixes with an output projection.

In a compact educational setup with n_embd = 32 and four heads, each head often uses dimension 8 so that 4 × 8 = 32 channels match after concatenation—analogous in spirit to grouped filters in convolution: multiple independent communication pathways, each narrower, then fused. Different heads specialize to different relational patterns (local punctuation, vowel–consonant rhythm, longer-range line structure, etc.).

Single head

One routing pattern; simpler, fewer parameters per layer; can underfit rich syntactic/semantic patterns.

Multi-head

Multiple independent attention subspaces; analogous to grouped filters in CNNs; better capacity at similar total width.

09

Positional encodings: token + position embeddings

Self-attention is permutation equivariant on its own: it has no notion of left vs. right unless you inject positional information. Add a learned table position_embedding_table of shape (block_size, n_embd) to the token embeddings.

x = token_emb(idx) + pos_emb(0:T)

Broadcasting aligns (B,T,n_embd) with (T,n_embd). During generation, never feed more than block_size tokens without cropping, or indices exceed the position table.

It helps to introduce an intermediate width n_embd (for example 32 in a toy configuration) even before attention: token_embedding_table maps vocab_size → n_embd, and a separate lm_head linear maps n_embd → vocab_size to produce logits. For a pure bigram model, position embeddings carry no useful gradient signal (translation invariance), but the moment self-attention couples positions, those positional vectors become essential.

Attention is applied per batch index: you can picture batch_size disjoint graphs. With B = 4 and T = 8, you have four separate pools of eight nodes — no edges between pools. Batched matrix multiply is purely a performance convenience.

PE(pos, 2i) = sin(pos / 100002i/d)  PE(pos, 2i+1) = cos(pos / 100002i/d)

10

Feed-forward network (MLP) inside each block

After attention mixes information across positions, each position needs private computation. The Transformer block’s MLP applies the same two-layer network at every time step independently. A minimal first version is Linear → ReLU → Linear confined to per-token channels. The original Transformer diagram labels this “position-wise feed-forward network”; the paper’s prototype sizes used an inner dimension four times the model width (e.g. 512-dimensional residual vectors with a 2048-dimensional inner layer). Matching that 4× expansion in tiny models is a deliberate echo of the same compute pattern.

Loss checkpoint: moving from attention-only wiring to attention-plus-MLP on Tiny Shakespeare often shaves validation loss on the order of ≈2.28 → ≈2.24 under comparable training budgets—the generations still look rough, but the trend confirms that nonlinearity after mixing helps.

11

Residual connections and layer normalization

Residuals fork around sublayers: x = x + sublayer(ln(x)) in the common pre-norm arrangement. Skip connections let gradient flow directly through addition nodes, so early layers receive supervision even in deep stacks.

LayerNorm normalizes each token’s activations across the embedding dimension (see formula below). Unlike BatchNorm (Chapter 04), it needs no running statistics and behaves the same at train and test time — which is why Transformers use it by default.

LN(x) = γ ⊙ (x − μ) / √(σ² + ε) + β  (per token, μ, σ over embedding dim)

Post-LN vs pre-LN: the original “Attention Is All You Need” figures place “Add & Norm” after the sublayer. Many contemporary decoder stacks (including GPT-style training recipes) apply LayerNorm before attention and before the MLP—the pre-norm variant. Same modules; different wiring. Pre-norm tends to optimize more smoothly when depth grows.

Loss checkpoint: after pre-norm LayerNorm inside each block plus a final ln_f before lm_head, validation loss on Tiny Shakespeare often lands near ≈2.06 before aggressive scaling — down from roughly 2.28 at the first architectural additions. The win grows more pronounced as width and depth increase.

Stacking blocks: n_layer depth

Repeat the block n_layer times via nn.Sequential or ModuleList. Depth increases receptive field through repeated mixing: later layers indirectly integrate information from farther away, bounded by context length block_size.

Width (n_embd), depth (n_layer), heads, and FFN expansion together determine parameter count and compute.

14

Dropout as regularization

nn.Dropout(p) randomly zeroes a subset of activations (or attention weights) on each forward pass during training. The mask changes every step, which effectively trains a mixture of many “thinned” sub-networks; at evaluation time dropout is disabled so those sub-networks are averaged in expectation. The technique originates in the mid-2010s literature on regularizing large nets by breaking co-adaptation.

Typical placements in a decoder block: on attention probabilities after softmax, on the attention output after the output projection, on the residual path back into the trunk, and inside the MLP. For Tiny Shakespeare, once you widen and deepen the model, dropout with p ≈ 0.2 (20% of the nominated activations dropped per pass) is a practical default when you fear overfitting to a one-megabyte corpus.

Full GPT module: embeddings, blocks, final norm, LM head

logits = lm_head( ln_f( blocks( token_emb(idx) + pos_emb(0…T−1) ) ) )

The class holds token_embedding_table, position_embedding_table, a sequence of Block modules, final ln_f, and lm_head mapping n_embd → vocab_size. Some implementations weight-tie the token embedding with lm_head to save parameters; pedagogical code often keeps them separate for clarity.

A representative “small but serious” Shakespeare run uses on the order of ten million parameters—large enough to show structure, tiny by production standards. The reference educational stack that hits validation loss ≈ 1.48 after scaled training often sets batch_size = 64, block_size = 256 (256 characters of context to predict the 257th), n_embd = 384, n_head = 6 (so head dimension 384/6 = 64), n_layer = 6, AdamW with a reduced learning rate as the model grows, and dropout = 0.2. On a high-end GPU (e.g. A100-class), that training might complete in on the order of fifteen minutes; on CPU or small laptops you should shrink depth and width first.

16

Training loop on Shakespeare

Sample random chunks of length block_size from the train split. Inputs x are characters 0…T-1; targets y are the next character at every position (offset by one inside the chunk). A batch stacks independent sequences along dimension B.

Optimizer is commonly AdamW. A useful default for many Transformer language-model runs is learning rate ≈ 3×10⁻⁴, but you must retune as depth and width grow—self-attention stacks are less tolerant of aggressive steps than a lone embedding table. Move tensors and modules to cuda when available so embedding lookups and batched matmuls run on the accelerator.

Printing loss.item() every step is misleading: each minibatch is a noisy draw. Instead, periodically call an estimate_loss helper that switches the model to eval(), runs eval_iters batches on both train and validation splits with torch.no_grad(), averages cross-entropy, then returns to train(). Even when eval() is a no-op (pure embedding table), that pattern is worth keeping because dropout and similar layers behave differently across modes.

Loss trajectory on Tiny Shakespeare (representative educational run). Numbers depend on seeds and steps, but the following plateaus are the ones to anchor intuition: bigram trained ≈2.5 validation loss; single-head scaled causal attention ≈2.4 (a real improvement over 2.5, but text still weak); multi-head attention ≈2.28; + position-wise feed-forward MLP ≈2.24; + residual connections with a 4× inner FFN ≈2.08 (train loss may dip below validation—early overfitting); + pre-norm LayerNorm in blocks and final norm ≈2.06; after scaling width/depth/context (six layers, 384 channels, 256 context, six heads, dropout 0.2, larger batch) validation loss near 1.48, down from roughly the low 2.0s before that scale-up. Initial bigram cross-entropy before training is about 4.87 with 65 classes versus a uniform baseline of ln(65)≈4.17.

17

Generating text autoregressively

Start from a context tensor idx of shape (B,T). Repeat: forward pass with targets=None, take logits at final time, apply softmax, sample (multinomial or top-p), append sampled id, crop the sequence to at most block_size tokens from the end if needed, then concatenate along time. Cropping matters because learned positional embeddings only cover indices 0…block_size−1; feeding longer streams would index past the table.

Training taught a distribution; generation is sequential draws from the learned conditionals — not retrieval from the corpus, though small models partially memorize. For inspection, dumping tens of thousands of characters to a file makes the rhythm obvious: line breaks and speaker-like phrasing emerge long before coherent plot.

Sample flavor at ~1.48 val loss (character Shakespeare): locally the text mirrors punctuation, capitalization, and clause length of the training file, yet long-range sense remains absent—lines such as fragmented stage speech (“…every crimp tap be a house…”) illustrate the gap between statistical texture and understanding.

18

Encoder vs decoder transformers

Encoder (bidirectional)

No causal mask: every token may attend to every other token. Useful when the full input is observed at once (classification, encoding for retrieval).

Decoder (causal)

Lower-triangular mask preserves autoregressive factorization; suitable for generation and language modeling.

Encoder–decoder models (original translation setup) use an encoder stack to build representations of a source sentence and a decoder stack that attends cross to encoder states while masking its own future. Cross-attention uses queries from the decoder and keys/values from the encoder.

Our Shakespeare model is decoder-only like GPT — no separate encoder because there is no external conditioning signal beyond the growing prefix.

Machine translation needs to read a source sentence in full (French tokens, say) while writing English left-to-right. The encoder stack applies bidirectional self-attention without a causal mask so every source token can attend to every other source token; the decoder stack keeps the triangular mask for autoregressive generation and adds cross-attention layers where queries come from the decoder states and keys/values come from encoder outputs. Unconditional character modeling has no parallel source stream — only one tape of text — so the encoder and cross-attention blocks disappear. What remains is a decoder-shaped stack that models the training distribution, which is exactly the GPT family recipe.

19

Connection to GPT-2 and GPT-3 scale

Architecturally, a frontier decoder-only Transformer resembles what you coded: pre-norm, multi-head causal attention, MLP expansion ~4×, residuals, dropout, final layer norm, linear logits. What changes is scale: embedding dimension in the thousands, dozens of layers, dozens of heads, context windows in the thousands to hundreds of thousands of tokens after modern extensions.

The Shakespeare exercise lands near ~10⁷ parameters on ~10⁶ character tokens—roughly 300k subword tokens if you imagined packing the same corpus with a ~50k OpenAI-style vocabulary. GPT-3’s largest reported model is on the order of 175×10⁹ parameters trained on hundreds of billions of tokens (the GPT-3 paper highlights ~300B tokens in its largest regimes). That is roughly a million-fold data increase relative to the toy corpus, and parameter counts can span four to six orders of magnitude depending on how you count—before even reaching contemporary trillion-token schedules.

Training stacks of that size are an infrastructure problem: thousands of GPUs, checkpointing, distributed data loading, and careful learning-rate schedules. The reference nanoGPT-style codebase keeps the same mathematical skeleton in roughly two files of ~300 lines each—one for the model, one for the training loop—while scaling the loop to checkpoint resume, learning-rate decay, compilation, and multi-GPU distribution. On datasets such as OpenWebText, that minimal stack is enough to reproduce behavior of the smallest public GPT-2 checkpoint (~124M parameters) and verify correctness against released weights. Production versions swap toy ReLU MLPs for GELU activations to match OpenAI checkpoints byte-for-byte when loading state dicts. The conceptual map from the model you built here to those files should read almost line-for-line.

Parameter counts move from millions in toy runs to billions (GPT-2–class models) and hundreds of billions (largest GPT-3–class models on release). Compute shifts from minutes on one GPU to weeks on clusters.

Pre-training vs. assistants: The decoder-only stage produces a document completer: it continues whatever prefix looks like the training mixture—questions with more questions, half-finished blog posts with more blog post, etc. Turning that into a helpful assistant is a separate fine-tuning story: (1) supervised fine-tuning on curated prompt–answer pairs so the format looks like a user message followed by an assistant reply; (2) preference collection where human raters rank multiple model samples; (3) training a reward model to predict those preferences; (4) reinforcement-learning-style policy optimization (policy-gradient methods such as PPO) to steer generation toward higher reward. Much of that data and infrastructure is proprietary, but the pre-training core you built is stage zero of the pipeline.
