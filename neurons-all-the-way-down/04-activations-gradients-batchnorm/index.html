Recap: Bengio-style MLP, ~11K parameters, loss near 2.16

We continue the same character-level Bengio-style MLP from the previous chapter (~11K parameters, validation loss near ~2.16) — a tiny model that already exposes the scale and saturation problems this chapter fixes.

Sanity check: at initialization, if logits are well behaved, the negative log-likelihood should be close to -log(1/27) ≈ 3.30, not 27 or ∞. Giant initial loss usually means the softmax is confidently wrong, not that the task is harder.

𝔼[ NLL at uniform guesses ] = −log(1/V)   (V = vocabulary size, e.g. 27)

The running example uses on the order of 32,000 name-like strings; the notebook prints a handful (eight) as a sanity preview. Optimization can run for 200,000 update steps with batch size 32 — shallow enough that sloppy initialization still “eventually works,” but noisy enough that the early loss curve tells a story.

On iteration zero, a badly scaled head can report a loss on the order of 27 for a 27-way problem. That is not “the task got harder”; it is almost always confident wrongness in the softmax. The target for a near-uniform predictive distribution is −log(1/27) ≈ 3.29 (tiny differences from 3.30 are rounding). Shrinking W2 pulls logits toward zero: scaling by 0.1 might still leave you around 4.2 NLL on the first step, while 0.01 lands near 3.32 — close enough that training spends its budget on the model rather than on squashing logits.

Uniform softmax without all-zero logits: if every logit is the same constant (e.g. all ones), softmax still returns a uniform distribution because only differences matter. By symmetry we still initialize near zero for convenience. Setting W2 exactly to zero would give a perfectly flat start but removes diversity; a tiny random break in scale keeps symmetry breaking live.

In a toy vocabulary of four symbols, logits near zero give a perfectly diffuse softmax; the NLL for any label index is 1.38 — the same number whether the true class is 0, 1, 2, or 3. Push logits to more extreme values and one bucket tends to dominate incorrectly, inflating loss; push them toward infinity and numerical issues can blow up to effectively infinite loss at initialization.

After fixing the head, train and validation loss in the reference run often sit near 2.16. The loss curve’s hockey stick — a steep early drop followed by slower progress — is the telltale signature of the optimizer first crushing overconfident logits before it rearranges predictions to fit the data. Removing that pathology reallocates steps to “real” learning.

Wrapping evaluation in @torch.no_grad() (or with torch.no_grad():) tells PyTorch not to build the autograd graph for that code path — faster, less memory, appropriate whenever you are only measuring loss or sampling.

01

Why study activations and gradients before RNNs?

Recurrent models (and their gated relatives) are staggeringly expressive: in principle they are universal approximators. The painful part is not representational power but optimization — first-order methods such as SGD and Adam wander a landscape shaped by repeated composition, repeated nonlinearities, and long credit-assignment paths.

If you do not know what hidden pre-activations look like, what saturated tanh does to backward signals, or why fan_in appears under a square root, RNN training will feel like arbitrary wizardry. The shallow MLP is the cleanest microscope: all the same mechanisms appear — just with fewer places for error to compound.

Expressivity

RNNs can represent complex temporal maps; depth-through-time stacks many nonlinear layers when unrolled.

Optimization

Gradients can vanish or explode across time steps; activation statistics drift; careful init and normalization become essential.

Historically, practitioners had to babysit activations and gradients with almost painful care — histograms, gains, and nonlinearity-specific scaling. Residual connections, normalization layers (batch, layer, group, instance), and optimizers beyond vanilla SGD — RMSprop, Adam, and their descendants — greatly widened the basin of “good enough” initialization. None of that removes the value of the shallow MLP microscope: the same failure modes still exist; they simply compound when depth and recurrence enter the picture.

First forward pass: what hides inside h?

Flattened embeddings feed a linear map h_preact = embcat @ W1 + b1, then h = torch.tanh(h_preact). The loss only talks to the head, but learning in W1 must backpropagate through tanh. If h is mostly pinned to ±1, most hidden units sit in flat regions where small input changes barely move the output — and backward signals shrink accordingly.

Concrete shapes from the reference setup: with batch size 32 and 200 hidden units, h is a 32×200 tensor. Histograms are easier to read after h.reshape(-1) (or equivalent) to a single vector of 32 × 200 = 6,400 scalars, then tolist() for Matplotlib. The pre-activation tensor has the same shape before the nonlinearity squashes each element into (−1, 1).

03

tanh saturation and “dead” behavior

For output t = tanh(x), the local derivative is 1 − t². When t → ±1, that factor → 0: upstream gradients are multiplied by nearly zero, so updates to earlier weights slow dramatically. Intuitively, in the tail the curve is flat — nudging inputs barely moves outputs, so the loss is locally insensitive.

Tracing the chain rule the way we did for micrograd-style autodiff: backward through tanh multiplies the incoming adjoint by 1 − t² where t is the forward output. If t = 1 or t = −1, the local Jacobian is zero and no upstream signal reaches x, no matter how large ∂L/∂t might be. At t = 0, the local factor is one, so the gradient passes through unchanged — the unit is in its most “active” region. Between those extremes, the factor is always at most one; moving deeper into the tails monotonically attenuates backward flow, with the attenuation growing like the square of how close |t| is to one.

d/dx tanh(x) = 1 − tanh²(x)    (chain rule multiplies this into ∂L/∂x)

Dead neurons (informal): a unit is effectively “dead” if it never leaves a bad region — for tanh, stuck in saturation; for ReLU, never activating so the slope is identically zero. If an entire column across the batch saturates the same way, that feature may never receive useful credit assignment.

Picture the boolean mask as a 32×200 grid: rows are examples, columns are hidden units — white for saturated positions, black for steep ones. A column that is white for every row is pathological: that neuron presents zero slope to the backward pass for the whole batch.

The same “killed backward signal” story applies to sigmoid tails for the same geometric reason: squashing onto a bounded interval creates flat regions. For ReLU, the dead region is not a tail but the entire negative half-line, where the derivative is exactly zero rather than merely tiny. A ReLU that never fires for any training input never receives gradients — weights and bias for that unit freeze. That can happen at init by bad luck, or during training if a large update “knocks” a unit off the data manifold so nothing ever activates it again — sometimes described informally as a form of permanent damage to a slice of the network. Leaky ReLU-style nonlinearities leak a small slope on the negative side, so you almost always get some gradient; ELU can still have flat pieces worth watching.

A useful diagnostic masks positions where |h| > 0.99. Lots of white pixels means many examples sit on the flat tails. The network may still train if every neuron occasionally lands in the active region, but learning is slower and noisier than necessary.

Histograms: seeing the distribution, not just the tensor

Raw tensor printouts hide structure. A histogram of h reveals whether mass clusters at the rails. Matching plots for h_preact explain why: if pre-activations span a wide range (say −5 to 15), tanh has already decided most signs and magnitudes.

In the unfixed reference run, pre-activations commonly land in a band like about −5 to about +15 while post-tanh values pile up near −1 and +1. Hand-scaling W1 (and shrinking b1) pulls that cloud inward: after multiplying weights by 0.1, a typical batch might show pre-activations roughly in [−1.5, 1.5], the saturation mask can go completely dark (no |h| > 0.99), and optimization becomes materially more efficient. Tweaking toward 0.2 by eye trades off a bit more spread against still-reasonable tail mass.

Deeper stacks use stricter saturation metrics too: when you instrument many tanh layers in a single forward pass, tracking the fraction with |t| > 0.97 (instead of 0.99) can better match how quickly derivatives die in the shoulders of the curve. The qualitative story is unchanged: you want most mass away from the rails so both forward dynamics and backward Jacobians stay informative.

Weight initialization: fan_in and Kaiming scaling

Fan-in is the number of inputs contributing to each neuron’s dot product — for W1, that is block_size * n_embd (e.g., 3×10 = 30), not just n_embd. Each output is a sum of fan_in weighted inputs; variances add, so without scaling the standard deviation grows roughly with √fan_in.

A minimal linear algebra experiment makes the scaling visceral. Take X ∈ ℝ^{1000×10} with entries drawn from a standard normal, and W with the same shape convention as a single linear map so each of the 200 hidden neurons looks at 10 inputs (the demo’s toy fan-in). If entries of W are also standard normal, the per-neuron pre-activations (dot products) need not stay 𝒩(0,1): empirically the standard deviation of those scalars inflates from input scale 1 to output scale about 3 before any correction. Multiplying W by 5 pushes variation harder (roughly 15 in that demonstration); scaling by 0.2 shrinks it (roughly 0.6). The variance-preserving choice for this linear map is to divide by √fan_in; with fan_in = 10, that means scaling by 1/√10 = 10^{-0.5}, which lands the empirical standard deviation back near one.

To keep pre-activations near unit scale, draw weights from a zero-mean distribution whose standard deviation is proportional to 1/√fan_in. Kaiming He and co-authors analyze this deeply in Delving Deep into Rectifiers, focusing on ReLU / PReLU families in convolutional stacks. Their forward-pass analysis motivates initializing Gaussian weights with standard deviation √(2/fan_in) for ReLU — the extra factor of 2 compensates for zeroing half the pre-activation mass. They also study backward propagation and find that a careful forward scaling keeps backward statistics in a sane regime up to modest depth-dependent constants; empirically the exact fan-in versus fan-out choice matters less than getting the order of magnitude right.

PyTorch’s kaiming_normal_ encodes this story: nonlinearity='relu' uses gain √2; 'linear' uses gain 1; 'tanh' uses gain 5/3. Intuitively, tanh is contractive: like ReLU clipping negatives, it squeezes tails toward the interior of (−1,1). The gain boosts linear pre-activations slightly so that, after the squashing, activations still occupy a Gaussian-ish operating range rather than collapsing toward zero variance.

σ ≈ gain / √(fan_in)    (Kaiming normal, fan-in mode)

For the character MLP, fan_in on W1 is 30 (three embedded characters, each of dimension 10), not 10. Hand tuning by staring at histograms might land near scaling W1 by about 0.2; the Kaiming formula (5/3)/√30 is in the same ballpark (≈0.30) without eyeballing plots. Training with that principled scale reaches essentially the same validation loss (about 2.10) as the hand-picked scalar — the win is portability to wider and deeper nets.

Depth magnifies small mistakes: a fifty-layer feedforward network can fail outright when each layer multiplies Jacobian norms the wrong way, even though shallow nets forgive sloppy scales. Residual wiring, batch or layer normalization, and adaptive optimizers widened what “works,” but pre-activation variance, local derivatives, and how they compound still explain why those fixes help.

Batch Normalization (Ioffe & Szegedy, 2015)

    
BatchNorm entered practice from a 2015 Google research effort (Sergey Ioffe and Christian Szegedy) and quickly became one of the most reliable tools for training deep convolutional and feedforward models. The core empirical observation is easy to state: many networks benefit if hidden activations behave like well-scaled, approximately Gaussian signals — not so tiny that nonlinearities are inert, not so huge that saturating squashing kills gradients.

    

      
Ioffe and Szegedy write: “We refer to this phenomenon as internal covariate shift, and address the problem by normalizing layer inputs.” The preceding sentences in the same passage emphasize that, during training, each layer sees inputs whose distribution moves as earlier layers change — which tends to demand smaller learning rates, careful initialization, and makes saturating nonlinearities harder to optimize. Batch normalization targets that moving distribution directly.

    

    
BatchNorm standardizes activations using statistics computed across the batch (for each feature channel), then applies learnable scale and shift. The operation is differentiable end-to-end, so gradients tune not only weights but also how aggressively each unit re-centers and rescales its inputs.

    
The “mind-blown” implementation detail is that standardizing activations is a smooth, differentiable transformation of tensors. You are allowed to subtract a batch mean and divide by a batch standard deviation inside a model trained with backprop — nothing here is a discrete decision rule. The subtlety is that always enforcing exact unit Gaussian behavior would rob the network of representational freedom; that is why the paper pairs normalization with scale and shift parameters.

    
x̂ᵢ = (xᵢ − μB) / √(σ²B + ε)    yᵢ = γ x̂ᵢ + β

    
Here μB and σ²B are the batch mean and variance (per neuron). The reference implementation follows the paper’s convention of tracking running variance, not running standard deviation, under the hood — squaring and square-root relate the two, but the buffer semantics match the variance form. γ (weight in PyTorch BatchNorm1d) and β (bias) start near 1 and 0 so the layer begins life close to pure standardization.

    
Worked on paper for a batch of shape 32×200: for each of the 200 neurons, compute the mean across the 32 examples — a vector shaped 1×200 if you use keepdim=True along dimension 0. Compute the variance the same way (conceptually, average squared deviations from that mean). After normalization, within this batch, each neuron’s 32 values have zero mean and unit variance before γ, β. That per-batch constraint is why the method carries the word batch in its name.

Where to sit BatchNorm in the block: the most common pattern is Linear → BatchNorm → tanh (or Conv → BatchNorm → ReLU in vision). Practitioners have also experimented with normalization after the nonlinearity with similar empirical success in some settings; the lesson is that the invariant is controlled scale entering the next affine map, not a religious rule about which side of the squashing nonlinearity must host the statistics.

    
On the single-hidden-layer name model, validation loss with manual batch normalization lands around 2.10, essentially matching a well-tuned initialization without BN — expected, because you can still analytically set one layer’s scales. The payoff appears when depth, residual wiring, and heterogeneous blocks make closed-form scaling intractable; then “sprinkling” normalization after every matmul-like op is engineering time better spent than chasing per-tensor magic numbers.

Normalize, then scale (γ) and shift (β)

    
Pure standardization would force every neuron’s batch statistics to mean=0, var=1 — too rigid. The network may need a different operating point. Trainable γ and β restore expressivity: the layer can undo or reshape normalization when that helps the loss.

    
Optimization may want a sharper or more diffuse firing pattern for some units — some hidden features “trigger-happy,” others reluctant — even if the pre-normalized batch statistics drift. The affine parameters let SGD discover that: γ rescales the normalized channel; β recenters it. Include bn_gain and bn_bias in the parameter list passed to the optimizer alongside weights; they receive gradients every bit as legitimate as entries of W1.

Training vs inference: batch stats vs running averages

    
Training: use the current minibatch mean and variance — fast, noisy, couples examples in the same forward pass. Inference: you often want a deterministic map for a single example. The standard fix maintains running estimates of mean and variance updated during training (exponential moving average), then swaps them in when model.eval() is set.

    
running ← (1−m)·running + m·batch_stat

    
PyTorch’s momentum argument relates to how aggressively each step replaces the running estimate; tiny batches sometimes need gentler updates than large ones because batch statistics are high-variance.

    
A conceptually clean two-stage approach — train, then calibrate by scanning the entire training set once under torch.no_grad(), collecting per-neuron means and variances of pre-activations, and freezing those numbers for deployment — matches the story on paper. Almost nobody wants a separate calibration pass in production pipelines, which motivated online trackers. A manual EMA might look like running ← 0.99 · running + 0.001 · batch_stat: almost all mass on the old estimate, a tiny nudge from each new minibatch. Those buffers are not optimized with gradient descent; wrap their updates in no_grad so PyTorch does not build gigantic graphs for bookkeeping tensors that never receive a backward signal.

    

      

        
PyTorch default momentum ≈ 0.1

        
Works well when batch statistics are already low-variance — for example, large minibatches where mean and variance estimates do not thrash step to step.

      

      

        
Small batches (e.g. 32)

        
Noisier batch moments may need a smaller effective step on the running buffers (closer to the 0.001 illustration) so the EMA converges toward dataset-level statistics instead of chasing sampling noise.

      

    

    
Initialize running mean near zero and running variance near one when earlier layers already produce roughly unit-variance Gaussians at startup — that matches the typical default story and avoids a cold-start bias.

    
eps defaults to about 1e-5 — the same small constant added inside the square root so division never sees a hard zero variance. affine=True keeps the trainable γ, β; turning it off is rare. track_running_stats=True enables the running buffers updated during training; set it False only if you intentionally plan to estimate population moments in a separate calibration pass and do not want the module to maintain EMA state you will discard.

Why BatchNorm helps optimization

    
By keeping intermediate activations near a Gaussian-ish operating region, BN reduces internal covariate shift — the tendency of layer inputs to drift as earlier parameters move. Nonlinearities like tanh behave more predictably when inputs sit near their steepest slopes rather than deep in the tails.

    
For a shallow net you can sometimes hand-tune 1/√fan_in scaling so BN adds little marginal gain. For deep stacks mixing convolutions, skip connections, and heterogeneous blocks, sprinkling normalization after affine layers is far easier than a global closed-form scale for every tensor.

    
Before batch normalization, a minibatch was just a parallelization trick: each example could have been processed independently. With BN, the normalized values for example i depend on which other indices landed in the same minibatch — re-sample the batch and the logits jitter slightly even when example i is unchanged, because the mean and variance estimators move. That batch coupling often acts like mild implicit regularization, which is one reason alternatives (layer norm, instance norm, group norm) exist for settings where decoupled per-example dynamics matter more.

    

      
Biases before BN: a linear bias added immediately before mean-centering is often redundant — subtracting the batch mean cancels constant offsets. Common pattern: Linear(..., bias=False) followed by BatchNorm, letting β handle shifts.

    

    
In a bare manual implementation, if you keep b1 in h_preact = x @ W1 + b1 and then subtract the per-column batch mean, the constant bias cancels identically from the centered activations. b1.grad can sit at zero forever — not catastrophic, but wasteful. Prefer moving “where should this feature sit?” into β (and deleting the linear bias) when a BN block follows immediately.

    
The coupling is entangled with why BN helped historically: stabilization plus implicit regularization made it stubbornly strong on convnets. Modern research often prefers decoupled norms for small batches or sequence models, but the BN trade-off — mathematical ugliness versus reliable depth — shaped a decade of engineering defaults.

Gradient flow: too small, too large, and depth

    
Backward mode multiplies Jacobians along the path from loss to parameters. Factors repeatedly below 1 shrink signals (vanishing); factors above 1 amplify them (exploding). Saturated tanh supplies tiny local derivatives; poorly scaled matrices can magnify variance layer-to-layer.

    

      
Vanishing gradients: early layers receive negligible updates — the model “stops listening” to distant supervision. Exploding gradients: updates overshoot; loss spikes unless you clip, reduce learning rate, or fix scaling.

Diagnostics beyond a single scalar norm

    
When you stack multiple Linear → (BatchNorm) → tanh blocks into a six-layer network with on the order of 46,000 parameters, it pays to plot histograms of forward activations at every tanh output, histograms of backward gradients flowing into those tensors, and finally histograms of the weight tensors themselves. Color-code layers so you can see whether deeper blocks shrink toward zero, explode outward, or develop asymmetric tails.

    
For each tanh output T, track mean, standard deviation, and a saturation rate defined as the fraction of entries with |T| > 0.97 (a slightly looser threshold than the 0.99 mask used earlier, tuned for reading depth-stacked behavior). With Kaiming-style gain 5/3 on the linear maps, a typical picture is: the first tanh still shows visible tails (on the order of 20% “saturated” by the 0.97 rule), then deeper layers settle to a steadier Gaussian-ish bulk with standard deviation near 0.65 and saturation near 5% — a comfortable operating zone.

    

      

        
Gain too small (e.g. 1.0 without compensation)

        
Activations shrink toward zero layer by layer; backward gradients can develop an odd expanding shape — neither forward nor backward statistics match across depth.

      

      

        
Gain too large (e.g. 3.0)

        
Saturation percentages blow up; gradients show asymmetry across layers as some blocks live almost entirely in flat tanh tails.

      

    

    
Remove every tanh but keep an inflated gain like 5/3 and you are left with a deep purely linear sandwich. The forward map still collapses to a single effective linear transformation — arbitrarily many Wx + b compositions re-express as one matrix multiply plus one bias — so representational power does not grow with depth. Interestingly, training dynamics need not match a one-layer network with the same forward map: the parameterization and chain rule carve different optimization trajectories; there is active literature on linear networks with exotic depth. Nonlinearities exist precisely to break that collapse.

    
Also inspect gradient magnitude versus parameter magnitude. A useful raw ratio is std(grad) / std(weight). In a well-scaled run, gradient entries can be on the order of 1/1000 of the corresponding weight entries for many layers — except the last linear layer, which often shows gradients roughly ten times larger than the earlier hidden matrices at initialization because the head was deliberately shrunk (W2 *= 0.01) to keep softmax diffuse. That mismatch means vanilla SGD would update the head roughly 10× faster than the trunk unless you compensate with parameter-wise learning rates or a fancier optimizer.

    
More predictive than gradient-to-data alone is update-to-data: for each tensor, compare the standard deviation of the proposed SGD step −η · grad to the standard deviation of the tensor values. Track log₁₀ of that ratio across iterations. A coarse target is around 10⁻³ — parameter steps whose scale is roughly a thousandth of the existing parameter scale. If the log curve hovers near −2.5, updates are a bit aggressive but can still stabilize; if you drop the learning rate to 0.001 in an illustrative experiment, the same plot screams under-training — updates become ~1/10000 of the parameter scale. Forget 1/√fan_in scaling entirely and the activation, gradient, weight, and update panels all go haywire: saturation spikes, asymmetric depth profiles, and update ratios orders of magnitude away from the 10⁻³ heuristic (values like 1.0–1.5 on the log scale appear).

    

      
BatchNorm as a robustness knob (deep stacks): insert BatchNorm1d between each linear map and its tanh, set bias=False on the linear layers, and forward activations become homogeneous by construction — standard deviation ~0.65, saturation ~2–5% at every depth. You can even crank linear gains to values like 2.0 that would have been absurd without normalization: the normalized pre-tanh cloud barely moves, while update statistics still shift because BN’s backward pass rescales gradients. Removing fan_in scaling entirely under BN can still yield sane forward/backward histograms but often drives update ratios far below the 10⁻³ band — a sign you should raise the learning rate (sometimes by ~10×) rather than celebrate a free lunch.

Xavier / Glorot vs Kaiming in one glance

    
Xavier/Glorot initialization targets variance preservation for linear activations (or symmetric saturating nonlinearities under certain assumptions), often using fan_avg = (fan_in + fan_out)/2 in the denominator. Kaiming/He initialization explicitly models ReLU-style half-wave rectification and uses fan_in with a nonlinearity-dependent gain.

    
Xavier uniform: U[−a, a],   a = √(6 / (fan_in + fan_out))

    
Kaiming normal: W ~ 𝒩(0, σ²),   σ = gain / √(fan_in)

    
    
      
  • gain(ReLU) = √2, gain(tanh) = 5/3, gain(linear) = 1 in PyTorch’s lookup table.
    • 
      
  • Default nn.Linear uses a uniform scheme scaled like 1/√fan_in — same spirit, different constants.
    • 
    

    
PyTorch’s built-in nn.Linear initializes weights uniformly in [−1/√k, +1/√k] with k = fan_in — Gaussian versus uniform is not the important part; the 1/√fan_in width is. There is no automatic 5/3 boost in that default: you add Kaiming initialization explicitly when the following nonlinearity is contractive. The origin of the 5/3 constant for tanh is easy to take on faith from PyTorch’s tables; empirically it balances a repeated linear → tanh tower, but it is not as transparently derivable as the ReLU factor of 2 inside √(2/fan_in).

    
nn.Linear default (uniform):   Wij ~ U(−1/√fan_in, +1/√fan_in)

  






  

    12
    
Residual connections (preview)

    
Very deep feedforward stacks suffer from optimization friction: each layer must learn to approximate small perturbations to an identity map. Residual networks add skip connections so layers learn residuals f(x) atop x, easing gradient highways and softening vanishing effects.

    
y = x + F(x)   (shape-compatible skip + block output)

    
Modern CNN templates (e.g., Conv → BatchNorm → ReLU, repeated) mirror the MLP pattern: affine → normalize → nonlinearity, now with shortcuts threading depth. We will unpack convolutions and full residual blocks later; for now, view skips as complementary to good init and BN.

    
Open-source ResNet implementations (search “ResNet PyTorch torchvision”) show the same motif in production code: a convolution, a BatchNorm2d, a ReLU, another convolution, another batch norm, another ReLU, and only then the residual add. Convolution is “structured” linear algebra — still a weighted sum of inputs with learnable coefficients, but shared across spatial patches. Notice bias=False on those convolutions whenever batch norm follows: the affine shift lives in BN’s β instead of duplicating a bias that mean-centering would erase.

Putting it together

    
Stable training is rarely one trick. It is consistent scales at initialization (so softmax is not absurdly confident), nonlinearity-aware variance scaling via fan_in, and — when depth demands it — normalization that keeps tensors in a benign statistical regime. Together they prevent wasted early iterations on “squashing logits” and keep backward signals informative.

    
Concrete validation anchors from the same experimental thread: starting from about 2.17 before fixes, shrinking the output head and taming logits lands near 2.13; fixing hidden-layer saturation (hand scale or Kaiming) lands near 2.10; adding batch normalization to the shallow model returns essentially the same 2.10 ballpark because the network was never optimization-limited — the bottleneck is representational (context length three predicting the fourth character), not gradient noise. Pushing perplexity further requires richer models (recurrence, attention, longer context), not another normalization layer on this tiny MLP.

    

      
Optional BN placement at the output: some pipelines place batch norm after the final linear map and before the loss. Then the “softmax temperature” role played by shrinking W2 can migrate into the BN scale parameter γ instead of the raw weights — same idea, different knob.
