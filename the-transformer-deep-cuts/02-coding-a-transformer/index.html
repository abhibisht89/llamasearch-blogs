Roadmap: tensors, masks, and a trainable seq2seq stack

This chapter follows the same implementation arc as a from-scratch PyTorch translation system: you map parallel sentences to tensors, build an Encoder that sees the full source with a padding mask, and a Decoder that predicts Italian tokens left-to-right with a causal mask plus cross-attention into encoder memory. Every shape comment below uses (batch, seq, d_model) unless noted.

Model core

InputEmbeddings, PositionalEncoding, LayerNormalization, FeedForwardBlock, MultiHeadAttentionBlock, ResidualConnection, EncoderBlock, DecoderBlock, ProjectionLayer, and the composite Transformer with encode / decode / project.

Training loop

Opus Books via load_dataset, word-level tokenizers, BilingualDataset with <sos>, <eos>, <pad>, Adam, cross-entropy with label_smoothing, TensorBoard, and greedy_decode for inference.

Convention: src_mask hides padding on the encoder side (and in cross-attention keys). tgt_mask combines padding visibility with a lower-triangular causal mask so position t never attends to t+1. The goal is a relocatable mental model you can diff against your own model.py, dataset.py, and train.py.

01

InputEmbeddings and √d_model scaling

Token IDs index rows of a learned matrix nn.Embedding(vocab_size, d_model). As in Chapter 1, multiply by math.sqrt(d_model) so embedding magnitudes stay on the same scale as the sinusoidal position vectors added next.

output = Embedding(ids) × √d_model

Demo: embedding magnitude vs dimension

Random unit-scale draws per dimension; compare raw norm to norm after ×√d_model.

What the module stores

forward only does lookup and scale; there is no positional information yet. Vocabulary tensors stay long on input; the embedding table holds float rows of length d_model.

14        super().__init__()
15        self.d_model = d_model
16        self.embedding = nn.Embedding(vocab_size, d_model)
17
18    def forward(self, x):
19        return self.embedding(x) * math.sqrt(self.d_model)
02

PositionalEncoding: sinusoids in log-space

Attention is permutation-equivariant without positions. Chapter 1 derives the sinusoidal PE formula; here we implement it with exp(arange * (-log(10000)/d_model)) for numerical stability—mathematically identical to 1 / 10000^{2i/d_model}.

PE(pos,2i) = sin(pos / 100002i/d)  ·  PE(pos,2i+1) = cos(pos / 100002i/d)

Register pe with register_buffer so it moves with .to(device) and saves in state_dict, but stays non-trainable. requires_grad_(False) makes the intent explicit. nn.Dropout after the add regularizes the sum of embedding and position channels.

Demo: sine vs cosine traces

Broadcasting over batch

pe has shape (1, seq_len, d_model). Adding to x with shape (batch, seq_len, d_model) broadcasts the same position curve to every sentence in the batch.

model.pyL26–58 / ~420
26class PositionalEncoding(nn.Module):
27    def __init__(self, d_model, seq_len, dropout):
28        super().__init__()
29        self.dropout = nn.Dropout(dropout)
30        pe = torch.zeros(seq_len, d_model)
31        pos = torch.arange(0, seq_len, dtype=torch.float).unsqueeze(1)
32        div = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
33        pe[:, 0::2] = torch.sin(pos * div)
34        pe[:, 1::2] = torch.cos(pos * div)
35        self.register_buffer('pe', pe.unsqueeze(0), persistent=True)
36
37    def forward(self, x):
38        x = x + (self.pe[:, :x.size(1), :]).requires_grad_(False)
39        return self.dropout(x)
03

LayerNormalization

For each token vector, subtract mean and divide by standard deviation across the last dimension, then apply learnable gain alpha and bias bias. eps prevents blow-ups when variance is near zero. This differs from batch normalization: statistics are per-token, not pooled across the batch dimension.

ŷ = α ⊙ (x − μ) / √(σ² + ε) + β

Demo: three values through manual LayerNorm

keepdim=True

Means and variances must broadcast back onto x for elementwise subtraction and division. Forgetting keepdim is a classic shape bug.

model.pyL60–78 / ~420
60class LayerNormalization(nn.Module):
61    def __init__(self, d_model, eps=1e-6):
62        super().__init__()
63        self.eps = eps
64        self.alpha = nn.Parameter(torch.ones(d_model))
65        self.bias = nn.Parameter(torch.zeros(d_model))
66
67    def forward(self, x):
68        mean = x.mean(dim=-1, keepdim=True)
69        std = x.std(dim=-1, keepdim=True)
70        return self.alpha * (x - mean) / (std + self.eps) + self.bias
04

FeedForwardBlock: local computation after mixing

After attention redistributes information across positions, each position applies the same two-layer MLP: expand to d_ff (paper default 2048 when d_model=512), ReLU, dropout, then project back. PyTorch nn.Linear applies to the last dimension, so (B, T, d_model) flows through without explicit loops.

FFN(x) = W₂ · ReLU(W₁x + b₁) + b₂

Demo: width and parameter count

Why so wide?

The inner dimension is a per-token scratch space. Attention is global communication; FeedForwardBlock is where each position nonlinearly recombines its own vector.

model.pyL80–98 / ~420
80class FeedForwardBlock(nn.Module):
81    def __init__(self, d_model, d_ff, dropout):
82        super().__init__()
83        self.linear1 = nn.Linear(d_model, d_ff)
84        self.dropout = nn.Dropout(dropout)
85        self.linear2 = nn.Linear(d_ff, d_model)
86
87    def forward(self, x):
88        return self.linear2(self.dropout(torch.relu(self.linear1(x))))

MultiHeadAttentionBlock: Q, K, V, scale, mask, merge

Using the scaled dot-product attention formula from Chapter 1, project hidden states with w_q, w_k, w_v (each d_model → d_model), reshape to (B, h, T, d_k) with d_k = d_model // h, run attention per head, concatenate heads, then apply w_o. Store attention_scores when you need heatmaps.

head = softmax(QKT / √dk + mask) V  ·  multi-head = Wo concat(head₁…headh)

Constraint: d_model % h == 0. Otherwise equal head splits are impossible.

Demo: head split geometry

The static attention helper returns both context and probabilities so training and visualization share one path. Masking uses the same −∞ trick from Chapter 1: masked_fill with a large negative value before softmax so forbidden positions get weight ≈0.

model.pyL100–168 / ~420
100class MultiHeadAttentionBlock(nn.Module):
101    def __init__(self, d_model, h, dropout):
102        super().__init__()
103        assert d_model % h == 0
104        self.d_model = d_model; self.h = h
105        self.d_k = d_model // h
106        self.w_q = nn.Linear(d_model, d_model)
107        self.w_k = nn.Linear(d_model, d_model)
108        self.w_v = nn.Linear(d_model, d_model)
109        self.w_o = nn.Linear(d_model, d_model)
110        self.dropout = nn.Dropout(dropout)
111
112    @staticmethod
113    def attention(query, key, value, mask, dropout):
114        d_k = query.shape[-1]
115        scores = (query @ key.transpose(-2, -1)) / math.sqrt(d_k)
116        if mask is not None:
117            scores = scores.masked_fill(mask == 0, -1e9)
118        scores = scores.softmax(dim=-1)
119        scores = dropout(scores)
120        return scores @ value, scores
121
122    def forward(self, q, k, v, mask):
123        q = self.w_q(q); k = self.w_k(k); v = self.w_v(v)
124        B, T, _ = q.shape
125        q = q.view(B, T, self.h, self.d_k).transpose(1, 2)
126        k = k.view(B, -1, self.h, self.d_k).transpose(1, 2)
127        v = v.view(B, -1, self.h, self.d_k).transpose(1, 2)
128        x, self.attention_scores = MultiHeadAttentionBlock.attention(q,k,v,mask,self.dropout)
129        x = x.transpose(1, 2).contiguous().view(B, T, self.d_model)
130        return self.w_o(x)

ResidualConnection: pre-norm sublayer wrapper

Many educational implementations apply LayerNormalization before the sublayer, then add the sublayer output to the residual stream: x + dropout(sublayer(norm(x))). The original diagram in the paper is post-norm; both families train successfully if you stay consistent.

Shared template

Passing sublayer as a callable avoids duplicating dropout and add logic for attention and FFN branches.

model.pyL132–145 / ~420
132class ResidualConnection(nn.Module):
133    def __init__(self, d_model, dropout):
134        super().__init__()
135        self.dropout = nn.Dropout(dropout)
136        self.norm = LayerNormalization(d_model)
137
138    def forward(self, x, sublayer):
139        return x + self.dropout(sublayer(self.norm(x)))

EncoderBlock and Encoder stack

The encoder uses self-attention: q, k, and v all come from the same tensor. The only masking is padding on the source side so pad tokens do not attend or get attended to meaningfully.

DecoderBlock and Decoder: causal self-attn + cross-attn

The decoder runs three sublayers: masked self-attention on tgt (causal mask from Chapter 1), cross-attention where q is decoder state and k,v are encoder output, then FeedForwardBlock. Pass src_mask into cross-attention so padding keys are suppressed; pass tgt_mask into self-attention for causality and pad.

Cross-attention call shape

self.cross_attention_block(q, enc_out, enc_out, src_mask) — note three arguments for keys/values are identical encoder memory.

174        self.cross_attention_block = cross_attn

180        x = self.residual[1](x, lambda x: self.cross_attention_block(x,enc_out,enc_out,src_mask))
181        x = self.residual[2](x, self.feed_forward_block)

187    def forward(self, x, enc_out, src_mask, tgt_mask):

ProjectionLayer and Transformer façade

ProjectionLayer maps d_model → tgt_vocab. Training often uses raw logits with nn.CrossEntropyLoss; some codebases apply log_softmax and NLLLoss for numerical stability. Expose encode, decode, and project separately so inference reuses enc_out while the decoder grows one token at a time.

Why not one giant forward?

greedy_decode calls encode once, then loops decode → project → argmax. A monolithic forward would either re-encode each step or need awkward flags.

model.pyL214–268 / ~420
214class ProjectionLayer(nn.Module):
215    def __init__(self, d_model, vocab_size):
216        super().__init__(); self.proj = nn.Linear(d_model, vocab_size)
217    def forward(self, x):
218        return torch.log_softmax(self.proj(x), dim=-1)
219
220class Transformer(nn.Module):
221    def __init__(self, enc, dec, src_emb, tgt_emb, src_pos, tgt_pos, proj):
222        super().__init__()
223        self.encoder, self.decoder = enc, dec
224        self.src_embed, self.tgt_embed = src_emb, tgt_emb
225        self.src_pos, self.tgt_pos = src_pos, tgt_pos
226        self.project_layer = proj
227
228    def encode(self, src, src_mask):
229        x = self.src_embed(src); x = self.src_pos(x)
230        return self.encoder(x, src_mask)
231
232    def decode(self, enc, src_mask, tgt, tgt_mask):
233        x = self.tgt_embed(tgt); x = self.tgt_pos(x)
234        return self.decoder(x, enc, src_mask, tgt_mask)
235
236    def project(self, x):
237        return self.project_layer(x)

build_transformer and Xavier uniform init

The build_transformer factory function takes all hyperparameters and wires together every component we've built. It creates:

Two InputEmbeddings tables — one for the source vocabulary, one for the target vocabulary. They must be separate because English and Italian have different words and different vocabulary sizes.

Two PositionalEncoding modules — we could technically reuse one since positional encodings are the same regardless of language, but using two keeps the code explicit and gives each its own dropout random number stream.

N encoder blocks — each with its own MultiHeadAttentionBlock and FeedForwardBlock (fresh weights, no sharing between layers).

N decoder blocks — each with a self-attention block, a cross-attention block, and a feed-forward block.

One ProjectionLayer — maps from d_model to the target vocabulary size, since we're translating into the target language.

Xavier Initialization

nn.init.xavier_uniform_ initializes weight matrices so that activations and gradients maintain a healthy scale through the network. Without it, weights start at PyTorch's defaults (scaled by fan-in), which can lead to slow initial training. Xavier considers both the number of input and output units, producing weights from a uniform distribution with carefully chosen bounds. The if p.dim() > 1 check skips 1D parameters — those are biases (already zeros) and LayerNorm gains (already ones), which are well-initialized by default.

model.pyL240–244 / ~420 · Step 1 of 3
240def build_transformer(src_vs, tgt_vs, src_seq, tgt_seq, d_model, N, h, dropout, d_ff):
241    src_emb = InputEmbeddings(d_model, src_vs)
242    tgt_emb = InputEmbeddings(d_model, tgt_vs)
243    src_pos = PositionalEncoding(d_model, src_seq, dropout)
244    tgt_pos = PositionalEncoding(d_model, tgt_seq, dropout)

245    enc_layers = []
246    for _ in range(N):
247        enc_layers.append(EncoderBlock(d_model, MultiHeadAttentionBlock(d_model,h,dropout),
248            FeedForwardBlock(d_model,d_ff,dropout), dropout))
249    dec_layers = []
250    for _ in range(N):
251        dec_layers.append(DecoderBlock(d_model,
252            MultiHeadAttentionBlock(d_model,h,dropout),
253            MultiHeadAttentionBlock(d_model,h,dropout),
254            FeedForwardBlock(d_model,d_ff,dropout), dropout))
255    encoder = Encoder(d_model, nn.ModuleList(enc_layers))
256    decoder = Decoder(d_model, nn.ModuleList(dec_layers))
257    proj = ProjectionLayer(d_model, tgt_vs)

258    model = Transformer(encoder, decoder, src_emb, tgt_emb, src_pos, tgt_pos, proj)
259    for p in model.parameters():
260        if p.dim() > 1: nn.init.xavier_uniform_(p)
261    return model

Embeddings and positions first; then stacked blocks; finally Xavier on 2D+ tensors.

Opus Books and word-level tokenizers

We use the Opus Books dataset from HuggingFace — a collection of parallel sentence pairs extracted from famous books. Each data item is a pair: one sentence in English, one in Italian (or whichever language pair you choose). For example: "There was no possibility of taking a walk that day" paired with its Italian translation.

The Tokenizer

Before the model sees any text, we need a tokenizer — the component that sits before the input embeddings. Its job: split a sentence into tokens and map each token to a number (input ID). There are many tokenizer strategies (BPE, WordPiece, sub-word), but we use the simplest: a word-level tokenizer that splits by whitespace. Each space defines a word boundary.

We build one tokenizer per language (source and target), because English and Italian have different vocabularies. The tokenizer training uses the HuggingFace tokenizers library with a WordLevelTrainer and WhitespacePre tokenizer. We set min_frequency=2, meaning a word must appear at least twice in the dataset to earn its own vocabulary entry. Words below this threshold are mapped to the special <unk> (unknown) token.

Four special tokens are registered in every vocabulary:

<unk> — unknown word (not in vocabulary)

<pad> — padding (filler to reach fixed sequence length)

<sos> — start of sentence (signals the decoder to begin generating)

<eos> — end of sentence (signals generation is complete)

The tokenizer is built once and saved to disk. On subsequent runs, it loads from the saved file rather than retraining.

Train / Val Split and Sequence Length

The Opus Books dataset only provides a train split. We split it ourselves: 90% for training, 10% for validation, using torch.utils.data.random_split. Before training, we also scan every sentence to find the maximum token count in both languages — this helps choose an appropriate sequence length (350 tokens is more than enough for this dataset).

Data loading code

The subset string (e.g. 'en-it') is built dynamically from configuration so you can switch languages by changing two config values.

BilingualDataset: padding, masks, shifted labels

The BilingualDataset class transforms raw sentence pairs into the tensors the Transformer expects. For each pair, it produces three tensors:

Encoder input: [SOS] + src_tokens + [EOS] + PAD * N — the full source sentence wrapped in special tokens, padded to the fixed sequence length. We need seq_len - len(src_tokens) - 2 padding tokens (minus 2 for SOS and EOS).

Decoder input: [SOS] + tgt_tokens + PAD * N — only SOS is prepended (no EOS). We need seq_len - len(tgt_tokens) - 1 padding tokens (minus 1 for SOS only).

Label: tgt_tokens + [EOS] + PAD * N — only EOS is appended (no SOS). Same padding count as decoder input. This creates the shifted alignment: decoder sees [SOS] te amo molto, label expects te amo molto [EOS].

The code asserts that the number of padding tokens never goes negative — if it does, the chosen sequence length is too small for this sentence. All tensors use torch.long (64-bit integers) because vocabulary sizes can exceed 32-bit range.

Building the Masks

The encoder mask marks non-padding tokens as 1 and padding as 0 (shape (1, 1, seq_len), broadcasting across heads and query positions). The decoder mask combines that padding mask with the lower-triangular causal mask from Chapter 1 — use torch.triu and keep positions on and below the diagonal. Combine both with logical AND before masked_fill.

Use ignore_index=pad_id in the loss so padding positions do not contribute to gradients.

Training: Adam, label smoothing, TensorBoard

Configuration

The default hyperparameters follow the paper closely: d_model = 512, N = 6 layers (both encoder and decoder), h = 8 heads, d_ff = 2048, dropout = 0.1. For training: batch_size = 8 (increase if your GPU allows), epochs = 20, learning_rate = 10-4, and seq_len = 350 for the English→Italian dataset. If the model is too large for your GPU, try reducing the number of heads or layers — given the relatively small dataset, this shouldn't hurt quality significantly.

Loss Function and Label Smoothing

The loss function is CrossEntropyLoss with two important settings. First, ignore_index is set to the padding token ID so padding positions contribute zero to the loss. Second, label_smoothing = 0.1: instead of placing 100% probability on the correct token, we take 10% of that mass and spread it evenly across all other tokens. This makes the model less overconfident in its predictions and generally improves generalization.

To compare logits with labels, we flatten: logits from (batch, seq, vocab) to (batch * seq, vocab), and labels from (batch, seq) to (batch * seq). This is the shape CrossEntropyLoss expects.

Checkpointing and Resume

At the end of every epoch, we save not just the model's state_dict but also the optimizer's state. The Adam optimizer maintains per-weight statistics (running means and variances of gradients) that took many steps to accumulate. Without saving these, resuming training forces the optimizer to start from scratch — even with a pre-trained model, it must re-learn how to move each weight. The optimizer dictionary can be quite large, but it is essential for proper training resumption.

Loss values are logged to TensorBoard via SummaryWriter, enabling real-time visualization of training progress as loss curves.

Resuming Training from a Checkpoint

To resume after a crash or interruption, the code checks if a preload path exists in the configuration. If so, it loads the checkpoint file with torch.load, then calls model.load_state_dict and optimizer.load_state_dict to restore both. The saved global_step ensures TensorBoard logging continues from the correct position. Without restoring the optimizer state, training effectively restarts — the optimizer must re-learn its per-weight statistics (running means/variances), which can cause large, unstable updates.

Learning Rate Scheduling

A common practice is to start with a high learning rate and decay it gradually across epochs. We intentionally skip this here to keep the code focused on the Transformer itself. A fixed lr = 10-4 works well enough for this dataset size.

Greedy decode, validation, attention maps

Greedy Decoding: Step by Step

Set model.eval() and wrap everything in torch.no_grad() to disable gradient computation. The process mirrors inference from the theory chapter:

Step 1: Pre-compute the encoder output once — it never changes because the source sentence is fixed.

Step 2: Initialize decoder input with only the SOS token: torch.full((1, 1), sos_id).

Step 3 (loop): Build a causal mask for the current decoder input length. Run model.decode with the cached encoder output. Project only the last position (out[:, -1]) — this is the prediction for the next token. Take argmax to get the token with the highest probability (greedy search). Append this token to the decoder input. If it equals EOS, stop.

During validation, we run this greedy decode on a few sample sentences from the validation set (batch size = 1) and compare the model's output with the expected translation. We use tqdm's built-in write method for printing so the output doesn't interfere with the training progress bar.

Three Types of Attention to Visualize

Every MultiHeadAttentionBlock stores its attention_scores after each forward pass. We can extract these from any layer and any head to create attention heatmaps. There are three distinct attention types to examine:

1. Encoder self-attention: Each source word attending to other source words. We expect high diagonal values (word attending to itself) and interesting off-diagonal patterns showing syntactic relationships.

2. Decoder self-attention: Each target word attending to previous target words (causal — upper triangle is zeroed). Shows how the model builds the translation sequence.

3. Cross-attention (encoder-decoder): The most revealing — it shows how each target word attends to the source sentence. This is where the actual translation alignment happens. Rows are source words, columns are target words. Bright cells reveal which English words the model focused on when producing each Italian word.

Different heads and different layers learn different relationship patterns, which is exactly why multi-head attention is so powerful. Between one layer and the next, we also have different WQ, WK, WV matrices, so they learn different inter-word relationships.

Implementing Attention Visualization

To visualize attention, we create a dedicated notebook. The workflow: load the pre-trained model, run inference on a sample sentence, then extract attention_scores from the model's internal layers. Each MultiHeadAttentionBlock stores the softmax output as self.attention_scores — we retrieve it by navigating the model hierarchy: model.encoder.layers[layer_idx].self_attention_block.attention_scores.

For each layer and head, we build a heatmap grid. The rows and columns are the tokens of the sentence (or source/target sentences for cross-attention). Each cell's intensity represents the attention score between two tokens. When hovering over cells, we can read exact score values. The SOS and EOS tokens typically show weak connections to real words (especially in early layers), while content words show the strongest diagonal and syntactic patterns.

The cross-attention heatmap is particularly revealing — it shows how the model learned to align the source and target languages. This is where the actual translation relationship is visible.

Greedy decode note: During autoregressive decoding, the growing decoder sequence has no padding tokens — it's just [SOS] → [SOS, te] → [SOS, te, amo], etc. So only the causal mask is needed, not the padding mask. The padding mask is a training concern (where we batch fixed-length sequences).
