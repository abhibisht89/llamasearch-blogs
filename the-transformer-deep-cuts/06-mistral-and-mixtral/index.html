Mistral & Mixtral: Sliding Window Attention & MoE

How decoder-only stacks add local attention, bounded KV memory, chunked prefill, and sparse mixture-of-experts routing—plus how pipeline parallelism and xFormers block masks fit into production inference.

00

What this chapter connects

Mistral-style models sit in the same decoder-only family as LLaMA: token embeddings, a repeated transformer block (pre-norm, self-attention, residual, feed-forward, residual), final RMSNorm, and a linear head for next-token logits. The interesting differences are not “another brand name”—they change compute, memory, and how far information travels through depth.

Roadmap. Self-attention with a causal mask → restrict neighbors (sliding window) → explain long-range effects via depth (receptive field) → standard KV cache → shrink cache to window size (rolling buffer) → fill cache efficiently (prefill & chunking) → widen capacity without running every FFN (sparse MoE, top-K gating) → place layers on many devices (sharding & pipeline parallelism) → batch many prompts safely (xFormers block attention).

Mistral AI (the company behind these models) released the dense Mistral 7B and the sparse Mixtral 8×7B family. The organization has been one of the most visible European builders of open-weights language models; keeping that context in mind helps explain why the public artifacts emphasize efficient inference (sliding windows, packed batching) as much as raw parameter counts.

01

Decoder-only stack vs. vanilla Transformer

A decoder-only language model looks like the decoder side of the original Transformer: token embeddings, stacked blocks, then a projection to vocabulary. There is no cross-attention to another modality or source sequence—everything is self-attention over the running context. Encoder-only models (for example BERT) omit the final LM head by default; decoder-only models include it because next-token prediction is the core training target.

Terminology note: the repeated block is often called a transformer block, decoder block, or (by analogy to the encoder diagram) an encoder block in codebases—same residual structure, different mask inside attention.

Prerequisites. This chapter assumes comfort with the standard Transformer self-attention equations and autoregressive masking. Companion material in the same series covers RMSNorm, RoPE, and grouped-query attention in depth when you need the LLaMA/Mistral shared building blocks spelled out step by step.

02

Mistral vs. LLaMA at a glance

Architecturally, Mistral is “LLaMA-shaped” with a few high-impact swaps:

  • Attention mask: Mistral adds sliding-window attention on top of causality. Each position attends only to prior tokens within a fixed window width W (plus itself), not the entire prefix.
  • KV cache: With sliding windows, keys and values older than the window cannot affect the current attention output—they are masked out. The cache can be capped at W entries per layer: a rolling-buffer KV cache.
  • Activation in the FFN: The original Transformer decoder often used ReLU in the position-wise feed-forward block. LLaMA uses SwiGLU-style gating there. Mistral 7B uses SiLU (sigmoid linear unit, also known as Swish with β=1) in its two-layer FFN path—the high-level residual diagram matches LLaMA, but the nonlinearities and gating pattern are not identical.
  • Mixtral (8×7B): Instead of one MLP per block, eight parallel feed-forward “experts” exist; a router picks a small subset per token (in Mixtral, two), so compute stays sparse even though total parameters grow.

Shared DNA with LLaMA includes RMSNorm, rotary position embeddings (RoPE), grouped-query attention (GQA), and autoregressive training.

Vanilla Transformer FFN

Often ReLU between two linear projections—historically the default in many “encoder/decoder” papers before the LLaMA-era recipe changes.

LLaMA vs Mistral 7B

LLaMA: SwiGLU-gated feed-forward. Mistral 7B: SiLU in the FFN path. Mixtral 8×7B: same attention stack as the family convention, but the dense MLP is replaced by eight parallel FFN experts with top-2 routing.

The repeated block appears 32 times in the configurations discussed here: each layer’s output feeds the next, and only after the final block do RMSNorm, the vocabulary linear map, and softmax produce next-token logits.

04

Self-attention, scale, and the causal mask

Mistral’s decoder blocks use the same scaled dot-product self-attention and causal mask as any autoregressive LM (Chapter 01 derives QK^T / √d_k, softmax, and the upper-triangular −∞ mask). The score matrix is seqlen × seqlen per head; forbidden future positions get zero mass after softmax.

Attention(Q, K, V) = softmax( (Q K⊤) / √dk ) V

Everything new in Mistral starts in the next section: on top of causality, sliding-window attention zeroes interactions when query–key distance exceeds W.

05

Sliding-window attention

Causal full attention lets each token see the entire past. Sliding-window attention keeps causality but also zeroes interactions when the distance between query position i and key position j exceeds a window of width W (equivalently: each token attends only within the last W−1 predecessors, plus itself).

Tradeoff. Fewer dot products → faster training and inference, but direct attention links disappear between distant pairs. If W is too small, local context may be insufficient for some tasks—though depth changes the story (next section).

Worked example (window width W = 3 on six tokens). Index positions from 1 to 6 for the · cat · is · on · a · chair. From “chair” (position 6), tokens at graph distance greater than the window along the past direction are dropped: “chair” still sees itself, “a”, and “on”, but it does not attend directly to “is” (gap 4) or “the”. Likewise “a” (position 5) must not attend to “the” (position 1) when the same window applies—again gap 4. Causality is unchanged: no token attends forward in time.

Book analogy (full). When you read a long book, you usually do not need to relate a word in chapter five to every word in chapter one—those chapters may introduce unrelated material, and forcing dense long-range edges would spend parameters and compute on links that rarely matter. What you do need is strong coherence inside the local passage: words in the same section should exchange information freely. Sliding-window attention bakes in that bias: each position builds context from a finite neighborhood, which reduces the number of dot products per layer and speeds training and inference.

The tradeoff is real: if the window is too small for the task, quality can suffer because direct edges between distant siblings disappear. The next section explains why depth still rescues many long-range dependencies indirectly.

06

Receptive field across layers

Even when “chair” cannot attend directly to “the” in layer 1 because they sit outside the window, stacked layers compound information much like stacked convolutions: deeper representations mix already-mixed neighbors. After one layer, a hidden state at position i is a blend of tokens inside its window; after another layer, that blend itself aggregates slightly farther prefixes—so effective context grows with depth.

This is the transformer analogue of receptive field in CNNs: two 3×3 layers do not mean only 3 pixels of influence—features at stage two depend indirectly on a wider region. Here, windowed attention + depth yields indirect long-range dependencies without every layer using full attention.

CNN receptive field (expanded). Picture a 2D image convolved with a 3×3 kernel. The activation at one output location looks at a 3×3 patch of the input. Slide the kernel one step: the next activation sees a shifted 3×3 patch—so neighboring output cells share some inputs but not all. Stack another 3×3 convolution on those features. A cell in the second feature map may appear, at first glance, unrelated to a pixel several steps away in the original image—yet that second-layer cell depends on a 3×3 neighborhood of first-layer features, and each of those depended on 3×3 patches below. Chaining dependencies means indirect connectivity reaches farther than a single kernel width suggests. That is the classical receptive-field argument, and it transfers to transformers: a token in layer ℓ+1 mixes vectors that already mixed their own neighbors in layer ℓ.

After softmax, multiply by V. Continue the six-token example with a causal and sliding mask. The attention weight matrix multiplies V (same token sequence as queries/keys in self-attention). Row i of the weight matrix picks a convex combination of rows of V. Zeros from masked positions mean entire rows of V are irrelevant for that output position—for the sixth token, only the last three rows of V can receive non-zero weight. So the sixth output vector is built strictly from the embeddings (or projected values) of on, a, chair at that layer—even though deeper layers will remix those summaries again.

Second layer expands the union of influences. Feed the layer-1 outputs back through another identical masked attention block. The queries/keys/values at layer 2 are no longer “raw” token embeddings; each position already encodes a blend of prior neighbors allowed by the mask. When the fourth position in layer 2 forms its new vector, it may combine layer-1 representations that themselves already contained information from earlier words. A concrete chain: layer-1 position 2 might aggregate “the” and “cat”; layer-1 position 3 might aggregate “cat” and “is”; by the time layer 2 fuses what it can see within the window, the representation at position 4 can inherit pieces that trace back to the even though “chair” and “the” were never directly connected in one hop. With window width 3, a useful rule of thumb used in pedagogy is that each additional layer can extend how far information has traveled by roughly two more tokens along the past direction (until the sequence length caps the effect). After enough layers—Mistral uses 32—even a local window can support global reasoning, which matches the empirical plots in the Mistral technical report showing how deeper layers widen effective context under sliding attention.

Sliding windows limit direct edges per layer, but depth stacks local mixes so representations progressively aggregate information from farther away—analogous to deepening a CNN to grow the receptive field. The window controls per-layer sparsity; the stack controls how far information compounds.

07

KV cache for autoregressive decoding

Naively regenerating the full prefix every step repeats work: earlier keys and values do not change when only the newest token is appended. A KV cache stores past K and V projections; each step supplies a fresh query for the latest token only, appends new keys/values, and computes a single new output row. That removes redundant dot products and yields one next-token representation per step—what you need for sampling.

Throughput caveat. When compute drops, memory bandwidth (reading/writing large tensors) can dominate. Pure multi-query attention (many query heads, a single K/V head) aggressively cuts cache traffic and can improve latency by an order of magnitude in reported benchmarks, with only a small quality hit; grouped query attention splits the difference by using more than one K/V head but still fewer than Q heads—Mistral’s 32/8 split is a common compromise.

Training vs inference. During training with teacher forcing, you often present an entire labeled sequence at once (for example a line of poetry with a start-of-sequence token prepended and an end-of-sequence token appended), run one forward pass, and compute cross-entropy at every position in parallel. A line like “Love that can quickly seize the gentle heart” (plus special tokens) might yield nine supervised positions in one go: the model learns to emit “Love” after SOS, “that” after SOS+Love, and so on, all within a single graph.

At inference time you typically generate one token at a time: step 1 feeds only SOS and reads off the distribution for the first word; step 2 feeds SOS plus the sampled first word; step 3 feeds those two plus the new sample; continuing until EOS. You only need the final position’s logits to choose the next token, but every token in the prompt conditions that choice—you cannot predict “gentle” from the article “the” alone; you need the full preceding clause.

Naive autoregressive forward

Recompute attention over the entire growing prefix each step. Many dot products repeat work you already did at the previous time step, and under a causal mask large regions of the score matrix are unused for the final column anyway.

With KV cache

Append new keys and values for the token you just finished, but use only the latest hidden state as the query for the next projection—do not rebuild a full-sequence query tensor each time. You therefore materialize just the last output row of attention per step, which is exactly what you need before the final linear layer and softmax for next-token prediction.

Equivalently: without a cache you might append the new representation to Q, K, and V together; with a KV cache you append only to K and V while replacing the query side with the single new token’s query vector. That is the implementation pattern that removes redundant matmuls while preserving semantics.

08

Rolling-buffer KV cache

If attention never looks farther than W−1 steps back, storing more than W keys and values per layer cannot change outputs—those entries multiply masked (zero) attention weights. A rolling buffer caps storage at W slots: append until full, then overwrite the oldest slot circularly. Logical token order may no longer match physical array order, so implementations un-rotate using a head pointer: take entries from pointer→end, then 0→pointer.

The same masking argument shows early rows of V may be irrelevant for the current query row when their weights are zero—another way to see why trimming the cache is safe given the sliding mask.

Quantitative intuition. Suppose the sliding window covers W = 10 tokens. Even if the conversation history contains 1,000 prior tokens, attention with that mask never reads more than the last ten positions. Storing all 1,000 key/value pairs per layer therefore wastes memory and bandwidth: older slots never receive non-zero attention mass from the current query. The rolling buffer simply aligns storage with what the mask can ever use.

Illustration at inference step with eight cached tokens and W = 4. The newest query attends backward at most three steps. Dot products against keys older than that are masked to −∞, so after softmax those columns are zero. In the weighted sum with V, the first four rows of V (the ones that would correspond to the oldest keys) are multiplied by zeros for the current query row—they contribute nothing to the output. There is no reason to keep recomputing or storing those stale entries once they fall outside the window.

Circular buffer with W = 4 on the sentence “the cat is on a chair.” Fill slots with the first four tokens: the, cat, is, on. When token a arrives, overwrite the oldest physical slot (the position tracked by a head pointer) so the array may read a, cat, is, on in memory even though chronologically you mean cat, is, on, a. Implementations therefore un-rotate (the Mistral codebase names this idea in functions such as un_rotate): read from the head index to the end of the buffer, then wrap from the start up to the head, reconstructing true time order before attention or when debugging tensor layouts.

09

Prefill and chunked prefill

Before decoding, the model must prefill the KV cache with the prompt. The prompt is known up front, so all its tokens can be processed in parallel in principle—but implementations often chunk long prompts for memory or kernel efficiency.

For chunk k > 1, attention is set up so queries come from the current chunk while keys and values include the previous chunk’s cache plus the current chunk. That way tokens at the start of a new chunk can still attend to tokens at the end of the prior chunk; using only the current chunk as K/V would sever cross-chunk dependencies. After prefill, decoding returns to the familiar one-token-at-a-time pattern with KV growth (or rolling) as usual.

Why chunk size tracks W. In systems that tie chunking to the sliding window, a common choice is to set the prefill chunk length to the window width W (or a compatible divisor) so that each chunk’s attention kernel stays aligned with the local mask while still allowing cross-chunk context when keys and values include the prior cache. Very long prompts—retrieval-augmented setups with 5,000–6,000+ tokens are the usual motivating example—would require thousands of serial forward passes if you insisted on one token per prefill step, which under-utilizes the GPU; feeding the whole prompt at once may exceed device memory (often a few thousand tokens of working set depending on width, batch, and W). Chunked prefill is the middle path.

Concrete prompt chunking. Take W = 4 and the question “can you tell me who is the richest man in history”. Chunk 1 might be can · you · tell · me. Chunk 2 is who · is · the · richest. When prefilling chunk 2, queries come only from that chunk’s tokens, but keys and values must include the rolling cache after chunk 1 plus chunk 2’s tokens. Otherwise who could not attend to me or tell even when the sliding window says it should—there would be no keys present for those positions. The final chunk man · in · history repeats the pattern: queries from the current chunk, keys/values from everything cached from who is the richest plus the new tokens. After prefill completes, generation reverts to the single-query KV-cache stepping described earlier.

Implementation sketch. The first prefill chunk often builds an attention mask whose logical shape depends only on the fresh tokens (empty cache). Every later chunk uses mask dimensions derived from cached_length + current_chunk_length so prior tokens remain addressable. Token generation after prefill matches standard autoregressive caching: one new query, append K/V, softmax on the active window.

Sparse mixture of experts (MoE)

Classical mixture of experts combines several “expert” sub-networks; sparse MoE activates only a few per input. In Mixtral each transformer block still runs self-attention once, but the dense MLP is replaced by eight parallel FFN experts.

A router (typically a linear map from the hidden vector to eight logits) scores expert affinity for each token. The implementation keeps the top two logits, runs the token through those two experts, and forms a convex combination of their outputs. Weights come from softmax over just those two logits—not all eight—so expert masses always sum to one for the active pair, keeping output scale comparable across training runs and ablations (different expert counts, etc.).

Why sparse helps: eight full matmul chains per token would be eight times the FFN work; top-2 routing executes two, while total parameters rise because unused experts still exist in memory. Attention stays shared, so per-token compute is roughly one attention block plus two expert FFNs (~12–13B effective FLOPs in the usual Mixtral accounting, not a full 14B). Empirically, experts often specialize (syntax, language, lexical classes)—not guaranteed, but a useful mental model.

Numeric gate example. Suppose the router emits eight logits; the largest two might be 3.4 and 1.5 for experts A and B. Mixtral runs the token through experts A and B only, then forms weights by applying softmax solely to that pair—not to all eight logits. With only two arguments, softmax enforces wA + wB = 1, which stabilizes the scale of the mixture compared to taking softmax over all eight and then zeroing six experts (the discarded mass would otherwise change the magnitude of the combination).

y = wA · FFNA(x) + wB · FFNB(x), w = softmax([ℓA, ℓB])

Why softmax-after-top-k matters for research iterations. Teams routinely train variants with different expert counts (say 2, 3, 4, or 8). If the combination weights always summed to one per active expert subset, the residual stream’s scale stays comparable across ablations. If instead you softmaxed all experts and then masked, the surviving weights might no longer form a simplex subset with predictable norm, making it harder to swap configurations without retuning surrounding layers.

Specialization stories. After large-scale training, some experts pick up loose semantic or syntactic roles—one might see more multilingual tokens, another more verb-heavy spans, another noun-heavy spans. These patterns are emergent rather than guaranteed, but they explain why sparse routing can feel like delegating examples to different “sub-FFNs” without running all of them.

Model sharding and pipeline parallelism

When a model does not fit one GPU, one option is layer sharding: place contiguous layer groups on separate devices, stream activations GPU-by-GPU for each forward pass. That works, but a simple pipeline leaves most devices idle most of the time—only one stage is active at a given instant during a single large batch.

Pipeline parallelism (as in GPipe-style schedules) splits a logical batch into micro-batches and staggers them: while stage 2 processes micro-batch 1, stage 1 can start micro-batch 2. Gradients can be accumulated across micro-batches before an optimizer step. Inference can drop the backward half but keep the micro-batch overlap idea to raise utilization.

Schedules still exhibit bubbles—idle intervals at the start/end of the pipeline; larger batch depth reduces bubble overhead.

Layer sharding on four devices. Map Mistral’s 32 transformer blocks into four groups of eight consecutive layers. Device 1 runs layers 1–8 and hands activations to device 2, which runs 9–16, and so on until device 4 finishes 25–32; only then do the final RMSNorm and vocabulary projection run. This works but is sequential: at any instant a naive schedule keeps three GPUs idle while one executes.

Pipeline parallelism (GPipe-style). Split a logical minibatch into micro-batches and stagger them across stages so multiple GPUs stay busy. Bubble slots at the start and end of a wave are roughly fixed at stages − 1; deeper fill amortizes them (e.g. four micro-batches waste on the order of ~43% of stage-slots, eight ~27%, sixteen ~16%). Training accumulates gradients across micro-batches before an optimizer step; inference keeps only the forward overlap.

Even optimized pipelines retain bubble time steps at the start and end of a wave—moments when some stages have no work. Increasing the number of micro-batches (deeper pipeline fill) amortizes those bubbles; this is the same throughput–memory trade-off that appears in every production serving stack.

xFormers and block-diagonal causal masks

Serving many requests batches prompts together for throughput. Padding variable-length prompts wastes work: attention runs dot products involving pad positions you never read. A better pattern concatenates all tokens into one long sequence and stores per-prompt lengths.

The xFormers stack provides helpers for complex masks and memory-efficient attention kernels. Mistral inference code uses a block-diagonal causal mask: tokens attend causally within their prompt block but are forbidden from attending across prompts—equivalent to independent causal LMs packed into one tensor parallel kernel.

When sliding windows apply, the library composes window limits with those blocks. Separate mask builders cover first-chunk prefill (empty cache) versus later chunks (non-empty per-sequence caches of different sizes), so attention respects both which tokens exist in cache and which cross-prompt interactions must stay blocked.

Padding batching vs packed batching. Suppose three customer prompts (treating words as tokens for intuition) are “write a poem” (3 tokens), “write a historical novel” (4 tokens), and “tell me a funny joke” (5 tokens). Padding every row to length 5 produces a rectangular tensor but forces attention kernels to compute scores involving pad positions that never influence the real next-token loss—wasted FLOPs and memory traffic. Worse, when you read off hidden states to predict the next token, you must index the last non-padding position per row (position 3 for the first prompt, 4 for the second, 5 for the third), not the final column of the tensor.

The alternative is to concatenate all real tokens into one sequence of length 3 + 4 + 5 = 12, store the boundaries [3, 4, 5] (or prefix sums) in a side array, and build a block-diagonal causal mask: causality holds inside each prompt block, and entries that would let “novel” attend to “poem” are set to −∞. After one forward pass you still have twelve rows of hidden states, but the positions that matter for decoding are exactly the last real token of each block (indices 3, 7, and 12 in 1-based counting)—you gather those rows for the final linear map and softmax.

xFormers pairs structured masks with memory-efficient attention kernels so fused code respects causality and block structure without materializing dense N×N tensors for every batched request. Production paths must also track heterogeneous KV cache lengths when one user’s context is ~10 tokens and another’s is ~5,000.

Three mask families (as used in the reference implementation narrative). (1) First prefill chunk—cache starts empty, so the mask dimensions follow only the new tokens. (2) Later prefill chunks—cache is non-empty and differs per sequence; the mask must let current queries read prior cached keys/values while still enforcing block boundaries and sliding limits. (3) Block-diagonal causal with offset / padded keys—physical tensors allocate a fixed rolling width W, but only a prefix of slots is valid for a short prompt; the mask encodes how many slots actually contain live keys so padded slack is not attended as if it were real text.

As an illustration, three packed prompts of lengths 7, 5, and 6 with a sliding window of 3 tokens (two steps of history plus self) yield a sparse pattern where each token sees at most two predecessors within its own block—composed on top of the block-diagonal separation between customers. The exact index ranges depend on how you flatten batches, but the invariant is always no cross-customer attention and no backward window beyond W.
