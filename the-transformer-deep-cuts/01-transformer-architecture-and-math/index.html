The Transformer: Architecture, Math & Training

A complete walkthrough of the "Attention Is All You Need" architecture — from RNN limitations through self-attention, multi-head attention, encoder-decoder design, to training and inference pipelines.

This tutorial starts with the problems that recurrent neural networks face — slowness on long sequences and vanishing gradients — and shows how the Transformer solves every one of them. We build up the full architecture piece by piece: input embeddings, sinusoidal positional encodings, dot-product self-attention, multi-head attention with learned projections, layer normalization, the masked decoder, cross-attention, and the final linear projection. We then walk through how training works in a single pass and how autoregressive inference produces tokens one at a time.

00

Why We Need the Transformer

Before the Transformer, recurrent neural networks (RNNs) dominated sequence-to-sequence tasks. An RNN processes tokens one at a time: it takes the first input token x₁ along with an initial hidden state (usually all zeros), produces an output y₁ and a new hidden state, then feeds that hidden state along with x₂ to produce y₂, and so on. If you have n tokens, you need n sequential time steps.

This design has three fundamental problems:

  • ✗ Slow for long sequences: The process is a sequential for-loop. The longer the sequence, the longer the computation. You cannot parallelize across tokens because each step depends on the previous hidden state.
  • ✗ Vanishing / exploding gradients: Frameworks like PyTorch convert neural networks into computation graphs. When you backpropagate through a long chain, you multiply many partial derivatives together (the chain rule). If each factor is less than 1, the product shrinks toward zero — the gradient vanishes. If each factor is greater than 1, the product explodes toward infinity. This is compounded by the fact that CPUs and GPUs can only represent numbers up to a certain precision (e.g., 32-bit or 64-bit). If the gradient becomes too small, its contribution to weight updates is negligible — the weight barely moves. Either way, the network struggles to learn.
  • ✗ Difficulty accessing distant context: The hidden state is a fixed-size vector that must carry all information about earlier tokens. After hundreds of steps, the contribution of the first token to the current hidden state has nearly disappeared. The model effectively "forgets" early context, even though as humans we know that words 200 positions back can still be relevant.

The Chain Rule in Practice

To understand vanishing gradients concretely, consider a simple computation graph. We have two inputs x and y. First, a function f multiplies them: z = f(x, y) = x × y. Then a second function g squares the result: g(z) = z².

PyTorch computes the derivative of g with respect to x using the chain rule:

dg/dx = dg/dz × dz/dx

The key is: the longer the chain of computation (more nodes between input and output), the longer this multiplication chain becomes. With 2 nodes, we multiply 2 partial derivatives. With 100 nodes, we multiply 100.

Now suppose each partial derivative is 0.5. Two of them: 0.5 × 0.5 = 0.25. The product is smaller than either factor. Ten of them: 0.510 ≈ 0.001. A hundred of them: effectively zero. This is vanishing gradients. Conversely, if each factor is 1.5, then 1.5100 is astronomically large — the gradient explodes.

This is exactly what happens in RNNs: the hidden state passes through dozens or hundreds of computation nodes. The gradient of the loss with respect to early weights must travel through this entire chain. By the time it reaches the first token, it has either vanished or exploded.

Key insight: The Transformer solves all three problems simultaneously. It processes the entire sequence in one pass (no sequential for-loop), it avoids long multiplication chains through direct attention connections, and every token can directly attend to every other token regardless of distance.

The Transformer, introduced in the 2017 paper "Attention Is All You Need," replaces recurrence with attention — a mechanism that lets every position in a sequence directly look at every other position in a single step. The architecture splits into two macro blocks: an encoder (the left half of the diagram) and a decoder (the right half), connected by a cross-attention link where some output of the encoder is sent as input to the decoder. A final linear layer on top projects decoder outputs back into vocabulary space — it maps embeddings back to positions in the vocabulary so we can identify actual words.

Matrix Multiplication Notation

Before diving into the architecture, we need to be comfortable with one operation that appears everywhere: matrix multiplication and the dot product.

Take an input matrix of 6 words, each represented by 512 numbers — a (6 × 512) matrix. Multiplying by its transpose — a (512 × 6) matrix — cancels the inner dimensions and yields a (6 × 6) output matrix.

How is each value in this output computed? Take the first value: it is the dot product of the first row with the first column. You take the first number of the row, multiply by the first number of the column. Second number of the row, multiply by the second number of the column. You do this for all 512 pairs, then sum all 512 products. That single sum is one cell of the output matrix. Repeat for every row-column combination, and you fill the entire (6 × 6) grid.

The cell at position (i, j) is the dot product of word i's embedding with word j's embedding. This is exactly the operation at the heart of self-attention, as we will see shortly.

01

Input Embeddings

The first layer of both the encoder and decoder is the input embedding. A sentence (e.g., "your cat is a lovely cat") is tokenized — in the simplest case, one token per word; modern models often use sub-word tokenization (BPE, WordPiece), but the pipeline is the same. Each token maps to an input ID: an index into the vocabulary ("your" might be 105, "cat" 6500; the same word always gets the same ID). Each ID is then looked up in a learned table and replaced by a dense vector of size d_model (512 in the original paper) — random at initialization, then trained so the numbers capture meaning.

Input sentence → Tokens → Input IDs → Embedding vectors (seq × d_model)

The result is a matrix of shape (sequence_length × d_model) — in our example, 6 × 512. Each row is one word's embedding. The vocabulary and input IDs are fixed, but the embedding vectors change during training as the model learns to represent meaning.

Terminology note: d_model is the embedding dimension. The original Transformer paper uses d_model = 512. This same dimension is preserved throughout the encoder and decoder — every intermediate representation stays (seq × d_model). Embedding means learned (updated during training); encoding means fixed and computed (as with positional vectors below).

02

Positional Encoding

Embeddings capture meaning, but they carry no information about where a word sits in the sentence. The word "cat" at position 1 has the exact same embedding as "cat" at position 5. We need the model to know that nearby words are close and distant words are far apart.

Sinusoidal positional encoding solves this. For each position pos in the sentence and each dimension i in the embedding vector, we compute a fixed value using sine and cosine functions:

PE(pos, 2i) = sin(pos / 10000^(2i / d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i / d_model))

Even dimensions use sine, odd dimensions use cosine. The argument pos is the word's index in the sentence (0, 1, 2, ...) and 2i is the dimension index along the d_model vector. This creates a unique "fingerprint" for each position — a vector of 512 numbers that we add (element-wise) to the word embedding.

Walking Through the Calculation

Consider the sentence "your cat is" (3 words). We build a PE vector of size 512 for each word. Let's compute a few values explicitly:

Word "your" at position 0:

PE(0, 0) = sin(0 / 100000/512) = sin(0) = 0

PE(0, 1) = cos(0 / 100000/512) = cos(0) = 1

All even dimensions: sin(0) = 0. All odd dimensions: cos(0) = 1. So position 0 has a distinctive pattern: [0, 1, 0, 1, 0, 1, ...].

Word "cat" at position 1:

PE(1, 0) = sin(1 / 100000/512) = sin(1) ≈ 0.841

PE(1, 1) = cos(1 / 100000/512) = cos(1) ≈ 0.540

PE(1, 2) = sin(1 / 100002/512) = sin(1 / 100000.0039) ≈ sin(0.982) ≈ 0.834

The first argument (pos) tells us which word. The second argument (2i) tells us which dimension along the vector. Even dimensions use sine, odd dimensions use cosine.

These vectors are computed once when the model is created and reused for every sentence. They are not learned during training — they are deterministic. Different sentences with different words still get the same positional encoding vectors, because position is about where in the sentence, not which word. If you have a different sentence — say "the dog runs" — you still use the exact same PE vectors for positions 0, 1, 2.

Why sine and cosine? Multiple sine/cosine waves at different frequencies create a unique fingerprint per position — like clock hands rotating at different speeds. Nearby positions have similar fingerprints because the waves change smoothly. The model learns to read this pattern as spatial information.

03

Self-Attention (Single Head)

Now we have embeddings enriched with positional information. The next step is to let words relate to each other. This is the job of self-attention — a mechanism that actually existed before the Transformer. The key innovation of the "Attention Is All You Need" paper was scaling it into multi-head attention and using it as the sole mechanism for sequence modeling, removing recurrence entirely.

Self-attention takes the input matrix (seq × d_model) and uses it as three identical copies: Q (Query), K (Key), and V (Value). The attention formula is:

Attention(Q, K, V) = softmax(Q · KT / √d_k) · V

Multiply Q by KT: If Q is (6 × 512) and KT is (512 × 6), the result is a (6 × 6) matrix. Q and K are both (seq × 512), so K must be transposed to make the inner dimensions match. Each cell is the dot product of one word's embedding with another's — a score for how strongly two words relate.

Scale by √d_k: Divide by √d_k (√512 ≈ 22.6). This prevents dot products from growing too large, which would push softmax into regions with tiny gradients.

Apply softmax row-wise: Each row sums to 1.0 — a probability distribution over how much each word attends to every other word.

Multiply by V: The (6 × 512) result has the same shape as the input, but each word's embedding now captures its relationship with every other word in the sentence.

Properties of Self-Attention

Permutation invariant: If you swap two rows in the input, the corresponding output rows swap too, but their values don't change. The attention score between "cat" and "lovely" stays the same regardless of their position in the matrix.

No learned parameters (yet): Bare self-attention as described here has zero trainable parameters. We just multiply the input by itself (transposed), scale, softmax, and multiply by V again. Parameters will be introduced when we move to multi-head attention.

Diagonal dominance: Each word's dot product with itself is typically the largest value, so the diagonal of the attention matrix tends to be the maximum — each word attends most strongly to itself.

Masking with −∞

There is a powerful property of this attention matrix. Before applying softmax, we can replace any value in the (seq × seq) matrix with −∞. Why would we do this? If we don't want two words to interact — for example, we don't want "your" and "cat" to see each other — we replace their dot product score with −∞. When softmax processes this value, it computes e−∞, which equals zero. The interaction is completely suppressed.

This masking technique is used in the decoder to prevent words from attending to future words (the causal mask). It is also used to mask out padding tokens so they don't influence the attention computation. We will see both uses in detail later.

The Query-Key-Value Analogy

The names come from database terminology: a query searches against keys, and the matching scores weight the values. Dot product → softmax → weighted sum of values.

Key takeaway: Self-attention is "self" because Q, K, and V all come from the same sentence — each word attends to every other word within the same sequence. Later, cross-attention will have Q from one sentence and K, V from another.

04

Multi-Head Attention

Self-attention with a single head captures one "view" of how words relate. But words have many kinds of relationships — syntactic (subject-verb), semantic (synonym), positional (adjacent). Multi-head attention runs multiple attention computations in parallel, each looking at a different aspect of the embeddings.

Here is the process:

Linear projections: Multiply Q, K, V (each seq × d_model) by three learned weight matrices WQ, WK, WV (each d_model × d_model). This produces Q', K', V' — same shape, but now the model has learned what to focus on. WQ, WK, and WV project before attention; WO projects after, mixing head outputs into one representation.

Split into heads: Split Q', K', V' along the d_model dimension into h smaller matrices. If h = 8 and d_model = 512, each head gets matrices of size (seq × 64). We call this smaller dimension d_k = d_model / h.

Parallel attention: Apply the attention formula independently for each head: head_i = Attention(Q'_i, K'_i, V'_i). Each head sees the full sentence but only a slice of the embedding.

Concatenate: Concatenate all heads along the d_k dimension: Concat(head_1, ..., head_h) gives back (seq × d_model).

Final projection: Multiply by WO (d_model × d_model) to mix the independent head views into one unified output — like an editor combining separate reports into one summary.

MultiHead(Q, K, V) = Concat(head₁, ..., head_h) · WO

where head_i = Attention(Q · WiQ, K · WiK, V · WiV)

Why Multiple Heads? Specialization

Each head can specialize. In language, one word may serve as a noun in some contexts, a verb in others, or an adverb in yet others — depending on the surrounding words. We want each head to capture a different kind of relationship. One head might learn to connect nouns with their adjectives, another might link verbs with their subjects, and a third might track pronoun references.

The original paper includes a striking visualization. Consider the word "making" in a sentence. The blue head, the red head, and the green head all strongly connect "making" to the word "difficult" — they see the verb-adjective dependency. But the violet/pink head does not connect "making" to "difficult" at all. Instead, the pink head connects "making" to the word "2009." Why? Because each head sees a different slice of the 512-dimensional embedding. The pink head's 64 dimensions happen to encode temporal or contextual information that links "making" to a year, while the blue head's 64 dimensions encode the syntactic verb-modifier relationship.

This is exactly why we split along d_model (embedding dimension) rather than along the sequence dimension — every head sees all words, but a different aspect of each word. If we split along the sequence instead, each head would see different words with the full embedding, defeating the purpose of learning multiple relationship types.

05

Layer Normalization & Add-and-Norm

After multi-head attention (and again after the feed-forward network), the Transformer applies an Add & Norm step. This has two parts:

1. Residual connection (Add): The output of the sub-layer is added element-wise to its input. This skip connection gives gradients a direct path backward (the same principle as ResNet), so training stays stable even when the attention path would otherwise vanish.

2. Layer normalization (Norm): Each item in the batch is normalized independently. For a single embedding vector (one row of our matrix), we compute the mean and variance of all 512 values, then normalize:

x̂ᵢ = (xᵢ − μ) / √(σ² + ε)

output = γ · x̂ᵢ + β

Here μ and σ² are the mean and variance computed across the 512 dimensions of that single item. γ (gamma) and β (beta) are learned parameters — the model learns to scale and shift the normalized values, amplifying dimensions it considers important.

Layer Norm ✓

Normalizes across features (all 512 dimensions) for each item independently. Batch items don't interact. Works well for variable-length sequences.

Batch Norm ✗

Normalizes across the batch for each feature independently. Mixes information between different items. Doesn't work well with variable sequence lengths.

The Feed-Forward Network

After the Add & Norm that follows multi-head attention, each position passes through a feed-forward network (FFN). The paper defines it as:

FFN(x) = W&sub2; · ReLU(W&sub1; · x + b&sub1;) + b&sub2;

This is two linear layers with a ReLU activation in between. The dimensions are specific: W&sub1; maps from d_model (512) to d_ff (2048), and W&sub2; maps back from d_ff (2048) to d_model (512). So the input expands 4× into a wider internal representation, passes through ReLU (which zeros out all negative values), then compresses back to 512 dimensions. Both layers include learned bias vectors b&sub1; and b&sub2;.

The FFN processes each position independently — no cross-position interaction. It adds non-linearity and extra model capacity. Attention routes information via a weighted average of V vectors (linear on representations); softmax is non-linear only on scores, not on word vectors. The FFN is where complex patterns like "not + good = negative" are learned. The FFN output also goes through an Add & Norm step.

06

The Decoder & Causal Masking

The decoder mirrors the encoder structure — embeddings, positional encoding, multi-head attention, Add & Norm, feed-forward — but with two critical differences:

1. Masked Multi-Head Attention (Causal Mask)

The decoder must be causal: when predicting the output at position t, it can only look at positions ≤ t. It must not peek at future tokens. We achieve this by modifying the attention matrix before applying softmax.

For every position above the main diagonal (where word i would attend to a future word j > i), we replace the dot product score with −∞. When softmax processes e−∞, it outputs 0. The model can't see those positions — they effectively don't exist.

2. Cross-Attention

After masked self-attention, the decoder has a second multi-head attention layer. This one is not self-attention — it's cross-attention. The queries come from the decoder's previous layer, but the keys and values come from the encoder's output.

This is how the decoder "reads" the source sentence. The encoder has already processed the English sentence into rich embeddings that capture meaning, position, and inter-word relationships. The decoder's cross-attention asks: "Given what I've generated so far (query), which parts of the source sentence (keys/values) should I focus on?"

Summary of attention types:

• Self-attention (encoder): Q, K, V all from the same sentence.

• Masked self-attention (decoder): Q, K, V all from the decoder input, with a causal mask.

• Cross-attention (decoder): Q from decoder, K and V from encoder output.

An encoder alone cannot generate text — it is bidirectional, so every token has already seen future tokens. A stack with causal masking but no cross-attention is a decoder-only model (GPT). The encoder/decoder split is largely historical; the mechanical difference is masking strategy plus optional cross-attention.

07

Training: One Pass, All Tokens

Consider a translation task: English → Italian. We want to translate "I love you very much" into "te amo molto."

Encoder input: We prepend and append special tokens: [SOS] I love you very much [EOS]. This gets tokenized, embedded, positionally encoded, and fed through the encoder. The encoder produces a (seq × d_model) output — one rich embedding per token.

Decoder input: We give the decoder the Italian sentence with [SOS] prepended: [SOS] te amo molto.

Fixed-Length Sequences and Padding

In practice, both encoder and decoder inputs are padded to a fixed sequence length. If our model supports a sequence length of 1000 and our sentence has only 4 tokens, we append 996 padding tokens to fill the remaining positions. Every sentence in a batch becomes the same length. These padding tokens are special vocabulary entries that carry no meaning — we use the masking mechanism (setting attention scores to −∞) to ensure they don't participate in attention computations.

Label (target): The expected output is: te amo molto [EOS]. Notice the shift: the decoder input is shifted right by one position relative to the label. When the decoder sees [SOS], it should predict "te." When it sees "te," it should predict "amo." When it sees "molto," it should predict [EOS].

Decoder input:   [SOS]   te   amo   molto
Target label:     te   amo   molto   [EOS]

The decoder output (seq × d_model) is projected through a linear layer to (seq × vocab_size), then softmax is applied. Each position now has a probability distribution over the entire vocabulary. We compute the cross-entropy loss between these predictions and the target labels, then backpropagate.

The power of parallel training: Unlike RNNs, all of this happens in one forward pass. We give one input sequence to the encoder, one input sequence to the decoder, produce all outputs, compute the cross-entropy loss with the labels, and backpropagate — all in a single time step. No for-loop over tokens. This is what makes Transformers dramatically faster to train than RNNs on long sequences.

This training strategy is called teacher forcing: during training, we give the model the correct previous tokens as decoder input rather than the model's own predictions. The causal mask ensures the decoder can't peek at future positions, so each position genuinely predicts the next token from only the tokens before it. The result: one sentence generates multiple training examples simultaneously (position 0 predicts token 1, position 1 predicts token 2, and so on).

08

Inference: Token by Token

During inference (generation), we don't have the target sentence. We must produce it one token at a time.

Time step 1: Feed the English sentence through the encoder (once). Give the decoder just [SOS]. The decoder produces logits → softmax → the word with the highest probability is selected. Hopefully: "te."

Time step 2: Append "te" to the decoder input: [SOS] te. Feed through the decoder again (the encoder output is reused — we don't recompute it). The model predicts: "amo."

Time step 3: Decoder input: [SOS] te amo → predicts "molto."

Time step 4: Decoder input: [SOS] te amo molto → predicts [EOS]. We stop.

Notice that while training is fully parallel (one pass), inference is sequential — we need the previous output to generate the next one. This is the autoregressive nature of the Transformer decoder. If the model predicts a wrong token during inference, that error is fed back as input and can compound — exposure bias, because training always used correct tokens (teacher forcing) but inference uses the model's own predictions.

Encoder reuse: We compute the encoder output only once at time step 1, then reuse it at every subsequent time step. The English sentence doesn't change, so the encoder should always produce the same output. What changes at each step is only the decoder input — it grows by one token each time as we append the previous prediction.

Decoding Strategies

The strategy described above — always picking the token with the highest softmax score — is called greedy decoding. It's simple but not always optimal. A locally best token can lead to a globally worse sequence.

Beam search is a better alternative. Instead of keeping just the single best token at each step, beam search keeps the top B candidates (where B is the "beam width," typically 4–10). At each step, it expands all B candidates by generating the next possible tokens for each, scores the resulting sequences, and keeps only the top B most probable sequences. The others are discarded. This explores a wider space of possible translations and generally produces better results, because a locally sub-optimal token choice might lead to a globally superior sequence.

Greedy Decoding

Pick the single highest-probability token at each step. Fast, but can miss better sequences.

Beam Search

Keep top B candidates at each step. Explores more possibilities. Slower but produces higher-quality output.
