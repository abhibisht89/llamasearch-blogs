Mamba, S4 & State-Space Sequence Layers

From continuous ẋ = Ax + Bu through zero-order-hold discretization, dual recurrent–convolution views, HiPPO-structured S4 (Efficiently Modeling Long Sequences with Structured State Spaces), selective Δ,B,C in Mamba (Mamba: Linear-Time Sequence Modeling with Selective State Spaces), parallel scans, and fused GPU kernels — plus Mamba-2 / SSD as a structured attention layer.

00

Why state-space layers?

Transformers scale training cost roughly as O(L²) in sequence length L for the attention block. RNNs are O(L) per layer but resist parallel training across time. SSM layers aim for O(L) sequence-mixing with structured A so convolution and scan tricks apply.

A linear time-invariant (LTI) SSM is defined by (A,B,C,D) matrices (or tensors over channels). The hidden x carries memory; input u drives transitions; output y reads state. Deep models stack MambaBlock-style modules where u is a projected token stream.

Recurrent picture

Step with x_k = Āx_{k-1} + B̄u_k. Inference keeps one x per channel — O(1) state per step.

Convolution picture

When Ā,B̄,C do not vary with k, y is a causal conv1d of u with a fixed kernel — train with fft or Winograd-style fast paths.

A sequence model maps an input sequence to an output sequence. The input may be a continuous signal (for example audio) or a discrete signal (for example text after tokenization). Even audio is usually handled as discrete samples over time.

RNN

Hidden state updated sequentially; training resists parallelization across time; inference is roughly constant per step but long-range gradients vanish.

CNN on sequences

Shared kernel over a local window; training parallelizes across positions; receptive field grows with depth or dilation.

Transformer

Parallel training via attention, but cost scales ~O(L²); inference with a KV cache grows work with prefix length.

Ideal target

Parallel training like a Transformer, linear sequence-mixing cost, and roughly constant work per decoded token.

State-space sequence layers target that sweet spot: structured linear dynamics give a recurrent story for constant-memory decoding and a convolution or scan story for parallel training when parameters are shared across time.

01

Continuous-time SSM: ẋ = Ax + Bu

In control notation the latent x(t) ∈ ℝⁿ evolves under A ∈ ℝⁿˣⁿ, driven by input u(t) through B. Outputs y(t) = Cx(t) + Du(t) are read without storing full history. Neural SSM layers choose (A,B,C,D) (often diagonal or HiPPO-structured) so that discretization stays stable.

ẋ(t) = A x(t) + B u(t), y(t) = C x(t) + D u(t)

Warm-up: one scalar ODE before the full matrices

Start with exponential growth Ḃ = λ B (rate λ = 2 in the demo). Discretizing with step Δ gives the recurrence B(t+Δ) ≈ (1 + Δλ) B(t)—the same “next state is a linear function of the previous state” pattern as x_k = Ā x_{k−1} + B̄ u_k, but without an input term yet.

Ḃ(t) = λ B(t) → B(t+Δ) ≈ (1 + Δλ) B(t)

Large Δ makes explicit Euler diverge from the smooth exponential; production SSM code prefers zero-order hold (ZOH) discretization (Ā = exp(ΔA)) when Δ is learned and not infinitesimal.

Discretizing the full linear SSM

In implementation you usually do not hand-pick Δ as a fixed sampling period. Δ (or a positive map of it such as softplus) is a learned quantity, tuned by gradient descent from data, possibly varying per channel or per token in selective models.

Discretization picks a step Δ (scalar or per-channel). Euler gives Ā ≈ I + ΔA, B̄ ≈ ΔB. ZOH integrates exact linear dynamics between samples: Ā = exp(ΔA), B̄ = A⁻¹(Ā − I)B when A is invertible; diagonal A makes this elementwise.

From ODE to tensors

In PyTorch, A may be shape (D, N) for D independent SSM heads. Inputs u arrive as (B, L, D) after projection from token embeddings. The continuous view explains why torch.exp(delta * A) appears instead of 1 + delta * A in production mamba-ssm style code.

02

Discrete recurrence: xₖ = Āxₖ₋₁ + B̄uₖ

Unrolling with x₋₁ = 0 yields a causal map from u₀…uₖ to xₖ. Each step is one multiply-add per state dimension — ideal for autoregressive decoding where only the newest u arrives.

xₖ = Ā xₖ₋₁ + B̄ uₖ, yₖ = C xₖ + D uₖ

Step-by-step unrolling (scalar or block view)

Assume initial state x₋₁ = 0 and a discrete input u₀, u₁, u₂, …. The first state has no contribution from Ā x₋₁:

  • State h₀ / x₀: x₀ = B̄ u₀ (only the input injection term).
  • Output y₀: y₀ = C x₀ (and optionally + D u₀ when D is used).
  • Next state: x₁ = Ā x₀ + B̄ u₁, then y₁ = C x₁.
  • Continue: x₂ = Ā x₁ + B̄ u₂, y₂ = C x₂, and so on — the same pattern as a classic RNN, which is why this family is called recurrent.

At each step the work is structurally the same: one transition from previous state plus input, then one readout. That is why inference cost per token stays O(1) in depth for a fixed-width layer: producing y₉ is not inherently more expensive in layer depth than producing y₁ — you always apply one Ā, one B̄ injection, one C (per channel).

Training is another matter: when the whole sequence u₀…u_{L−1} is known upfront, you do not want a strict serial loop over L just to compute losses — you want a parallel path. That is where the convolution view (fixed Ā,B̄,C) or a parallel scan (time-varying parameters) enters.

03

Convolution mode and the global convolution theorem

Expanding the recurrence (scalar or diagonal case) gives y_k = Σⱼ≤ₖ C Ā^{k-j} B̄ u_j. That is causal convolution: kernel taps K̄[i] ∝ Ā^i (up to ordering). For length-L training, FFT convolution computes circular convolution in O(L log L); zero-padding enforces causality.

Why the kernel is CB, CĀB, CĀ²B, … (and how sliding matches the recurrence)

Unrolling the same update as in the previous section, the pattern for the readout at index k is: current input u_k weighted by C B̄, plus u_{k−1} weighted by C Ā B̄, plus u_{k−2} weighted by C Ā² B̄, and so on, up to u_0 multiplied by C Ā^k B̄. So the causal kernel’s taps are proportional to C B̄, C Ā B̄, C Ā² B̄, … (ordering conventions flip when matching conv1d’s filter direction — implementers reverse the tap list to align PyTorch’s convolution with the recurrence).

First position. Only u_0 lies in the causal window, so y_0 = (C B̄) u_0 — one tap times one input.

Second position. The window contains u_0, u_1. The contribution from the current input is (C B̄) u_1; from the previous input (C Ā B̄) u_0. That matches the expanded expression for y_1 obtained by substituting x_1 = Ā B̄ u_0 + B̄ u_1 into y_1 = C x_1.

Third position. Similarly y_2 = (C B̄) u_2 + (C Ā B̄) u_1 + (C Ā² B̄) u_0. Continuing this way shows that convolution with the constructed kernel reproduces the serial recurrence for every k.

Parallel training angle: each y_k can be formed as an inner product of the (reversed, zero-padded) kernel against the input segment — different k do not depend on having computed y_{k−1} first. Many y_k can therefore be scheduled in parallel on a GPU, unlike the strict state-machine recurrence.

Building or FFT-ing a long kernel has its own cost and memory footprint. For very long L, structured parameterizations (as in S4) avoid materializing a dense length-L impulse response naively in global memory.

The D term as a skip around the dynamics

When the full readout y = C x + D u is written out, the D u piece does not pass through the integrator: it is an immediate feed-through from input to output at each time. In block diagrams, that is exactly a skip path parallel to the state update. Many papers suppress D in the main exposition when it is zero or absorbed into other projections, but the structural role is “direct path” versus “state-filtered path.”

Vector channels: independent SSMs per feature (Transformer analogy)

Language models embed each token as a vector — for example width 512 in a “vanilla” Transformer setup. A practical SSM layer runs one scalar (or low-dimensional) SSM per feature dimension (per head or per channel), so 512 features might mean 512 independent structured dynamics, analogous to splitting 512 channels across 8 attention heads of 64 dimensions each: subspaces are processed in parallel and independently before later mixing layers.

Kernel length: In exact form the kernel is infinite; in practice truncate at L or use structured S4 to evaluate outputs without materializing full L kernels in HBM.

Recurrent vs conv in torch

Training often uses F.conv1d with flipped kernel. Inference streams with the for-loop recurrence. They must bitwise-match for fixed Ā,B̄,C.

Parallel scan: O(log L) depth associative reduction

    
Prefix sum s_k = s_{k-1} + u_k is a scan. More generally, if each step is an associative binary op on a lifted state, Blelloch-style parallel prefix yields logarithmic-depth parallel time. For SSMs the “combine” packages (Ā, B̄ u) into affine updates; selective scans use input-dependent parameters so the operator changes per step — still scan-shaped, fused in CUDA.

    
Prefix sums as the familiar picture of a scan

    
In competitive programming and basic algorithms, a prefix sum array is built so that each entry stores the sum of all earlier inputs up to that index. Starting from an array such as [10, 7, 6, 9, …], you compute sequentially: the first prefix entry is 10; the next is previous prefix plus current element 10 + 7 = 17; then 17 + 6 = 23; then 23 + 9 = 32. The value 32 is therefore 10 + 7 + 6 + 9 — the running total through that position.

    
A scan is the generalization: each position combines the previous accumulated value with the current input under some rule. The linear recurrence of an SSM,

    
x_k = Ā x_{k−1} + B̄ u_k

    
is scan-shaped: the new state is a fixed affine function of (x_{k−1}, u_k). Once outputs y_k = C x_k are needed, you can multiply each scanned state by C.

    
Parallelizing a scan: associativity

    
Scans look sequential because x_k seems to “need” x_{k−1}. They can still be parallelized when the pairwise combination is associative: (a ⊕ b) ⊕ c = a ⊕ (b ⊕ c) (the same idea as (a·b)·c = a·(b·c) for multiplication, or (a+b)+c = a+(b+c) for addition). For SSMs one lifts each step to an affine map and uses a custom associative “multiply” on pairs (α, β) representing x ↦ α x + β; composing two steps corresponds to multiplying those pairs. That is exactly the combine pattern in the code sketch below.

    
Parallel prefix algorithms (often illustrated with a tree: adjacent pairs summed in parallel, then pairs of those results, and so on — sources such as Wikipedia use 16-element examples; the same idea scales to 8, 32, …) proceed in rounds: first round combine neighbors, then combine results at stride two, then stride four, and so on, followed by a downward phase to fill missing prefix values. Informally you may see this described as a sweep down / reduce phase and a complementary pass to propagate full prefixes.

    
With T parallel workers, wall-clock depth drops toward O(\log n) rather than a single long chain. Once Ā_k, B̄_k vary per step because selective Δ, B, C depend on the token, there is no single convolution kernel—training uses a parallel selective scan instead.

    05
    
S4: HiPPO initialization and structured A

    
S4 (Structured State Space Sequence) constrains A via HiPPO theory so coefficients of orthogonal polynomials encode history — good memory of recent inputs, controlled forgetting. Implementation uses diagonal-plus-low-rank or normal-plus-low-rank forms for O(L) computation without dense L×L materialization.

    
Intuition: Fourier versus Legendre, local versus decayed global

    
A Fourier decomposition expresses a signal as a sum of sinusoids with different amplitudes; adding them reconstructs the original. HiPPO-style state spaces use a related mathematical idea with a different basis: Legendre polynomials (orthogonal polynomials on a bounded interval) instead of sines and cosines. The structured A matrix is built so that the hidden state coefficients act like coordinates in that basis summarizing the past input.

    
Reconstructing the input trajectory from the state tends to match recent time steps accurately, while older time steps are represented more coarsely — similar in spirit to an exponentially weighted emphasis on the present. For language modeling, that bias is appealing: the next token depends strongly on nearby context; tokens far in the past matter, but can often be summarized more aggressively than the immediate neighborhood.

    
Why the A matrix matters (control-theory angle)

    
In classical state-space control, A governs how past state feeds forward and is central to stability: poorly chosen A can blow up or forget everything. In sequence modeling, A similarly controls how information from prior positions is carried into the next hidden state. If A does not implement a good “memory policy,” the model cannot aggregate the prompt faithfully when predicting the next token.

    
The structured-state paper Efficiently Modeling Long Sequences with Structured State Spaces (the S4 line of work) reports that initializing the generator matrix from the HiPPO construction (skew-symmetric / triangular patterns with closed-form entries — upper triangle zero, diagonal and below-diagonal terms given by closed formulas involving indices i, j) yields a large empirical gain, because the recurrent dynamics start in a regime that already compresses history usefully before much gradient-based adaptation.

    
Your takeaway: A is not a free dense learnable matrix in baseline S4; structure + initialization buys stability and long context before Mamba makes B,C,Δ input-dependent.

Mamba: selective Δ, B, C

    
When Δ, B, C (and thus discretized Ā, B̄) depend on input token features, the system is time-varying: no single fixed conv1d kernel. Training uses a parallel selective scan kernel; inference still streams O(1) state.

    
What breaks in plain LTI SSMs: two synthetic diagnostics

    
The Mamba paper highlights tasks where vanilla (time-invariant) state-space layers and S4-style structured models struggle.

    
Shifting copy. Given a sequence of colored tokens, output the same stream shifted in time. A fixed linear convolution can learn a pure delay — the same parameters at every position already implement “move everything one step.”

    
Selective copying. Given a sequence where some positions are “blank” or irrelevant (for example white slots among colored ones), copy only the informative tokens into the output, skipping the blanks. A strictly time-invariant SSM applies the same A,B,C,D at every index: it cannot switch behavior based on which token arrived. There is no content-based route that says “ignore this symbol but propagate that one.”

    
A concrete analogy: you are asked to rewrite a social post by deleting every profanity while keeping the rest. Tokens to drop versus keep depend on the content of the message, not merely on their positions. A model that must treat position k identically for all sentences cannot implement that policy.

    
Induction-head-style recall. Another diagnostic asks the model: whenever you see a special trigger token (say a black marker), output the token that appeared in an earlier learned association (say blue). That requires remembering what occurred before, conditioned on the current symbol — again, content-based routing. Time-invariant linear dynamics alone do not provide a per-token gate that reweights memory and input injection.

    
From both the recurrent viewpoint (how Ā, B̄ blend state and input) and the convolutional viewpoint (a single shared kernel), the missing ingredient is input-dependent parameters. Mamba supplies that by making Δ, B, C (hence discretized Ā, B̄) functions of the current hidden features.

    
Shapes: batch, length, model width, state width

    
As with Transformers, activations are organized as (B, L, D): batch, sequence length, model dimension (for example D = 512 in a typical embedding size). The baseline SSM uses a structured A of size D × N (one state of width N per feature channel in the diagonal / structured setup), with B, C also aligned to D and N, and one learned Δ per channel after whatever positive parametrization you choose.

    
In Mamba, learnable linear maps S_B, S_C (names vary by codebase) project the per-token hidden vector from dimension D into the state width N for B and C, introducing an explicit L axis in the effective parameters: B, C, Δ become tensors of shape like (B, L, D, N) after broadcasting / heads. After discretization, Ā_k, B̄_k vary with step index k, so the dynamics are not time-invariant and the FFT convolution trick for a single global kernel no longer applies — you run the recurrence, accelerated by selective scan + fusion.

    
Selective copying / induction heads need content-based routing. Fixed LTI SSMs treat every position identically — silu-gated selective parameters fix that bottleneck.

Mamba block: conv1d → selective SSM → gate

    
One block: rms_norm residual in, expand to d_inner, short causal conv1d for local mixing, then selective SSM core, multiply by silu branch, project back. Stacks interleave with MLP or SwiGLU-style FFN in full models.

    
Inside the block (width expansion and local mixing)

    
Let D_model be the residual width (for example 512 as a running example). Two linear projections map into an inner width D_inner, often chosen as a multiple such as 2 × D_model — the public implementations call this expansion “inner” explicitly. One branch feeds a short-depth causal convolution across time so channels mix before the SSM core; without that local mixing, independent per-dimension SSMs would never blend information across features inside the block.

    
The SSM path computes the selective scan (parallel on GPU during training). A parallel branch applies SiLU (also known as Swish with β = 1, the sigmoid-linear unit) and the two streams are multiplied elementwise — gating the SSM output. A final linear projects from D_inner back to D_model, then a residual add combines with the sublayer input (pre-norm layout matches common Transformer practice).

    
Full language-model stack (macro view)

    
Token IDs embed into vectors of size D_model. A stack of N repeated blocks applies the Mamba sublayer (with its norm and skip) plus feed-forward / MLP-style sublayers depending on the published hybrid. After the last block, an RMSNorm (as in LLaMA / Mistral-style stacks) precedes a linear map to vocabulary logits and a softmax for next-token probabilities during autoregressive generation.

Reported behavior on synthetic diagnostics and scaling (Mamba paper)

    
On selective copying, structured SSM baselines such as S4 trail badly while the selective layer used in Mamba (sometimes denoted S6 in figures contrasting against the earlier S4 block) reaches on the order of 99.8% accuracy — the intended demonstration that input-dependent Δ, B, C unlock content-aware filtering that fixed LTI cores miss.

    
On induction-style recall evaluated out to extremely long contexts, reported curves show Mamba near 100% accuracy even at sequence lengths around 10⁶, whereas Transformer variants with absolute or rotary position encodings eventually degrade as length grows into the thousands (they may remain strong in the low hundreds of tokens, then soften). Exact crossing points depend on task setup; the qualitative claim is robust long-context recall on those synthetic protocols.

    
For language modeling quality versus compute, published comparisons place Mamba-class models in the same ballpark as strong Transformer baselines in the LLaMA / Mistral generation of architectures at matched-ish training budgets — the perplexity–throughput frontier is competitive even before accounting for linear-time sequence mixing advantages on long contexts. Practical wins accumulate when prompts or retrieved context grow large (retrieval-augmented setups, long chats, multimodal sequences).

    
Open research questions remain: selective SSMs are still fundamentally a recurrent computation graph, and scaling laws on the largest web-scale corpora used to train the biggest attention LMs are still being mapped out. The field treats Mamba as a compelling alternative axis, not a drop-in proof that attention is obsolete at every scale.

Kernel fusion: SRAM vs HBM

    
Each separate torch op may write a full tensor to HBM. Fused CUDA/Triton keeps Δ, discretized matrices, and running x_k in SRAM registers / shared memory — one write of y instead of four intermediate tensors. Recomputation in backward can trade extra FLOPs for lower activation memory on long L.

    
GPU memory hierarchy (why bandwidth dominates)

    
Accelerators such as the NVIDIA A100 expose two headline numbers that are easy to misread against each other: on the order of ~20 TFLOPS of FP32-style compute versus on the order of ~2 TB/s of memory bandwidth for the high-capacity HBM (“DRAM” in marketing sheets). In back-of-the-envelope ratios quoted for that generation, the peak arithmetic rate can land about 40× higher than what global memory can sustain in practice — so a kernel that repeatedly spills to HBM may be IO bound long before it is compute bound. On-chip SRAM is far smaller (megabytes-class scratch space where warps actually execute) but sits next to the execution units.

    
The selective scan implementation therefore tries to materialize trajectories of the hidden state mainly in SRAM: load Δ, A, B, C (and activations) from HBM into fast memory, run discretization and the scan recurrence there, and write only the final outputs back to HBM, instead of spilling every intermediate tensor after each sub-operation.

    
What “kernel fusion” means operationally

    
Suppose a framework runs three elementwise or small tensor ops in sequence on the same data. A naive schedule loads from HBM → computes kernel 1 → stores to HBM → loads again → kernel 2 → stores → loads again → kernel 3 → stores. Most elapsed time can be the round trips, not the arithmetic.

    
Fusion rewrites those three stages as one custom CUDA kernel so intermediate values live in registers / shared memory until the chain finishes; only the last result returns to HBM. That removes two full write/read cycles in the toy example — and the same principle scales to the SSM discretization + scan + gating pipeline.

    

      
Unfused
proj_delta → store → reload → exp → store → reload → scan → … High DRAM traffic dominates.

      
Fused
Single kernel: load tile of x, compute Ā,B̄ on the fly, update state, write y tile — approaches compute-bound regime.

    

    
Recomputation versus caching activations

    
Back-propagation normally caches forward activations at each graph node so gradients can flow backward through products and nonlinearities. Those caches can dominate memory on long sequences. The Mamba authors instead apply the classical recomputation trick: do not keep every intermediate state in HBM; during the backward pass, reload the cheap-to-fetch inputs and re-run the forward recurrence locally in fast memory when needed.

    
As stated in the paper discussing the selective scan implementation: “Finally, we must also avoid saving the intermediate states which are necessary for backpropagation. We carefully apply the classic technique of recomputation to reduce the memory requirements of the intermediate states. These intermediate states are not stored in the high bandwidth memory but recomputed during the backward pass when the inputs are loaded from the high bandwidth memory to the fast SRAM.” Recomputation wins when extra arithmetic is cheaper than spilling huge activation tensors to HBM and reading them back.

Mamba-2 and the SSD layer

    
The selective-scan story above — continuous SSM, ZOH discretization, convolution when LTI, parallel scan when time-varying, fusion, and recomputation — forms the core stack for Mamba. Mamba-2 / SSD is a later algorithmic layer that re-expresses similar dynamics in a block matrix form amenable to tensor-core matmuls; keep it in mind as an engineering upgrade path once the recurrent / scan picture is solid.

    
Mamba-2 reframes selective SSMs as a structured form of state-space duality (SSD): the same layer can be computed via a blockwise attention-like factorization or via SSM mode, improving hardware utilization on GPU tensor cores. Think chunked matmuls with a semiseparable mask rather than materializing full L×L attention.

    
SSD(L) ≈ structured masked attention + diagonal state carry (conceptual)
