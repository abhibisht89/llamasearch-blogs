Variational Autoencoders: ELBO, Latent Space & Math

00

Why variational autoencoders matter

A variational autoencoder (VAE) is a standard building block for models that compress high-dimensional observations into a latent space and generate new samples by decoding random draws from that space. The same probabilistic picture—approximate posterior, reconstruction likelihood, KL to a simple prior—shows up wherever you train a deep generative model with an explicit latent variable.

In latent diffusion (Stable Diffusion–style pipelines), a VAE maps pixels to a lower-dimensional tensor and a diffusion model denoises in that space. ELBO, the decoder p(x|z), and the approximate posterior q(z|x) are the same machinery that shapes those latents before diffusion runs.

01

Autoencoders: bottleneck compression

A plain autoencoder is two networks: an encoder maps input x to a low-dimensional code z; a decoder maps z back to a reconstruction x̂. The goal is to keep the code small while making x̂ close to x.

Concretely, imagine a file named zebra.jpg. If you compress it into zebra.zip and then decompress, you expect to recover the same image: classical compression is built to be (near) lossless or controlled-loss. An autoencoder is not guaranteed to recover every bit. It is a neural network: it learns a mapping whose bottleneck is small, and it is trained so the reconstruction matches the input as well as the loss allows—pixel-wise MSE, a Bernoulli likelihood on pixels, or another choice—but not necessarily exactly.

What makes a good autoencoder, in the classical sense? First, the code should be as small as possible: the bottleneck should squeeze out redundancy. Second, the reconstruction should be as close to the original input as that small code allows. Those two desires pull against each other; training finds a compromise.

The deeper problem is semantics. The encoder may learn an arbitrary hash of the dataset: the code for a photograph of a tomato might sit next to the code for a zebra, and the code for a cat might resemble the code for a pizza. Nothing in the plain autoencoder objective forces neighborhoods in z to respect categories or attributes. The model memorizes a mapping from inputs to codes; it does not, by itself, organize z so that “food,” “animals,” “cars,” or “buildings” form coherent regions you can navigate or sample from.

Plain autoencoder

Encoder outputs a single vector z = fφ(x). Training pushes reconstructions toward x while keeping the bottleneck small. Sampling or interpolating in z is not part of the contract—so the geometry of z can be irregular or meaningless for generation.

Variational autoencoder

Encoder outputs a distribution qφ(z|x) (often Gaussian parameters). Training maximizes a lower bound on log p(x) that includes a KL penalty to a prior p(z). The latent space is shaped for sampling and for smooth semantic structure when the model and data cooperate.

Deterministic AE

Encoder outputs a single vector z = fφ(x). No distribution—just a point in latent space. Interpolation between codes can produce meaningless decodings because the space is not organized as a smooth generative manifold.

VAE

Encoder outputs parameters of a distribution qφ(z|x) (typically Gaussian mean and variance). You sample z, decode, and regularize so the aggregate posterior stays close to a chosen prior p(z)—enabling meaningful sampling and interpolation.

02

Latent space, semantics, and sampling

A weakness of standard autoencoders is that the learned code can be an arbitrary hash: unrelated inputs may land near each other in z, and there is no guarantee that Euclidean geometry in the bottleneck reflects semantic similarity (e.g. unrelated object categories with adjacent codes).

A VAE instead learns a latent distribution over data—conceptually, a multivariate distribution over the data, not a single code vector per example. The hope is that this distribution captures semantic structure: all food images occupy a region related to other food images, all animals relate to other animals, and similarly for cars, buildings, or a stadium versus other structures. The organizing principle is statistical proximity in z, not hand-labeled taxonomies.

Sampling the latent space means: draw a random vector z from a distribution (often the prior), run the decoder, and read off a synthetic x. That is the same idea as using Python to draw an integer uniformly from 1 to 100: each draw is a sample from the uniform distribution because every outcome in the range has the same probability. Here, the distribution is typically Gaussian (or another choice), but the sampling metaphor is identical—z is random, the decoder is deterministic given z.

Suppose a VAE was trained on food photographs. If you sample a point in latent space that lies between three training images—say, egg, flour, and basil leaves—you hope the decoder produces something semantically in the same family, such as pasta with basil. That would indicate the model has learned relations in the training distribution rather than isolated memorized codes.

Why “latent”? We observe x but posit a hidden variable z such that x is generated conditioned on z. Latent means not directly observed. A common modeling choice is p(z) = 𝒩(0, I) and qφ(z|x) = 𝒩(μφ(x), diag(σφ²(x))).

Plato’s allegory of the cave is a compact metaphor: prisoners see only shadows on a wall, not the objects casting them. Observed data x plays the role of those shadows; the generative model posits a hidden cause z we never measure directly, and the VAE learns approximate inference for z given x.

03

Variational inference and the intractable marginal

Tools you will use repeatedly

Three ideas show up in almost every derivation of the ELBO: the expectation of a function of a random variable (an integral or sum against a density), the chain rule of probability (factorizations such as p(x, z) = p(x|z)p(z)), and Bayes’ rule (relating p(z|x) to p(x|z) and p(x)). They are standard undergraduate probability; what follows applies them in a specific pattern.

A fourth object is Kullback–Leibler (KL) divergence. Given two distributions P and Q (discrete or continuous on a common support), KL measures how much information is lost if you approximate P with Q. It is not a distance in the metric sense: in general KL(P ‖ Q) ≠ KL(Q ‖ P). Physical distance from A to B matches B to A; KL does not obey that symmetry. Nonetheless, KL(P ‖ Q) ≥ 0, and KL(P ‖ Q) = 0 if and only if the two distributions are the same (on the support where the definition is finite).

KL(P ‖ Q) = 𝔼x∼P[ log P(x) − log Q(x) ]   (continuous case: ∫ p(x) log(p(x)/q(x)) dx when defined)

We posit a generative story: sample z ∼ p(z), then sample x ∼ pθ(x|z). The marginal density of observations is

pθ(x) = ∫ pθ(x|z) p(z) dz .

For flexible neural pθ(x|z), this integral is generally intractable: you could define it on paper, but computing it by brute force over the latent space is prohibitively expensive. “Intractable” here means: in principle the quantity exists, but exhaustive computation is so slow or so memory-heavy that it is not a viable algorithm. A vivid analogy is guessing a neighbor’s Wi‑Fi password: in theory you could enumerate every possible string and try each one; in practice the search space makes that approach useless on human timescales.

The true posterior pθ(z|x) = pθ(x|z)p(z) / pθ(x) is also hard because it divides by pθ(x). You want pθ(x) (learning) and pθ(z|x) (inference), but each seems to require the other—a chicken-and-egg loop.

The way out is variational inference: introduce a tractable approximate posterior qφ(z|x) with its own parameters φ, and fit (θ, φ) so that qφ is close to the true posterior while improving the generative model.

You can also write the marginal using the joint and marginalize over z, but the same obstacle appears: integrating over all latent z with a rich decoder is what blocks closed-form likelihood evaluation. Meanwhile, the quantity pθ(z|x) depends on pθ(x), which is what you are trying to compute—so treating learning and exact inference as naïvely separable leads straight back to the chicken-and-egg loop.

When you cannot compute exactly what you want, the standard move is to introduce a surrogate you can optimize. The ELBO is that surrogate: a lower bound on log pθ(x) built from expectations under qφ(z|x).

Demo: Kullback–Leibler divergence is asymmetric

KL(p ‖ q) measures how much information is lost when q is used to approximate p. It is not a metric: KL(p ‖ q) ≠ KL(q ‖ p) in general. It is always ≥ 0, and equals 0 only when the distributions match (on the support). Adjust means of two 1D Gaussians with fixed variance.

04

From log-likelihood to the ELBO

Training seeks parameters θ that assign high density to observed data: we care about log pθ(x) for each example x (or sums over a dataset). The obstacle is that pθ(x) is the marginal obtained from pθ(x|z) and p(z), and that marginal is hard to evaluate. The ELBO is derived by exact algebra starting from log pθ(x)—no approximation in the identities—until a non-negative KL term appears and can be dropped from the bound.

For fixed x, introduce any tractable density qφ(z|x). Since ∫ qφ(z|x) dz = 1 and log pθ(x) does not depend on z,

log pθ(x) = ∫ qφ(z|x) log pθ(x) dz = 𝔼qφ(z|x)[ log pθ(x) ] .

For every z with pθ(z|x) > 0, Bayes’ rule gives log pθ(x) = log pθ(x, z) − log pθ(z|x). Averaging under z ∼ qφ(z|x):

log pθ(x) = 𝔼qφ(z|x)[ log pθ(x, z) − log pθ(z|x) ] .

Factor the joint with the generative model, pθ(x, z) = pθ(x|z) p(z):

log pθ(x) = 𝔼qφ[ log pθ(x|z) + log p(z) − log pθ(z|x) ] .

Now add and subtract log qφ(z|x) inside the expectation—again, adding zero pointwise:

log pθ(x) = 𝔼qφ[ log pθ(x|z) + log p(z) − log qφ(z|x) ] + 𝔼qφ[ log qφ(z|x) − log pθ(z|x) ] .

Identify the two KL divergences. By definition, KL(qφ(z|x) ‖ p(z)) = 𝔼qφ[log qφ(z|x) − log p(z)], so 𝔼qφ[log p(z) − log qφ(z|x)] = −KL(qφ ‖ p(z)). The second expectation is KL(qφ(z|x) ‖ pθ(z|x)) = 𝔼qφ[log qφ(z|x) − log pθ(z|x)] ≥ 0.

KL( qφ(z|x) ‖ pθ(z|x) ) = 𝔼qφ[ log qφ(z|x) − log pθ(z|x) ] ≥ 0 .

Collecting terms:

log pθ(x) = 𝔼qφ(z|x)[ log pθ(x|z) ] − KL( qφ(z|x) ‖ p(z) ) + KL( qφ(z|x) ‖ pθ(z|x) ) .

The final KL is non-negative, so log pθ(x) ≥ ELBO(x). Define the evidence lower bound (ELBO):

ELBO(x) = 𝔼qφ(z|x)[ log pθ(x|z) ] − KL( qφ(z|x) ‖ p(z) ) .
log pθ(x) = ELBO(x) + KL( qφ(z|x) ‖ pθ(z|x) )  ≥  ELBO(x) .

Equivalent form and “reverse” KL bookkeeping

By regrouping the same expectations, the ELBO is often written to display reconstruction minus KL to the prior explicitly (the form used in implementations). Starting again from log pθ(x) = 𝔼q[log pθ(x|z) + log p(z) − log qφ(z|x)] + KL(q‖pθ(z|x)), the part before the trailing KL is exactly 𝔼q[log pθ(x|z)] − KL(qφ‖p(z)). Some textbook steps instead exhibit a minus sign in front of a KL because they expand a different KL orientation (reverse KL) relative to the first display; the key invariant is always: log p = ELBO + (a non-negative gap).

Do not confuse KL(qφ ‖ p(z)) with KL(qφ ‖ pθ(z|x)). The former compares the approximate posterior to the prior—that is the KL you regularize with in the standard Gaussian VAE. The latter compares q to the true posterior; it is the gap between bound and evidence. They are different objects, and KL is not symmetric, so swapping arguments changes the measure entirely.

What maximizing ELBO does

Equivalently, ELBO is often written as reconstruction expectation minus KL to the prior. Maximizing ELBO therefore:

  • Increases 𝔼qφ[log pθ(x|z)]—the decoder explains the data well when latents are drawn from the encoder’s distribution.
  • Decreases KL(qφ(z|x) ‖ p(z))—latents stay close to the prior (typically standard Gaussian), which makes the latent space smooth enough to sample from at generation time.

Maximizing ELBO therefore increases expected reconstruction quality and shrinks KL to the prior, keeping the latent space smooth enough to sample from at generation time.

Gradients through stochastic latents: reparameterization

Why “gradient descent” in code is usually stochastic

When you minimize a smooth loss, the prototype is gradient descent: move parameters opposite the gradient. Picture a convex bowl: your current weights sit somewhere on the surface; the gradient points uphill along steepest ascent, so stepping against it reduces the loss. When you maximize an objective, you step with the gradient instead. Deep models reuse the same calculus, even when the loss landscape is far from convex.

In real training loops you almost never evaluate the gradient on the entire dataset before each update. True gradient descent would require a pass over all examples to get the exact gradient of the full loss. Stochastic gradient descent uses a minibatch: you estimate the gradient from a subset. That estimate is a random variable—different batches yield slightly different directions. Over one full epoch (enough batches to cover the data once), those estimates average toward the true gradient under standard assumptions; that is why the method is called stochastic. The estimator has a mean (what you want) and a variance (noise). For many supervised losses the variance is small enough that SGD works reliably.

The expectation 𝔼qφ[·] involves sampling z. A naive Monte Carlo estimator built directly on samples from qφ(z|x) can have high variance: imagine descending a valley where most stochastic gradient draws point the right way, but occasionally a draw points almost sideways or backward. If you are lucky, the estimated gradient aligns with the true descent direction; if you are unlucky, a high-variance estimate can send you away from the minimum. An estimator can be unbiased—averaging over infinitely many draws would center on the correct quantity—and still be unusable in practice because the variance is too large for stable optimization.

Kingma and Welling analyze an ELBO gradient estimator of the naive kind and show it suffers from this pathology. There is a second, separate problem: backpropagation through a raw “sample” node. Frameworks like PyTorch build derivatives through deterministic ops; drawing z ∼ qφ is not a smooth function of φ in the naive representation, so you cannot ask autograd for ∂(sample)/∂φ the way you would for a matrix multiply. You need a different estimator that both exposes parameters to gradients and keeps variance under control.

The reparameterization trick moves randomness to an independent noise variable ε that sits outside the learnable map from parameters to z. Instead of treating z itself as the stochastic node whose derivative you cannot define, you sample ε—typically from a standard Gaussian—and combine it with the encoder outputs. If qφ(z|x) is Gaussian with mean μφ(x) and (diagonal) scale σφ(x) (standard deviation, elementwise),

ε ∼ 𝒩(0, I),   z = μφ(x) + σφ(x) ⊙ ε .

Here ⊙ is elementwise multiplication, not a full matrix product. Conditional on ε, the map (μ, σ) ↦ z is smooth; autograd can differentiate through μφ and σφ. The backward pass will also compute contributions along the sampling branch for ε, but those are discarded in the conceptual picture: ε is drawn, then held fixed for the backward through the deterministic path—your randomness source is external, like drawing from torch.randn for a zero-mean, unit-variance Gaussian (or the multivariate analogue).

The reparameterized objective is a Monte Carlo estimator: you approximate expectations by a finite number of ε draws. One can show this reparameterized estimator remains unbiased—averaging over enough samples tracks the true gradient in expectation—and empirically it exhibits much lower variance than the score-function (likelihood-ratio / REINFORCE-style) gradient for this model class, which is what makes VAE training practical.

Symbolically, if L denotes an ELBO built from samples, one argues along the lines: ∇φ,θ 𝔼ε[L(ε)] = 𝔼ε[∇φ,θ L(ε)] under regularity conditions—the gradient passes through the expectation because the distribution you differentiate against no longer depends on those parameters in the awkward way it did before the reparameterization. That interchange is the calculus mirror of the engineering fix “sample noise outside, then mix with μ and σ.”

In practice, networks often predict log σ² rather than σ² directly. Variance must be positive; forcing positivity by hand on raw network outputs is awkward. If the network emits log σ², you recover a nonnegative variance as σ² = exp(log σ²). The forward pass is stable, and the reparameterization still uses σ (the square root of that positive quantity) when forming z = μ + σ ⊙ ε.

You cannot backprop through a generic torch.sample draw the way you do through matrix multiplication. Gaussian location-scale families are special: simulate them as a deterministic transform of independent noise—that is what reparameterization exploits.

Practical loss and connection to latent diffusion

End-to-end training pass (conceptual)

Combine the pieces in the order a computation graph actually runs. Take an observed input x (for example an image tensor). Run it through the encoder; the encoder returns parameters of the approximate posterior—mean μφ(x) and (typically) a parameterization of variance or log-variance. Draw noise outside the encoder’s stochastic node: sample ε from a standard Gaussian (in PyTorch, torch.randn with the right shape implements draws from 𝒩(0, I)). Form z = μ + σ ⊙ ε with elementwise multiplication. Feed z to the decoder, which outputs parameters of pθ(x|z)—for continuous pixels with Gaussian observation noise, maximizing log-likelihood corresponds to penalizing squared error, so practitioners often use mean squared error (MSE) pixel by pixel between the reconstruction and the original image. Add the KL term between qφ(z|x) and the prior p(z). Minimize the sum of what amounts to negative ELBO (possibly with a β weight on KL in a β-VAE).

Putting it together for a Gaussian prior and diagonal Gaussian encoder, the objective used in training is the negative ELBO (plus optional β scaling). One term is reconstruction—often MSE for continuous pixels or Bernoulli cross-entropy for bounded inputs—matching −𝔼[log pθ(x|z)] under the chosen observation model. The other is closed-form KL between two Gaussians when both are diagonal, comparing qφ(z|x) to 𝒩(0,I).

At generation time: sample z ∼ 𝒩(0,I), run the decoder—no encoder needed. At training time: encode to get μ, σ, sample z via ε, decode, compute loss, backpropagate.

Diagonal Gaussian KL to the standard normal — step by step

Why the implementation formulas look the way they do is pure calculus on Gaussians. Let q be 𝒩(μ, σ²) in one dimension and p be 𝒩(0, 1). By definition,

KL(q ‖ p) = 𝔼x∼q[ log q(x) − log p(x) ] .

Write the log-densities explicitly (constants included so nothing is hidden):

log q(x) = −½ log(2π) − ½ log σ² − (x − μ)² / (2σ²),
log p(x) = −½ log(2π) − x² / 2 .

Subtract and simplify the integrand log q(x) − log p(x):

log q(x) − log p(x) = −½ log σ² − (x − μ)² / (2σ²) + x² / 2 .

Take expectations under x ∼ 𝒩(μ, σ²). Use 𝔼[(x − μ)²] = σ² and 𝔼[x²] = σ² + μ²:

𝔼[log q(x) − log p(x)] = −½ log σ² − σ² / (2σ²) + (σ² + μ²) / 2 = −½ log σ² − ½ + ½σ² + ½μ² .

Collect terms into the form you see in code:

KL(𝒩(μ, σ²) ‖ 𝒩(0, 1)) = ½ ( σ² + μ² − 1 − log σ² ) .

If the encoder outputs log-variance v = log σ², substitute σ² = exp(v) and log σ² = v so the expression stays numerically stable and automatically enforces σ² > 0. For a diagonal multivariate encoder and spherical unit prior, sum the same scalar KL across dimensions:

KL( 𝒩(μ, diag(σ²)) ‖ 𝒩(0, I) ) = ½ Σi ( σi² + μi² − 1 − log σi² ) .

The closed-form KL is the standard term in VAE implementations. If you want every algebraic maneuver in one place, a detailed walkthrough is easy to find on Stack Exchange and similar references; the calculation is lengthy but elementary—products of Gaussians, completing squares, and collecting coefficients.

Kingma and Welling print the full variational objective—including this KL and the reconstruction term—in their original VAE paper; that display is the blueprint most codebases follow, modulo sign conventions (maximizing ELBO versus minimizing negative ELBO).

Latent diffusion. A convolutional VAE compresses an image to a smaller latent tensor with a learned encoder/decoder pair. A separate diffusion model is trained to model the distribution of those latents. Denoising in pixel space would be far more expensive; working in VAE latents is the architectural compromise that makes high-resolution synthesis tractable. The ELBO-trained VAE therefore defines the geometry and noise level of the space in which the diffusion objective operates.
