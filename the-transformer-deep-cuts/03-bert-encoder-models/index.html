BERT: Encoder Models, Pretraining & Fine-Tuning

From autoregressive language modeling to bidirectional encoders: how masked language modeling, next-sentence prediction, and the [CLS] token define a different path than decoder-only models—and how you adapt BERT with task-specific heads.

00

Language models: probabilities over text

A language model is a probabilistic model: it assigns probabilities to sequences of tokens. In practice it lets you score how plausible a continuation is—for example, the probability of the word China following the fragment “Shanghai is a city in …”. That conditional probability is exactly the quantity a neural language model is trained to approximate from very large text corpora.

When the training corpus is very large, people often call them large language models (LLMs). The label reflects data scale and usually model scale as well—the same probabilistic idea applies to a tiny corpus or a huge one, but the LLM name is reserved for networks trained on very large text with many parameters. Models pretrained on broad data—think entire Wikipedia, or billions of web pages, plus books and similar sources—are also called foundation models: downstream use can rely on prompting or on fine-tuning, depending on architecture and tooling.

Conditional next-token view. Many systems emphasize P(wt+1 | w1, …, wt): the probability of the next token given everything to its left. BERT is not trained primarily in this autoregressive way; it uses bidirectional context instead (see sections 06–08).

01

Training an autoregressive LM on a corpus

Take a line of text and turn it into a token sequence. For illustration, assume one token per word (real systems use subword tokenizers). Prepend a start-of-sequence symbol so the network always sees an explicit beginning. The model is sequence-to-sequence in shape: length in equals length out.

The target is the same text with an end-of-sequence symbol appended at the end instead of a start symbol at the front—the total length matches the input length. For each prefix of the input, the last position of the model output is trained to predict the next token of the target sequence.

Why boundary tokens matter

If you feed only the first token, the network produces one output vector; that vector should align with the first target token. If you feed the first two tokens, the second output position should match the second target token, and so on. The final output position carries the prediction for the next token in the original sentence. Optimization uses cross-entropy between predicted and true next tokens, then backpropagation.

On a concrete line of text, take a famous line from Li Bai (often romanized as Li Po): “Before my bed lies a pool of moon bright.” Suppose you are training on that single line as your entire corpus for the sake of a toy example. Build the input sequence by prepending a start-of-sequence token, so the network always sees an explicit left boundary. For a deliberately simple tokenizer, pretend one word = one token (real systems use subwords; BERT uses WordPiece—section 05).

Feed that input into a stack that behaves like the encoder side of a Transformer, followed by a linear layer and softmax over the vocabulary—this is the same high-level pattern many decoder-style LMs use for next-token modeling (for example LLaMA-style models), even though the internal block diagram differs in details from “encoder-only” BERT.

Because the network is sequence-to-sequence in width—n tokens in produce n token positions out—you can read off training cases by sliding the prefix:

  • Input prefix [SOS] only → the output position aligned with that prefix should target the first real word: before.
  • Input [SOS] before → the last output position should predict my (the next token after before).
  • Input [SOS] before my → predict bed.
  • Continue until the model learns to emit the full line, with an end-of-sequence token learned at the final position of the parallel target sequence (target = same words, EOS at the end instead of SOS at the front).

Training target shape. The target is the same sentence without the leading SOS, but with EOS appended at the end, so total length still matches the input length. Every time you grow the input by one token on the left, the last output slot is the one trained to predict the next token in that target stream.

02

Inference: greedy (or sampled) continuation

At inference time you supply a prompt—a prefix of tokens (with the start symbol as needed). Run the model, read the predicted next token from the appropriate position, append it to the input, and repeat until you emit an end symbol or hit a length limit. Decoder-only models such as many GPT-style and LLaMA-style stacks are built around this loop for open-ended generation.

Prepend [SOS], supply a short prefix such as before my, run the network, and read the predicted next token from the last output position. Append that token, run again, and repeat until the model emits EOS or you hit a length limit. Each step conditions only on tokens already generated—that prompt → predict → append loop is autoregressive inference. BERT is generally not used this way for long-form generation (section 06).

03

Encoder building blocks (Transformer)

The vanilla Transformer—the architecture introduced in the paper “Attention Is All You Need”—has both an encoder stack and a decoder stack. Most language-model systems you meet in the wild use either the encoder side or the decoder side (plus output projections), depending on the task. BERT uses the encoder side: token embeddings, position information, self-attention, residual connections, layer normalization, and feed-forward sublayers, then a task head (which changes at fine-tuning time). The full treatment of scaled dot-product self-attention, multi-head attention, layer normalization, and feed-forward sublayers is in Chapter 01: Transformer Architecture & Math. Here we highlight what differs for BERT—especially bidirectional self-attention with no causal mask—and skip re-deriving the attention formula.

Token IDs → embeddings

Text is split into tokens. Each token maps to an index in a vocabulary, then to a dense vector (e.g. 512 dimensions in the original “Attention Is All You Need” configuration; BERT-Base uses 768—section 05). Those vectors encode semantic similarity: related words tend to point in similar directions in space; unrelated words diverge. Similarity is often measured with cosine similarity, which builds on the dot product—the same operation that appears inside attention scores.

In two dimensions, digital and information might point in similar directions (small angle), while cherry and digital diverge (large angle). Cosine similarity formalizes that geometry from the dot product—the same operation that drives attention scores between positions.

Positional information (sinusoidal, original encoder)

Embeddings alone are permutation-invariant. Texts refer to these additions as positional encodings or positional embeddings; in the original Transformer they are deterministic functions, while in BERT they are learned vectors (section 05). Either way, the model must know each token’s index in the sequence. In the vanilla Transformer, fixed sinusoidal features are used: for each position pos and dimension index i,

PE(pos, 2i) = sin(pos / 100002i/d)
PE(pos, 2i+1) = cos(pos / 100002i/d)

The same position vectors are reused for every sentence: slot 0 always gets the same positional vector, regardless of which word sits there. If another sentence also has three tokens—say “I love you”—it reuses the same position-0, position-1, and position-2 vectors as any other length-three sentence. The vector is tied to the index in the sentence, not to the identity of the word occupying that slot.

Self-attention (Chapter 01)

BERT encoder layers apply the same scaled dot-product self-attention as the vanilla Transformer: linear projections to Q, K, and V, a softmax over keys, then a weighted sum of values. Matrix shapes, multi-head wiring, and the full formula are in Chapter 01. For BERT the critical difference is what is absent: there is no causal mask, so every position may attend to every other position in the packed input—exactly what masked language modeling needs (sections 04 and 08).

04

Causal (triangular) masking for autoregressive models

For next-token prediction, a token must not attend to future tokens—only to left context. Without a mask, the “start” position could attend to words that have not been predicted yet, leaking information. A causal mask sets forbidden attention logits to −∞ before softmax; those entries become zero after softmax, removing rightward influence.

After masking, the first token only attends to itself; each later token attends to itself and all previous tokens. The final token’s row can attend to the full prefix. Multiplying the attention matrix by V mixes value vectors according to these allowed weights, producing updated representations that respect causality.

Why does −∞ before softmax implement a hard ban? Write softmax for a row with logits zi:

softmax(zi) = ezi / Σj ezj

Any position forced to −∞ has e−∞ = 0, so it contributes nothing to the denominator or numerator. After the mask, forbidden future positions carry zero mass; the model never receives gradient pressure to “peek” rightward. Geometrically, everything above the main diagonal of the score matrix (future keys seen from an earlier query) is wiped before normalization.

Shape check: with sequence length 10 and model width 512, the softmax output is still 10 × 10, while V remains 10 × 512. The product yields a 10 × 512 updated representation. Focus on the first row’s first dimension: it is a weighted sum of the first coordinate of every value row, using only the non-zero weights the mask left alive—so the first token’s new vector depends only on itself. The second row mixes value rows 1–2 only; by induction, row t depends on tokens 1…t. That is the matrix view of “each step sees only left context.” Only the final token’s row can attend with non-zero mass to every earlier token; every other row has at least one structural zero on the right half of the matrix. Language modeling needs P(next | left context only); without a causal mask, a position trained to predict the next token could attend to future evidence and cheat the autoregressive contract.

05

BERT’s encoder stack

BERT’s architecture is a stack of Transformer encoder layers: embeddings + self-attention + normalization + feed-forward + residual pathways, then a linear task head chosen for pretraining or fine-tuning. Two public sizes ship with the original release: BERT-Base stacks 12 identical encoder layers (the gray block repeated twelve times), uses 12 attention heads inside multi-head self-attention, and sets the hidden width to 768. BERT-Large doubles depth to 24 layers, widens hidden states to 1024, and uses 16 heads.

The position-wise feed-forward sublayer is two linear layers with a nonlinearity between them. In BERT-Base the inner feed-forward width is four times the hidden size: 4 × 768 = 3072 intermediate units, then back to 768—this is the standard configuration documented with the architecture. Positional embeddings are learned, not sinusoidal, and BERT supports up to 512 positions—longer sequences need truncation or another architecture. Vocabulary size is on the order of 30,000 subword units via WordPiece tokenization (words often split into multiple tokens).

Vanilla Transformer (encoder LM sketch)

Often discussed with dmodel = 512 in the original diagrams; sinusoidal PE(pos) added to token embeddings; simple tokenization in toy examples (one word ↔ one token); task head depends on the job (LM softmax over vocabulary at each position, etc.).

BERT-Base / BERT-Large

Wider vectors—768 (Base) or 1024 (Large)—with learned position embeddings summed alongside token embeddings; hard cap of 512 learned position slots; WordPiece vocabulary ≈30k; the final linear head swaps with the objective (MLM, NSP, classification, spans…).

Tokenizer contrast. Decoder-only stacks—what many people simply call “language models” in casual speech, GPT-style or LLaMA-style— frequently rely on BPE or SentencePiece merges. BERT’s original recipe uses WordPiece, which is why a surface word may fracture into several subword pieces—always check the tokenizer, not the whitespace, when counting tokens.

06

BERT vs GPT-style / LLaMA-style decoders

Decoder-only LLMs (typical)

  • Trained with next-token prediction and causal attention.
  • Strong at open-ended generation from a prompt.
  • Often use BPE or SentencePiece-style tokenization.
  • Many tasks can be handled with in-context prompts (zero- or few-shot).

BERT (encoder-only)

  • Pretrained with MLM and (in original BERT) NSP, not pure next-token LM loss.
  • Uses left and right context simultaneously—bidirectional self-attention.
  • Not aimed at long autoregressive generation; excels at understanding and span tasks.
  • Specialization usually via fine-tuning with a small task head—not prompt-only chat.

Question answering contrast. A decoder-only model can be steered with a carefully written prompt (instructions plus examples) so it continues with an answer. BERT-style QA instead adds a span head over context tokens after fine-tuning on labeled (question, context, answer-span) data (section 11).

In extractive question answering, GPT-style or LLaMA-style decoders are often steered with a few-shot prompt: instructions, optional worked examples, then the live passage and question. The model continues with tokens that quote or paraphrase the support span—everything is mediated by natural language in the prompt. BERT does not specialize that way. You typically fine-tune the encoder on supervised (question, passage, answer-span) tuples so a small head can emit start/end logits directly (section 11). Original BERT checkpoints are not trained for multi-turn chat or chain-of-thought prompting; you add a task head and continue gradient updates on labeled data instead.

07

Left context, right context, and why both matter

Left context is what you have heard or read so far—natural for dialogue turns where each reply conditions on the prior stream. Right context is what comes later; humans sometimes choose an early phrase to set up a later clause (planning how a sentence will end). Statistical models that only condition on the left (autoregressive LMs) differ from encoders that can use the full sentence at once.

BERT’s lack of causal masking during pretraining is exactly what allows a masked position to gather evidence from both sides of the blank—ideal for fill-in-the-blank objectives.

Left context: the telephone operator pattern

Left context is the prefix already spoken or written. In a support call, each operator reply conditions on everything the customer said so far—each turn is a draw from P(next turn | everything to the left). Autoregressive language models enforce the same contract at the token level.

Right context: planning the ending in advance

Right context is trickier: reading flows left-to-right, yet speakers often choose an early clause to set up a later payoff. A child confessing a broken necklace might open with a long preamble before landing on “your favorite necklace has broken”—the opener is chosen because the ending is already known. That is one informal way to see why rightward context matters for understanding even when generation unfolds sequentially.

Statistical models differ in how they treat those dependencies. A classic left-to-right LM scores the next token using only earlier tokens. BERT’s encoder, during MLM pretraining, lets a masked slot peek at both flanks inside the same sentence—closer to “reading the whole line before filling the blank” than to “guessing forward without looking back.”

08

Masked Language Modeling (MLM)

MLM is the same genre of exercise as a cloze test: someone removes a word and you fill the gap, familiar from language exams where a sentence arrives with a blank and you supply the missing lemma. Masked language modeling is the neural scale version of that worksheet. During BERT pretraining, roughly 15% of input tokens are chosen. Of those:

  • 80% of the time the token is replaced by [MASK].
  • 10% of the time it is replaced by a random vocabulary token.
  • 10% of the time the token is left unchanged.

In all three cases, the training label is still the original token. The random and unchanged cases reduce a mismatch between pretraining (heavy use of literal mask symbols) and fine-tuning (where masks are absent).

The encoder outputs one vector per input position. Loss is computed only on the masked positions: compare the head’s prediction at those indices to the true token IDs, then average for the batch.

Take the sentence “Rome is the capital of Italy, which is why it hosts many government buildings.” Suppose pretraining selects the word capital among the 15% of tokens slated for corruption. With probability 0.8 it becomes the literal [MASK] token; with probability 0.1 it is swapped for a random vocabulary draw (picture a decoy such as zebra—any unrelated token will do); with probability 0.1 it stays capital even though the model is still asked to reconstruct the original. In all three variants the label remains capital, which forces the network to rely on context instead of blindly emitting the surface form it saw.

Because BERT is a Transformer encoder, length in equals length out: if the masked sentence packs 14 WordPiece tokens (including punctuation splits), the stack returns 14 hidden vectors. Training does not average loss over every slot—only the positions that were chosen for corruption. For instance, if capital occupied slot k, compare the MLM head’s logits at index k against the true ID for capital, accumulate cross-entropy, and backpropagate.

None of this works with a causal mask. Recall the attention construction softmax(QKT / √dk) V with no triangular mask: every token attends to neighbors on the left and right, so the hidden state at the mask can fuse evidence from Italy, from which is why…, and from Rome is… simultaneously. That bidirectional reach is exactly what a cloze-style objective rewards.

09

Next Sentence Prediction (NSP)

Original BERT also uses next sentence prediction. Sample a sentence A. With probability 0.5, sentence B is the actual next sentence in the corpus; otherwise B is a random sentence from elsewhere. The model must classify whether B truly follows A.

Two sentences are packed into one input: special token [CLS], then tokens of A, then [SEP], then tokens of B, then [SEP]. Token and position embeddings are summed with segment embeddings: one learned vector for “sentence A” tokens and another for “sentence B” tokens, so the model can tell which segment each token belongs to.

The final hidden state at the [CLS] position is passed through a small classifier (e.g. linear layer to two logits: IsNext / NotNext), softmax, and cross-entropy against the label.

Two engineering questions arise immediately. First, how do you serialize two sentences into one tensor without ambiguity? Second, how does the model know whether sentence B truly follows A in the original corpus? The training recipe answers both. Concatenate [CLS], every token of A, [SEP], every token of B, and a closing [SEP]. Without extra structure, the encoder would not know whether my belongs to the first sentence or likes to the second, so BERT adds segment embeddings—a learned vector for “sentence A” and another for “sentence B”— summed together with the usual token and position embeddings.

input_to_encoder = TokenEmbed(token) + PositionEmbed(index) + SegmentEmbed(A or B)

Example: let sentence A be “The moon shines over the quiet lake.” With probability 0.5, B is the next sentence in the corpus; otherwise B is a random sentence from elsewhere. Feed the packed input through BERT. If B truly follows A, the label is IsNext; if B is a decoy, NotNext. Only the [CLS] output participates in this auxiliary loss, but gradients still flow through the shared encoder, teaching it to represent discourse continuity.

10

The [CLS] token as a pooled representation

The letters CLS abbreviate classifier: historically this slot is the one sequence-level summary vector that downstream linear heads read when you need a single embedding for an entire sentence or pair. With full self-attention, [CLS] can attend to every token in the sequence. Its output vector is trained—especially under NSP—to aggregate information useful for a sentence-pair decision. For single-sentence classification fine-tuning, the same position is commonly used as the input to a linear classifier.

Analogy. Think of [CLS] as a single slot whose representation is encouraged to summarize the whole input, similar to routing all reports through one coordinator who talks to every team member before a yes/no decision.

With hidden size 768 in BERT-Base and no causal mask, the [CLS] row of the attention matrix can assign non-zero mass to every token. After softmax, each weight is learned rather than structurally forbidden; the representation at [CLS] becomes a learned mixture of the entire sequence, which is why sentence-pair heads and single-vector classifiers attach there. (The attention formula and matrix walkthrough are in Chapter 01.)

Boardroom analogy (full version). Treat [CLS] as the CEO and yourself as a shareholder who wants a single executive summary. You do not interview every engineer separately; you expect the CEO to walk the floor, talk with each team, synthesize competing facts, and return with a decision. The CEO embedding is not “the first word” of the document—it is a slot whose whole training pressure pushes it to compress what every other token contributed. That is why classifier heads read out [CLS]: the architecture has been encouraged to make that position a sentence-level or pair-level summary vector.

11

Fine-tuning: classification and extractive QA

Text classification

Map each example to [CLS] + tokenized text. Run BERT; take the hidden state at [CLS], apply a linear map to C classes, softmax, and cross-entropy against the gold label. Example domains: routing ISP support tickets into hardware, software, or building (facilities) issues—whatever your label set is. If there are three classes, the linear head has three output logits; softmax converts them to probabilities; the cross-entropy target is the one-hot (or soft) label supplied by your annotators.

A ticket describing a faulty cable modem should route to hardware; one about a buggy mobile app to software; elevator outages to building maintenance. During fine-tuning every example follows the same recipe: [CLS] + tokenized complaint → transformer layers → vector at [CLS] → Linear(768 → C) → softmax → compare against the supervised class ID → backpropagate through the entire stack (or through the head only if you freeze lower layers).

Extractive question answering

Concatenate question (segment A) and passage (segment B) with separators, using segment embeddings to mark which tokens belong to which part. For each token in the passage (sometimes restricted), a head produces two scores: probability that this token is the start of the answer span and probability that it is the end. Training matches predicted start/end to the labeled span.

Pack the string as [CLS] + tokenized question + [SEP] + tokenized passage + [SEP], exactly as in NSP formatting, but now segment IDs tell BERT which side is the interrogative clause versus the evidence paragraph. After the encoder runs, attach a span head: a linear map with two logits per token—one signaling “start of answer,” one signaling “end of answer.” Softmax is applied across positions separately for starts and ends (implementation details vary slightly by codebase, but the conceptual object is a distribution over token indices for each role).

Example. Context: “Shanghai is a city in China. It is also a financial center, its fashion capital, and industrial city.” Question: “What is the fashion capital of China?” A valid span highlights Shanghai. In a toy numbering where the token Shanghai lands at index 10 inside the packed sequence, both the start label and the end label point to 10—a degenerate span of length one. The training loss encourages the start logit at index 10 (and the end logit at the same index) to dominate all other positions.

If the packed question+passage uses, say, 27 WordPiece tokens, BERT emits 27 hidden vectors; the span head scores each position twice (start/end). Cross-entropy (or a smooth variant) compares those distributions to the human-annotated span, gradients flow backward, and the encoder learns to align factual cues in the passage with linguistic triggers in the question.
