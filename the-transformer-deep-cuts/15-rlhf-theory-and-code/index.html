RLHF End-to-End: Policy Gradients, PPO & Code

From alignment goals to preference-trained reward models, policy-gradient derivations, variance reduction, PPO clipping, KL control, and how libraries like Hugging Face TRL implement the loop.

Section 00

Why alignment matters

Large language models absorb broad pretraining data. That teaches fluency and knowledge, not necessarily the behavior you want at deployment: avoiding harmful content, staying on task, or matching a product’s tone. Alignment steers the model toward desired outputs while preserving usefulness.

Reinforcement learning from human feedback (RLHF) is one major alignment recipe: learn a reward signal from human preferences, then optimize the generative policy with reinforcement learning so sampled completions score highly under that reward—subject to staying close to a reference model so the text remains coherent.

RLHF is not the only post-training approach; direct preference optimization (DPO) and related methods skip an explicit RL loop. This chapter focuses on the RLHF + PPO path because it exposes policy gradients, advantage estimation, and clipping in full.

RLHF is also the family of techniques used to align assistants such as ChatGPT toward safer, more helpful behavior. The same story applies whenever you want fluency and knowledge from pretraining to be steered without throwing away the base model.

This chapter assumes comfort with expectations and basic probability, gradient-based optimization (loss, backward pass), and the MDP vocabulary: agent, state, environment, reward. It leans heavily on the transformer: causal masking, per-position hidden states, and one forward pass over a full sequence.
Section 01

Language models as stochastic policies

A causal LM assigns P(next token | prefix). Autoregressive generation repeatedly appends a sampled token, so the prefix grows: that is a Markov decision process in disguise.

  • State: current token sequence (prompt + generated prefix).
  • Action: the next token (possibly sampled with temperature, top-k, nucleus sampling, etc.).
  • Policy πθ: the LM itself, parameterized by weights θ.

What is missing for RL is a numeric reward for partial or full generations. That is supplied by a reward model trained on human judgments.

For clarity, the exposition often treats one word as one token. Real tokenizers split text more finely (subwords), but the MDP picture is unchanged: each decoding step is an action.

Greedy decoding as an MDP roll-out. Prompt: “Where is Shanghai?” The model assigns probabilities over the vocabulary for the next token; greedily take the argmax, append it, and repeat.

  1. State = prompt only → action might be Shanghai.
  2. State = prompt + Shanghai → action might be is.
  3. State = … + is → action might be in.
  4. Continue until a stop criterion (max length, EOS, or task-specific heuristics). A completed answer might read “Shanghai is in China.”

Sampling strategies (temperature, top-k, nucleus / top-p) only change how actions are drawn from the same conditional distributions πθ(a|s).

Section 02

RL basics: states, actions, rewards, trajectories

An agent acts in an environment: at each step it observes a state, samples an action from a policy, transitions (often stochastically) to a new state, and receives a scalar reward. A trajectory τ = (s0, a0, s1, a1, …) is one roll-out.

The return is usually discounted so future rewards are weighted less than immediate ones:

R(τ) = Σt=0T γt rt, 0 < γ < 1

Discounting encourages shorter successful paths when dynamics are stochastic and keeps infinite-horizon sums bounded when needed.

The objective is to find policy parameters that maximize expected return:

J(θ) = Eτ ∼ πθ[ R(τ) ]

Equivalently, the objective is an expectation over trajectories weighted by their probability under the policy—often written as an integral or sum: ∫ P(τ|θ) R(τ) dτ in the continuous view.

Concrete grid-world intuition

Picture a cat on a grid: state = coordinates (x, y); actions = up/down/left/right. Rewards might be 0 on empty cells, −1 on a broom, −10 in the bathtub, and +100 at meat. The policy π(a|s) assigns action probabilities per cell—analogous to a language model’s next-token distribution.

Stochastic transitions

Next states need not be deterministic. The cat may intend “down” yet slip—model that as P(s′|s, a). The same formalism covers noisy robots (e.g., broken wheels: “move down” might leave you in place). That is why trajectory probability includes both policy factors and transition dynamics.

Probability of a trajectory

A trajectory τ = (s₀, a₀, s₁, a₁, …) factorizes because of the Markov structure: the choice of at depends on st, and st+1 depends on (st, at). Under standard assumptions these factors multiply:

P(τ) = P(s₀) · ∏t πθ(at|st) · P(st+1|st, at)

Many paths of bounded length exist (straight to the goal, detours, wasted steps until a horizon). RL seeks a policy that maximizes expected return across those paths.

Why discount? Money, risk, and convergence

Time preference. Receiving \$10,000 today beats receiving it in a year because you can earn interest—so future money is discounted.

Shorter paths under noise. If transitions are stochastic, long routes expose you to more hazard (more chances to hit the broom or bathtub). Preferring earlier success aligns with lower discount-weighted risk.

Mathematics. With 0 < γ < 1, infinite-horizon sums can converge when rewards are bounded.

Worked discounting example

Along one path the cat hits the broom once (reward −1 at an early step), then many zeros, then +100 at the meat on step index 8 from the start. With per-step discounting applied to the return:

R = γ · (−1) + γ8 · 100

Every intermediate zero contributes nothing; the terminal +100 is downweighted by γ8 because it arrives eight steps later. Smaller γ penalizes delay more sharply. In language modeling the same structure applies: state = prompt plus prefix, action = next token, return from the reward model (and KL penalties)—implementations vary, but the RL object is still “maximize expected discounted return under πθ.”

Section 03

Reward modeling from preferences

Absolute scalar scores for free-form answers are noisy and subjective. Humans compare pairs reliably: “A is better than B” is easier than “A is 7.3/10.”

Data collection: for each prompt, sample multiple completions (e.g., higher temperature), then record which completion labelers prefer.

Architecture: start from a pretrained transformer; instead of a vocabulary projection head for next-token prediction, attach a single linear output so the model emits one score rφ(x, y) for prompt x and response y.

Bradley–Terry / logistic loss for a chosen response y+ and rejected y−:

LRM = −log σ( rφ(x, y+) − rφ(x, y−) )

When the model ranks the preferred answer higher, r+ − r− is positive, σ(·) is above 1/2, and the loss is small; swapping scores inflates the loss. Minimizing this pushes the reward model to respect pairwise preferences.

Absolute scores

Asking “rate this answer 1–10” is noisy: one annotator may love a short reply (“Shanghai is in China”), another may want more detail. The same holds for “what is 2+2?” answered only with “four”—too terse for some, perfect for others.

Pairwise preferences

Humans compare reliably: “A is better than B” yields cleaner supervision. So the pipeline samples several completions (e.g., higher temperature), labelers pick the winner, and the network learns a scalar scorer consistent with those choices.

Architecture detail

Start from a pretrained transformer. Feed the concatenation [question tokens ∥ answer tokens]. The stack produces hidden states per position; instead of projecting the last hidden state to vocabulary size for next-token prediction, attach a single-output linear head so the model emits one real number rφ(x, y) for the pair.

Step-by-step behavior of the loss

Let Δ = rφ(x, y+) − rφ(x, y−).

  • If the model is correct (higher score on the chosen answer), Δ > 0. Then σ(Δ) ∈ (½, 1). The quantity −log σ(Δ) is a small positive loss (bounded roughly in a modest range above 0).
  • If the model is wrong (higher score on the rejected answer), Δ < 0. Then σ(Δ) ∈ (0, ½). Now log σ(Δ) is a large-magnitude negative number, so −log σ(Δ) becomes large—the optimizer is heavily penalized.

Training therefore forces high reward on winning responses and low reward on losing ones, because that is how the loss is minimized.

In Hugging Face TRL, RewardTrainer pairs with AutoModelForSequenceClassification configured so the classification head has one logit—exactly this scalar reward architecture. The implementation computes rewards for the chosen and rejected sequences, then applies the same −log σ(rchosen − rrejected) structure.

Section 04

Trajectory probability and the policy-gradient target

For a trajectory, probability factors into start state, policy choices, and transition dynamics. Only terms that depend on θ survive in ∇θ log P(τ | θ): the sum of ∇θ log πθ(at | st) over time steps.

Monte Carlo estimation replaces the expectation over all trajectories with a finite sample—unbiased in expectation but high variance when the sample is small.

For LMs, log πθ(at|st) is the log-probability of the actually sampled token at position t, obtained from one forward pass with causal masking: compute logits at each position, log_softmax, then gather the index of the realized token.

Per-token rewards can come from a reward head at each generated position, or a single scalar (e.g., classifier score) placed on the final token with per-step KL penalties—implementations differ; the math structure (returns, advantages) stays the same.

Gradient of the objective (sketch)

Start from the expected return under the policy:

J(θ) = Eτ∼πθ[R(τ)] = ∫ P(τ|θ) R(τ) dτ

Exchange gradient and integral (sum of derivatives):

∇θJ(θ) = ∫ R(τ) ∇θP(τ|θ) dτ

Log-derivative trick. Use ∇θ log P(τ|θ) = ∇θP(τ|θ) / P(τ|θ), hence ∇θP(τ|θ) = P(τ|θ) ∇θ log P(τ|θ). Substitute:

∇θJ(θ) = ∫ P(τ|θ) R(τ) ∇θ log P(τ|θ) dτ = Eτ∼πθ[ R(τ) ∇θ log P(τ|θ) ]

Expand log P(τ|θ) as a sum: initial state (often independent of θ), transition terms log P(st+1|st, at) (typically independent of θ when the environment is fixed), and policy terms log πθ(at|st). Only the latter survive in ∇θ:

∇θ log P(τ|θ) = ∑t ∇θ log πθ(at|st)

So the policy-gradient direction weights each per-step log-probability gradient by return (or improved surrogates below).

Why Monte Carlo is expensive for LMs

Exact expectations require summing over enormous trajectory spaces—e.g., all length-100 token sequences. That is intractable. The standard fix is Monte Carlo: sample trajectories from the current policy and replace the expectation with an empirical mean. The estimator is unbiased in expectation but can have high variance when the batch of trajectories is small.

Log-probabilities for a concrete LM trajectory

Prompt: “Where is Shanghai?” Generated continuation: “Shanghai is in China.” Concatenate query + response and run one causal forward pass. For each position, the model produces logits for the next token; apply log_softmax along the vocabulary dimension. Because of the causal mask, the hidden state at “Shanghai” encodes the prefix ending at “Shanghai” and predicts the token that actually followed—here is. Gather only the log-prob entries for the realized actions (the tokens that were actually sampled during roll-out). That yields the sequence log πθ(at|st) needed for the policy gradient.

This is the same trick used in supervised LM training (teacher forcing), except actions are the tokens you chose at generation time, not tokens from a fixed dataset.

Rewarding the trajectory with the reward model

Feed the same concatenated sequence through the reward transformer. You may read a scalar after the final position, or attach the linear head to each response position and sum (or discounted-sum) per-step scores:

R ≈ r0 + γ r1 + γ2 r2 + γ3 r3 + …

Either way, once returns and log-probs exist, multiply—conceptually—by advantages (after variance reduction) and ascend.

Section 05

Policy gradient theorem (REINFORCE)

Using the log-derivative trick,

∇θ J(θ) = Eτ∼πθ[ R(τ) · ∑t ∇θ log πθ(at | st) ]

Empirically: sample trajectories, multiply score gradients by return (or a better surrogate below), and ascend. This is the REINFORCE family: high-return actions get reinforced; low-return actions get suppressed.

Optimization sign. Supervised learning usually minimizes a loss with gradient descent. Here we maximize J(θ) with gradient ascent: update θ ← θ + α ∇θ J(θ) (same mechanics as descent, opposite sign).

Practical loop (conceptual). (1) Roll out trajectories from the current policy—grid-world cat or LM completions for prompts. (2) For each trajectory, accumulate rewards and retrieve the log-probabilities of taken actions. (3) Let automatic differentiation compute ∇θ log πθ (e.g., PyTorch backward through a surrogate loss that encodes those log-probs). (4) Scale by return/advantage and step θ uphill. (5) Refresh roll-outs and repeat.

Vanilla REINFORCE is workable on toy problems but becomes fragile for large LMs: Monte Carlo return estimates are noisy, and fresh roll-outs every tiny step are prohibitively expensive.

Section 06

Variance reduction: causality, baselines, advantages

Reward-to-go / causality: past rewards do not depend on future actions. Replace full return with the sum of rewards from step t onward when weighting ∇ log π(at|st).

Baseline b(st): subtracting a state-dependent baseline does not introduce bias in the policy gradient expectation but can greatly reduce variance. A common choice is the value function Vπ(s)—expected return from s following π.

Q and advantage:

Qπ(s, a) = E[ return after taking a in s ]
Aπ(s, a) = Qπ(s, a) − Vπ(s)

Positive advantage means the action was better than the policy’s average from that state; negative means worse. The usable gradient estimate uses At instead of total return.

In practice V is another head on the policy network (shared trunk, separate linear layer). It is trained to predict returns along sampled trajectories.

Variance intuition: estimating the mean age of a country

Suppose the true average age of the U.S. population is about 40–45 years. Census-perfect evaluation requires everyone (~330 million)—impossible. Instead you sample.

  • Interview one random person who happens to be six → estimate 6—wildly wrong.
  • Interview a handful from a retirement home → estimate ~80—also wrong.
  • Interview 1,000 diverse people → much likelier to land near the true mean.

The central limit theorem explains why larger samples stabilize the mean. Policy-gradient Monte Carlo is analogous: the sampled-trajectory gradient is unbiased but noisy; without enough data or variance reduction, updates point erratically. Increasing roll-outs is costly for LMs, so we reduce variance algorithmically.

Reward-to-go (causality)

Past rewards do not depend on future actions. When you weight ∇θ log πθ(at|st), only returns from time t onward should appear—the reward-to-go from t to horizon T. Dropping irrelevant past terms removes noise that would otherwise push gradients off the true expectation’s direction.

Baselines stay unbiased but cut variance

Subtract a baseline b(st) (often the state-value V(st)). Under standard conditions the expected policy gradient is unchanged, yet the estimator’s variance can shrink dramatically—same spirit as the age example: less luck-driven swing.

Value examples in language modeling

After “Where is Shanghai?” if the prefix already reads “Shanghai is”, the next token is likely “in” then “China”—high expected return under a good reward model. If the model veered to “chocolate muffins”, future tokens probably drift away from a correct geographic answer: low expected return. Values summarize that forward-looking quality.

Shared trunk, two heads

Typical design: one transformer body, one linear head to vocabulary (policy / actor) and another single-output head predicting V(s) at each position. Gradients flow through shared layers while each head specializes.

Qπ(s, a)

Expected return if you take action a in state s now, then follow π. “How good is this specific move?”

Vπ(s)

Expected return if you start from s and always follow π for actions. “How good is this board / prefix on average under the current policy?”

Advantage as relative quality. On a grid cell where moving down approaches the meat, A(s, down) is larger than A(s, left) if down is better than the average action from that cell. For “Where is Shanghai?”, choosing Shanghai as the first token should carry higher advantage than chocolate because it leads to completions the reward model prefers.

The policy update then increases log-probabilities of above-average actions and decreases those of below-average actions—always scaled by the advantage estimate.

Section 07

Advantage estimation & GAE

One-step TD residual:

δt = rt + γ V(st+1) − V(st)

Generalized advantage estimation (GAE) blends bias and variance with parameter λ ∈ [0,1]:

At = Σl=0∞ (γλ)l δt+l

Implemented backward along a trajectory: At = δt + γλ At+1. Larger λ uses more of the actual rewards (lower bias, higher variance); smaller λ leans on the value estimator.

Bias–variance trade-off inside advantage estimation

Approximate Q by truncating the reward chain after a few real rewards and replacing the tail with V. Stop after too few true rewards → high bias (the critic dominates and can be wrong). Use many raw rewards with little bootstrapping → high variance. GAE averages multiple such k-step shapes with weights that decay by powers of λ, interpolating between TD(0)-like and Monte-Carlo-like extremes.

Backward pass on a toy trajectory

Label states/actions (s₀,a₀), (s₁,a₁), … with rewards r₀, r₁, …. At the last useful index (say t = 3), there is no A₄; the recursion starts from a one-step TD residual involving the terminal value. Then

A₂ = δ₂ + (γλ) A₃, with δ₂ = r₂ + γ V(s₃) − V(s₂)

and similarly for earlier t. Code implementations often loop from last token to first, then reverse the advantage tensor so it aligns with time-forward indexing.

Section 08

Importance sampling & “old” vs “new” policy

Fresh trajectory collection every gradient step is expensive for LMs. Importance sampling reweights data drawn from one distribution to estimate expectations under another. Multiply and divide by the proposal density q inside the integral, then regroup:

Ex∼p[f(x)] = ∫ p(x) f(x) dx = ∫ q(x) · (p(x)/q(x)) f(x) dx = Ex∼q[ (p(x)/q(x)) f(x) ]

In policy gradients, trajectories are often collected with policy πθold (or the parameters frozen at rollout time). Updates use ratios πθ(a|s) / πθold(a|s) so multiple epochs of optimization can run on the same batch—off-policy correction—until the policies drift too far.

Why this matters for LMs

If every optimizer step required brand-new roll-outs, each tiny move θ ← θ + α g would trigger full generations, reward-model scoring, advantage computation, and log-prob traces—far too slow. Importance sampling lets you sample trajectories once, store them, and take several gradient steps using importance ratios before refreshing data.

Offline / “behavior” vs online / “learning” policy

Name the snapshot that generated data πθold (offline / behavior). While optimizing, treat the current trainable weights as πθ (online). They are the same network at different moments: freeze a copy for denominators, update the active weights for numerators, periodically sync.

Pseudocode shape: sample trajectories with the current policy into a replay buffer → for multiple mini-batches, recompute log-probs under the updated weights, form ratios and policy losses, call backward → after enough inner steps, regenerate trajectories. KL penalties and PPO clipping keep the mismatch between old and new from exploding.

Section 09

PPO: clipped surrogate objective

Proximal Policy Optimization limits how much the policy can move in one update. Let rt(θ) = πθ(at|st) / πθold(at|st). The clipped objective (scalarized over tokens/batches) is:

LCLIP(θ) = Et[ min( rt(θ) Ât, clip(rt(θ), 1−ε, 1+ε) Ât ) ]

Taking the minimum is a pessimistic bound: large increases in probability ratio when Â > 0 (or large decreases when Â < 0) are capped. That stabilizes training compared to unconstrained policy gradients.

Reading the ratio. If the optimized policy assigns much higher probability than the snapshot policy to a token that already had positive advantage, rt grows. Clipping at 1+ε prevents an overly greedy jump. Symmetrically, when reducing an action’s probability (Â < 0), clipping near 1−ε stops the policy from crushing that action in one shot. The min chooses the more conservative (pessimistic) of the clipped and unclipped surrogate—so updates stay incremental even when raw ratios would suggest aggressive steps.

Full PPO-style loss in implementations often adds:

  • Value loss: regression of Vθ toward empirical returns (or TD(λ) targets).
  • Entropy bonus: encourage exploration so the policy does not collapse prematurely.

Value head target from samples. Along a realized trajectory you can form targets for the critic by combining advantages and values: Q̂t = Ât + Vθ(st) (a Monte Carlo–style return proxy). The value loss pushes predictions toward those targets.

Entropy motivation. Without entropy regularization, the policy might always replay the single token that once yielded high advantage—e.g., always emit “Shanghai” after a geography prompt. That is brittle. Keeping entropy high preserves probability mass on alternatives such as “it” leading to “It is in China…”, enabling continued exploration.

PyTorch optimizers default to minimization. Implementations therefore minimize −LCLIP (plus value loss, minus entropy coefficient times entropy) so the effect matches maximizing the surrogate.

Unclipped term r Â

Can explode if the new policy deviates far from the data-collection policy—large policy updates destabilize training.

Clipped term clip(r) Â

Flattens the objective beyond [1−ε, 1+ε], yielding a trust-region-like effect without explicit quadratic penalty solves.

Optimization frameworks typically minimize negative surrogate plus value loss minus entropy scale.

Section 10

KL penalty & reference model

Reward models can be exploited: the policy might find high-scoring but incoherent patterns (“reward hacking”). A common fix is a reference policy πref (often the SFT model, frozen). Per-token penalties proportional to something like KL( πθ ‖ πref ) are subtracted from rewards or added to the loss so updates stay in-distribution.

In practice KL is approximated from log-prob differences along the sampled sequence. The effective per-step reward becomes “task reward” plus (negative) KL cost, shaping the advantage signal.

r̃t ≈ rRM(t) − β · KLt(πθ ‖ πref)

Concrete failure mode from polite-only rewards: the model may loop “thank you” forever—maximally polite, nonsense to humans, yet high scalar reward. KL to a frozen unaligned reference penalizes drifting into such hacks by charging large divergence when logits move away from the pretrained/SFT behavior.

Implementation-wise, duplicate the policy weights, freeze them, and compare log-probabilities tokenwise between trainable and frozen forward passes—the KL penalty is often assembled from those differences (plus coefficients), while a classifier-style reward may attach only to the final token of the response.

Section 11

Full RLHF pipeline

1. Pretrain LM (optional starting point). 2. Supervised fine-tuning (SFT) on demonstration data (optional but typical). 3. Collect preference data; train reward model rφ with pairwise loss. 4. RL phase: sample completions from current policy; score with rφ; add KL vs πref. 5. Compute logprobs, values, advantages (e.g., GAE); optimize PPO objective for several mini-batch epochs. 6. Periodically refresh rollouts with updated weights; repeat.

The loop couples three models: policy (trainable), reference (frozen, for KL), reward (frozen during RL, trained earlier). Value head rides on the policy trunk.

Reference tutorial setup: sentiment as a proxy reward

A pedagogical recipe (mirroring public TRL demos) swaps human preference batches for an IMDb sentiment classifier: positive movie reviews get high score, negative ones low score. Take a GPT-2–class model already familiar with review text, attach a frozen copy for KL, and optimize with PPO so generations become more positive while staying near the reference distribution.

Prompt construction. Sample a review from IMDb, truncate a random prefix to use as the prompt, and let the policy continue the review up to a sampled max length—those continuations are trajectories. Score each continuation with the positive-class logit from the sentiment pipeline; that scalar is the “reward model” output. IMDb is a cheap stand-in for human preferences: labels exist at scale, the reward is fast to compute, and the lesson transfers once you swap in a pairwise-trained rφ.

Section 12

Implementation notes: Hugging Face TRL

The trl library exposes trainers such as PPOTrainer and RewardTrainer. A typical flow (conceptually):

  • Rollout: batched generation from the policy for prompts (queries).
  • Forward pass on concatenated query+response: logits → log_softmax → gather chosen-token logprobs for response positions only (mask).
  • Reference logprobs: same pass through frozen reference for KL.
  • Rewards: e.g., classifier score on full response assigned to last token; KL penalty spread per token; then backward GAE for advantages.
  • PPO update: recompute logprobs with current weights; form ratio exp(log_new − log_old); clipped surrogate + value loss (+ optional entropy); Adam step.
# Illustrative-only: TRL wires these pieces for you
from trl import PPOConfig, PPOTrainer, AutoModelForCausalLMWithValueHead
# policy with value head, ref model, reward model / scoring fn, tokenizer …

Study the library source to see exact tensor shapes, masking, and where the sentiment or RM score is injected—behavior matches the math above even when spread across helper functions.

Inside PPOTrainer.step (conceptual ordering)

  1. Validate tensors for dtypes/shapes; convert Python reward lists to tensors.
  2. Batched forward on the policy that produced the roll-outs: concatenate query+response, compute logits, apply log_softmax, gather the log-prob of the token that actually occurred at each response position. Mask so only generated tokens contribute (not prompt positions).
  3. Reference forward pass with identical masking to obtain frozen-policy log-probs for KL.
  4. Per-token “rewards”: typically negative KL penalty everywhere the response is active, plus the scalar classifier score placed on the last response token only (earlier positions may see only KL shaping). Backward GAE then propagates credit across time steps.
  5. Value predictions from the auxiliary head returned alongside logits during the forward pass.
  6. Advantages: compute δt = rt + γ Vt+1 − Vt with appropriate masking for terminals; recurse At = δt + γλ At+1 from the end of the sequence backward, then reverse to time order.
  7. Q-style returns for the critic: Q̂t = Ât + Vt supplies regression targets for the value loss (libraries may add clipping between old/new value predictions for stability).
  8. Mini-batch PPO phase: re-run forward passes on sharded data, form rt(θ) = exp(log πθ − log πold), build clipped surrogate + value term + entropy (often via a numerically stable logsumexp formulation related to softmax entropy).
  9. Minimize the negated objectives with Adam-style optimizers; repeat inner epochs before sampling fresh trajectories.
Libraries hide log-prob bookkeeping on purpose: users supply queries, responses, and rewards—TRL computes masks, KL penalties, advantages, and PPO losses internally.

Entropy in code. Production trainers may compute entropy through stable reductions over logits (equivalent to treating Shannon entropy as a conjugate of the log-sum-exp potential—see standard softmax entropy derivations) rather than the textbook sum −∑ p log p in naive form.

Terminology and synonyms

  • Policy / actor — the trainable LM producing πθ(a|s).
  • Behavior / offline policy — snapshot used to generate stored trajectories (πold).
  • Online policy — weights being updated during inner PPO loops.
  • Reward model (RM) — scalar scorer from preferences (or a surrogate such as sentiment).
  • Reference model — frozen copy for KL trust-region.
  • SFT — supervised fine-tuning before preference data or RL.
  • GAE — generalized advantage estimation; blends TD residuals with λ.
  • Reward hacking — optimizing the proxy reward while breaking human-meaningful quality.
