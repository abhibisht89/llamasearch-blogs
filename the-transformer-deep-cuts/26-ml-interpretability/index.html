00

What is machine learning interpretability?

Interpretability asks what a model has internalized, which inputs drive its outputs, and where it is likely to fail. In 2016, press reporting (including The Guardian) described a fatal Tesla collision where the sensor suite, against a bright sky, allegedly failed to register a large white truck crossing the highway. The lesson for ML practice: high average accuracy does not excuse rare, catastrophic misreads when background statistics correlate with labels in training.

For a self-driving stack you need defensible answers: what did the detector actually learn? If “person” is recognized from clothing color rather than body shape, unusual attire becomes a failure mode. The same logic applies to any model whose mistakes carry physical risk.

Typical questions practitioners want to answer include:

  • What did the model learn? Does a “person” detector use shape, texture, clothing color, or spurious context?
  • Which input features cause a particular output? For text models, which tokens or phrases correlate with a completion—for example, if a language model produces profanity, which input tokens disproportionately steer it there?
  • How do we debug and improve training? Gradients and attributions link errors to parameters and data; they support hyperparameter and data decisions when the model “will not learn” what you intended.
  • What are the failure modes before deployment? Stress tests and attribution often reveal shortcut rules (sky = tank, grass = no tank) long before field incidents.
  • Can we earn justified trust? For autonomy and medicine, evidence that the model uses the right evidence matters as much as headline accuracy.
  • Can the model surface novel structure in data? Sometimes high-performing models attend to cues humans did not prioritize—for example, in a cancer vs. non-cancer cell classifier, saliency or prototypes may highlight regions of the cell that clinicians had not emphasized, yet those regions are predictive. The model can then suggest new hypotheses for biological markers.

Interpretability is not a single algorithm: it is a toolkit of objectives, visualizations, probes, and behavioral tests. The same automatic differentiation machinery that trains networks also powers many explanation methods—by backpropagating through the computation graph to inputs or internal units.

01

Computation graphs, backpropagation, and gradients

Frameworks such as PyTorch build a computation graph: each tensor operation is a node; data flows forward from inputs to outputs (for example, linear layers, biases, ReLU, and a scalar loss). Training minimizes that loss with respect to weights (and biases), using partial derivatives linked by the chain rule.

A minimal template: predict house price from bedroom and bathroom counts with nn.Linear(2, 2) → ReLU → nn.Linear(2, 1), trained with MSE. After the forward pass, backpropagation applies the chain rule to compute ∂L/∂w for every weight.

Gradient descent on weights:  w ← w − α · ∇wL   (α = learning rate; step opposite to ∇L because we want to decrease loss)

The training loop: forward pass → loss → backward pass → parameter update. The same graph can be queried for ∂L/∂x when inputs require gradients—powering adversarial examples and input attribution below.

A smooth 1D loss L(w) with a local and a global minimum. Drag the slider to set the current weight; each “step” moves w ← w − α · dL/dw (finite-difference derivative on the curve).

02

Adversarial examples: fooling classifiers with tiny input changes

A classifier maps inputs (for example, images) to one of several classes. Large vision models such as ResNet variants map an image to one of on the order of 1000 ImageNet-style classes (fish, dog, volcano, car, pencil, …). The penultimate layer emits logits z—one real score per class—before a softmax turns them into probabilities that sum to 1. The predicted class is typically argmax(softmax(z)). If after softmax one class sits at 95%, the model is effectively asserting that label (for example, “fish”) with high confidence.

softmax(z)i = exp(zi) / Σj exp(zj)

In training, one computes ∂L/∂(weights) and updates weights. For an adversarial attack with a fixed model, the weights stay frozen; instead you optimize or adjust the input. The attack goal: feed an image that humans still read as a fish (or dog, or person) while the network assigns very high probability to a target class you choose—say “volcano.” The only lever is the pixel tensor x.

Construct a target loss—for example cross-entropy that rewards assigning mass to “volcano”—different from the training loss that used the true label “fish.” Backpropagation through the frozen network gives ∇xL: the direction in pixel space in which small changes increase that target loss from its current value. To drive the target loss down (so the model becomes confident in the wrong class), step opposite to that gradient—the same sign convention as weight updates during training, but the free tensor is x. Repeat for multiple steps until the network predicts the target class with high confidence. In PyTorch-style code you set requires_grad=True on the image tensor, not only on parameters, then call backward() into the pixels.

x ← x − α · ∇xLtarget(x)

(stepping to decrease the target-oriented loss) produces a perturbed image that the network classifies as the target, often with only imperceptible noise. To a human the perturbed fish and the original fish are the same object; to the network the logits have crossed a decision boundary. That gap is central to work on adversarial robustness (including foundational analyses in the deep learning security literature) and to why interpretability matters: the model may be sensitive to patterns that are not human-meaningful.

Training (standard)

Minimize loss w.r.t. weights on a labeled dataset. Inputs are fixed batches from real data; parameters move so predictions match labels.

Adversarial crafting

Minimize (or maximize) a chosen objective w.r.t. pixels while weights are frozen. Gradients flow to x instead of W.

Same math, different free variable. Training optimizes weights; adversarial crafting optimizes input. The gradient of a loss w.r.t. inputs tells you how to increase that loss; to drive a target cross-entropy down, step −α∇xL on pixels—the same sign convention as weight updates.

03

Feature visualization: what activates a neuron or layer?

In convolutional vision models, early layers often encode edges and textures; deeper layers compose parts and objects. Feature visualization asks: what input image (or pattern) maximizes the activation of a chosen unit, channel, or layer—or, at the head of the network, a particular class logit? You can pose the problem at three scales: a single neuron (“what makes this unit fire?”), an entire layer or channel aggregate (“what pattern does this stage detect?”), or the logit for one class in a classifier (“what image would this network score as ‘dog’ before softmax?”).

Practitioners treat this as an optimization problem: start from random noise (or occasionally a seed image), run the image through the frozen network, read off activations at the chosen hook point, and treat that scalar or sum as the quantity to maximize by updating pixels. Backpropagation is identical in implementation to training; only the free variables change from weights to pixels. When you maximize a quantity you perform gradient ascent on the input; when you minimize error during training you perform gradient descent on weights. Same autograd engine; the sign and the tensor being updated differ.

Objective (example): maximize alayer(x)  or  zclass “dog”(x)  by updating x (pixels), CNN weights fixed.

Starting from noise and maximizing the logit for “dog” does yield a prototype-like image: it reveals which directions in pixel space the network associates with that class. Published visualizations from architectures such as ResNet illustrate the idea: for flamingo, optimized images emphasize elongated neck-like structures; for goldfish, large round eyes and fish-shaped silhouettes; for tarantula, long dark legs. Those motifs align with the cues the classifier exploits—even when the composite image is not a photograph anyone would mistake for a real scene.

Naive maximization from pure noise often produces high-frequency, adversarial-looking textures: the network can achieve extreme activations using patterns that lie off the natural image manifold—similar to adversarial examples, the model responds to structure humans do not parse as “object.” Production-oriented prototype generators therefore stack regularizers so the optimized image stays closer to the statistics of training data while still maximizing the objective.

Regularization in training (for example L1 on weights) adds a term to the loss so optimization prefers sparse weights: the L1 term uses absolute values of parameters; its subgradient pushes many coefficients toward zero, encouraging the model to use fewer input features and shrinking effective model size. The philosophy for feature visualization is analogous—add terms that constrain how the input may change—even though there the variables are pixels, not weights.

Two families matter especially for natural-looking feature images:

  • Frequency / smoothness penalties. Natural photographs have correlated neighboring pixels (your shirt in a video frame does not flicker randomly pixel-to-pixel). Penalize high variance between neighbors—a frequency penalty—so the optimizer cannot “cheat” with fine checkerboards that fool the net but look like static to humans.
  • Transformation robustness. At each optimization step, apply random geometric transforms to the current candidate—random scaling and rotation (as in reference code from the Lucid library, widely used for feature visualization research), crops, translations—then evaluate the objective on the transformed image. The optimizer must find a pattern that still strongly activates the unit despite those perturbations, which biases solutions toward stable, object-like motifs (a dog-like blob reads as a dog under small rotation; a fragile high-frequency hack does not).

Intuition: the training distribution occupies a thin region of pixel space. The network can still assign huge logits to points far outside that region. Regularizers pull optimized x back toward the in-distribution hull so prototypes resemble plausible inputs—even when generation never conditions on a real dataset image, only on the frozen model.

Publication link. Industrial prototype systems often cite methods along the lines of prototype generation via robust feature visualization for data-independent interpretability—combining multiple regularization techniques (frequency penalties, random transformations, and related terms) so synthetic images maximize class scores while remaining visually coherent, without feeding a reference photo into the optimizer.

Gradient descent (training)

Minimize a loss (e.g. cross-entropy) w.r.t. parameters. Each step reduces the loss on the batch.

Gradient ascent (feature viz)

Maximize an objective (activations or a logit) w.r.t. pixels. Same backprop; opposite optimization direction and different free tensor.

Naming: minimizing error is a loss; maximizing an activation is an objective—same mechanics, opposite sign in the update (gradient ascent on inputs vs descent on weights during training).

Each cell has intensity pij. A fixed weight mask W (center-heavy) defines activation a = Σ Wij pij. Gradient ascent on pixels increases a; a smoothness penalty pulls neighbors toward similar values (toy frequency regularizer). Watch the pattern sharpen or stay blob-like as you change the penalty.

04

Saliency maps and input attribution

A saliency map highlights which input dimensions (pixels, tokens, or time steps) most influence an output under a local linear approximation. A common recipe for images: compute the gradient of the target logit (or predicted probability) with respect to each input pixel, ∂zclass/∂x, and visualize magnitudes (for example, |∂z/∂x|) as a heatmap. Intuitively, pixels with large gradient magnitude are “sensitive”: small changes there swing the logit. This is the same automatic-differentiation machinery as adversarial crafting and feature visualization, but the output is a diagnostic map on a fixed real image rather than an optimized pattern. Related ideas include integrated gradients, SmoothGrad, and layer-wise relevance propagation; each differs in how gradients are accumulated or smoothed.

Feature isolation in product-style interpretability stacks similarly asks which regions of an image drive a class score—useful for spotting models that attend to background instead of the object (a form of spurious correlation).

Feature visualization synthesizes an input to maximize an internal signal. Saliency holds a given input fixed and asks which coordinates most affect the output under a first-order expansion—complementary questions, same autograd machinery.

05

Interpretability workflows: prototypes, shared features, and failure modes

Beyond single-map attributions, teams often use global views: prototypes (synthetic or optimized inputs that strongly activate a class), entanglement or similarity structure between classes (which categories share internal features), and region attribution or feature isolation on real images. These tools help answer whether a model’s internal concept matches the human one. Research and product interpretability engines package gradient-based optimization, regularization (as in §03), and reporting UI so engineers can audit production vision systems without reimplementing Lucid-style pipelines by hand.

Prototypes

A prototype for class c answers: “What input would push the model toward label c?”—generated without supplying a dataset image, by optimizing pixels (or a parameterized image) against the frozen network. On a well-behaved food classifier (ice cream, hamburger, pancakes, waffles, …), prototypes for “hamburger” and “pancake” often look recognizably like those foods: that is evidence the network latched onto food appearance, not an arbitrary shortcut.

Entanglement between classes

Entanglement measures how much internal representations (or attribution profiles) overlap between two labels. Some overlap is expected: ice cream and frozen yogurt should show high entanglement for a human-aligned model because the classes are visually similar (“they both look like ice cream”). Conversely, for a broad object detector you would not expect cheesecake and dog to share much structure—if entanglement is high anyway, the model may be reading wrong shared cues and you should expect a higher risk of mutual confusion or brittle behavior.

Feature isolation on a real image

Feature isolation highlights which pixels support a particular prediction. Example pattern from a food model: a bowl photograph is classified as frozen yogurt with about 98% probability. Isolation correctly emphasizes the frozen-yogurt-like region—but because yogurt and ice cream are entangled, some shared features also receive weight toward “ice cream” at low probability. A subtler failure: the same image may receive a small probability mass on waffle because berries on top resemble training images where waffles were topped with berries. The model learned “berries ⇒ waffle” as a spurious cue; isolation makes that hypothesis auditable.

Case study: binary “tank / no tank.” Imagine a classifier intended for battlefield assist: it must flag whether a photograph contains a tank. On a held-out tank photo the network may output ≈98% probability for “tank”—excellent headline accuracy. Prototype generation paints a different picture: the tank-class prototype may show cloudy gray texture with no cannon, wheels, or hull; the no-tank prototype may emphasize green grass. That pattern suggests training tanks were often photographed under cloudy skies on certain terrain, so the model learned “cloudy sky ⇒ tank” instead of “tank geometry ⇒ tank.”

Feature isolation on a genuine tank image can confirm the pathology: the tank body appears unused (masked out in attribution), while sky and ground drive the positive class—possibly also global saturation or color statistics. Mitigation: retrain on diverse environments—sun, heavy cloud, snow, forest, urban rubble—so that no single background correlates with the label except the vehicle itself. After such retraining, isolation should concentrate on the armored vehicle, not the weather.

Healthy signals

Prototypes resemble the object; entanglement aligns with human similarity; isolation covers the object, not only background.

Shortcut signals

Prototypes show sky or grass; unrelated classes entangle; isolation lights up berries, sky, or JPEG artifacts instead of the nominal target.

Libraries oriented toward convolutional models (for example, the Lucid line of work for feature visualization, associated with the Distill / Circuits research thread) implement differentiable objectives plus image-parameterization tricks; commercial stacks add API access, batch jobs, and dashboards. Prototype jobs on a single GPU (for example a mid-range datacenter card) may take on the order of tens of seconds to about a minute per class depending on image resolution, model size, and regularizer stack—enough to run interactively in a notebook during an audit, but not free at scale.

06

Interpretability for language models

A language model assigns probabilities to token sequences. Given a prompt such as “Shanghai is a city in …”, the model defines a distribution over the next token—whether the continuation is “China,” “Beijing,” “cat,” “pizza,” or any vocabulary entry. Exposition often equates tokens with words for clarity; in real tokenizers a word may split into several tokens and a token may be a subword fragment, but the probabilistic machinery is unchanged: each step is a categorical distribution over a finite vocabulary.

The same question that motivated vision prototypes applies here: given a desired next-token distribution, what prompt does the model “want” to see? For vision we optimized pixels; for LMs we optimize continuous embedding vectors that sit upstream of the discrete choice, because there is no derivative through “token index 42.7.”

At each position, the final hidden state is mapped through an unembedding to logits over the vocabulary; softmax yields next-token probabilities. Tokens are discrete IDs; you cannot take a meaningful gradient through “token 42.7,” so continuous relaxations optimize in embedding space instead: treat a sequence of embedding vectors as free variables, run the transformer, and backprop into those vectors to maximize the probability of a target continuation. A regularizer can pull optimized vectors toward the nearest real token embeddings so the result maps back to readable text—otherwise you obtain arbitrary directions in ℝd that activate the target but correspond to no token.

Prompt optimization and dataset bias

Research from interpretability-focused labs optimizes prompts from random embedding noise so the model assigns maximal probability to a chosen next token. Recovered prompts describe the training corpus, not normative behavior—useful as a bias audit. Restart from many random initializations and aggregate to build frequency maps of recurring context tokens.

Multi-token targets and the autoregressive loop

Suppose the target word factorizes into two tokens—call them GI and RL—rather than one. You still initialize (for example) three learnable input embedding vectors e₁, e₂, e₃ from noise. Feed them through a transformer LM, which returns a sequence of hidden states (one per input position). For next-token prediction you typically read the last position’s hidden state, apply the unembedding matrix, and obtain logits over the vocabulary for the token immediately following the prompt.

Step A — first extension token. From those logits, pull the entries for GI (and whichever logit defines the current argmax if you also track greedy decoding). Apply softmax to turn logits into probabilities. Your optimization objective includes a term that increases the probability of GI—equivalently, minimize the negative log-probability −log P(GI | e₁,e₂,e₃).

Step B — roll the model forward. In a real generator you would append the embedding of the sampled token. Here, to score the second target piece RL, concatenate the embedding for GI after your three optimized vectors, run the LM again on the length-four prefix, read the new last hidden state, compute logits for the following position, and add a term such as −log P(RL | e₁,e₂,e₃, embed(GI)) to the objective. The full loss is the sum of negative log-probabilities (or a weighted variant) for every target token in the continuation you care about.

Minimize −log P(token₁ | prompt) − log P(token₂ | prompt, token₁) − …  w.r.t. input embeddings, + regularizer

Without extra constraints, optimized embeddings may land in dead regions of embedding space—activating the logits yet not close to any row of the embedding table, so no real token sequence reproduces the effect. The standard fix mirrors vision regularization: add a penalty proportional to distance from each optimized vector to its nearest vocabulary embedding (often the closest token embedding in L2). That term appears in the same scalar objective you minimize with gradient descent, trading off “make GI and RL likely” against “stay on the manifold of actual tokens.”

Discrete token IDs such as [0, 5, 9] cannot be nudged by ±0.01; optimization must run on continuous embeddings, then (optionally) snap or regularize toward discrete tokens for interpretability.

Attention visualization

Self-attention weights (after softmax) show where each position looks—see Chapter 01 for the full \(Q,K,V\) formulation. They are easy to plot but easy to misread: multiple heads run in parallel, and weights alone do not tell the full story of information flow in residual streams.

Probing classifiers

A probe is a small supervised model (often linear) trained on internal activations (per layer, per token) to predict a linguistic property (part of speech, syntactic depth, entity type). High probe accuracy suggests the property is linearly decodable from representations—not that the model “uses” that property in the same way a linguist would, but that the information is present.

Mechanistic interpretability

Mechanistic interpretability seeks circuits—combinations of neurons or attention heads that implement algorithms (induction heads, indirect object identification, etc.). Goals include reverse-engineering model computations enough to predict behavior under intervention (ablations, patching, causal tracing). This line of work complements gradient-based attribution with causal experiments on the model’s internals.
