Building a Multimodal Vision-Language Model

From contrastive vision encoders and the Vision Transformer to token fusion, rotary position embeddings, and key–value caching for efficient multimodal decoding—this chapter traces a PaliGemma-style architecture end to end.

00 — Overview

What you are assembling

A vision-language model (VLM) answers questions about pixels by conditioning a text decoder on visual features. The pipeline in this family of models typically includes:

  • Contrastive vision encoder (often a SigLIP-trained ViT): maps an image to a sequence of patch tokens aligned with text in embedding space.
  • Multimodal projector: a linear map from vision hidden size to language hidden size so tensors can be concatenated.
  • Causal language model (decoder-only): Gemma-style stack with RMSNorm, grouped-query attention, and rotary positional embeddings (RoPE).
  • Fusion: placeholder token IDs in the text sequence are replaced by projected vision features; attention masks treat image tokens as bidirectional context and text tokens as causal for generation.

Conditional generation. The image and the user prefix are not “contrasted” at inference the way training pairs are; they act as context the decoder attends to while predicting the next token.

Concretely, a VLM can answer a question such as “where is the photographer resting?” when given a beach photograph: the model conditions on pixels and produces a short answer (for example, that the person is in a hammock under a tree). That behavior is not produced by running contrastive scoring over caption candidates at decode time; the decoder is simply an autoregressive LM whose prefix includes fused visual tokens.

Contrastive pretraining still matters because it shapes the vision tower: image patches are mapped to vectors that already “live in” a space compatible with text. A practical data source is web-scale image–text pairs (captions, HTML alt text, encyclopedia descriptions). Noise in those pairs is expected; training at very large scale tends to wash out occasional mismatches and yields representations that align well with language.

Contrastive pretraining shapes the vision tower: patch embeddings must sit in a space compatible with text when the decoder attends over a fused sequence. A SigLIP-trained ViT is the usual choice—paired image–text supervision at scale, without dense labels per downstream task.

01 — Contrastive pretraining

Vision tower from CLIP / SigLIP

Using the CLIP framework from Chapter 22, encoders map image–caption pairs into a shared space: matched pairs score high, mismatches low. PaliGemma-style VLMs typically adopt a SigLIP-trained ViT—sigmoid pairwise training instead of row softmax—because it scales to larger batches without global row normalization. At inference the VLM does not run contrastive scoring; it reuses the vision encoder’s patch tokens as decoder context.

CLIP (softmax over a row)

Cross-entropy along rows and columns of an \(N \times N\) similarity matrix. Needs the full row on one device for the softmax partition function.

SigLIP (sigmoid per cell)

Each \((i,j)\) pair is an independent binary target after a sigmoid—cells can be sharded for very large batches.

02 — Vision Transformer (ViT)

Patch embeddings and full self-attention

An image tensor has shape \((B, 3, H, W)\). A patch embedding uses a 2D convolution with kernel_size = patch_size, stride = patch_size, and padding = 'valid' so patches do not overlap. Each spatial location becomes one token of dimension hidden_size.

\(\displaystyle N_{\text{patches}} = \left(\frac{H}{\text{patch\_size}}\right)\left(\frac{W}{\text{patch\_size}}\right)\)

For a square \(224 \times 224\) image and \(16 \times 16\) patches, \(N_{\text{patches}} = 14 \times 14 = 196\) spatial tokens; configurations may expose a fixed num_image_tokens (e.g. 256) depending on variant and pooling.

Positional information in ViT is usually a learned embedding table (one vector per patch index), added to patch embeddings—unlike sinusoidal encodings common in original NLP Transformers.

Attention mask. ViT uses bidirectional self-attention over patches—every patch may attend to every other patch.

The original Vision Transformer treats non-overlapping patches as a token sequence with learned position vectors and encoder blocks—no causal mask inside the vision tower, unlike the text decoder in Chapter 04.

For global contrastive training, some systems pool patch states into one image vector. PaliGemma-style VLMs keep all patch tokens, project each to the text hidden size, and splice them into the decoder prefix for fine-grained spatial evidence.

Patch count vs. num_image_tokens. For \(224\times 224\) inputs with \(16\times 16\) patches, the natural grid is \(14\times 14 = 196\) spatial tokens. Many released checkpoints instead fix num_image_tokens (often 256 for the smallest PaliGemma image size) so the tokenizer and projector agree on placeholder count—consult the model config rather than assuming 196.

Convolution with stride equal to kernel size walks the image in a non-overlapping grid. Flattening spatial dimensions yields a sequence of patch tokens for the Transformer encoder stack (pre-norm blocks: LayerNorm → attention → residual; LayerNorm → MLP → residual).

Interactive: multi-head split (conceptual)

Embedding dimension \(d_{\text{model}}\) is partitioned into \(h\) heads, each of size \(d_{\text{head}} = d_{\text{model}} / h\). Heads run scaled dot-product attention in parallel; outputs are concatenated and mixed by \(W_o\).

03 — Normalization

LayerNorm in ViT, RMSNorm in the decoder

ViT encoder blocks use LayerNorm per token (pre-norm: normalize before attention and MLP). The text decoder uses RMSNorm instead—see Chapter 04 for the full treatment. BatchNorm (batch-axis statistics) appears in CNN image pipelines but not in these Transformer stacks.

04 — PaliGemma-style assembly

Vision tower, projector, and decoder

The end-to-end model is a composition of three trainable pieces plus preprocessing:

  1. SigLIP / ViT tower: pixels → sequence of vision hidden states.
  2. Multimodal projector: linear layer \(W \in \mathbb{R}^{d_v \times d_\ell}\) mapping each vision token to \(d_\ell\) (language hidden size).
  3. Decoder LM: decoder-only stack from Chapter 04 / Chapter 05 (RMSNorm, RoPE, GQA); final logits tied or untied with input embeddings.

Weight tying. Sharing parameters between the input embedding matrix and the output projection to vocabulary reduces parameter count when the vocabulary is large.

In a typical PaliGemma-style bundle, the text decoder (Gemma family) uses hidden width \(d_\ell\) on the order of 2048 for a “base”-scale checkpoint, while the SigLIP ViT tower often exposes a different width \(d_v\) (commonly 1152 in public configs). The multimodal projector is a single linear map \(\mathbb{R}^{d_v} \to \mathbb{R}^{d_\ell}\) applied per patch token. Matching names with the Hugging Face state dict (e.g. vision_tower, multi_modal_projector) avoids brittle weight-import scripts.

Released variants resize inputs to different squares—224, 448, and 896 pixels appear across the family—with corresponding increases in patch-token count. The processor must resize, rescale pixels from \([0,255]\) toward \([0,1]\), then normalize channels (often with per-channel mean/std close to ImageNet statistics, sometimes simplified to \(0.5\) scalars in code for convenience).

Implementations sometimes rescale projected image features by \(1/\sqrt{d_\ell}\) (same spirit as attention scaling) so doubling embedding width does not automatically explode activation magnitudes. Treat this as a training-time convention carried into inference.

05 — Fusing image and text tokens

Placeholders, merge, and attention mask

Tokenizer output is a list of integer IDs. The recipe adds many copies of a dedicated <image> placeholder ID at the start of the sequence, then BOS, then the task prefix string, often with a newline separator tokenized carefully so it does not merge incorrectly with the prefix.

Embeddings are looked up for all IDs. Rows corresponding to placeholder positions are discarded and replaced by the projected vision features (same count as placeholders). The result is one long sequence of vectors fed to the decoder.

The published PaliGemma prompt template follows the schematic: \(k\) image placeholders (with \(k\) equal to num_image_tokens from config—often 256 for the smallest image setting), then BOS, then the user’s task string (“describe…”, “where is…”), then a newline separator. The paper recommends tokenizing the newline separately so byte-pair merges do not glue it to the last word of the instruction.

A practical merge implementation builds three boolean masks over positions—image, text, padding—broadcasts them across \(d_\ell\), and uses torch.where / masked scatter: copy ordinary text embeddings where the text mask is true; write scaled projector outputs where the image mask is true; zero or ignore padding. The placeholder rows produced by the embedding table are throwaway; only positions matter.

Beyond captioning, the same tokenizer family can carry extra special tokens for dense tasks (for example, large grids of location tokens for bounding-box style outputs and additional tokens for segmentation masks). Conditional captioning only needs the image placeholders plus text instructions; detection/segmentation tokens stay unused in that mode.

06 — RoPE & KV cache

Positions and efficient autoregressive decoding

The text decoder follows the stack from Chapter 04 and Chapter 05: RoPE on queries and keys, grouped-query attention, and a KV cache for autoregressive generation. With hundreds of image tokens in the prefix, cache size and memory bandwidth dominate latency—GQA shrinks the KV footprint compared to full multi-head attention.

Prefill vs. decode. First forward: run the entire prefix (all image + instruction tokens) to populate per-layer KV caches in one parallel pass. Each subsequent step appends one token: compute \(q,k,v\) for that token, concatenate new \(k,v\) along the sequence axis, and attend over the growing cache.

Position IDs through prefill. If the prefix contains 256 image tokens plus three text tokens, RoPE consumes positions \(0,1,\ldots,255,256,257,258\) in order. The first decode step uses position \(259\) for the newly sampled token, then \(260\), and so on.

Interactive: multimodal KV cache timeline

Prefill: compute K,V for the entire prefix (image + text so far) once. Decode: append one new token per step; cache past K,V so only the new position’s projections and attention over the growing cache are needed.

07 — Full forward pass

End-to-end inference checklist

  1. Resize and normalize the image (channel-first tensor; mean/std scaling as in the checkpoint).
  2. Run the vision tower forward → (B, N_p, d_v).
  3. Apply multimodal projector → (B, N_p, d_\ell).
  4. Build token IDs: k image placeholders + BOS + prefix (+ separator as specified).
  5. Embed tokens; overwrite the first k rows with projected patch features.
  6. Run decoder with appropriate attention mask; optionally fill KV cache during prefill.
  7. Sample or greedy-decode from logits at the last position until EOS.

Padding. Batched inference requires padding masks aligned with the fused sequence; single-sequence tutorials often omit this for clarity.

Sampling mechanics. Greedy decoding takes \(\arg\max\) over the vocabulary on the final position’s logits. Temperature divides logits by \(T>1\) before softmax to flatten the distribution (more diversity); \(T<1\) sharpens it. Top-p (nucleus) sampling sorts probabilities, keeps the smallest set whose cumulative mass exceeds \(p\) (say \(p=0.7\)), renormalizes, and draws from that truncated distribution—e.g. if sorted masses are \(0.5, 0.2, 0.1,\ldots\), only the first two might survive for \(p=0.7\), yielding a two-way lottery after renormalization (illustratively \(\approx 0.71 / 0.29\)).

Weights load from stacked safetensors shards plus config.json; keeping module names aligned with the reference implementation lets you load_state_dict without a rename map. After load, call the tie-weights hook so the input embedding matrix and LM head share storage—often on the order of ~10% of total parameters for large vocabularies.

ViT MLP (SiGLIP)

Two linear layers with an inner GELU: expand to an intermediate multiple of the hidden size (often ~4× in ViT literature), then project back. Operates per token independently after attention mixes information.

Gemma FFN

Gated SwiGLU-style expansion—details in Chapter 04.
