CLIP: Contrastive Image-Text Alignment

CLIP (Contrastive Language–Image Pre-training, OpenAI 2021) learns a joint embedding space for images and text. This chapter covers the contrastive objective on an N×N similarity grid, zero-shot classification via prompts, and how the text tower conditions generative models such as Stable Diffusion.

00

Why connect text and images?

Many real-world problems are fundamentally classification: assign a discrete label to an image. Classic pipelines learn a function from pixels to one of K predefined categories. That works when categories are stable, cheap to annotate, and visually separable.

CLIP (Contrastive Language–Image Pre-training; Radford et al., OpenAI, 2021) learns a joint embedding space: images and natural-language descriptions that belong together should land near each other as vectors. Once aligned, you can compare an image to any short text—class names, sentences, attributes—without retraining the backbone for a new label set. Language is a compressible interface to an open set of concepts: the same encoder can score “dog,” “a photo of a dog,” or “a shaggy dog in snow” without architectural changes.

01

Image classification before CLIP-style alignment

A traditional supervised image classifier stacks convolutional layers, max pooling, and nonlinearities, then ends in a fully connected layer that outputs one score per class. At inference, whichever class receives the largest activation is taken as the prediction. Picture a two-class setup—cats versus dogs—on a standard benchmark-style diagram: feed a cat image, and the “cat” logit or activation should be highest; feed a dog image, and the “dog” side should win. That local behavior is intuitive and, with enough data, remarkably strong.

What worked well

  • Strong performance when the number of classes is modest and classes are visually distinct.
  • Clear training objective: minimize cross-entropy over fixed classes.
  • End-to-end CNN training was the dominant recipe for years and still matters inside many encoders.

Structural limitations

  • Label cost: you need many images per class and someone to build, label, and verify that labels are correct. In medical imaging, that often means a clinician—not a random crowd worker—separating cancer from non-cancer on device output; expertise is expensive and throughput is limited.
  • Poor open-set behavior: a model trained on cats vs. dogs does not automatically handle new categories without retraining or retuning the head.
  • Task brittleness: performance drops when the target taxonomy or visual domain shifts; a classifier tuned to one narrow taxonomy can perform very badly on other classification protocols.

CLIP addresses the representation problem first: learn general vision–language features from noisy but abundant (image, text) pairs, then specialize at inference via prompts rather than by rebuilding a labeled closed-set dataset for every new task.

02

CLIP architecture and training data at a glance

The name CLIP encodes the idea: Contrastive Language–Image Pre-training—contrastive learning over paired images and free-form text. The architecture is deliberately dual: two encoders, an image encoder and a text encoder. A training batch contains N images and N text strings, and alignment is known by construction: the first caption corresponds to the first image, the second to the second, and so on. Think of a concrete pair—a short caption like “Pepper the Aussie pup” matched to its photograph—so that batch index i is a true positive for (imagei, texti) and a negative for every cross term.

Radford et al. assembled on the order of 400 million image–text pairs scraped from the public internet—images that were, in principle, “well described” by the accompanying user text (titles, comments, alt text, captions). That scale trades pristine manual ontology for breadth: the model sees how people actually write about pictures.

Web supervision is noisy: not every caption is faithful, and filtering matters. Compare that to classic ImageNet-scale collection: the CLIP authors note that ImageNet-class efforts involved on the order of 25,000 workers annotating about 14 million images for roughly 22,000 object categories. Against that labor-intensive baseline, learning from internet text paired with images can look—colloquially—almost free at the margin: the raw material is abundant, even though curation and compute are still serious costs.

The same broad pattern—download public text and images, then train large models—shows up in modern language modeling (e.g., GPT-style corpora) and in generative stacks that reuse CLIP-style representations. CLIP is not the only ingredient, but it is a canonical example of scaling with weak supervision instead of a single closed taxonomy.

Forward pass, matching the paper’s pseudocode narrative: run the batch of images through the image encoder to obtain one feature vector per image of dimension di (image-side dimension before projection). Run the N texts through the text encoder to obtain text features of dimension dt. Multiply image features by one learned matrix and text features by another so that both sides land in a shared dimension de. After normalization, take dot products (equivalently cosine similarity when vectors are unit length) between every image embedding and every text embedding. That yields an N×N grid of scores—the logits for contrastive training.

03

Image encoder: ResNet and Vision Transformer (ViT)

The image tower can be implemented as a ResNet-style convolutional network or a Vision Transformer (ViT). In both cases, Radford et al. take the feature vector from the last layer of the vision backbone—after the usual global pooling for ResNet-style models or the appropriate pooled token for ViT variants—and treat that as the image embedding before the projection head.

Those raw features typically pass through a learned linear map into a shared embedding dimension d_e, so image vectors are comparable to text vectors after normalization.

Notation (matching the paper-style description)

Let the image encoder output features of dimension d_i for each image in a batch. A weight matrix maps from d_i to d_e. Text features analogously start at d_t before projection to d_e.

04

Text encoder: Transformer and the end-of-text representation

The text tower uses the encoder stack of a Transformer only—not a decoder stack for this representation step. Following Radford et al., the text sequence is bracketed with a start-of-sequence token and an end-of-text token. The model reads the whole caption; the activation at the highest (final) layer of the Transformer, at the position of the end-of-text token, is treated as the feature representation of the text. That vector is then multiplied by a learned projection Wt into the same dimension de as the projected image embeddings so cosine similarities are well-defined in a shared space.

htext = Wt · TransformerEnc(x)EOT

Intuitively, the end-of-text position aggregates context over the full caption via self-attention. The paper fixes one unambiguous readout: last layer, end-of-text index—so checkpoints and fine-tunes stay comparable.

05

The N×N similarity matrix and contrastive loss

After L2-normalizing the projected embeddings (so dot products equal cosine similarity), form logits L ∈ ℝN×N where L[i,j] compares image i with text j. Ground-truth pairs lie on the main diagonal: (i,i) for i = 0…N−1. Training should push those diagonal entries to be the largest in their row and column; off-diagonal pairs—every mismatched image–caption combination in the batch—should score lower, ideally far lower, so they act as negatives within the mini-batch.

The training objective is exactly that diagonal-dominance constraint, implemented with softmax cross-entropy. For rows: fix an image row i and treat the N text columns as a categorical problem where the correct class index is i—the label you would enumerate as 0, 1, …, N−1 aligned with batch order. Row i should put maximum mass on column i. For columns: fix a text column j and require the highest similarity at row j among all images. Compute cross-entropy between the row-wise softmax predictions and those indices; compute cross-entropy again for the column-wise reading of the same logits; sum the two losses and divide by two. That average is the standard CLIP contrastive loss—symmetric InfoNCE / noise-contrastive estimation across the batch, penalizing both “which text matches this image?” and “which image matches this text?” mistakes.

logits L[i,j] = cos(ziimg, zjtxt)  (after projection to de and ℓ2-normalization)
ℓi→t = −log ( eLi,i / Σk eLi,k )
ℓt→i analogously on columns  →  ℒ = (ℓi→t + ℓt→i) / 2

Row view (image → texts)

For each image i, among all N captions in the batch, caption i is the positive. Every other caption in that row is a hard negative drawn from the same minibatch.

Column view (text → images)

For each text j, among all N images, image j is the positive. Symmetry ensures the similarity matrix is trained coherently from both modalities’ viewpoints.

Concretely, take N = 3. Indices 0, 1, 2 are both the batch order and the supervised targets. For each row i, softmax cross-entropy should concentrate probability on column i; for each column j, on row j. Compute row-oriented CE, column-oriented CE, add them, divide by two. Because the image and text towers are different networks, optimizing only one direction would let the other free-ride—averaging both forces each modality to predict the other.

06

Zero-shot transfer and inference

Inference is deliberately simple and, in deployment, often efficient. Suppose you are given a new image—say, a dog photo—and a closed list of candidate classes you care about right now, such as plane, car, dog, bird (the exact inventory is up to you). First, build a prompt for each class using a template like “a photo of a {class}” (or richer variants you prefer). Run every prompt through the text encoder once, apply the text projection, and store the resulting vectors—call them t1, t2, …, tK for K classes. Those embeddings are cacheable: if your label set does not change, you never need to recompute them for the next image.

Then encode the query image with the image encoder and its projection to obtain a single vector zimg. Compute cosine similarity (dot product after normalization) between zimg and each stored tk. The index k with the highest score wins; the corresponding text prompt’s class name is your zero-shot label. No fine-tuning step is required—only forward passes and a small vector comparison.

Amortization: text-side work is paid once per label set. Each additional image costs one image forward pass plus similarity against K cached vectors—exactly the pattern that makes large-scale screening cheap once prompts are fixed.

Zero-shot CLIP is strong on many benchmarks that resemble internet captions—coarse object recognition, some action phrases, and certain OCR-adjacent cues—but it is not uniformly capable. Tasks that are hard for humans in a strict zero-shot setting can still be hard for the model. Domains far from the training mixture also hurt. Concrete failure families include counting objects in an image and other fine-grained relational reasoning that short captions rarely supervise at scale.

Relative to traditional pipelines that train a new softmax head per taxonomy, the same backbone supports many tasks by swapping prompts—an operational reason CLIP-style models became popular entry points for vision–language experimentation.

07

Prompt engineering for classification

Because labels enter through the text encoder, wording matters. Zero-shot classification is not “class index 7”—it is “the vector for a hand-written prompt.” A minimal pattern from the CLIP recipe is “a photo of a …” filled with each candidate class name: a photo of a plane, a photo of a car, a photo of a dog, and so on. Templates like a sketch of a {label}, domain-specific phrasing, or ensembling several prompts per class can shift decision boundaries without changing image weights—useful when the default phrase under-represents a category’s real appearance in your deployment data.

Prompt engineering is a lever, not a cheat code: if the vision encoder never saw supervision similar to your domain, better strings help only up to a point.

08

Connection to text-conditioned diffusion

CLIP’s visibility spiked again when generative image models such as Stable Diffusion reused its ideas: download large-scale web data, train multimodal representations, then plug the text side (or related open-weight variants) into a denoising stack. Latent diffusion models in that family typically condition generation on a text embedding produced by a frozen language encoder. Early public checkpoints often used a CLIP-derived text tower (or closely related OpenCLIP weights) to map prompts into vectors that the U-Net or transformer denoiser conditions on via cross-attention or projection layers.

The same contrastive pre-training that aligns captions with images also yields semantically organized text features that are useful as conditioning signals: nearby prompts tend to produce related generations even though diffusion training is a different objective than CLIP’s contrastive loss.

Quick reference

  • Training: maximize diagonal of N×N cosine logits; symmetric CE over rows and columns; targets are indices 0…N−1 aligned with batch order.
  • Scale (Radford et al.): ~400M image–text pairs from the web vs. ImageNet-era annotation on the order of 25k workers, 14M images, 22k object categories.
  • Image tower: ResNet or ViT → last-layer features → linear map to d_e.
  • Text tower: Transformer encoder only; pool final layer at end-of-text; linear map to d_e.
  • Zero-shot: embed class prompts once (e.g. “a photo of a {class}”); encode image; take argmax similarity.
  • Strengths / limits: strong on many open-vocabulary tasks; weak on e.g. counting, some human-hard zero-shot settings, and domains far from pre-training.
  • Diffusion link: CLIP-style text embeddings as conditioning for denoisers (e.g. Stable Diffusion lineage).
