Skeleton-first: see the stack before the lemmas

A practical way to own LLaMA-style code is to instantiate the outer Transformer first: tok_embeddings, a ModuleList of identical TransformerBlock modules, final RMSNorm, and an output linear that maps hidden states to vocab_size logits. Each inner block is “pre-norm” attention plus residual, then pre-norm FeedForward plus residual. Only after that shell exists do you implement precompute_freqs_cis, Attention with start_pos, and the three-matrix w1/w3/w2 MLP.

This matches how inference code is read in the wild: the forward you care about is short, while apply_rotary_emb and cache indexing are where bugs hide. Training would disable the cache and allow seqlen > 1; the path below targets loading pretrained weights and torch.inference_mode() generation.

Inference contract. With a populated KV cache, each step passes a batch of shape (B, 1) token ids. start_pos is the absolute index of that token in the full prefix so RoPE rows and cache writes stay aligned.

A practical stack for reproducing official behavior pairs this module code with a SentencePiece-style tokenizer (BPE / byte-pair style subwords): tokens are rarely whole words—they can be affixes, fragments, whitespace runs, or digits. The embedding table maps each vocabulary index to a learned vector (4096-wide in the 7B-style configuration cited in releases, not the original Transformer’s 512).

The chapter follows a top-down read order: outer Transformer first, then RoPE, GQA, and cache details—the same path inference code takes in reference implementations.

01

Decoder-only language modeling

LLaMA 2 is a causal model: position t may attend only to positions ≤ t. The objective is next-token prediction: model a conditional P(x_{t+1} | x_{≤t}) and sample or argmax at decode time. Unlike encoder–decoder stacks, there is no cross-attention stream—only self.attention over the residual hidden state h.

Training view

Usually pack a chunk of length T, mask future positions, and compute logits for every offset in one forward (no KV cache).

Inference view

After a prompt warm-up, feed one new token_id per step; reuse stored k_cache and v_cache so you do not re-project old tokens.

P(x_{1:L}) = ∏_{t=0}^{L-1} P(x_{t+1} | x_{≤t})

Training packs a length-T chunk with targets shifted one step: position t predicts token t+1 from prefix x_{≤t}, and the causal mask hides future positions. Inference reuses the same conditional—one new token per forward after the prompt is cached.

02

ModelArgs: one dataclass, every dimension

Hyperparameters that must agree across modules live in a @dataclass (here ModelArgs): dim (model width), n_layers, n_heads (query heads), n_kv_heads (key/value heads for GQA), vocab_size, ffn_dim_multiplier, multiple_of for rounding the SwiGLU interior, norm_eps, and cache bounds max_batch_size, max_seq_len. Head width is head_dim = dim // n_heads; GQA requires n_heads % n_kv_heads == 0 for the simple repeat_kv layout.

When researchers shrink the number of KV heads for speed, they often widen the feed-forward block (via ffn_dim_multiplier and related knobs) so total parameter count stays comparable to an older “full MHA” baseline. That way comparisons isolate architectural choices instead of model size.

Why centralize?

Constructor signatures stay small: every submodule reads args.dim, args.n_heads, etc. When you parse params.json from a release directory, you fill this object once and call Transformer(args).

Official checkpoints name tensors like layers.{i}.attention.wq.weight; mirroring those attribute paths avoids a brittle rename map.

Transformer outline and RoPE table

04

RoPE: precompute_freqs_cis and apply_rotary_emb

RoPE rotates adjacent pairs in q and k by position-dependent angles; v stays unrotated. Chapter 04 derives the math (relative offsets via composed rotations, complex phasors, frequency schedule). Here the implementation task is wiring the table into the forward pass: precompute_freqs_cis builds e^{i m \theta_i} with torch.polar, and apply_rotary_emb packs pairs as complex, multiplies by the slice freqs_cis[start_pos:start_pos+seqlen], and flattens back.

RoPE requires an even head dimension d_h. The reference uses base θ = 10000 and often precomputes 2 × max_seq_len rows for long prompts.

θ_i = 10000^{-2i/d_h},   i = 0, …, d_h/2 − 1

Complex multiply = fused rotation

torch.view_as_complex(x.float().reshape(…, 2)) packs pairs; multiplying by unit-magnitude complexes applies cos/sin mixing without huge sparse matrices.

RoPE touches only q and k after projections; v stays unrotated.

60def precompute_freqs_cis(dim: int, end: int, theta: float = 10000.0):
61    freqs = 1.0 / (theta ** (torch.arange(0, dim, 2)[: (dim // 2)].float() / dim))
62    t = torch.arange(end, device=freqs.device, dtype=torch.float32)
63    freqs = torch.outer(t, freqs).float()
64    freqs_cis = torch.polar(torch.ones_like(freqs), freqs)
65    return freqs_cis

67def reshape_for_broadcast(freqs_cis, x):
68    ndim = x.ndim
69    assert 0 <= 1 < ndim
70    shape = [d if i == 1 or i == ndim - 1 else 1 for i, d in enumerate(x.shape)]
71    return freqs_cis.view(*shape)

73def apply_rotary_emb(xq, xk, freqs_cis):
74    xq_ = torch.view_as_complex(xq.float().reshape(*xq.shape[:-1], -1, 2))
75    xk_ = torch.view_as_complex(xk.float().reshape(*xk.shape[:-1], -1, 2))
76    freqs = reshape_for_broadcast(freqs_cis, xq_)
77    xq_out = torch.view_as_real(xq_ * freqs).flatten(3)
78    xk_out = torch.view_as_real(xk_ * freqs).flatten(3)
79    return xq_out.type_as(xq), xk_out.type_as(xk)

05

RMSNorm

RMSNorm scales each token vector by the reciprocal root-mean-square of its features—no per-token mean subtraction (unlike LayerNorm). A learnable vector weight (often called γ) rescales after normalization; eps inside the sqrt avoids divide-by-zero.

RMS(x) = √(mean(x²) + ε)   ·   RMSNorm(x) = (x / RMS(x)) ⊙ γ

Layer normalization, as in the original Transformer, imagines a batch of tokens where each row is one token and columns are features—say ten tokens with three features (a_1,a_2,a_3) per row. It computes a mean \mu and variance \sigma^2 along the feature axis for each row, then standardizes: (x-\mu)/\sigma, giving approximately zero mean and unit variance per row before the learnable affine \gamma,\beta. The variance formula \frac{1}{n}\sum (x_i-\mu)^2 explicitly needs \mu.

RMSNorm (Zhang & Sennrich, 2019) keeps the scaling story but drops recentering: the RMS statistic uses raw squares, so no mean is subtracted. The authors write: “In this paper we hypothesize that the rescaling invariance is the reason for success of layer Norm, rather than the re-centering invariance.” Operationally you divide by \mathrm{RMS}(x)=\sqrt{\mathrm{mean}(x^2)+\varepsilon} and multiply by a learnable \gamma (called weight in code)—same gain path, less work than full LayerNorm.

torch.rsqrt computes 1/\sqrt{\cdot} in one fused step—what the reference uses inside _norm before the elementwise multiply with weight.

rsqrt for one fused inverse

torch.rsqrt computes 1/√· in a single op—standard in reference implementations. Output dtype follows x after the cast from stats in float32 if you stabilize in full precision.

102    def _norm(self, x):
103        return x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)

06

TransformerBlock (pre-norm)

Each block stores two RMSNorm layers and submodules attention and feed_forward. The residual stream is h; attention and FFN never change width—they return tensors shaped like h. Both sublayers receive the rotary slice freqs_cis only where needed (attention); the FFN is position-agnostic.

With dim = 4096 and n_heads = 32, each head sees head\_dim = 4096/32 = 128 features from every token—still “full sentence” along sequence, but only a slice of the per-token embedding per head.

Decoder-only blocks use self-attention only—q, k, and v all come from the same residual stream. Cross-attention (queries from one stream, keys/values from another) appears in encoder–decoder models, not here.

Residual ordering

h = h + submodule(norm(h)) is the LLaMA pattern (pre-norm). Deep stacks train more stably than post-norm variants at large depth.

208            dim=args.dim, hidden_dim=4 * args.dim, multiple_of=args.multiple_of,

212        self.ffn_norm = RMSNorm(args.dim, eps=args.norm_eps)
213

215        h = x + self.attention.forward(self.attention_norm.forward(x), start_pos, freqs_cis)
216        out = h + self.feed_forward.forward(self.ffn_norm.forward(h))
217        return out
07

KV cache: store keys and values, query only the new row

Without a cache, each decode step would recompute k and v for the entire prefix. Instead, allocate cache_k and cache_v with shape (max_batch, max_seq, n_kv_heads, head_dim) per layer, write into index start_pos on every forward, and read the prefix 0 : start_pos + 1 when building attention scores. The incoming x still has seqlen == 1 for incremental generation after priming.

Memory trade. Cache size scales with layers × batch × seq × n_kv_heads × head_dim × 2 (K and V) × dtype bytes. GQA shrinks n_kv_heads versus full multi-head KV.

Picture autoregressive decoding on a memorized line: training packs the full prefix with a causal mask; a naïve rollout that refeeds the entire prefix each step recomputes old query rows even though only the last query row is new—on the order of 1+2+3+4 = 10 row-length dot products’ worth of redundant work versus 4 fresh dots when past keys and values are cached.

Without KV cache

Each step grows the query tensor with all prior tokens; QK^T revisits old query rows even though only the newest next-token logit matters. Many violet cells in the score matrix are recomputed from scratch.

With KV cache

Queries are just the latest token projection; k and v tensors append that token’s rows. Attention becomes one new query row against all cached keys—output width stays one token. At step 4, you do on the order of four key dot products instead of sixteen if you counted a full 4×4 rebuild each time.

GQA and repeat_kv

n_kv_heads can be smaller than n_heads. Each KV head is shared by n_rep = n_heads // n_kv_heads query heads. After projecting k and v with wk and wv, expand heads with repeat_kv: reshape to (B, n_kv, 1, seqlen, dim), tile n_rep times on the head axis, flatten back to (B, n_heads, seqlen, dim) for the batched QK^T.

VariantQuery headsKV headsNote
MHAHHBaseline bandwidth to KV.
GQAHH_kv < HLLaMA 2 70B-style compromise.
MQAH1Minimum KV footprint.

GQA trades a modest quality hit for much lower KV-cache bandwidth (Chapter 04 covers MHA → GQA → MQA). LLaMA 2 checkpoints store fewer wk/wv heads than wq; repeat_kv expands them at runtime so batched matmuls still see n_heads aligned heads.

Reference LLaMA code often implements GQA by expanding each KV head with repeat_kv to match n_heads, then running a standard batched matmul. That is not the most bandwidth-optimal fused kernel, but it matches checkpoints and is easy to verify; a fused path would skip materializing repeated heads.

Why repeat instead of wider wk?

Checkpoints store wk with out_features = n_kv_heads * head_dim. Repeating is the straightforward way to match wq's n_heads split without duplicating learned weights on disk.

Attention forward: RoPE, cache, softmax, wo

Linear maps wq, wk, wv (no bias) produce q, k, v. View as (B, n_*_heads, seqlen, head_dim), apply apply_rotary_emb to q and k, convert freqs_cis dtype/device to match. Scatter the new k, v into cache_k/cache_v, concatenate past via slicing, repeat_kv if needed, scale scores by 1/√head_dim, apply causal mask (including padding past length), softmax, matmul v, merge heads, wo projection.

Attention(Q,K,V) = softmax(QK^T / √d_h + \text{mask}) V

After wq/wk/wv, a useful shape story for incremental decode is: xq becomes (B,\,1,\,n_\text{heads},\,d_h) then transposes to (B,\,n_\text{heads},\,1,\,d_h); cached keys gather to (B,\,n_\text{kv},\,T,\,d_h) before repeat_kv aligns heads. Scores are (B,\,n_\text{heads},\,1,\,T)—one live query row against the whole prefix—then softmax and values yield a single updated contextual vector per batch row.

The cache write at cache_k[start_pos:start_pos+seqlen] stores this step’s keys and values; the slice [:start_pos+seqlen] then gathers the full valid prefix including the row just written. start_pos is the absolute token index so RoPE slices and cache indices stay aligned across layers.

Score layout

With seqlen_q = 1, scores are a row vector per head. The mask must allow positions ≤ start_pos + seqlen - 1 and block the rest up to max_seq_len if you pad cache.

SwiGLU FeedForward

Three matrices: w1 and w3 map dim → hidden_dim, w2 maps hidden_dim → dim. Forward: silu(x @ w1) * (x @ w3) then @ w2. Hidden width is often ≈ 2/3 × 4 × dim times optional ffn_dim_multiplier, then rounded up to multiple_of (commonly 256) for tensor-core alignment.

FFN(x) = W_2 · (SiLU(x W_1) ⊙ (x W_3))

The gating nonlinearity is SiLU, also called Swish with β = 1 (same functional form as the “sigmoid-weighted linear unit”). Three weight matrices are used—w1, w3 up-project, w2 down-project—whereas the vanilla Transformer ReLU block used two matrices; the 2/3 shrink plus rounding keeps total parameter budgets comparable when researchers swap attention mechanisms.

Rounding example. Suppose the raw hidden width computes to 7 but tensor cores want multiples of 5. Integer ceiling via multiple_of * ((hidden + multiple_of - 1) // multiple_of) does: 7 + 4 = 11, 11 // 5 = 2, 2 × 5 = 10—the least multiple of 5 not less than 7. LLaMA uses large multiples (often 256) for the same reason.

Where the 2/3 comes from

SwiGLU uses two up-projections (w1, w3) into the same bottleneck. To keep parameter count near the old 4d ReLU FFN, LLaMA shrinks hidden_dim by about 2/3 so 2 × (d × h) + (h × d) stays in family with 2 × (4d × d) at comparable scale.

When scaling SwiGLU and related MLP tweaks, practitioners often lean on empirics over theory—paraphrasing a line that appears in discussions of very large LMs: “we offer no explanation as to why these architectures seem to work we attribute their success as all else to Divine benevolence.” The point stands: SiLU-gated FFNs are adopted because they work in practice, not because we have a crisp first-principles proof.

Loading official Meta checkpoints

Sharded consolidated.*.pth or multi-part .pth files concatenate into one state dict. Read params.json for dim, n_layers, n_heads, n_kv_heads, vocab_size, etc. Before load_state_dict, drop keys you recompute—commonly rope.freqs if your Transformer builds freqs_cis in __init__ and does not register them as persistent buffers matching the file.

Official releases pair these tensors with a SentencePiece tokenizer (Google’s library). On a laptop CPU, loading sharded checkpoints often lands in the 10–20 second range—mostly disk IO and deserialization—before the first forward pass. Weight directories are usually obtained through the project’s published download script (plus an accepted license), not checked into source.

Match checkpoint dtype to hardware intent: reference code often sets a default CUDA half dtype for inference. CPU-only runs should keep tensors on float32 or a supported CPU half path to avoid silent dtype/device mismatches.

Temperature, top-p, and sampling

Logits from output(h) become a distribution after softmax. temperature divides logits before softmax; top_p (nucleus) keeps the smallest set of highest-probability tokens whose cumulative mass reaches p, then renormalizes and samples. Reference code often sorts once, applies cumulative mass logic, zeros the tail, and draws with torch.multinomial.

Greedy argmax

Always pick the highest-probability token. Example: after “Cecilia, you’re breaking my heart / You’re shaking my…” the intended lyric is confidence; greedy takes the argmax each step, then daily next if that’s the peak—fine when the model’s peaks align with the text. If step 1 wrongly peaks on an absurd word (say liver), the continuation rarely recovers because the context is corrupted.

Beam search (width k)

Keep the top-k partial hypotheses each step. Example: if step 1 keeps both pizza (40%) and confidence (20%), step 2 scores continuations for both; cumulative products like 0.40 × 0.01 for pizza→margherita can lose to 0.20 × 0.8 for confidence→daily even when the greedy first pick was wrong. Costs ~k× more forwards per depth.

Temperature scales logits before softmax: low temperature (e.g. 0.4) sharpens the distribution—an 80% peak can jump toward 98%; high temperature flattens masses so unlikely tokens gain probability. It composes with sampling variants below.

Pure multinomial sampling respects the full softmax—including tiny tails—so a low-mass junk token (think a absurd tail word with 10% mass in a sloppy distribution) occasionally wins. Top-k trims everything outside the k largest logits, then renormalizes. That fixes some tails but behaves oddly on flat versus peaked distributions: the same k may keep many nearly-equal tokens in the flat case yet still admit mediocre continuations in the peaked case because the cutoff is count-based, not mass-based.

Top-p (nucleus) keeps the smallest prefix of sorted probabilities whose cumulative mass reaches p. If one token already carries 0.9 mass and p=0.5, you stop at that single token—long tail never enters. If masses are spread, more tokens join the nucleus, preserving diversity when the model is uncertain.

Reference text_completion often defaults near temperature = 0.6 (slightly sharper than 1.0) and top_p = 0.9 (90% nucleus). Greedy is the temperature → 0 limit in spirit; nucleus sampling is the production compromise between diversity and tail risk.

\text{sorted masses e.g. } 0.44,\,0.40,\,0.06,\,0.04,\,0.03,\ldots \quad\Rightarrow\quad \text{cum: } 0.44,\,0.84,\,0.90,\,0.94,\ldots

The mask cumsum - sorted > p implements “include the token that pushes cumulative mass over the threshold.” With p = 0.9, cumulative hits 0.84 after two tokens, 0.90 after the third—so the third mass (0.06) is kept even though the running sum minus its own share dipped below the cutoff logic; subtracting sorted shifts inclusion correctly so the boundary token is not dropped. Zeros are applied to the tail, masses renormalized, then multinomial draws; gather maps sorted indices back to vocabulary ids.

Logits are unnormalized scores—one per vocabulary entry from the final linear layer. Softmax turns them into a probability simplex; temperature, top-k, and top-p only change how that distribution is sampled or truncated.

sample_top_p sketch

Sort probabilities descending. Mask tokens outside the nucleus. Renormalize remaining mass so the conditional is still a proper distribution.

generation.pyL10–28
10def sample_top_p(probs, p):
11    probs_sort, probs_idx = torch.sort(probs, dim=-1, descending=True)
12    probs_sum = torch.cumsum(probs_sort, dim=-1)
13    mask = probs_sum - probs_sort > p
14    probs_sort.masked_fill_(mask, 0.0)
15    probs_sort.div_(probs_sort.sum(dim=-1, keepdim=True))
16    next_token = torch.multinomial(probs_sort, num_samples=1)
17    next_token = torch.gather(probs_idx, -1, next_token)
18    return next_token

text_completion: prime the cache, then decode

Encode the prompt to token ids, respect max_batch_size and max_seq_len chosen at construction. For each prompt position during warm-up, run model.forward(tokens[:, i:i+1], start_pos=i) (or batched prompt variants) to fill caches—then switch to sampling from the last column of logits. Append sampled ids, increment start_pos, stop at EOS or max_gen_len. Use torch.inference_mode() and the same dtype as weights (float16/bfloat16 on GPU) for throughput.

The reference keeps assert seqlen == 1 in the cached forward to enforce incremental decode—one new embedding row per step after priming. Prompt processing can use a batched path or a loop with growing start_pos; the reference loops one token at a time for simplicity.

During prompt priming you still call the model on each prompt token mainly to fill cache_k/cache_v; logits on padded prompt positions are disposable. Implementation-wise, tensors often reserve the full max length with padding, copy true prompt ids into the prefix, then overwrite only non-prompt slots as generation proceeds. End-of-sequence handling should trigger on newly generated positions—hitting EOS inside the warm-up prompt should not abort decoding early.
