Titans: Learning to Memorize at Test Time

How a separate neural memory module can adapt its weights during inference to compress whatever context you give it—so attention receives a faithful summary of the current prompt, not only patterns seen during pretraining. This chapter follows the ideas in the paper Titans: Learning to Memorize at Test Time and the background needed to read it critically.

Section 00

Sequence modeling and next-token prediction

Sequence modeling maps an input sequence to an output sequence. In language modeling, the usual objective is to predict the next token at each position: the model may use all preceding tokens (autoregressive conditioning) to guess what comes next.

Training uses pairs of input and target sequences. The target is typically the input shifted by one position: for each prefix, the supervision signal is the following token. After the full phrase, a special end-of-sequence token marks completion. Optimization compares model outputs (logits) to these targets, backpropagates, and updates parameters so the model learns to generate the target given the input.

For clarity, examples often treat one word as one token. Real tokenizers usually split words into subwords, but the supervision pattern is unchanged: each position still predicts a single next unit from the vocabulary.

The sequence the model is asked to produce during training is called the target sequence. Training compares the model’s outputs to those targets position by position. During inference, the same prefix grows one token at a time: each step appends the sampled token and runs again, so the effective context the Transformer sees lengthens with every decode step.

Autoregressive generation feeds the model a prefix, samples or takes the argmax next token, appends it to the prefix, and repeats. Thus the effective “state” visible to a Transformer at each step is the growing list of tokens processed so far—unlike a fixed-size recurrent state.

Section 01

Transformers: parallelism and the growing memory problem

The Transformer processes sequences through attention so that, during training, outputs at all positions can be computed in parallel—a major reason large language models rely on this family. Keys and values materialize the past; at inference, cached activations are reused so each new token only adds one row to the cache rather than recomputing the full history every time.

During training, past positions act as keys and values in self-attention and every position can be computed in parallel. During inference, those past key and value vectors are cached—the KV cache—per layer. Deeper models multiply storage and bandwidth; very long contexts therefore explode memory and inference cost, and deployed context limits are often set by that footprint rather than modeling ambition alone.

Scaling laws for large models lean on the Transformer partly because full-sequence forward passes can be spread across many devices: more GPUs can be thrown at parallel attention and large batches. The flip side at deployment is that the cache and attention over the full prefix remain the dominant cost for very long prompts.

Section 02

Recurrent networks: fixed memory and sequential updates

A recurrent neural network (RNN) consumes one token at a time. Each step produces an output and a hidden state that summarizes what has been seen so far—often described as the network’s memory. The next token is processed together with that state, so earlier context influences predictions indirectly through the state rather than through a full attention map.

In the basic form, RNN training is inherently sequential: you cannot compute all positions’ hidden states in parallel the way Transformer layers can (some modern recurrent designs use parallel scan ideas to mitigate this, but the classic picture is a time loop). RNNs also contend with vanishing gradients over long dependencies—mentioned as a known issue, though not the central focus here.

Crucially, the hidden state has fixed dimensionality once the architecture is chosen. It can be large, but it is bounded. That forces compression: the network must decide what to retain and what to discard, without an explicit slot per past token the way a full KV cache provides.

Once the architecture is fixed, the hidden state has a bounded size. It might be very large in principle—“as big as you like” in design space—but after you choose the width, that capacity is fixed for every forward pass.

Picture asking a single person to memorize 3,000 books. A human brain does not grow to add one new neuron per fact; capacity is bounded. A recurrent state is similar: it must compress an unbounded stream into a fixed-size vector or tensor. Whatever does not fit into that representation is at risk of being lost, not because the model is lazy, but because the bottleneck is structural.

Transformer prefix

To predict a later token (for example pizza in “I like to eat pizza”), the model can attend over all preceding tokens at once because the full prefix is presented together. That full visibility is exactly what makes parallel training across positions possible.

RNN recurrence

At step two the network sees the token like directly and the token I only indirectly, through the hidden state carried from step one. Earlier content is always mediated by compression into that state. There is no per-token slot unless the architecture adds one elsewhere.

Section 03

Hybrid attention + RNN: training success vs test-time distribution shift

A common pattern stacks attention layers on top of a module that compresses long input into a shorter sequence (or a fixed tensor) for attention to read. Because self-attention cost scales roughly quadratically with sequence length, feeding attention a shorter stream saves compute; the recurrent side’s job is token compression (a continuous bottleneck), though you can picture it informally like keeping only the top-k most useful tokens for the next prediction.

Attention is strong at using whatever vectors it is given—but if the recurrent side has already lost information, attention cannot recover it.

During training, gradient descent pushes the compressor and attention jointly so loss decreases: the RNN learns to retain statistics of the training distribution (for example, emphasizing code syntax over repetitive comments, or expressions over redundant punctuation in certain languages).

At inference, prompts can be out-of-distribution (OOD). The frozen compressor may not know what to keep or drop on unseen styles of text or code. Poor compression then starves attention, and next-token quality suffers even though training loss looked healthy.

Large-scale language model training often mixes many sources—Wikipedia, broad web crawls, books, and more—so the compressor sees enormous diversity. Joint training can make the hybrid stack look excellent on average: loss falls, and metrics on in-distribution validation look strong.

The recurrent side can learn domain-specific heuristics for what to keep. On long Python source, it may learn to emphasize executable structure over repetitive comments. On C or C-like code, it may learn to de-emphasize syntactic noise such as dense nesting of parentheses when those patterns are redundant for the prediction objective. Those choices are tuned to the training distribution; they are not guaranteed to transfer when the test prompt comes from a new repository, genre, or notation style.

Attention is only as good as the vectors it receives. If the recurrent pathway has already discarded a detail the next token depends on, no amount of attention over the compressed state can recover what was never represented there—the failure is upstream of attention, not inside it.

Section 04

Titans: a memory module that learns during inference

The motivating question: can we have a compressed memory that remains efficient like a recurrent state, but adapts at test time so retrieval stays faithful to the current context—not only to regimes seen during pretraining?

Titans introduces a neural memory module, conceptually separate from the main stack of attention layers. Training proceeds with two coupled ideas:

  • Inner loop: given a long chunk of context, specialize the memory parameters so they encode that chunk—optimizing a memorization objective—before asking attention to predict the next token.
  • Outer loop: update the large model (and shared projections) so it learns to use what the memory retrieves across many examples.

Contrast this mental picture with a classic hybrid stack. Suppose the recurrent pathway must map 1,000,000 tokens down to on the order of 1,000 vectors before attention runs—because attention cost scales roughly quadratically with sequence length, and a shorter stream is far cheaper. You can think of that operation informally as keeping the “top thousand” most useful pieces of context for the next-token objective, even though the implementation is continuous compression rather than discrete pruning.

In the recurrent-plus-attention setup, that compression is trained once on the pretraining mixture. At inference, a huge prompt—say, an entire large GitHub repository serialized to tokens—must pass through the same fixed compressor. If that prompt is out-of-distribution, the module may not know what to keep or drop; attention then receives an impoverished summary and performance collapses even when training curves looked healthy.

Titans instead runs the inner loop on the fly: specialize the neural memory on the current million-token context (or whatever length you feed), retrieve a compressed packet, and only then let attention consume that packet alongside live tokens. The outer loop still trains the main Transformer weights so the stack learns, across many examples, how to use what the memory produces—including behavior when memory was adapted at inference, not only during pretraining.

At inference, the same inner-loop adaptation runs on the fly: embeddings of the prompt (possibly millions of tokens in principle) are used to train the memory for that instance, then retrieved content is fed to attention. The base weights may stay fixed while the memory matrix moves—addressing the frozen-compressor failure mode for OOD prompts.

Published benchmarks are useful orientation, but they follow the same incentives as everywhere in ML research: aggregate tables can hide variance by task, data, and compute. Treat leaderboard entries as hypotheses to validate on your own workloads and latency budgets, not as ground truth.

Across the tasks reported in the Titans paper, the architecture tends to show higher average scores than several strong baselines in the same family as Mamba and related recurrent / structured-state designs—when judged by the paper’s own aggregate summaries. Independent replication and task-specific measurement still matter.

Section 05

Memory as a learnable operator: read, write, reconstruct

The memory supports write and read operations at both training and inference. In the paper’s core instantiation, the memory is a weight matrix W (a linear map)—though the same algorithmic picture extends to small MLPs (two layers with a nonlinearity) as the memory parameterization.

For a token embedding x, learnable projections produce key- and value-like quantities k = W_K x, v = W_V x, analogous to attention’s linear maps. Retrieval applies the current memory to a query q = W_Q x: a read is ŷ = W q (shape conventions as in the paper).

The memorization loss is a reconstruction objective—conceptually an L2-style penalty—so that querying with the key direction should recover the associated value. If the memory can reconstruct what was written, it is retaining usable information about the stream.

The memory module is a neural network in its own right, logically separate from the main stack: a Transformer (or hybrid) consumes reads from this module while outer-loop training aligns the whole system. The paper’s default instantiation is a single linear map—so the memory is literally a weight matrix W—but the same training picture extends to a small MLP (for example two layers with a nonlinearity between them). The chunk-parallel inner training procedure carries over to that parameterization.

Reconstruction idea: minimize ‖ W qt − vt ‖² (with q, k, v from projections of xt)

Intuitively: write by updating W so that the mapping implied by current keys and values is absorbed; read by applying the current W to a query. The better the readout matches the value projection, the lower the memorization loss and the more faithfully the matrix encodes the stream seen so far.

Inference-time inner loop: token-by-token accumulation

Suppose generation starts from a prompt of one token. That token is embedded, projected to k with W_K and to v with W_V. Retrieval uses the query q = W_Q x. With a linear memory, the readout is ŷ = W q. The memorization loss compares that readout to v; its gradient with respect to W is what the Titans paper calls surprise—large loss means the memory failed to reconstruct the current projection, so the update should be stronger.

After one gradient-style update, the refreshed W is used to retrieve a compressed summary (again via q and the product W q) that is passed into the first attention layer, then the next, until logits predict the first new token. That produced token is not swapped in as a replacement memory; it is folded in like every prior token—projected through W_V and W_K, scored with the reconstruction loss, and used to update W again, now with both past surprise (momentum over prior memory gradients) and momentary surprise from the current token. After the second update, W should encode information about both the original prompt token and the newly generated one. The same pattern repeats for every additional token for the lifetime of the session.

θi = θi−1 − η · St   where St combines scaled surprise; for the very first step the past-surprise contribution can be initialized to zero, leaving the momentary gradient (times learning rate) as the sole driver.

Here θ stands in for the memory parameters (the matrix W in the linear case); η is a learning rate (the transcript uses γ; either symbol denotes the same scalar step size). The important operational point: W is simultaneously the stored memory and the trainable tensor being nudged at every token.

Section 06

Updating memory: gradients, surprise, and chunked parallelism

Memory updates follow gradient descent on the reconstruction loss with respect to W. Write schematically:

θi = θi−1 − γ ∇θ ℒ(θ)

Read literally: parameters at step i equal the previous parameters minus a learning rate γ times the gradient of the loss with respect to those parameters. The gradient points toward steeper loss; stepping opposite to it is what reduces the memorization (reconstruction) objective. Updating the memory matrix is the same game as updating any other network weights: move them toward lower loss on the current write/read objective.

Here γ is a learning rate. The gradient of the loss with respect to the memory is termed surprise: large loss means the memory struggled to reconstruct the current projection—so the update magnitude reflects how “unexpected” or poorly fit the new pattern is.

In ordinary deep learning, mini-batch stochastic gradient descent estimates the gradient on a small subset of data, not the full dataset. The true gradient direction is unknown; each batch gives a noisy direction that on average points the right way but oscillates step to step. Without care, you might overreact to one noisy draw. That is why practical optimizers accumulate history— momentum forms an exponential moving average of past gradients so updates are smoothed and single spikes do not dominate.

Plain per-token updates interact with stochastic noise (the same story as mini-batch SGD: each step’s direction fluctuates). Optimizers therefore use momentum—an exponential moving average of past gradients—to smooth updates. Titans analogously uses a past surprise term (history of memory gradients) together with the momentary surprise from the current token, so brief periods of small gradient do not cause the module to ignore genuinely novel content. Together, these terms implement surprise-based gating of memory writes: large reconstruction error yields a larger corrective gradient, so unexpected patterns push W harder, while smoothed history prevents single noisy steps from erasing what was already learned in the chunk.

Past surprise is the analogue of the accumulated gradient term in momentum-style optimizers (the same family of ideas that appears in widely used adaptive methods such as Adam). Momentary surprise is the gradient from the token (or batch fragment) you are processing right now. Together they gate writes so brief stretches of easy-to-fit tokens do not cause the module to overlook genuinely new patterns that arrive a few steps later.

A naive inner loop that updates W strictly one token at a time serializes work over very long contexts. The paper gives a hybrid algorithm that parallelizes within chunks: e.g. length 1,000,000 with chunk size 1,000 yields on the order of 1,000 sequential outer steps over chunks instead of one million per-token serial steps—still not full-sequence parallelism, but a practical compromise for GPU utilization.

Sequence length T = 1,000,000 · chunk size C = 1,000 ⇒ ⌈T / C⌉ = 1,000 sequential chunk passes (parallel work inside each chunk), not 1,000,000 strictly serial token updates.

Without chunking, a million-token prompt would force a purely serial chain: token 1 → update memory → token 2 → update memory → … a million times—hard to keep GPUs busy. Chunk-wise inner training is the compromise the paper proposes: parallelize inside each block of C tokens, then move to the next block with the updated memory state carried forward.

Section 07

Architecture variants: MAC, MAG, and MAL

The memory can be wired into the Transformer stack in several ways. Three useful patterns:

VariantNameIdea
MAC Memory as Context Retrieve a compressed packet from memory and prepend (or append) it to the token stream entering attention, so self-attention sees both live tokens and the memory summary.
MAG Memory as Gate Run attention on the current token(s) while the memory is updated; combine attention outputs with memory readouts (gated fusion) for the layer representation.
MAL Memory as Layer Skip attention entirely for the memory path: continuously update memory, read compressed state, and map it directly toward logits with a linear (or wider) head—pure memory-decoder stack.

Optional persistent memory tokens are additional prefix tokens trained only in the outer loop—they are not part of the inner-loop memory matrix and are not required for test-time adaptation; the core mechanism is the adapting W.

Names in the paper line up with roles: Memory as Context (MAC) treats the memory readout as extra tokens prepended or appended to the live stream before attention runs. Memory as Gate (MAG) runs attention on the current token(s), updates memory in parallel, and fuses attention outputs with memory readouts. Memory as Layer (MAL) bypasses attention blocks for the memory-centric path: keep updating memory, read a compressed state, and map it with a linear (or wider) head straight to logits.

Worked routing example: predicting the eleventh token

Suppose the memory has already absorbed ten tokens and you are about to predict the eleventh. The memory’s job is compression: even after ten writes, the readout need not be ten tokens long. Imagine the readout is a packet of five compressed vectors.

Under MAC, take those five vectors, prepend them to the embedding of the eleventh token, and feed the resulting sequence of six vectors into the first attention layer. Propagate layer by layer, use the attention outputs both to form the next representation and to drive the memory update recipe for this timestep, then continue down the stack.

Under MAG, feed the eleventh token into attention while the memory is updated from the same timestep’s information; combine the five-vector memory readout with the single-token attention output (gating or addition as in the paper’s diagrams) to form the layer output. The point is dual use of the same token: attended over explicitly and written into the adaptive memory.

Under MAL, skip the attention stack for this pathway: stream tokens (whether one or a million) into continuous memory updates, read the compressed state, and apply a linear layer to obtain logits. The design space admits many hybrids—the crucial invariant is not the wiring diagram but the test-time training of the memory itself.

Section 08

Positioning: long-context bottlenecks and related lines of work

Long-context modeling sits between two pains: Transformers give full visibility to the prefix but pay with a growing KV cache and heavy attention costs; classic RNNs offer fixed states and sequential processing, which limits parallelism and can mishandle OOD text after training.

Architectures like Mamba use structured state transitions—including state matrices shaped by HiPPO (a particular structured parameterization meant to retain long-range information in fixed state)—to improve what a recurrent-style memory can hold. Empirically, such models still trail the strongest Transformer baselines often enough that researchers continue to explore qualitatively different fixes, including Titans-style test-time adaptation of a separate memory module.

Titans belongs to the broader research thread of test-time adaptation (often called test-time training in related work): using extra gradient steps or rapid learning rules at inference to specialize behavior to the current input distribution, without assuming the prompt matches pretraining statistics.

Published aggregate benchmarks report higher average scores than several strong recurrent and state-space baselines across the tasks evaluated in the paper. Treat such summaries as orientation, not a substitute for task-specific evaluation on your own data and latency budget.

Classic recurrent compressor

Trained once; weights frozen at deployment. Strong on in-distribution compression heuristics, brittle when the prompt style shifts. Mistakes happen before attention ever runs.

Titans neural memory

The same reconstruction objective can be optimized during inference on the live context, so the memory’s writes reflect the document you actually fed—codebase, book, or chat log—not only the average statistics of pretraining.

Release timelines move quickly: when a paper ships without code, the fastest way to solidify understanding is often to read an official implementation once it appears. Treat “no code yet” as a snapshot of the publication moment, not a permanent fact—check the authors’ repositories for updates.
