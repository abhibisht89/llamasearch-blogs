Forward & Backward Propagation

How neural language models turn a prefix into a probability distribution — and how they learn to do it better. From composition functions and RNNs to gradient descent and backpropagation.

12 Core Concepts
8 Interactive Demos
1 Playground

Neural language models compose token embeddings into a prefix representation, pass it through a softmax layer, and output a probability distribution over the next word. This chapter covers the forward pass — averaging, fixed-window networks, and RNNs — and the backward pass via gradient descent and backpropagation.

00

From Prefix to Distribution

A neural language model takes an input sequence (a prefix) and produces a probability distribution over the next word. The pipeline has two main stages: composition — turning a sequence of embeddings into a single vector — and prediction — turning that vector into a distribution via a linear layer and softmax.

Terminology

The notation below uses a prefix of four tokens:

  • C₁, C₂, C₃, C₄ — token embeddings (each d-dimensional)
  • X — the prefix vector: a single representation of the entire sequence
  • Y — the output: a V-dimensional probability distribution over the vocabulary

The weight matrix W in the softmax layer is V × d: it projects the d-dimensional prefix vector into V logits, which softmax then turns into probabilities. Y is V-dimensional, X is d-dimensional. W could be stored as d × V instead — you would use X·W or transpose accordingly; the result must be V-dimensional.

Y = softmax(W · X)    where X ∈ ℝᵈ, W ∈ ℝᵥˣᵈ, Y ∈ ℝᵥ

The softmax function ensures all outputs are positive and sum to one — a valid probability distribution. The composition step maps the token embeddings C₁, C₂, C₃, C₄ to the prefix vector X.

A concrete toy size that keeps the algebra small is d = 3 for embedding dimension and V = 4 for vocabulary size: then X lives in ℝ³, W is 4×3, and Y is a 4-way distribution. The same story scales to modern models where d and V are enormous.

Composition functions increase in complexity from elementwise transforms (few parameters, limited expressivity) through fixed-window neural language models (like n-grams, but with embeddings and learned projections) and recurrent neural networks (sequential composition with shared weights) to transformers, which replace recurrence with self-attention. Forward propagation through any of these blocks feeds the same softmax head.

With random initialization, every weight matrix and embedding is random, but the pipeline still maps a prefix to logits and then to a proper probability distribution. The distribution is unrelated to language until training nudges parameters so that likely continuations receive more mass.

01

Composition: From Sequence to Vector

A composition function takes a sequence of d-dimensional embeddings (one per token in the prefix) and outputs a single vector representing the entire prefix. Ideally, this vector encodes everything useful for predicting the next word.

Naive Composition: Elementwise Sum

The simplest approach is to add the embeddings:

X = C₁ + C₂ + C₃ + ... + Cₙ

This satisfies the input/output requirements but has severe limitations. You lose all position information: "my favorite LLM is" and "favorite is LLM my" produce the exact same sum, even though one is grammatical and the other isn't. You also have no notion of the immediate previous word, part of speech, or syntactic structure. A vector with large magnitude can dominate the sum. And critically, the composition function has no learned parameters — only the embeddings are trainable, which limits expressivity.

Fixed Window: Concatenation

Instead of summing, we can concatenate the last n embeddings. With window size 4 and d-dimensional embeddings, we get a 4d-dimensional vector Z:

Z = [C₁; C₂; C₃; C₄]    (concatenation, 4d-dimensional)

The semicolon notation denotes concatenation — the same convention appears later in transformer notation (for example when packing heads or features). If each embedding has dimension d, concatenating four of them yields a vector in ℝ⁴ᵈ. We make the same Markov-style assumption as a classic n-gram: only the last n tokens matter; earlier context is dropped (truncated), just as a 4-gram table ignores everything before its 4-word prefix.

This architecture is a fixed-window neural language model; you will also see it called a neural n-gram model. It is the natural embedding-based cousin of a count-based n-gram: a table of strings versus a continuous function of concatenated embeddings.

For a generic composition function, the output vector does not have to match the embedding dimension d. You only need a fixed-size vector to multiply by the softmax matrix. Often we pick a hidden width dhid that may equal d, but it is a design choice, not a mathematical requirement.

We could feed Z straight into the vocabulary logits, but we usually insert at least one hidden layer so the model has extra parameters and can learn richer interactions between positions. Concretely, if Z ∈ ℝ⁴ᵈ, one choice is to map back into ℝᵈ with a weight matrix of shape d × 4d: the linear map has one row per output coordinate and consumes the full concatenated prefix. Other shapes are equally valid — the designer picks hidden widths.

H = f(W1 · Z) ,    Y = softmax(WY · H)

Here W1 is the hidden-layer projection and WY is a separate output matrix for logits (the earlier softmax weight W in the two-stage diagram). Subscripts keep the roles distinct when both layers are on the page. The nonlinearity f is not softmax — softmax is reserved for the final distribution over the vocabulary; f is an elementwise nonlinearity such as ReLU or tanh.

Count-based n-grams store a count for every n-word string; increasing n from 4 to 5 multiplies storage roughly like Vⁿ — exponential in context length. The fixed-window neural model instead grows linearly in n in the sense that only the input width of the first matrix grows (from 4d to 5d, and so on): we store one embedding per word type and weight matrices, not a giant sparse table of every observed prefix. That is the storage win.

Count-based n-gram

Easy to interpret: inspect the table of counts. Sparsity hurts: unseen prefixes need back-off or smoothing. Storage explodes as n grows.

Fixed-window neural LM

Harder to interpret: dense vectors and matrices. Smoother generalization: similar strings share structure through embeddings. Size scales linearly in n for the first layer width, not exponentially in Vⁿ.

Unlike one-hot bags of words, embeddings let movie and film live near each other in vector space even though they are distinct tokens, which alleviates the extreme sparsity of exact string matching. At test time, a prefix never seen verbatim can still receive a sensible hidden state because the function is continuous in the embeddings rather than a lookup that returns zero counts.

Long context and weight tying across positions. A fixed window cannot capture long-range dependencies: predicting the next word in a long document still uses only the last n surface words. A subtler issue is that different rows of W1 are tied to absolute positions inside the window. Compare the prefixes my favorite LLM is and favorite LLM really is: the next-word distribution should plausibly both favor continuations like language models. Yet the token LLM occupies position 3 in the first string and position 2 in the second, so the block of weights that processes “slot 3” never shares parameters with the block for “slot 2.” Scaling n to 50 or 500 makes this worse: there is little principled reason to treat the same lexeme at position 400 completely differently from position 450. Recurrent networks and later transformers address this in different ways.

Speed vs recurrence. Summing or concatenating the whole window and applying one or two feed-forward layers is parallel over the prefix and therefore fast at forward time. An RNN performs a separate update per token; it is typically slower for long sequences even though it fixes weight sharing and unbounded (in principle) context.

Linear Layer (Feed-Forward / Fully Connected)

The hidden layer has the form:

H = f(W · Z + b)    or simply H = f(W · Z)

This operation — multiply by a weight matrix, optionally add bias, then apply an elementwise nonlinearity — is called a linear layer (as in nn.Linear in PyTorch), a feed-forward layer, or a fully connected layer. Papers and libraries use different names for the same map.

Bias vectors are real parameters in code, but we often omit bias from the chalkboard equations for cleanliness — you can always imagine an extra column appended to W or an augmented input with a constant 1. Nothing essential changes in the derivation.

Why must f be nonlinear? Suppose instead we only stack linear maps. Let B = W a for some input a, and then C = W′ B without any nonlinearity between them. Then C = W′W a = W″ a for a single combined matrix W″ = W′W. Fifty stacked linear layers still collapse to one linear transformation. As soon as we insert genuine nonlinearities between layers, no such global collapse is possible, and depth buys expressivity.

Without f:   C = W′(W a) = (W′W) a.    With f:   C = f₂(W′ · f₁(W · a)) — not generally a single linear map.

The function f is a nonlinearity, applied elementwise to the vector produced by the linear map. Language pairs (prefix, next word) depend on syntax, semantics, and discourse in ways that are highly nonlinear; linear maps alone cannot capture those interactions, no matter how wide the matrices are.

02

Recurrent Neural Networks

Recurrent neural networks address the main weaknesses of fixed-window models: infinite sequence length (in theory) and weight sharing across all positions. Instead of processing the whole sequence at once, an RNN goes left to right, one word at a time.

Sequential Composition

At each time step t, we compute a hidden state hₜ that depends on the previous hidden state hₜ₋₁ and the current token embedding cₜ:

hₜ = f(W_H · hₜ₋₁ + W_C · cₜ)

Write ht for the hidden state at time step t (or position t). The name “time step” carries over from time-series applications; in text, it is simply the index in the sequence. The recurrence says that ht is a function of the previous hidden state ht−1 and the current token embedding ct. The hidden size dhid and the embedding size dm need not match; the matrices are sized to make the addition legal inside f.

W_H is dhid × dhid (same hidden size in and out). W_C is dhid × dm (projects the embedding into hidden space). The nonlinearity f is typically tanh for shallow RNNs; ReLU appears in deeper stacks in practice. The same W_H and W_C are used at every time step — that's the weight sharing. The final hidden state hn is the prefix representation fed into the vocabulary logits (what we earlier called X before the softmax layer).

h₁ = f(W_C · c₁)    (first position: no prior hidden state in the minimal setup; implementations often seed h₀ = 0)

Step-by-Step Processing

For the sequence "my favorite LLM is": h₁ depends only on c₁; h₂ depends on h₁ and c₂; h₃ on h₂ and c₃; h₄ on h₃ and c₄. Each step incorporates one more token. Because the recurrence is sequential, the RNN is typically slower at long prefixes than a fixed-window model that touches all embeddings in one shot, but it gains variable-length context and shared weights across positions.

RNNs handle sequences of arbitrary length because the recurrence uses the same weights at every step. There is no fixed window — the hidden state carries information from the entire prefix.

Neither RNNs nor the transformers that superseded them solve interpretability. Count-based n-grams wear their reasoning on their sleeve: low probability often traces to a missing or rare count. Neural models bury decisions in thousands of dense dimensions; a whole research area, neural language model interpretability, tries to attribute predictions to neurons, heads, or training facts. Expect opacity by default.

03

Nonlinearities: ReLU and Tanh

Nonlinearities are applied elementwise to the output of a linear layer. They're essential: without them, any stack of linear layers collapses to a single linear transformation. Language modeling requires modeling highly complex, nonlinear relationships between prefix and next word.

ReLU

ReLU (Rectified Linear Unit) is the elementwise map ReLU(x) = max(0, x). For negative inputs the output is 0; for nonnegative inputs the output equals the input. On paper the graph has a kink at x = 0 (a discontinuity in the derivative there), but in practice optimizers handle this the same way they handle other piecewise-smooth activations.

x = [−2.3,   5.7,   0]  ⇒  ReLU(x) = [0,   5.7,   0]

Every coordinate is processed independently: large negative entries become zero, positive entries are unchanged. The derivative is simple (0 on the negative side, 1 on the positive side), which matters when we propagate gradients. The failure mode is dead neurons: if a unit’s pre-activation is always nonpositive for the data you see, the output stays 0, the gradient through that ReLU is 0, and the unit may never turn back on. Leaky ReLU and related variants use a tiny positive slope on the negative side so some signal still flows.

Tanh

Tanh (hyperbolic tangent) is smooth and bounded in (−1, 1): large positive inputs approach +1, large negative inputs approach −1, and 0 maps to 0. Compared with ReLU, there is no sharp corner at the origin; the function is differentiable everywhere.

d/dz tanh(z) = 1 − tanh²(z)

If the forward pass already stored tanh(z), the backward pass can reuse it: the derivative is an inexpensive function of the activation itself. That reuse is one reason tanh-like activations are pleasant in manual derivations and in libraries. The cost is saturation: when |z| is large, tanh(z) is extremely close to ±1, the derivative is nearly 0, and gradients multiplied through many steps vanish. Deep RNNs are especially exposed to this pathology (and to exploding gradients when gains exceed 1). ReLU avoids vanishing gradients on the positive side but trades that for the dead-neuron issue on the negative side.

Vanishing gradients in shallow fixed windows. In a compact feed-forward language model with only a couple of layers, you may not see dramatic vanishing gradients unless the network is deep or uses saturating nonlinearities aggressively. The topic becomes unavoidable for deep stacks and for RNNs unrolled over long sequences.

04

Training Neural Language Models

Neural language models start with randomly initialized parameters. They produce valid probability distributions from the start — but those distributions are meaningless. Training adjusts the parameters so the model assigns higher probability to the correct next words in the training data.

At initialization, the conditional probability of the next token given the entire prefix is as random as the weights: the model has never seen natural language. After training on pairs (prefix, next word), we hope that when the prefix appears again, more probability mass sits on tokens that actually occurred in the corpus. A concrete supervision picture: for prefix my favorite LLM is, the model might initially assign high probability to nonsense like cat while the training target is Gemini; the loss penalizes that mismatch, and gradient-based updates rotate parameters toward better predictions.

A model can only learn what its data contains. Train predominantly on source code and it will struggle to write literary prose; train on short stories and it will be a weak coding assistant. If the objective is a broad general-purpose system, you want a large, diverse corpus so the empirical distribution you maximize resembles the mixture of tasks you care about at deployment time.

Parameters

The parameters (often denoted θ) are what we train. For an RNN language model, these include: the embedding matrix (all Cᵢ), W_H, W_C, and the output matrix W_y for the softmax layer. Intermediate variables like hidden states are not parameters — they're computed from the input and parameters and change for every training example.

The trainable pieces are the embedding lookup table (every ci you might index), the hidden weight matrix W, and the output matrix Wout that maps hidden units to logits. The tensor H is an activation: it depends on the particular prefix and disappears when the next example arrives. The symbol f names a fixed nonlinear function (ReLU, tanh, …) with no learnable weights of its own in the usual setup.

Training Objective

We want to maximize the likelihood of the training data. Equivalently, we minimize the negative log likelihood of the correct next word. The loss function tells us how bad we're doing: high loss = bad, low loss = good. We need it to be smooth and differentiable so we can compute gradients.

Gradient Descent

The gradient of the loss with respect to each parameter gives the direction of steepest ascent. To minimize the loss, we take a step in the opposite direction — the negative gradient. The update rule:

θ_new = θ_old − η · ∇L(θ)

Here η is the learning rate — a hyperparameter that controls step size. Too small: training is slow. Too large: we overshoot minima and oscillate. The loss landscape is highly non-convex; we typically find a local minimum, not the global one.

For each scalar parameter θj in a weight matrix, the partial derivative ∂L/∂θj answers: if I nudge θj by an infinitesimal positive amount while holding everything else fixed, how does the loss change? You could approximate that quantity by brute force — perturb every entry, rerun the forward pass, and difference the losses — but analytic differentiation through the network is far cheaper. Differentiable nonlinearities and a differentiable loss make the gradient exact for a given minibatch.

Non-convexity and local minima. Because of depth, nonlinearities, and messy data, the training loss is not a nice bowl with a unique bottom. Gradient-based methods typically settle in some local basin. The hope — borne out empirically for large language models — is that “good enough” minima produce strong predictors even though we cannot certify global optimality.

Picture a one-dimensional slice of loss versus a single parameter: you might land randomly on the curve, step downhill along the negative gradient, and eventually nestle near a valley. If the learning rate is too large, a single update can jump past the minimum to the opposite wall; the next gradient may point the other way, producing zig-zagging or divergence. If η is too small, each step barely moves, and reaching a low-loss region may take prohibitive wall-clock time. The art is choosing η (or an adaptive schedule) so progress is steady without instability.

Parameter

Learned by gradient descent: entries of weight matrices, embedding vectors, biases. Collectively θ.

Hyperparameter

Set before training: learning rate η, batch size, embedding dimension, hidden width, depth, choice of architecture, regularization knobs, random seeds. They shape optimization but are not updated by ∂L/∂· on equal footing with weights.

The update rule we have written is vanilla stochastic gradient descent (SGD) on minibatches. Production language models almost always use adaptive optimizers — Adam is the de facto default — that maintain running statistics per parameter to rescale steps. Research continues: optimizers such as Muon appear in recent large-scale training recipes. PyTorch exposes these as drop-in replacements: you still call loss.backward(), but optimizer.step() applies a more intricate rule than θ ← θ − η∇L.

Batch size controls how many training tokens or sequences contribute to one gradient estimate before an update. The extremal cases clarify the trade-off. With trillions of tokens, you could forward the entire corpus, average the loss everywhere, compute one perfect gradient, and take a single giant step — statistically ideal, computationally absurd. At the other extreme, a batch of one sequence yields a very noisy gradient: cheap per step, but the direction may swing wildly. Practical training picks a middle ground. Example sizing: batch size 10 sequences, each padded or truncated to 1,000 tokens, yields on the order of 10,000 token positions contributing to one averaged loss; you differentiate that average and step. Whether you average per token, per sequence, or with extra normalization is an implementation detail, but the principle is to aggregate enough mass that the gradient points sensibly while finishing the pass in reasonable time. Conventional wisdom is to use as large a batch as memory allows for more stable gradient estimates, subject to budget.

05

Loss Function and Cross-Entropy

For language modeling, we use the negative log likelihood of the correct next word. Given a prefix and the ground-truth next word (from training data), we want the model to assign that word high probability. Maximizing probability is equivalent to minimizing negative log probability.

L = −log P(correct next word | prefix)

On a full corpus we sum or average that quantity over every supervised position; the average negative log likelihood is the quantity tied to perplexity (perplexity exponentiates it). Minimizing the negative log probability is the same as maximizing the log probability of the observed token — the sign flip is purely convention for posing optimization as minimization.

This is a special case of cross-entropy loss. The general form is:

L = − Σ_w P(w) log Q(w)    (P = reference, Q = model prediction)

For next-word prediction, the reference P is one-hot: 1 on the correct word, 0 elsewhere. Then the sum has only one nonzero term, and cross-entropy reduces to −log Q(correct word).

Denote by Q the model’s predicted distribution over the vocabulary and by P the target distribution. The general cross-entropy is H(P, Q) = −∑w P(w) log Q(w). Language modeling usually uses a one-hot target: P(wgold) = 1 and P(w) = 0 elsewhere, which collapses the sum to −log Q(wgold). The framework still allows richer P (for example soft labels), but the default next-word setup is the degenerate case.

Real corpora repeat prefixes with different continuations: the same five-word context might be followed by ChatGPT in one document, Claude in another, Gemini in a third. Training still uses a one-hot target per occurrence, but across examples the model sees conflicting signals. The learned Q(· | prefix) then approximates the empirical conditional distribution: if most writers pick ChatGPT, the peak sits there with smaller mass on the alternatives. The predicted distribution may be peaked when the data are consistent or spread out when many endings are plausible — behavior tied to the entropy of the true continuation distribution given the prefix.

Optimization uses the negative log likelihood (equivalently cross-entropy) directly. Perplexity is the exponential of the average NLL — a monotone transform for monitoring and evaluation, easy to interpret as "how many equally likely choices the model thinks it has" — but not an extra term in ∂L/∂θ.

Batch Size and SGD

Batch size is how many training examples we use to estimate the gradient before taking a step. Using the entire dataset gives the best gradient estimate but is slow. Using a single example (pure SGD) is fast but noisy. In practice we use mini-batches — a compromise. Stochastic gradient descent (SGD) typically refers to mini-batch updates. Modern optimizers like Adam use adaptive step sizes.

Conflicting training data: If the same prefix appears with different next words in the data (e.g., "my favorite LLM is" followed by ChatGPT, Claude, or Gemini in different documents), the model will learn to put probability mass on all of them, reflecting the empirical distribution. Data quality and filtering matter — biases in the data propagate to the model.

06

Backpropagation

Backpropagation is the algorithm for computing the gradient of the loss with respect to all parameters efficiently. It uses the chain rule of calculus: if L depends on O, and O depends on W, then dL/dW = (dL/dO)(dO/dW). We work from the output layer backward to the input, reusing cached derivatives to avoid redundant computation.

The same recipe applies no matter which architecture feeds the loss: softmax on top of an RNN, a transformer block, or a tiny toy graph. In production, every weight is a tensor, but the scalar case below shows the pattern without index clutter.

Chain rule (composition):   d/dx [ g(f(x)) ] = g′(f(x)) · f′(x)

Worked example: two tanh layers with square loss

Consider scalars only. The input x is a real number supplied by the dataset (not a parameter). Two scalar weights w₁ and w₂ define

h = tanh(w₁ x),    o = tanh(w₂ h)

Here h is a hidden activation and o is the model’s prediction. For regression pedagogy (not next-word classification), use the square loss

L = ½ (y − o)²

where y is a ground-truth target. A concrete training pair might be x = 3 and y = −0.5: we want updates that move o toward −0.5 when x is 3. The parameter set is θ = {w₁, w₂}; the gradient ∇L lists the partial derivatives ∂L/∂w₁ and ∂L/∂w₂.

Introduce intermediate variables to mirror automatic differentiation:

b = w₁ x,   h = tanh(b),   a = w₂ h,   o = tanh(a)

The identity d/dz tanh(z) = 1 − tanh²(z) means we can write the derivative of o with respect to a purely in terms of o itself: since o = tanh(a), we have do/da = 1 − o². During the forward pass we already computed o; the backward pass squares it once and subtracts from 1.

Computing ∂L/∂w₂ (closest to the loss)

Apply the chain rule tracing from L back to w₂:

∂L/∂w₂ = (∂L/∂o) · (∂o/∂a) · (∂a/∂w₂)

Term by term: L = ½(y − o)² gives ∂L/∂o = −(y − o) (the leading ½ cancels with the factor 2 from the square). Next, ∂o/∂a = 1 − o² as above. Finally a = w₂ h implies ∂a/∂w₂ = h. Multiplying the three scalars yields ∂L/∂w₂ for the current forward values.

Computing ∂L/∂w₁ (deeper in the graph)

w₁ influences L only through b → h → a → o. The full chain is

∂L/∂w₁ = (∂L/∂o) · (∂o/∂a) · (∂a/∂h) · (∂h/∂b) · (∂b/∂w₁)

We already know ∂L/∂o and ∂o/∂a from the previous block. New pieces: a = w₂ h gives ∂a/∂h = w₂; h = tanh(b) gives ∂h/∂b = 1 − h²; b = w₁ x gives ∂b/∂w₁ = x. Multiply everything in order to obtain ∂L/∂w₁.

The Key Insight

Compare the two expansions. The product (∂L/∂o)(∂o/∂a) appears verbatim in both ∂L/∂w₂ and ∂L/∂w₁. Backpropagation’s speed comes from caching that shared upstream signal the first time it is needed, then multiplying by the local derivatives of the lower layer. In deeper nets the cached object is often called the upstream gradient or error signal arriving at a node. Branchy architectures may need several caches; for a straight chain, one running product suffices.

Gradient Flow

Gradients flow backward through: softmax → linear layer → (for RNN) through each time step. In RNNs, gradients can vanish (shrink to near zero) or explode (grow very large) as they propagate through many time steps. Tanh saturation contributes to vanishing gradients. This is a fundamental challenge in training RNNs on long sequences.

Parameter Update

Once we have the gradient, we update each parameter: θⱼ_new = θⱼ_old − η · ∂L/∂θⱼ. In PyTorch, loss.backward() accumulates gradients into each parameter’s .grad buffer, and optimizer.step() applies the update rule configured for that optimizer. A typical micro-loop is: forward pass → compute scalar loss (for example negative log likelihood of the gold next token) → loss.backward() → optimizer.step() → optimizer.zero_grad() (or equivalent) so the next iteration does not add to stale derivatives. The heavy engineering work lives in defining the forward graph; differentiation is delegated to the framework.

Automatic differentiation: Modern frameworks compute gradients automatically from the forward pass. Define your network and loss; call loss.backward() and the gradients for every parameter are computed. This has made implementing and debugging neural networks much easier than manual gradient derivation.

w₁new = w₁old − η · ∂L/∂w₁ ,    w₂new = w₂old − η · ∂L/∂w₂

After each minibatch (or single example in the toy setting), evaluate L, backpropagate, apply the update, then advance to the next data. Repeat until the loss curve flattens — that empirical stationarity is the practical notion of convergence for deep networks.

Scope in real models. Language models use matrix-valued weights, sequence losses summed over positions, and softmax rather than scalar square error. The chain rule is identical in spirit; only dimension bookkeeping grows. Hand-deriving ∂L/∂W for every layer is rarely done in research workflows because automatic differentiation is exact for the forward graph you implement.

Gradient descent as written refreshes the entire θ. In practice you sometimes freeze subsets of parameters — for example fine-tuning only the last linear head on a tiny dataset to limit overfitting, or updating a low-rank adapter such as LoRA while keeping the base transformer fixed. The mathematics is the same; you zero out or skip the gradients for frozen blocks.
