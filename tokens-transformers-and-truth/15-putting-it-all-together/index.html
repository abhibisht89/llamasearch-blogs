01

Language Modeling Foundations

A language model assigns a probability to text via the chain rule — each next word conditioned on all previous words. N-gram models truncate context with the Markov assumption; perplexity (exponentiated average negative log likelihood) measures held-out prediction quality and doubles as the pre-training loss.

P(w₁, w₂, ..., wₙ) = P(w₁) · P(w₂|w₁) · P(w₃|w₁,w₂) · ... · P(wₙ|w₁,...,wₙ₋₁)
PPL = exp( −(1/T) · Σᵢ log P(wᵢ | w₁,...,wᵢ₋₁) )
02

Neural Language Models

Neural models replace count-based n-grams with word embeddings — dense vectors where similar words sit close in space. Early composition used sums or RNN recurrence; the Transformer replaced recurrence with self-attention. Forward pass: embeddings → transformer blocks → softmax over the vocabulary for next-token prediction.

03

Training

Training minimizes negative log likelihood via gradient descent and backpropagation. Key hyperparameters — batch size, learning rate, schedules — govern stability and convergence. Deep networks risk vanishing or exploding gradients; residual connections and layer normalization in the Transformer mitigate both. The same optimization machinery applies to pre-training and post-training; only the data and objective change.

04

The Transformer

The Transformer backbone uses self-attention: each token attends to others via Q, K, V projections; multi-head attention runs parallel attention paths; causal masking restricts decoder-only models to past tokens. Residual connections, layer normalization, and per-position FFNs complete each block. Position is encoded via learned embeddings, sinusoidal encodings, ALiBi, or RoPE. Parallel attention over sequence length is what made billion-parameter scaling practical.

05

Pre-training & Tokenization

Pre-training learns general language from massive corpora via next-token prediction (or MLM for encoders like BERT). Configurations span decoder-only (GPT), encoder-only (BERT), and encoder-decoder (T5). BPE tokenization builds subword vocabularies by merging frequent pairs. Scale — trillions of tokens, hundreds of billions of parameters — drives capability. Some systems add mid-training instruction examples into the pre-training mix to nudge base models toward task-following before SFT.

How this connects downstream: If you skip SFT and jump straight from a base model to RL on instruction prompts, you may see almost no useful learning signal: rollouts that ignore the instruction dominate, and the optimizer has little to latch onto. Mid-training (when used) and SFT both exist partly to make “reasonable” rollouts frequent enough that RL can rank and improve them.

06

Scaling Laws

Scaling laws describe power-law improvements with compute, data, and model size. Chinchilla showed compute-optimal training favors smaller models on more data (~20 tokens per parameter). Some capabilities appear suddenly at scale as emergent capabilities, making extrapolation from small models unreliable.

07

Post-training

Post-training adapts the base model through SFT (instruction tuning on human demonstrations), then RL or preference methods (DPO). SFT must come first — RL amplifies existing behavior but cannot create instruction-following from scratch. PEFT methods (LoRA, adapters, prompt tuning) specialize large models cheaply: LoRA updates internal layers; prompt tuning optimizes virtual prefix embeddings.

RLHF trains a Bradley–Terry reward model on pairwise preferences, then optimizes the policy with PPO or GRPO. RLVR uses verifiable rewards (unit tests, math checks) where hacking is harder. RAFT and best-of-N score samples without full RL. KL penalties anchor policies to SFT when rewards are hackable. See Chapters 8–11 for full derivations.

RLHF-style learned rewards

Reward models internalize subtle criteria (tone, helpfulness) but invite reward hacking. KL to SFT mitigates drift.

RLVR (verifiable rewards)

Binary correctness checks (code tests, math verification) resist hacking but cover only checkable tasks. Often paired with GRPO.

Key takeaway: SFT teaches instruction-following; RL refines behavior using a reward signal. The choice of reward (human preferences vs. verifiable correctness) and algorithm (PPO vs. GRPO) depends on the task and compute budget.

08

Reasoning & Test-Time Scaling

Chain-of-thought prompting and reasoning models extend internal computation before answering — especially effective on math and code. RLVR with verifiable rewards incentivizes longer reasoning chains under delimited scratchpad formats: as accuracy improves, models spend more test-time tokens where the verifier rewards it. This couples training-time RL with inference-time compute — a shift from “train bigger” to “think longer.”

09

Applications & Deployment

RAG grounds generation on retrieved documents; tool use and agents extend models with external APIs and multi-turn control loops. Evaluation spans static benchmarks (MMLU, HumanEval), dynamic sets that combat data contamination, and LLM judges for open-ended tasks. Use BLEU when references are stable; prefer LLM judges (with calibration) for open-ended generation. Static leaderboard scores may overstate capability when benchmark items leaked into pre-training.

10

Safety & Reliability

Deployment risks include jailbreaking (user-crafted prompts bypassing refusals), prompt injection (hidden instructions in retrieved content), and data poisoning (malicious training data). Jailbreak resistance and injection resistance are related but distinct: a model can refuse direct user misbehavior yet obey malicious text pulled into context by a tool. Membership inference, memorization, and hallucination remain open challenges — RAG, citations, and verification help but do not eliminate them.
