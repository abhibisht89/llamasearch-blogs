Position Encodings for Transformers

How transformers learn where words are — from learned embeddings to ALiBi and RoPE. A deep dive into position encoding methods and why relative position matters.

7 Core Concepts
6 Interactive Demos
1 Playground

Self-attention is permutation-invariant without positional side information. This chapter compares learned embeddings, sinusoidal encodings, ALiBi's linear biases, and RoPE — the rotation-based scheme behind Llama, Mistral, and most modern LLMs.

* Many recent schemes are called position encodings rather than position embeddings because they modify queries and keys (RoPE) or attention logits (ALiBi) instead of adding a learned vector per index. Additive learned and sinusoidal schemes remain true embeddings in the usual sense.

01

Why Position Matters

Self-attention scores depend only on content embeddings: permute the input and the Q·KT matrix permutes with it. As shown in Chapter 04, the model has no notion of order until position information is injected — "The cat sat on the mat" and "The mat sat on the cat" would yield identical attention patterns.

Element-wise addition of token embeddings alone does not break this symmetry. Position must enter either through additive vectors, modified Q/K projections, or logits biases.

Additive embeddings only

Summing token vectors is commutative: every permutation yields the same vector before any downstream layer.

Self-attention without position

Scores are content-driven dot products. Without positional terms, only token types matter — not their slot along the string.

02

Absolute Additive Position Embeddings (Learned)

The simplest approach: learn a separate embedding vector Pi for each position i. Add it to the word embedding Ci before feeding into the transformer:

inputi = Ci + Pi

This design injects absolute positional information: position 529 receives a different vector from position 528, 2, or 7. The model can therefore discriminate “exactly where in the window” a token appeared, not only what the token is.

These position embeddings are trained via backpropagation — just like word embeddings. The model learns what each position "means" during training. This approach was used extensively in BERT-era models.

For each index i:   xi = Ci + Pi   (Pi ∈ ℝd learned, one row per position up to max length)

Critical Flaw: No Position Extrapolation

The fatal weakness: no extrapolation to longer sequences. At test time, if your sequence exceeds the maximum training length, there are no learned embeddings for those positions — a typical implementation raises an index error or requires an ad hoc extension of the table (with freshly initialized rows and usually fine-tuning).

You must choose a maximum sequence length during pre-training based on compute. Attention has quadratic complexity in sequence length, so longer contexts are expensive. A deeper model with more heads also consumes memory and FLOPs; for a fixed GPU budget, that often forces a shorter maximum context than a smaller stack could have used. Once the cap is fixed, naive learned-absolute models are locked to that length unless you change the embedding table.

Failure mode: Train with max length 512 and deploy on 1,024 tokens without architectural changes — indices 513…1,023 have no trained Pi. There is nothing to add to the word embeddings for those slots, so the positional channel is simply missing.

What absolute embeddings buy you

Simple implementation, strong in-distribution behavior within the trained window, and a direct handle on “I am the k-th token” — useful when the task cares about global index.

What they do not buy you

O(L·d) extra parameters in the position table, no free lunch past Lmax, and sensitivity to shifts in absolute index when the same syntactic pattern moves earlier or later in the window.

Trade-off: Learned absolute embeddings are simple and effective within the training length. But they cannot generalize to sequences longer than what they were trained on. For models that need to handle variable or very long contexts, this is a deal-breaker.

03

Sinusoidal Position Embeddings

Used in the original transformer paper ("Attention Is All You Need"). Instead of learning position vectors, use sine and cosine functions at different frequencies:

PE(pos, 2d) = sin(pos / 100002d/d_model)    PE(pos, 2d+1) = cos(pos / 100002d/d_model)

No learned parameters — the position encoding is deterministic. Still additive (added to word embeddings). The original Transformer paper suggested this family might extrapolate to longer contexts more gracefully than a finite learned lookup table, because the mapping from index to vector is a smooth periodic function rather than an arbitrary row per position.

Later empirical work painted a more sober picture: sinusoidal features are not a silver bullet for length generalization, and in practice they have largely been superseded by methods that target relative structure more directly (ALiBi, RoPE, and related ideas). They remain important historically and as a reference point when reading the original architecture.

Exam-style takeaway: Sinusoidal PE is still additive at the input (same interface as learned absolute), but the positional pattern itself is fixed by sines and cosines — no gradient updates change the wave frequencies, only the model’s use of those dimensions.

Reality check: Do not assume “sinusoidal = strong zero-shot extrapolation.” The claim in the 2017 paper was optimistic relative to what later benchmarks found; modern stacks rarely rely on this mechanism.

04

Relative Position — Motivation

Absolute position is rarely what matters. Knowing a word is at position 529 vs 528 doesn't help much. What matters is relative distance between tokens.

A Concrete Example

Consider two sequences:

Sequence A: "my favorite LLM is Qwen" (positions 1–5)

Sequence B: "I like honestly, my favorite LLM is Qwen" (positions 1–8 in this tokenization)

In both sequences, "LLM" and "Qwen" are two steps apart along the string (in A, indexing from 1: LLM at 3 and Qwen at 5; in B with the eight-token split below: LLM at 6 and Qwen at 8). With absolute embeddings, the vectors added to those tokens differ between the two sentences, so the raw attention logits between the pair are not forced to match even though the linguistic configuration — the same local pattern with the same gap — is unchanged. A relative-friendly scheme aims to make those logits depend primarily on content and on how far apart the tokens are, not on their global indices.

The challenge: relative position changes for each pair of tokens. It's not as simple as adding a single vector to the input — we need a mechanism that encodes pairwise distances.

Goal (schematic): attention score for token pair (i, j) should depend on content and on (i − j) or |i − j|, not on the raw values of i and j alone.

Design tension: Absolute position is easy — add Pi to each slot. Relative position is pairwise: every ordered pair (i, j) has its own offset j − i, so the mechanism must inject distance information into the attention computation itself (biases, rotations, or learned pairwise tables), not only into a single vector per token.

05

ALiBi (Attention with Linear Biases)

Key idea: don't add anything to input embeddings at all. Compute QKT as normal (no position info). Then, after computing QKT, add a linear bias matrix:

  • ● Diagonal = 0 (same position → no bias)
  • ● Off-diagonal = negative linear values (−1, −2, −3, ...)
  • ● The bias penalizes tokens that are farther apart

Multiply the structured bias by a scalar m (typically chosen in (0, 1] in the literature; the slope acts like a knob on how hard distance penalizes logits). m is a hyperparameter per head — it controls position sensitivity. A very small m shrinks every off-diagonal penalty toward zero, so the head behaves almost like vanilla content-only attention; a large m makes distant keys much less attractive before softmax. Different heads can use different slopes so some specialize in long-range patterns and others behave more locally.

ALiBi logits (conceptual):   Sij = (Q KT)ij + m · (−|i − j|)   for i ≥ j after causal masking conventions; diagonal pairs have offset 0.

No extra parameters to train for the positional pattern itself — only the choice of m per head (and the fixed template of negative distances). Empirically, models with ALiBi often extrapolate to sequences longer than the training window substantially better than learned absolute tables, because there are no position rows to overfit to a finite set of indices. Performance tends to improve as context grows, then plateaus; in reported experiments the benefit is often strongest up to roughly twice the training length — an empirical ceiling rather than a clean theorem.

Why extrapolation can help: The bias matrix for length L′ is the same recipe as for length L — extend the grid of pairwise distances. Nothing requires new rows in an embedding table, so the model is not missing parameters for “position 800” the way a learned P800 would be missing if the table only went to 512.

Effect on mass: Suppose m = 1 and the raw dot product Q4·K1 is 2.1. After adding a bias of −3 for that pair (three steps back along the causal direction), the logit becomes −0.9. Relative to other keys in the same row, softmax may now assign almost no mass to that distant key even though content alone suggested a strong match — illustrating that ALiBi is explicitly trading off “content similarity” against “how far away” the key is.

Edge of the design space: Using a negative m would flip the sign of the bias and reward distant keys relative to nearby ones — not a choice that tends to help autoregressive language modeling, though it is mathematically possible. The linear template itself is also not sacred; variants with different distance shapes exist, but the simple linear penalty is the standard starting point because it works well with minimal machinery.

06

RoPE (Rotary Position Encoding)

Rotary Position Embedding (RoPE), introduced in the RoFormer line of work (Microsoft research, circa 2021), is the positional mechanism behind virtually all widely used open LLMs today — Llama, Mistral, Qwen, and many others. Like ALiBi, RoPE bakes distance into the attention computation rather than only into static input vectors — but via rotation of query and key vectors instead of a bias matrix on QKT.

Core intuition: rotation in 2D subspaces

Partition each query and key into consecutive dimension pairs. In each pair, rotate the vector by an angle proportional to its absolute position p. In 2D the rotation matrix is:

R(p) = [[cos(pθ), −sin(pθ)], [sin(pθ), cos(pθ)]]

Rotations compose: when you form the dot product between a query at position i and a key at position j, the phase factors combine so the score depends on (i − j), not on i and j separately. Shifting both indices by the same constant leaves the score unchanged — the property relative encodings aim for.

Q(Qwen@5) · K(favorite@2) = standard_Q · R(5−2) · standard_K

High-dimensional Q/K vectors stack many such 2×2 rotation planes, each with its own frequency (θ ladder). Some subspaces capture fine positional detail, others coarse structure — analogous to multi-frequency sinusoidal encodings. θ (or the base generating the frequency ladder) is a hyperparameter; extending to much longer contexts than training sometimes requires revisiting those constants or vendor interpolation schemes.

ALiBi

Leave Q and K as usual; add a structured distance penalty to the logits before softmax. Extremely simple forward pass change; explicit linear inductive bias toward locality.

RoPE

Multiply projected Q and K by position-dependent rotations so relative offset drops out of the dot product cleanly. No large bias matrix stored — the rotation is applied on the fly per head and dimension group.

07

Comparison & Summary

  • Learned absolute: Simple but no extrapolation, extra parameters. Must fix max length at pre-training.
  • Sinusoidal: No extra parameters, some extrapolation, rarely used in modern models.
  • ALiBi: No extra parameters, additive bias after QKT, good extrapolation (~2×), per-head slope m.
  • RoPE: No extra parameters, rotation of Q and K, elegant math, relative position via rotation properties, used in all modern LLMs.

Where position enters

  • Learned / sinusoidal: Added to input embeddings before the first block.
  • ALiBi: Added to attention logits (after QKT, with mask).
  • RoPE: Applied to Q and K (or equivalently folded into how projections are computed) so dot products encode offset.

Parameters & extrapolation

  • Learned table: O(L·d) trainable offsets; hard stop at Lmax.
  • Sinusoidal: zero positional params; extrapolation mixed in practice.
  • ALiBi / RoPE: no positional embedding matrix; extrapolation behavior depends on architecture and training but avoids “missing row” failures.

Related building block (transformers more broadly): Residual connections give gradients a shortcut path through each block, mitigating depth-related optimization issues. They are not a substitute for position information — attention remains permutation-symmetric without a positional scheme — but they explain why very deep stacks are trainable at all.

The trend: From absolute → relative. From additive embeddings → multiplicative rotations. Modern models prioritize relative position and extrapolation over simplicity.

Playground

Experiment with position encodings. Visualize how different methods handle sequences at various lengths, and test what happens when you exceed training length.

Why length dominates cost: Standard dense self-attention builds an n×n score matrix (every token attends to every token, subject to masking). That means both time and memory scale quadratically in sequence length n — doubling the context roughly quadruples the attention work. Choosing a training context limit is therefore as much a hardware decision as a modeling one; methods that extrapolate beyond that limit still pay the n² bill at inference, but they avoid the separate failure mode of “no embedding row for this index.”
